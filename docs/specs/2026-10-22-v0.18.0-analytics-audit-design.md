# v0.18.0 全站统计、访问明细与操作审计设计

## 1. 意图与边界

部署者需要了解全站使用情况、检查某条短链最近的成功跳转，以及追溯谁修改了业务数据。交付三个相互关联但独立可验证的模块，沿用 Go／Chi／SQLC／PostgreSQL 和 Vue／Vuetify／TanStack Query。以下范围、权限、隐私和保留策略是本次自主设计的决定；不扩大既有访客数据采集边界，不引入第三方分析平台。

## 2. 全站仪表盘

页面 `/admin/dashboard`，导航位于管理区首项，与个人 `/console` 分开。API 为 `GET /api/v1/admin/dashboard`，要求当前有效登录用户拥有 `admin:access` 和 `statistics:read_all`。

返回 `summary`（`userCount`、`activeUserCount`、`linkCount`、`activeLinkCount`、`todayCreatedLinkCount`、`todayVisitCount`、`rangeVisitCount`）、`range`（`startDate`、`endDate`、`timeZone: UTC`）、`trend`（`date`、`visitCount`）、`topLinks`（最多 10 个，`id`、`slug`、`url`、`title`、`deleted`、`visitCount`）及 `generatedAt`。用户数排除 guest 与软删除用户；短链数量和今日新增排除软删除短链，active 仅表示保存的 active 状态。访问量统计所有成功跳转历史，包括之后被删除的短链；热门短链的删除状态明确标注，已删除项目不提供无法打开的详情入口。

日期参数 `days=7|30|90` 或成对 `startDate`、`endDate`，默认 7 天，包含结束日。区间最多 90 天，不允许未来、反向或混合输入；连续趋势补零、UTC 日界线与现有分析一致。今日卡片独立于所选区间，所有访问数仅统计 `redirect_response_sent`。不虚构 UV、在线人数、目标加载成功或机器健康指标。

多查询在一个带 5 秒上限的只读 repeatable-read 事务中完成，捕获同一数据库时间和权限快照。增加成功事件全局时间索引、未删除短链创建时间索引；聚合按范围执行，热门记录先聚合再限制，不对每条短链循环查询，不新增全生命周期事件总量扫描卡片。

## 3. 匿名访问明细

个人和管理 API 分别为 `GET /api/v1/short-link/visits`、`GET /api/v1/admin/short-link/visits`。要求 `short_link:read_visits`，再叠加 `short_link:read_own` 与本人归属，或 `admin:access` 与 `short_link:read_all`。不存在、软删除和越权链接沿用短链不存在语义；新查询不使访客获得任何访问数据。

参数包括 `id`、同上日期范围、`pageSize`（默认 25，1–100）、可选 `cursor`、`deviceType`、`countryCode`。设备接受现有分类及 `unknown`；国家只接受两位大写 ASCII 代码或 `unknown`，空值与未知值区分。重复、显式空值、非法日期、UUID、枚举、页大小或游标在数据库操作前拒绝。

响应 `items` 包含 `id`、`occurredAt`、`referrerHost`、`deviceType`、`browserFamily`、`osFamily`、`countryCode`；同时返回 `range`、`pageSize`、`hasMore`、`nextCursor`。未知维度为 `null`，由客户端本地化。按 `(created_at DESC, id DESC)` 唯一稳定排序，读取 pageSize+1，不使用深 offset 或为分页执行全量 count。游标为有界 base64url JSON 的时间和 UUID，不作为任何授权证据；每次查询重新检查账号、权限、归属、范围和过滤条件。

明细位于现有个人／管理单链分析页的“访问记录”区域，不新增全局个人分析导航。日期沿用已应用范围，范围／筛选／链接／身份变化清空游标历史。显示真实时间和匿名维度、前后翻页、空数据与失败重试，不把请求错误渲染为零访问。

`00020` 增加可空 `browser_family`、`os_family` 字段；新事件只保存有界分类名称，去除版本与任意 UA 文本。分类取稳定白名单（主要浏览器与操作系统，其他已识别值归 other，缺失为 unknown）；机器人显示 bot，不能将完整 UA 原样落库。现有 Referer 主机、设备及可信国家规则不变。聚合、访问额度和最终响应后记录时机不变，旧事件不回填虚构维度。

访问明细复用原事件，不另存个人识别信息。原事件长期保留和全生命周期聚合行为不改；本版限定单次读取范围，不对旧数据执行自动删除。未来如需事件保留期，须先设计不损坏历史总量的归档／聚合方案。

## 4. 权限与迁移

新增可配置 `short_link:read_visits`，属于 short_link_basic，user／admin 默认拥有，standard 包含，guest／basic／restricted 不含。新增受保护 `statistics:read_all` 与 `audit:read`，属于 administration，只允许 admin 拥有且不能移除。更新真实数据库迁移、Go 目录／验证、前端类型／翻译和生成的权限 fixture；不手工编辑生成物。

`00020` 同时追加新权限及统计字段／索引，权限回滚沿用 UPDATE 编辑追踪，Down 只撤销本迁移追加且未独立编辑的授权，不移除迁移后单独授予的权限。真实数据库测试覆盖 Up、Down、再次 Up、人工编辑保留和默认组预设一致性。

新查询都拒绝缺失／无效／停用／软删除账号，并重查数据库当前组与权限；不会仅信任客户端、旧 session 组名或前端缓存。普通用户不能查询其他用户的访问记录，管理员也必须满足具体能力。HTTP 沿用统一业务 envelope、`100001` 无效输入、`120001` 无权限、基础设施 500；不符合基础登录／后台访问规则的 401／403 沿用现有 middleware。所有响应 no-store。

## 5. 审计事务与覆盖面

`00021` 新增 `audit_log`：递增 bigint ID、可空操作者 UUID、资源类型／ID、动作、变更字段数组和 UTC 创建时间。操作者为空表示明确的系统供应／初始化，不伪装为某个用户；读取时可关联当前用户名供管理员识别，UUID 保留且不因用户删除级联丢失日志。日志不引用可级联删除的业务外键，不复制秘密或业务值。

采用事务级上下文与精确字段触发器：`internal/db.WithAuditTx(ctx,pool,actorID,fn)` 校验 actor UUID，开启事务、设置事务局部的审计启用标志及 actor，再执行现有业务，统一提交或回滚；空 actor 仅用于明确系统操作。不得对池连接设置持久 GUC。已有跨层事务可用 `WithAuditActor(ctx,actorID)` 传递标记，由 `WithTx` 在开始后设置局部上下文；OIDC Provider 的事务 store 必须保留同一 ctx，Create 也必须经事务 wrapper。手工 Begin 的已存在事务使用 `SetAuditContext(ctx,tx,actorID)`：自助改密在重新验证账号／会话之后绑定真实账号，错误密码仍提交失败计数，成功修改凭据及撤销会话与审计一起提交或回滚，不能直接替换为“返回错误全部回滚”的 callback。

触发器仅在显式审计上下文启用时写入。数据库管理员直接 SQL、历史 migration 和测试 fixture 不在应用操作审计保证范围内。所有下列应用写入必须使用该上下文，不允许依靠触发器自行猜 actor；强制 audit insert 故障时原业务应回滚，事务回滚也不能留下日志。

| 表／操作 | 必须覆盖的应用入口 | 记录语义 |
| --- | --- | --- |
| short_link | 个人／管理创建、更新、单删、批量启停／软删除 | create、update、enable、disable、delete；仅有 visits_used 领取变化时不记录 |
| app_user | 管理员创建、资料／状态／密码重置、自助昵称／密码更新、OIDC 首次供应 | create、update、enable、disable、credential_change；无密码值／哈希 |
| user_group | 内置组权限修改 | permissions_change；不受迁移触发器重复编辑影响 |
| domain、domain_user_group | 创建、编辑、启停、删除、默认切换、组授权 | create、update、enable、disable、delete、assignment_change；默认切换在同一事务产生相关资源记录 |
| system_setting | 初始化及管理员可编辑系统设置 | settings_change；仅记录键，跳过内部 revision 与实现细节标记 |
| oidc_provider | 新增、修改、启停、删除 | create、update、enable、disable、delete；Secret 只标记变更字段 |

只记录实际业务字段变化；仅更新时间变化的 no-op 不写日志，语言／主题个人偏好、访问次数领取、后台过期清理和 auth_session／登录失败计数不生成操作噪音。用户主动修改密码仍为 credential_change。域名授权由原有“全部删除再插入”改为同事务集合差量增删：相同集合不写授权记录，仅改显示名称不能伪造 assignment_change。批量操作按每条资源写入，最多 100 条，与原整批原子语义一致。触发器 whitelist 只生成资源标识、动作和字段名，不使用 `to_jsonb(NEW)` 或请求体快照持久化。

`00021 Down` 先阻止并发审计写入，再检查 audit_log；存在审计记录时安全失败以保护历史，空表时可正常回滚／再次升级。支持的旧应用回退保留兼容 schema，不提供直接清空日志的在线绕过步骤。

## 6. 审计查询与保留

API `GET /api/v1/admin/audit/list`，要求 admin:access 和 audit:read。参数为同上日期范围、pageSize／cursor、actorId（UUID）、resourceType、action，资源和动作必须属于公开目录。按创建时间和递增 ID 倒序游标分页，ID 以十进制字符串返回避免 JS 精度损失。响应包含 `items`（id、actorId、actorUsername、resourceType、resourceId、action、changedFields、occurredAt）、range、pageSize、hasMore、nextCursor、retentionDays:180；仅使用固定字段，不返回前后值。

页面 `/admin/audit` 位于“系统维护”，只读查询与筛选，显示未知／系统操作者及已删除资源，不提供修改和删除按钮。记录会包含敏感操作的存在，因此权限、身份变化和网络失败时不能展示旧身份缓存。

新日志保留滚动 180 天，API 总是排除早于保留截止时间的数据。应用新增每小时清理周期，每周期最多 4 批、每批 500 条，少于 500 条提前结束；整个周期 10 秒超时，退出取消可中断，失败只记录无敏感内容的错误且不阻塞请求。通过 `(created_at,id)` 索引按最旧记录清理。业务审计是事务内写入，清理是独立维护操作，不将二者混为 best-effort。

## 7. 前端、失败与性能

复用现有控制台 Shell、日期筛选、Chart.js、Vuetify 表格和可堆叠 Toast；表格仅在容器内横向滚动，长主机／UUID 省略并保留 title。受保护的新入口与路由使用相同权限交集。服务器状态只放 TanStack Query，key 包含身份作用域、资源、日期、过滤和游标；已确认退出／换号／撤权立即隐藏旧数据，迟到响应不能重新展示。

不新增外部依赖、不加载外部地图或字体。所有查询设置 5 秒上限；范围、pageSize、游标长度和分类字段均有界，排序有唯一 tie-breaker。测试使用真实 PostgreSQL 18 验证查询／回滚／批量原子性，使用受控同步验证并发和取消，不靠固定 sleep。

## 8. 验收与运行

从真实入口覆盖管理员仪表盘、普通用户自己的访问明细、越权／撤权、桌面／移动查询和审计生成／筛选。事件尽力写入导致短暂延迟时用有界条件轮询，不把等待超时改为成功。审计需要覆盖触发器 whitelist、各类写入接线、实际变更/no-op、失败回滚、游标并列时间、分页期间新增、保留期、权限目录生成、迁移回滚保护和清理取消。

保持现有 Go 与前端 100% 业务覆盖率阈值，不排除可测试分支、不新增无价值镜像测试。阶段证据、命令、候选、环境和清理分别记录，当前基线的 CI 不替代新分支门禁；功能完成、合并和正式发布分开。
