# 权限模型

## 权限优先

MoeURL 的核心控制逻辑是权限系统。

凡是涉及「能不能使用某个功能」「能不能使用某个域名」「能不能使用某种跳转方式」「能不能配置某类跳转页」的问题，都应优先通过权限系统表达。

系统不单独设计「是否允许游客创建短链」这类割裂配置。游客能力由内置的 `guest` 用户组和 `guest` 用户决定。

## 内置 guest 身份

系统内置两个不可删除对象：

- `guest` 用户组
- `guest` 用户

所有未登录访问者都视为 `guest` 用户，并继承 `guest` 用户组的权限。

`guest` 用户组默认启用，但默认不开放任何实际操作能力。也就是说，未登录访问者默认可以浏览首页、登录、切换语言和主题，但不能创建短链、使用域名、查看统计或执行其他需要授权的操作。

后续如需开放游客能力，应直接调整 `guest` 用户组权限，例如：

- 是否允许创建短链。
- 是否允许自定义短码。
- 是否允许使用指定域名。
- 是否允许使用指定跳转方式。
- 是否允许创建带访问密码的短链。
- 是否允许查看短链统计。
- 每日可创建数量。
- 短链默认有效期。

`guest` 用户是系统内部身份，不允许直接登录，不允许修改资料，也不允许删除。若后续开放游客创建短链能力，游客短链默认归属于内置 `guest` 用户；是否支持游客短链认领到登录用户，属于后续扩展能力，初版不要求实现。

## 用户类型

系统初版建议包含以下用户类型：

| 类型 | 说明 |
| --- | --- |
| guest | 内置游客用户，代表所有未登录访问者。 |
| 普通用户 | 通过本地登录或外部登录进入系统的常规用户。 |
| 管理员 | 拥有系统管理能力的用户。 |

后续可以扩展更多类型，例如团队成员、审计员、高级用户等。

## 用户组

用户组用于统一配置权限。

系统至少包含：

| 用户组 | 说明 |
| --- | --- |
| guest | 内置不可删除用户组，控制未登录用户能力；默认启用但默认无实际操作权限。 |
| user | 普通登录用户默认用户组；默认具备创建短链的基础能力。 |
| admin | 管理员用户组；具备系统最高管理能力。 |

v0.0.1 阶段，一个用户只启用一个主用户组。用户最终权限由主用户组决定，初版不设计针对单个用户的功能授权例外。

工程模型不应把「单用户组」写死为不可扩展约束。后续如需支持团队空间、组织角色、审计员、高级用户或套餐能力，可以在主用户组模型之上演进为多用户组、团队角色或组织级权限。

v0.5.0 只管理 `guest`、`user`、`admin` 三个内置用户组。管理员可以查看三个组，并调整 `user` 和 `admin` 的可配置权限，但不能创建、删除、重命名用户组或迁移成员。`guest` 在访客短链归属和滥用防护实现前固定为空权限且保持只读。权限写入使用数据库中的 `updated_at` 做乐观并发，避免两个管理请求静默覆盖。

## 权限分类

权限可以按模块划分。

### 短链创建权限

- 创建短链。
- 自定义短码。
- 使用随机短码。
- 设置短链标题。
- 设置短链备注。
- 设置短链标签。
- 设置短链有效期。
- 设置最大访问次数。
- 创建长期有效短链。

v0.2.0 首次落地以下增强权限标识：

- `short_link:use_intermediate`：创建或编辑中间页跳转短链。
- `short_link:set_expiration`：创建或编辑带固定过期时间的短链。

内置 `user` 和 `admin` 用户组默认拥有这两项权限，`guest` 默认不拥有。直接跳转继续作为既有短链创建能力的默认行为，避免破坏升级前实例的权限兼容性。二维码仅编码公开短链 URL，不形成新的服务端业务能力，因此不增加独立权限。

有效期相关能力边界如下：

- 设置短链有效期：允许用户手动选择过期时间。
- 创建长期有效短链：允许用户选择无固定过期时间。
- 短链默认有效期：用户未手动设置时，由系统或用户组提供的默认值。

### 访问条件权限

v0.3.0 新增 `short_link:set_password`：允许创建或编辑受密码保护的短链。内置 `user` 和 `admin` 用户组默认拥有该权限，`guest` 默认不拥有；密码保护属于独立访问条件，不形成新的跳转模式。

### 跳转方式权限

- 使用直接跳转。
- 使用中间页跳转。
- 使用确认页跳转：由 `short_link:use_confirmation` 控制创建和编辑。
- 使用指定跳转页模板。

普通用户只能选择自己可用的跳转方式和模板，不能任意自定义系统跳转页。

当前实现中，直接跳转不要求额外高级模式权限；中间页和确认页分别由对应的跳转方式权限控制。用户失去高级模式权限后仍可把自己有权更新的短链切回直接跳转。

### 域名权限

- 使用指定域名。
- 设置个人默认域名。
- 管理域名。

域名使用权限严格基于用户组分配。不存在「管理员专属域名」这类独立逻辑；如果某个域名只允许管理员使用，应将它配置为仅 `admin` 用户组可用。

初版不允许用户绑定自己的域名。所有可用域名由管理员统一管理，并按用户组分配使用范围。

### 统计权限

- 查看自己的短链基础统计。
- 查看自己的短链基础维度统计。
- 查看自己的短链完整详细统计。
- 导出统计数据。
- 查看全站统计。

### 模板与主题权限

- 使用系统跳转页模板。
- 使用指定模板的可编辑元数据。
- 管理跳转页模板。
- 管理站点主题。
- 管理系统页脚。
- 设置自定义 Open Graph 信息。

系统页脚配置属于主题配置的一部分，只允许管理员配置。普通用户不应拥有独立修改系统页脚的能力。

### 管理权限

- 管理用户。
- 管理用户组。
- 配置用户组权限。
- 管理全部短链。
- 管理全部域名。
- 管理系统配置。
- 管理系统主题。
- 管理登录、安全和访问策略。
- 查看审计日志和操作记录。

v0.5.0 已将 `admin:access`、`short_link:read_all`、`short_link:update_all`、`short_link:delete_all` 定义为受保护管理权限：`admin` 必须拥有，`guest` 和 `user` 必须不拥有。保护规则只约束权限配置写入；所有管理业务仍按当前权限快照检查 `admin:access` 和对应能力，不能按用户组标识直接放行。

## 权限预设

为了降低管理员的配置心智负担，系统可以提供预置权限模型，用于快速套用常见部署场景。

v0.5.0 已交付三个内置预设：

- `restricted`：不包含可配置业务权限。
- `basic`：允许创建、查看、更新和删除自己的短链，并允许使用默认域名。
- `standard`：包含当前全部可配置业务权限，与内置 `user` 的默认能力一致。

预设只适用于 `user` 和 `admin`。套用预设只替换当前编辑草稿中的可配置权限，受保护管理权限保持目标用户组的固定归属。管理员必须主动保存后才写入数据库，预设本身不成为新的授权层或数据库字段。`guest` 只展示固定 `restricted` 状态。

远期预设可以继续覆盖以下部署场景：

- 公开展示站点：`guest` 默认不可创建，仅展示首页和登录入口。
- 公开免费站点：`guest` 可创建基础短链，但受数量、频率、域名和跳转方式限制。
- 仅登录用户：`guest` 不可创建，普通用户可创建和管理自己的短链。
- 团队内部：仅指定用户组可创建短链，并限制可用域名和跳转方式。
- 管理员私有：仅 `admin` 用户组可创建和管理短链。

预置权限模型只是快速初始化和批量配置工具，不替代底层精细权限控制。管理员套用预设后，仍应能继续调整每一个具体权限项。
