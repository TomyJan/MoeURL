# v0.75.0 CSV 过期时间导入设计

## 决策与现有结构

在现有 linked worktree 内联执行，沿用 Go／Chi／SQLC／PostgreSQL、Vue／TanStack Query／i18n，不新增依赖。持续无人值守授权覆盖常规设计、提交、正常集成和精确清理；这是 Agent 的设计选择，不写成用户逐项批准。只有版末一次 fresh 最强整分支终审，不派 builder、逐任务代理或复审。

CodeGraph 与当前源码已核：`bulk_create_service.go` 的共享事务依次锁目标规则、配额、域名创建 gate、账号和组；模式授权在回执查询前。`GetDatabaseTime` 已使用 `clock_timestamp()`，可由绑定事务的 queries 取锁后真实数据库时刻。`CreateBulkShortLink` 的 expires_at 目前固定 null。新能力只扩这一私有事务和查询参数，不改五个旧 wire DTO。

## 严格时间与线协议

新增 `BatchCreateExpirationItem`、`BatchCreateWithExpirationsInput`、`BatchCreateWithExpirations`，外层恰 `requestId/items`，每项恰六字段。tags 仍为非 null、最多 10 项的字符串数组，其余字段为字符串。沿既有 64 KiB、20 行、唯一网址、标题／标签／短码、UTF-8／surrogate、重复未知键与尾随 JSON 拒绝规则。

新增 `parseBulkExpiration(value string) (pgtype.Timestamptz, error)`：空返回无值；非空必须恰 20 个 ASCII 字节、时间能以 `2006-01-02T15:04:05Z` 原样往返且年份非 0000。只允许 UTC 整秒，避免浏览器本地时区、宽松日期归一化和 PostgreSQL 微秒舍入。语法非法返回 ErrInvalidInput，已过去或等于数据库时刻返回 ErrInvalidExpiration（200108）。前端同一严格日历规则，但不以 Date.now 拒绝输入；用户在预览期间等到过期，由后端明确整体拒绝。

normalize 复用五列验证，保留原文六字段，摘要为 `SHA256("moeurl:bulk-create:expirations:v1:" + Go JSON 原始有序 items)`。空过期与其他协议仍为不同摘要；旧五种摘要逐项保持。新 DTO 不把时间直接解码为 time.Time，避免格式别名或原文丢失。

## 事务与重放顺序

prepared item 增加 `ExpiresAt pgtype.Timestamptz`；私有 options 增加 `Expirations bool`，只有新入口为 true。所有旧入口显式保持旧 flags，新项默认无过期。

1. 现有锁序及当前账号／组状态保持；先核四项基础能力与实际行的模式能力。新协议存在任何有效非空时间时，还要求当前 `short_link:set_expiration`，即使重放也必须检查。
2. 以原 actor/requestId 查询回执并比较摘要。成功命中即返回原创建数量，不因既有短链后来过期而拒绝，不再次消费配额、审计或链接。
3. 回执不存在且有非空时间时，仅一次 `q.GetDatabaseTime(ctx)`；q 绑定当前事务。每项非空时间必须严格大于该时刻。锁等待跨过截止时间则拒绝，不能借事务开始时刻或宿主时钟。
4. 现有域名／七规则／配额／短码分配与全部写入保持同一事务。SQLC `CreateBulkShortLink` 增加 `sqlc.narg(expires_at)`，旧调用传无值；中间页仍固定 5 秒。标准 SQLC 1.30.0 生成及第二次全生成物零漂移，不手改生成物。

不在日志／回执额外返回目标或时间原文，不新增审计动作或权限。参数化查询无字符串插值。数据库、链接、审计、配额或回执写入失败全部回滚。

## 前端与生命周期

新增独立 strict schema、client 和 `expirations` Protocol。parser 只接受精确第六个表头，不把六列降级五列；保持五份旧模板逐字节。第六份模板放示例未来 UTC 与空值；帮助说明只接受 UTC 秒、空时间无固定期限、服务器决定是否过期、中间页仍 5 秒。

预览每行以纯文本显示实际模式及原始 UTC 时间，空值显示本地化“无固定过期时间”，不自动转换到显示偏好时区，避免误认文件原文。完整请求深冻，含每项与 tags，未来 JSON 编码体也限制 65536 字节。

`useBulkCreate` 保留全部现有 guard，新增独立 expirationEpoch；异步读文件开始记录该值，解析后仅实际非空时间需要当前权限和 epoch 未变。存在实际过期值的 importedItems/snapshot 在撤权时同步清空；空时间、已清除旧导入后的手动或低权限草稿不得误清。恢复权限不使旧读取复活。preview 和 mutationFn 同步再检查 cache。200108 显示“至少一个过期时间已到，请放弃本次预览并修改后重试”，保留明确失败批次的编辑入口；unknown 始终保留原 UUID／端点／payload，不能被后续明确错误洗掉。

## 验证重点

- 通过真实 app HTTP 在端点不存在时取得业务 RED，再验证三种模式、空时间／未来时间和精确持久化、原子回执与审计。
- 真实 PostgreSQL 锁队列下撤销账号、组或过期权限；重放在授权之前不能返回回执；锁等待跨过截止时间不能使用过时“现在”。用数据库条件／锁观测同步，不固定 sleep。
- 成功后等待数据库时刻越过截止，再以原 requestId 重放，返回原回执且链接／审计／配额不增加；修改时间或跨六个协议重用键均冲突。
- 严格日期矩阵包括闰日、年0000、非法月日、闰秒、小写、偏移、分数秒、空白；65536/65537 文件与 JSON 双预算、20/21 行、恶意 quoting、标签和单词纯文本。
- epoch 撤销／恢复间的迟到 File、未知重试及双身份 success/error/finally、清空旧快照后的低权限草稿均有行为测试。
- 准确新 app/web 产品，Goose 仅闭包相同才复用；真实入口验证过期拦截不计成功访问，UTC 及空值存储，双语1280/390布局、窄屏20行、明确过期后修改及原回执重放。保留原图并准确清理产品资源。
