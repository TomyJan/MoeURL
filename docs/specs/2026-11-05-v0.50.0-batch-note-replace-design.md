# v0.50.0 批量替换内部备注设计

基于 PR269 已交付的 master `4b5d4dc4db6d14a430cdc3cdf7238f3d9516da77`，由执行者依据路线图和无人值守授权自主选择。见[范围](../product/scope-v0.50.0.md)、[计划](../implementation/v0.50.0-plan.md)与[验收](../implementation/v0.50.0-acceptance.md)。

## 选择与范围

当前批量清空已交付，统一替换仍需逐条操作。优先统一替换：当前页选择 1–100 条，在本人／全站列表输入同一备注，实际预览变化数，再显式确认覆盖。比直接提交多一道核对，比追加避免分隔符、重复追加和超长组合的新语义；历史留存需要独立隐私策略，本版不做。

不新增 schema、migration、权限、依赖、跨页全选、撤销、历史、导入导出、后台任务或公开行为。单条编辑和现有批量清空协议不变；空白内容走已有“清空备注”入口，替换拒绝规范化后空串。BOM 仍不是 Go 空白，允许其作为非空文本。

## 流程与确认

工具栏“替换备注”／“Replace notes”打开独立对话框，固定目标 id 和列表主版本。输入框接入现有 shortLinkNoteSchema，服务端沿用 normalizeNote：CRLF 转 LF；控制字符先拒绝，仅 LF/TAB 放行；再 Go TrimSpace，最多 1000 Unicode 码点。客户端与后端保持同一规范化结果。

第一步输入非空新备注；“预览变更”发送实际只读请求，显示选中数、将替换数及相同无需更改数。只显示用户自己输入的文本，绝不返回或展示目标旧正文。全部相同不显示写按钮。明确提示“这会覆盖所选内部备注，无法撤销。”，不能把关闭描述成撤销写入。

草稿任意改动同步退休旧预览及在途读请求，即使改回原值也要重新预览。确认时固定规范化正文与本次预览全部备注版本，不重新读取可变输入。双击和排队事件只能发一次。写入期间禁止改草稿和普通关闭；身份／授权退休始终清除私密状态。

传输失败、5xx 或成功响应畸形为未知结果。固定目标和正文，冻结确认与编辑，允许关闭或“重新核对”。后者仅实际重新预览，失败仍未知；成功只展示新数量，用户仍须再次确认才能写。冲突或资源不可见时退出本次确认，刷新后重新选择，不悄悄换掉主版本。

桌面／手机、中英、键盘和焦点恢复遵循现有清空对话框。初始焦点置输入框，提交并非默认回车动作；安全取消可用。关闭后回到仍属于当前身份的入口，否则到列表焦点容器。成功清选择和刷新，保持筛选／每页大小；按真实刷新结果归一化页码。

## 精确接口

本人 POST /api/v1/short-link/note/batch-replace/preview 与 POST /api/v1/short-link/note/batch-replace；全站固定 /api/v1/admin/short-link/note/batch-replace 同名路径。不接受 scope／actor 字段。

- 预览输入：{items:[{id,expectedUpdatedAt}],note}。
- 预览输出：{items:[{id,expectedUpdatedAt,expectedNoteUpdatedAt,willChange}],changedCount,unchangedCount}。
- 写输入：{items:[{id,expectedUpdatedAt,expectedNoteUpdatedAt}],note}。
- 写输出：{changedCount,unchangedCount}。

note 仅存在于输入，不在响应、错误、审计、URL、storage、列表、CSV、统计或公开 DTO 中。预览按输入顺序返回准确同一 ID 集合；主版本表示与选中时相同的完整时刻，不能由预览替换旧主版本。计数为 0–100 整数，总和等于目标数，changedCount 精确等于 willChange 的真值数。客户端严格验证所有字段，失败错误不携带响应正文或元数据。

JSON 原始上限 65536 bytes；拒绝 unknown／duplicate keys、null、错误类型、尾随 JSON、坏 UTF-8 和未配对代理字符。items 为 1–100 唯一规范非零小写 UUID。完整版本沿用 parseNoteVersion／noteVersionSchema：保留纳秒精度和原 CAS 字符串，等价 offset 可接受，差 1ns 必冲突。application/json、无 query、Cookie Session、身份绑定 header 和 no-store 沿用旧规则。

复用错误码 100001／200104／200116／120001 及既有基础登录／基础设施状态；不暴露单个失败 ID、旧正文或当前版本。

## 授权与事务

权限与单条备注写入相同：本人 read_own＋update_own＋set_metadata；全站 admin:access＋read_all＋update_all＋set_metadata。每次重查 active、未删除、非 guest 账号及组当前权限，客户端快照不授权。

总期限五秒。锁序 actor share→当前组 share→UUID 排序完整目标锁；预览 share，写入 update。新增 SQLC 比较查询仅投影 ID／owner／主版本／备注版本／note <> replacement 的 willChange，不向 service 取旧正文。先核完整集合和所有 owner／可见性，再核所有主版本，写入再核所有备注版本，全部核完才改实际变化项。

预览 WithTx，不设置审计 actor，不开启 PostgreSQL READ ONLY（行锁不允许）；写入 WithAuditTx。只调用现有 UpdateShortLinkNote：变化推进 note_updated_at，主版本及其他字段不变；相同 no-op 不推进版本且无新审计。审计仅 actor、资源、note 字段名。错误、取消、审计拒写和连接故障全部事务回滚。

两次同版本非 no-op 替换至多一方成功，另一方冲突；相同 no-op 仍检查双版本。与单条编辑／清空／其他批量互相遵守现有锁序。缺失或不可见优先于版本冲突，避免输入顺序泄露。

## 前端状态

独立 batch-note-replace entity、useBatchNoteReplace controller 和 BatchNoteReplaceDialog；复用既有规范化／版本解析，不把新行为塞进旧清空 controller。捕获身份 epoch、实时授权签名、打开代际、草稿代际和请求编号；所有 success／error／finally、toast、cache 和锁均检查同一 capture。

实时撤权再恢复、ABA 登录、卸载、关闭重开、筛选／页／大小变化均退休旧上下文。预览不进共享缓存、不持久化。对外只暴露只读草稿和同步 setter，组件不能直接改 ref 绕过代际更新；setter 在 saving／unknown 时拒绝编辑。同步草稿更新使旧预览、旧请求和排队确认失效；旧 finally 不清新 pending。清空／替换与全部既有写、创建、导出、QR 及筛选／分页双向互斥，包括排队动作。

## 自检结论

规范化后而非原始空白判断是否可预览；规范化相同的草稿编辑也退休旧预览，避免 ABA。未知写期间禁编辑防止用新草稿掩盖旧结果。必须核全部目标版本，即使某项当前已等于新正文。服务端不信任客户端预览计数；写时以锁后数据库比较实际变化。草稿不是服务端签名 token，API 保持双版本显式写契约，不声称预览对外部客户端是额外授权层。
