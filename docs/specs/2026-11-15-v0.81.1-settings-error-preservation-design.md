# v0.81.1 访问配置测试错误保留设计

## 原因与边界

v0.80.1 浏览器测试的列表刷新断言位于 try 中，finally 内顺序释放请求并恢复网络。若业务断言已失败且 `setOffline(false)` 再失败，JavaScript 的 finally 拒绝覆盖原业务错误；外层虽然仍能失败并清理，但丢失首个故障上下文。这是已延期的测试诊断 Minor，不是产品保存或权限缺陷。

Agent 选择在现有 `web/e2e/settings-dialog-cleanup.ts` 中增加测试专用 `withSettingsCleanup(body, steps): Promise<void>`，不把它加入产品代码。另一方案是只在 spec 内联收集错误，无法从现成 Node 测试直接执行实际消费逻辑；通用资源管理框架又超出此次单场景需求，因此均不采用。

## 精确行为

`body` 为无参数、返回任意值或 Promise 的回调；`steps` 复用现有顺序清理回调类型。先 await body，捕获任意抛出值放入数组，包括 undefined／null／0。随后调用现有 `collectSettingsCleanupErrors` 顺序尝试所有 steps；任一步同步抛出或异步拒绝均追加原值并继续。

无错误时 resolve void。有错误时抛一个 AggregateError，errors 按原始错误后各步错误的顺序排列，保留对象身份；不 flatten 任意用户 AggregateError，不把它改成字符串，也不以错误值的 truthy 判断是否失败。包装只承诺保留诊断与执行清理，不重试业务或写操作。

实际 spec 将内层 try/finally 换为包装，清理回调分别为 `releaseList?.()`、`context.setOffline(false)`。原断言、请求截留、原生 wheel、完整保存 payload、外层 catch 及全部外层清理不弱化。包装抛出的聚合错误被原外层收集，因此首错仍可沿 errors 链读取，外层附件／删除／close 继续。

## 验证

先在 Node 用真实临时文件副作用、原 Error 对象及拒绝值运行旧 try/finally 基线，证明原错被覆盖的行为 RED；之后实现最小收集并通过。具名覆盖业务／恢复同时失败、仅业务失败、仅清理失败、无错误、同步抛出／异步拒绝、假值 rejection 和后续文件清理。不得以缺失 import 或类型错误冒 RED，不断言被测源码包含某行。

完整 Node 脚本套件、受影响 E2E strict／lint 后，准确恢复已交付 0.81.0 产品，逐 hash 核 102 个产品文件，无编译或依赖安装。用新测试提交跑原 setup 与中英320×500、390×800、1280×900六个场景，保留完整 HTTP／几何与必要原图；Node 受控失败组合证明异常路径，正常浏览器证明真实接线，二者不互相冒充。复用原 smoke／扫描／产品套件只按完整投影与原执行身份归属。
