# v0.65.0 本人每日创建用量设计

## 目的与边界

用户在创建前能看见当天已用与剩余量，减少遇到耗尽错误后的困惑。只增加现有 `/console` 的独立只读卡片，不新增固定前端路径、不改创建授权、计量、回执、管理员保存或数据库 schema。沿 Go／SQLC／PostgreSQL 和 Vue／TanStack Query／Vuetify／i18n，不加依赖。

这是 Agent 在持续自主开发授权下选择的增量，未声称用户逐项批准。相比扩展原概览 DTO，独立资源让失败、授权和身份缓存有明确边界；相比创建入口轮询，不增加后台流量或把快照误当授权。

## API 与数据

`GET /api/v1/account/daily-create-usage`，拒绝所有查询参数（包括空问号），不接受 actor ID。成功 `200/code=0`，data 恰为 `{usageDay: "YYYY-MM-DD", used: "0", dailyLimit: null, remaining: null}`。`used` 为 0 至 int64 最大值的规范十进制字符串，避免 JavaScript 精度丢失；上限为 null 或 0–1000000 整数，有限剩余量为 0–1000000 整数。返回数据库当前 UTC 日（有效年份 1–9999），不随账号时区转换。

Cookie 当前身份决定资源所有者。可选 `X-MoeURL-Expected-User-ID` 仅用于拒绝旧浏览器身份：缺省保留当前本人语义；存在则必须恰一个且精确等于当前有效规范 UUID，空值、重复值或不匹配拒绝。浏览器始终传捕获的当前 UUID；该 header 不能选择他人。后端在数据库重新检查 active、未删除、非 builtin 账号及当前组的 `short_link:create`，不信请求中的旧权限，不硬编码 admin；缺身份或撤权返回 `200/120001`。

独立 `UsagePort.GetOwnUsage(context.Context, auth.CurrentUser) (Usage,error)`、UsageHandler 以及 router/app 注入，不扩大管理 Port。五秒有界 readonly RepeatableRead 事务读取当前身份／权限、严格策略、本人可选计量行和数据库 UTC 日。无 `FOR UPDATE`、Ensure、UPDATE、审计或缓存。缺行或有效历史日为 0；当前日为原 used。任何负 used、无效／无穷／未来日或坏策略均 `500/900000`，不以历史分支吞掉坏计量。非法 query 为 `200/100001`。全部响应 no-store，日志只有不透明事件与 request ID，不含用量或身份明细。

结果为事务快照：并发创建或管理员改额可能在读取后发生，创建仍执行现有最终校验。读取不与写入争夺配额行锁。UTC 日界的验证使用真实数据库历史行和受控日期边界；除非实际执行，不能宣称等待午夜跨日验证。

## 前端

独立严格 entity 解码恰四字段，验证规范日期、int64 字符串、nullable 配对和剩余量关系；使用 BigInt 比较，不把已用转 Number。调用共享 apiGet 的既有 headers 参数，不改共享 client。

`OwnDailyCreateUsageCard.vue` 放在概览指标与最近短链之间。只在真实当前身份且当前 auth/me 具有 create 权限时读取；卡片不显示他人、访客或无权限数据。query key 含本人 UUID 和身份 epoch，响应必须仍属于当前 scope／请求代次。retry=false、refetchOnWindowFocus=false、refetchOnReconnect=false；仅初次挂载及主动刷新。刷新中先隐藏旧数字，失败显示局部错误，不回退旧快照或伪 0。授权失败清私有数据并停用当前轮，主动恢复先获取新的 auth/me，只有仍有权限才读取。

身份／权限变化及卸载清本卡片 cache、取消并退役 pending 请求；同一账号退出再进入也不能复用旧结果。成功显示 UTC 日期、已用、有限上限／剩余或“无限额”，并说明按创建时校验。无剩余额度的快照不禁创建、不自动重试。长数字换行可读、按钮有可访问名称，原四指标及最近短链独立运行。
