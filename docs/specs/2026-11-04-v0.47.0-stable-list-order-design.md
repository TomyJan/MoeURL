# v0.47.0短链列表确定顺序

基线为 PR260 已验 master `47e170b455e6b2a8d02d89bcbdaef15a63b06df3`。当前设计启动，测试和交付分别按实际证据判定；未宣称复现旧故障。

## 目的与选择

v0.45 引入分页，v0.46 扩展备注交集查询；两者底层列表只按创建时间倒序。PostgreSQL 不保证同时间记录之间的顺序。CSV 已用创建时间、UUID 倒序。本轮自主选择把相同规则用于列表，使不变数据集的重复读取和页界具备确定顺序。这是新保证，不将历史“未实证风险”改称已证实漏项。

比较后采用最小两字段排序：保留单字段排序无法定义同时间先后；改用 keyset 或快照令牌会扩大 API、界面和并发语义。UUID 是唯一、非空且既有的次级键，不需迁移或新增序号。

## 契约

- 本人和全站的普通列表、备注关键词列表统一按 `created_at DESC, id DESC` 返回。
- 在数据及过滤条件不变时，各页联合集合按上述顺序排列，重复请求一致，不重不漏。仍不保证并发新增、删除或修改期间的跨请求快照。
- 固定界面每页 20 条、API 原有分页规范、筛选交集及授权均沿用；有无备注筛选和私密搜索保持既有五秒授权／count-data 快照，普通空备注条件 GET 不扩大事务保证。
- CSV 不改顺序和 17 列契约；备注正文、私密查询词及敏感凭据不进入列表或 CSV。
- 不新增接口、字段、迁移、索引、权限、依赖或界面。性能仅能记录实际验证，不能声明生产大规模性能已验证。

## 验证设计

服务测试 `TestListCreatedAtIDOrderAcrossPages` 使用隔离 PG、真实数据库权限服务和两名账号。fixture 至少 43 条目标记录，固定 UUID 尾号 1..43，创建时间为三个可核时间组；写入顺序与期望不同。期望由预先列明的组和 UUID 序号独立构造，禁止通过被测列表或同一 SQL 计算。额外他人及软删记录验证边界；用专属标签隔离既有 fixture。

普通本人／全站和备注查询本人／全站各读第 1..3 页（20/20/3）与空第 4 页，核 total、每页确切 ID、联合不重复／遗漏，再按 3、1、2 顺序重读。备注查询包含 literal `%_\\` 私密 canary；元数据和 CSV 不得包含 canary。CSV 全量按同一独立期望核顺序及 17 列；已有权限／状态／标签／撤权测试继续保留。

真实 HTTP 测试 `TestShortLinkListOrderRoutes` 用 newTestApplication 和真实登录 Cookie，受控写入同时间记录，通过本人／全站 GET 与备注 POST 核确切 ID、total、无私密字段和 no-store。请求参数以当前路由实读为准，不猜 URL。

先运行真实测试，区分缺排序导致的目标 RED、fixture 或环境错误以及首次即通过。若首次通过，仍可为确定顺序契约补最小排序，但不得伪 RED；测试应能抓住去掉次级键的现实变异。不得靠固定 sleep、物理返回偶然顺序或查询计划文本刷门禁。
