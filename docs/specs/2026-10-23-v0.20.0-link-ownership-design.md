# v0.20.0 短链归属转移设计

## 意图与盘点

管理员处理离职、账号停用和误建链接时，需要移交维护权而不更换已经分发的地址。admin.md 已规划修改短链所属用户；目前只有全站管理和用户改组，没有转移闭环。

| 能力及来源 | 现状／本版取舍 | 影响与验证 | 风险 |
| --- | --- | --- | --- |
| admin.md 的短链所属用户调整 | 未实现，本版纳入单条转移 | 新增管理 POST、SQLC 行锁、列表版本、确认框；真实 PG 和浏览器 | 高：授权及历史数据归属 |
| short-links.md 的个人管理与统计 | 已实现，本版保留并验证转移后权限 | 旧／新所有者列表、编辑、统计验证 | 高：旧所有者残留写权限 |
| v0.18.0 事务审计 | 已实现，本版复用 owner_id 字段白名单 | 审计故障回滚、no-op 无记录 | 中 |
| roadmap 的批量转移／导入导出 | 未实现，不纳入本版 | 不开放入口，不新增队列或导入模型 | 低 |

## API 与错误契约

新增 `POST /api/v1/admin/short-link/transfer`，请求为一个严格的 JSON 对象：`id`、`newOwnerUsername`、`expectedUpdatedAt`。UUID 必须是非零规范形式，时间是非零 RFC3339Nano；用户名沿用既有账号创建契约，仅要求非空并精确匹配，不新增长度限制、不裁剪首尾空白、不折叠大小写、不自动选择相近账号，以兼容既有合法账号。表单要求管理员准确输入接收账号用户名，并勾选后果确认。

成功返回 `{id, ownerId, updatedAt}`；全站列表新增 `updatedAt`（RFC3339Nano，保持数据库微秒精度）。无权限 `120001`，参数错误 `100001`，短链不存在／已删除 `200104`，陈旧版本 `200116`，接收账号不存在、已删除、禁用或 guest 为 `200117`；均为 HTTP 200 业务错误。未知基础设施错误为既有 HTTP 500／900000，只记录安全类别、类型和请求 ID，不能输出数据库诊断。缺失媒体类型、未知字段、null／数组和尾随 JSON 在服务调用前拒绝。

## 事务与并发

沿用既有 `admin:access` 和 `short_link:update_all`，不新增权限或 schema。这是本次设计选择：全站修改权限本已覆盖管理员修改任意链接，转移作为其明确管理动作，不向普通账号开放。

使用 5 秒上下文预算与 WithAuditTx。按 UUID 顺序锁定 actor 和通过用户名查出的接收用户行，重查 actor 启用／未删除和当前用户组；share-lock 当前组并解码数据库权限，验证权限交集。接收人必须启用、未删除、主组为 user 或 admin；允许转移出禁用账号，允许交给管理员本人或内置 admin，禁止 guest。之后锁定短链，要求未删除且版本与 expectedUpdatedAt 相同。同 owner 时返回当前版本，不写、不审计。实际转移仅写 owner_id，并以 greatest(clock_timestamp(), updated_at + 1 microsecond) 前进版本。

用户锁先于短链锁，与改组及批量写入保持一致的锁序。原有个人写入 SQL 的 owner_id 条件必须在等待行锁后仍重新生效；测试验证与转移竞争时旧所有者不能修改已移交记录。转移后收到的后续个人读取／更新／删除／统计按新 owner_id 判断；已经授权完成的在途读取不追溯撤销。历史事件通过 short_link_id 保留，因而新所有者可见完整既有匿名统计，原所有者不能继续访问单链统计。域名创建授权只约束新建，不迁移域名或授予接收人创建能力。密码 Cookie 仍是公开访问授权，不作为所有者凭据。

## 界面

全站列表的「更多」增加「转移归属」，仅身份就绪且具有管理／全站更新权限时显示。打开时固定链接 ID、公开 URL、原所有者、完整版本及 actor 身份轮次；弹窗展示原账号、准确用户名输入和包含历史统计移交的确认项。提交期间禁止关闭、重复提交及同时发起列表批量操作；后续身份切换或撤权清除弹窗，迟到结果不污染新身份状态。

失败使用统一 Toast 并保留输入。版本冲突关闭旧弹窗、刷新列表，仅在列表成功且刷新结束后允许重新打开确认；迟到菜单事件同样检查，不能复用刷新期间的旧缓存版本。成功关闭并刷新全站／个人列表、概览、统计和仪表盘相关缓存，不自动重试写入。沿用当前 Vuetify、主题、响应式和减少动态效果规则，不新增独立导航。

## 实现者决定与验证

不新增账号枚举接口：准确用户名输入满足管理员已有用户列表的工作流，避免加载全部账号或只允许选择前 20 个账号。组件切分和测试辅助函数由实现者按既有模式决定。

真实 PG 覆盖当前数据库授权、保护接收人、精确版本、同 owner 无变化、单版本并发、旧／新所有者权限、配置与统计保留、审计失败／数据库失败回滚。HTTP 测试覆盖严格文档及全部错误映射和诊断不泄漏。组件测试覆盖快照、确认、pending、错误／冲突、撤权／换号和迟到响应。真实桌面／手机浏览器从独立 fixture 验证完整移交；完整本地门禁与目标 CI、合并、发布分开记录。
