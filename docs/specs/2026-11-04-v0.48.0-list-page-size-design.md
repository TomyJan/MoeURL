# v0.48.0 短链列表每页条数设计

2026-11-04 设计启动。PR261 已完整交付，基线为已验 master `5ed2939c6de3f75e3cb46dac37fcb6ffa06ad74f`，分支 `feat/v0.48.0-list-page-size`。目前未实施或验收。本设计由执行者依据无人值守自主授权定稿。

## 意图与范围选择

本人和管理员列表已具有筛选、上一页／下一页及单页批量操作。固定 20 条会让处理几十条匹配项需要反复翻页；服务已有 pageSize 且最大 100，不需要扩大后端接口。选择增加 20／50／100 三档，是执行者依据路线图作出的最小产品增量。

任意整数会扩大输入和交互面，账号偏好持久化会扩大身份与偏好协议，所以采用三档挂载内状态。默认 20 保持既有使用方式；筛选时保留当前大小，退出、换身份、读授权变化及重新挂载恢复默认。

## 用户可见行为

分页区域增加带标签的选择框，中文“每页条数”，英文“Rows per page”，选项为 20、50、100。初次进入显示 20。选择其他值立即回第 1 页，清除本页勾选，显示新请求的加载状态；旧集合不因为回到相同大小而恢复。相同值事件没有效果。

当前成功且已经结束读取的响应提供 total，摘要按当前大小计算总页数，0条仍显示第1／1页。下一页只在当前成功响应证明存在时可用；读取期间可切条数，但不能以旧total开启新大小的下一页。失败时保留大小并提供原有“重试本页”；换大小可以主动请求新的第一页。普通筛选应用后回第1页且保持大小。

备注编辑、设置／二维码窗口、批量确认／写入、导出或批量创建打开时禁用条数选择；已排队事件仍重查当前权限及操作锁。Shell里的单条创建沿用既有覆盖层和原边界，不新增全局锁。无写权限但有读取权限的账号仍可选择条数。

## 查询、身份与退休约束

每个页面独立持有有界页大小。现有十槽查询key不移动，在末尾加入 size；queryFn从自身 context.queryKey 捕获 page、size和筛选，不在await后读取当前ref。新的size触发与换页相同的全局单调 listRevision，所以20→50→20不复用原20集合，卸载重挂载同样不复用。

size加入批量filters和备注编辑器reset观察集合。换档即使原来在page1也清勾选并退休目标上下文；回到旧档也不能恢复旧勾选。当前身份scope变化或实时读授权发生变化时，先退休上下文，再以默认20和page1继续合法读取；不能让同账号撤权恢复重新展示旧集合。

筛选的原始草稿、应用后的值、500ms防抖与无效草稿规则保持。无效或尚未应用草稿禁止条数动作，不能用条数切换绕开。关键词仍只在私密POST正文和当前页面内存，不进入URL、storage或导出文件名；换档不主动清除合法筛选。

下一页边界与成功total收缩使用当前size。只有当前key成功、非fetching、授权有效且分页操作未锁定时才收敛到最后合法页；失败、pending或旧响应均不证明新页界。一个切换过程中所有短暂请求都只属于各自捕获key，不得将其中任何响应借给后续key。

## 最小实现边界

新增一个小的pageSize模块，仅导出选项、默认值、联合类型及unknown guard。两页面继续各自接入现有逻辑，不借机抽整个列表控制器，不改共享客户端兼容契约或backend参数范围。分页组件采用受控prop和事件，不自行保存第二份size。

测试共享VSelect stub通过原生DOM发出字符串，不能代表真实Vuetify number选项。新size测试局部使用保留number语义的stub；生产handler不为测试接受字符串，旧全局stub不改。

没有migration、SQLC变更、API／路由／权限／依赖变化，不影响公开短链、访问统计或备注CAS。历史M6固定20常量建议随本行为自然解决；M5和M9继续按实际事实单独判定，不因版本推进自动关闭。

先写既有页面挂载的真实控件行为测试，取得缺功能导致的RED，随后实现GREEN。覆盖本人／全站、GET／私密POST、20／50／100页界、非法和同值事件、ABA／重挂载、同tick授权／操作锁、清选择、筛选保留、身份归零、失败重试与total收缩；响应fixture必须使用实际请求大小。

本版前端完整覆盖率四100、lint、types和隔离build必须实际运行。完整后端物理输入与原成功合同逐set／hash／bytes相同才按原执行身份复用，不把新前端集合冒旧完整suite。

真实浏览器使用61条独立数据，中文桌面与英文390px手机覆盖大小选择、前后翻页、单页选择、私密筛选和全匹配CSV。61条按20／20／20／1原子创建；每批成功立即登记finally清理，错误聚合。真实100档下61条无下一页，独立101条HTTPfixture另外证明100档下一页存在。原图保留通知并逐张ROOT核，页面无横向溢出，表格内部滚动沿用。

## 自检结论

有界选项解决条数选择；附加key／单调代际解决ABA；实时handler守卫解决queued事件；上下文观察解决旧选择；原CSV范围解决导出边界。三个工程任务见[实施计划](../implementation/v0.48.0-plan.md)，未增加远期能力。本设计所有产品选择均是执行者根据既有无人值守授权作出的决定，不虚称用户逐项指定。
