# v0.74.1 CSV 草稿与帮助维护设计

## 原因与边界

`useBulkCreate.edit()` 清空 snapshot，`clearImport()` 归还手动输入，但旧 snapshotMode 仍参与 custom_slug 撤权检查。用户已放弃旧结构化内容后，不应因旧模式失去新的手动草稿。当前固定 SQL 参数和公开临时账号 fixture 的诊断已经核实为误报，不改后端或测试账号模型。

## 行为选择

保留 importedMode 的现有检查；只有 snapshot 实际存在时才检查其 snapshotMode。相较在多个状态出口重置标记，此选择直接把权限检查绑定到当前资源，避免未来新增出口再次漏清标记。旧模式标记不是权限或有效快照。

覆盖五列和四列导入的“预览→编辑→清除导入→手动输入”，以及编辑后改读单列或标题 CSV；仅撤销 custom_slug 后，对话框和新草稿保留，可按当前低权限协议预览提交。真正的四／五列导入和有效快照仍立即退休；metadata、模式和身份轮次守卫不变，未知结果不能编辑。

CSV 错误提示直接使用既有中英帮助标题“CSV 格式示例与模板”／“CSV format example and template”，不改变 i18n 键或帮助布局。用真实组件读取可见标题，并确认实际错误提示包含该标题；保留原固定表头、合法模式和“不自动提交”的断言。
