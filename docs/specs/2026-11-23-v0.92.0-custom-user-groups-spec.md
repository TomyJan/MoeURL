# v0.92.0 自定义用户组规格

本规格是产品约束的文档入口；完整设计讨论见 [设计记录](../superpowers/specs/2026-11-23-v0.92.0-custom-user-groups-design.md)。若规格与实现冲突，以安全和数据完整性要求为准，不以兼容旧 UI 限制为由放宽服务端校验。

## 用户组模型

- 账号仍通过既有 `app_user.group_id` 只属于一个主组；不添加多组关联表。
- `guest`、`user`、`admin` 的 key、既有权限与兼容行为保持。自定义组 key 由服务端 UUID 生成，不可由客户端指定或编辑。
- 名称去首尾空白后须为 1–64 个 Unicode 字符，在 builtin 与 custom 组间不区分大小写且唯一；描述最多 500 个 Unicode 字符。
- 新组权限、域名授权、默认域名均为空，遵循 fail-closed。组列表返回 `builtin`、`editable`、`memberCount`、权限和完整更新时间。
- 权限必须来自当前 catalog、无重复并按目录规范化。Protected 权限只属于 builtin `admin`；preset 仅适用于 builtin `user`／`admin`，不能给 custom 组套用。

## 管理和成员操作

- 创建只接受 name、description 并返回服务端组；编辑详情及权限更新使用 `{groupKey, expectedUpdatedAt}` 精确指向目标并 CAS。
- 删除只接受目标 key 与完整版本；数据库事务确认该组没有任何 `app_user` 引用。成员数量非零时 UI 阻止，服务端仍是最终保护。组删除仅清除其关系和默认值，不删除域名或短链。
- 创建用户和单账号迁组使用当前可分配组列表；拒绝 guest、builtin 账号和操作者本人。单账号组变更的会话撤销及审计与既有 v0.19 合同相同。
- 批量组迁移维持 builtin-only `user`／`admin`，不得借助动态 UI 将 custom key 送入批量 API。

## 域名、权限与并发

- 域名授权请求和响应保存运行时 group key。新 custom 组不继承任何 builtin 域名 grant。
- 组默认域名必须是已启用且由该组显式获授权的域名，并满足组权限。个人可用域名读取不得泄漏失效保存值。
- 组权限与组默认域名共享原 `updated_at` CAS；名称／描述和成员变化不得被旧客户端快照静默覆盖。权限解析每个请求读取当前数据库值。
- 所有管理写入在事务内验证当前 actor、admin 身份及权限；域名操作还验证 `domain:manage`。不得依赖客户端 builtin 标志或缓存授权。
- `migrations/00050_custom_user_groups.sql` 扩展规范化名称唯一约束、名称/描述长度、custom 默认域名约束及白名单审计。Up 先检查现存数据；Down 在 custom 组存在时明确拒绝，不删除或转换数据。

## API 约定

沿用 `/api/v1`、严格 JSON、既有错误 envelope 和管理 no-store 约定：`GET /admin/user-group/list`；`POST /admin/user-group/create`、`/update`、`/update-custom-permissions`、`/delete`；builtin 权限更新仍用 `/update-permissions`。管理响应不暴露秘密；用户组 key 是不透明标识，不可被解析为名称或权限。

## 明确非目标

多主组、权限优先级／拒绝规则、guest 持久化管理、个人权限例外、批量 custom 成员迁移、OIDC 自动组映射、模板市场及对既有短链进行迁移。
