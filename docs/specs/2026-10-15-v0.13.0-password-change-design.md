# v0.13.0 个人密码修改设计

## 1. 现状与方案

个人设置已有昵称、语言和主题；本地认证已有 Argon2id、数据库失败窗口及两层并发限制。管理员重置不能代替用户自助改密。选择在 Auth Service 增加独立密码管理端口，复用同一个 Service 的登录与 Argon2 槽位；不扩展所有既有 Auth Port 替身。

比较方案：仅替换哈希最简单，但泄露的 Session 仍有效；保留当前 Session 并轮换令牌需要额外签发和客户端状态协调；撤销全部 Session 并重新登录边界最清晰，采用第三种。纯 OIDC 用户无当前密码证明，因此只显示外部身份说明。

## 3. API 与输入

`GET /api/v1/auth/password/status` 返回 `data.canChangePassword`。仅对有效 Session、启用且未删除的非内置、非 guest 账号返回状态；有受支持的本地哈希才为 true。不返回哈希或身份提供商信息。

`POST /api/v1/auth/password/change` 只接受单个 `application/json` 对象：

```json
{"currentPassword":"原始当前密码","newPassword":"原始新密码"}
```

禁止未知字段和额外 JSON 值。当前密码非空，最多 4096 UTF-8 字节；新密码为有效 UTF-8，8–128 个 Unicode 字符，不与当前值相同。旧密码不套用新密码最短长度，以兼容已有凭据。所有密码保留首尾空格、特殊字符及大小写。

成功返回 `data.changed=true` 并清除 Session Cookie。输入错误 `100001`、当前密码错误 `110101`、限流 `110103`、没有可修改的本地凭据 `110105`，均 HTTP 200；无效 Session 返回 HTTP 401 和 `110101`；未知基础设施错误 HTTP 500、`900000`，不记录凭据、Session ID 或数据库错误正文。两接口均 no-store，注册于独立 API 路由组，由密码服务直接验证 Cookie，不经过重复解析身份的 CurrentUserMiddleware；改密事务的取消与失败计数由操作 Context 控制。

## 4. 事务与并发

1. 获取与 Login 共享的 8 个操作槽位；使用脱离客户端取消但最多 10 秒的操作 Context。
2. 按有效 Session 查找账号标识和用户名。服务端唯一决定目标账号。
3. 开启事务，按用户名摘要锁定／创建已有 `auth_login_attempt`，检查阻断状态。
4. 锁定该 `app_user` 行（FOR UPDATE），重检启停、软删除、builtin、guest 和哈希格式；锁定用户后另行重读并锁定当前 Session，检查归属、撤销和数据库时间有效期。
5. 取得与 Login 共享的两个 Argon2 槽位之一，覆盖当前密码验证和新哈希计算。错误密码按现有窗口记录并提交；限流不计算哈希。
6. 正确密码使用现有 HashPassword 生成新哈希；更新用户密码、撤销该账号全部未撤销 Session、删除共享失败状态，然后提交。任一错误回滚全部改动，回滚使用独立有界 Context。

Login 的用户读取新增 `FOR SHARE OF app_user`，锁序与改密一致：失败窗口 → 用户 → Session。这样旧密码登录若先完成，其 Session 随后被改密撤销；改密先完成时，等待中的登录读取新哈希。两次并发改密只能一次成功，第二次锁定用户后重新检查的 Session 已失效。

OIDC 不建立或修改本地密码；改密不禁止之后通过合法外部身份新建 Session。管理员重置保持既有语义，不扩展到本版。当前请求已读取的其他业务身份不追溯取消，撤销影响之后的身份解析。

## 5. 前端

新建 `features/password-change/PasswordChangePanel.vue`，在 ProfilePage 嵌入，复用 Vuetify、表单校验、TanStack Query 和 Toast。状态查询失败保留重试，不能因缓存数据开放错误状态下提交。表单包含当前、新密码与确认；原值提交，确认只在客户端校验。

敏感字段仅留在局部表单与请求调用栈，不作为 TanStack mutation variables、查询数据、Pinia、本地存储或消息。提交后清空三个字段，无自动重试；成功取消并清理旧身份查询缓存后转 `/login?redirect=/profile`，Toast 说明所有设备已退出。失败按稳定业务码显示友好提示，字段错误留在表单，基本要求优先于跨字段比较错误。卸载时清理字段；即使改密写入的成功或 401 响应晚于卸载，仍取消并清理缓存，但不再导航或提示。昵称保存的迟到回调不得在退出或卸载后重新写入旧身份缓存。布局沿用鸢尾蓝与薄荷青主题及减少动态效果设置。

## 6. 验证

真实 PostgreSQL 验证成功、旧密码失败、新密码原值可登录、所有旧 Session 失效、其他账号不受影响、失败计数／阻断／取消、OIDC-only、用户禁用删除、事务失败回滚和确定性并发。受控依赖或真实数据库故障覆盖可测试错误分支，不扩覆盖率排除。

前端覆盖可用状态、加载错误重试、验证边界、Toast、敏感载荷清理、重新登录和错误状态；E2E 每个场景创建专用用户及两份 Session，在桌面／移动视口改密并验证旧会话、旧密码、新密码。运行完整 Go、前端覆盖率与静态门禁、SQLC 双次生成零漂移、Playwright 和可执行 Compose 检查；容器不可用时使用独立本地数据库并记录差异。
