# v0.67.0 目标 DNS 后缀黑名单设计

## 意图与边界

在现有精确黑名单之外，让管理员以一个规则限制某主机及所有下级 DNS 主机的新目标写入。选择独立资源，旧严格 DTO 和“精确不含子域”的含义继续兼容；可配置正则、DNS 网络检查和访问阶段追溯封禁不纳入。范围见[scope](../product/scope-v0.67.0.md)。这些是 Agent 的自主取舍，不写作用户逐项批准。

## 管理协议

key 为 `security.target_host_suffix_denylist`，默认 `{"suffixes":[]}`。

- GET `/api/v1/admin/system/target-host-suffix-denylist` 返回 `{suffixes,updatedAt}`。
- POST 同路径 `/update` 接受 `{suffixes,expectedUpdatedAt}`，返回同一资源。
- 32768 B 上限；两个字段必须存在且非 null；未知／重复／错误类型、尾随 JSON、查询参数、非法媒体类型或读取失败均整体拒绝。
- 0–100 项，复用 `normalizeHosts` 的完整边界。规范重复拒绝；父子重叠允许且不自动消除。存储必须已经规范、排序、唯一，读取不暗中修复。
- 完整 UTC RFC3339Nano 微秒版本，先 CAS 后 no-op；陈旧同内容也冲突，真 no-op 保留版本且不记审计，未来版本之后仍单调前进。
- 当前有效非 builtin 账号、builtin admin 组、`admin:access` 与 `system:manage` 双权限；读在有界一致快照内重查，写在审计事务内重查。五秒 deadline 覆盖 gate、行锁与 I/O。
- 输入错误 `900216`，冲突 `900217`；实施前已核当前全仓未占用。权限沿用 `120001`，目标受限沿用 `200121`，缺行／坏存储／I/O 为 HTTP500／`900000`。所有响应 no-store，日志不含规则列表、目标或原 JSON。

## 规范化与匹配

管理输入先拒控制字符、非法 UTF-8，再 trim；ASCII／有效 ACE、小写、至多一个终止点、253 字节主机／63 字节标签，禁止 URL、端口、userinfo、Unicode 原文、空标签、通配符、IP 和数字式尾标签。保持普通双连字符的已有语义。规范化后按 ASCII 排序。

目标先经过原 URL 校验，复用 `targetHost` 的 Unicode IDNA、单尾点和 IP 分类，不接受 IDNA 错误的部分输出，不改保存原文。非空后缀列表对每个目标取 canonical host；主机与规则完全相同，或以 `.` 加规则结尾时拒绝。标签边界避免 `badexample.com` 被 `example.com` 误封；`example.com.evil.test` 也不匹配。IP 的空 DNS 分类不匹配，原白名单可继续拒绝它。

空后缀列表不触发新的目标语法限制。非空时分类失败保留原非法目标错误，不降为未命中。没有公共后缀表或“注册域”推导：`com` 等宽范围 canonical DNS 项会按明确标签规则覆盖全部对应下级主机，卡片应提示配置范围。父子重叠只冗余，不改变保存内容或授权。

三个资源均合法时先执行精确黑名单、再后缀黑名单、最后精确白名单，任一拒绝不能被允许项绕过；三个存储任何一个缺失或损坏都失败关闭。该检查不做 DNS 查询、服务端抓取、重定向跟踪或 SSRF 安全认证。

## 写入、锁与迁移

`CheckTargets` 继续由现有四个 service 路径承接七个 HTTP 协议。单条创建、四类批量和本人／管理员实际改目标均执行新规则；无管理员绕过。当前授权先于已提交回执恢复，同 key 同内容仍恢复，异内容冲突。无回执的新批次有一项被拒则整批零链接、成功审计和回执；先 unknown 后确定拒绝仍 unknown，保留不可变 payload／requestId。

Update 先在授权范围锁定链接，省略目标或锁内目标原文字节完全相同不读新限制，可改其他配置；改 path／query 仍是新目标。公开 open／preview／unlock／continue 不读新规则，保持其他访问条件。

沿用双 int32 gate `(0x4d4f4555,0x54504f4c)`：目标写先 shared，再既有业务锁；任一策略保存先 exclusive，再当前 actor／group，再对应 setting FOR UPDATE。持有同一事务读取三个 canonical 资源，无跨请求缓存。先进入的 reader 可先提交，保存提交后才进入的新 writer 必须见新策略。不同资源保存串行，但不承诺其多个独立提交原子化。队列测试通过真实 blocking PID／有界同步证明，不用固定 sleep。

新增 `00043_target_host_suffix_denylist.sql`（实施前再次核序号），默认空、ON CONFLICT DO NOTHING，独立仅 key 的审计 trigger／function。Down 只卸对应 trigger／function，保留配置、精确版本与历史，再 Up 不覆盖；其他设置和旧 trigger 不变。旧应用回退忽略新 key，无法执行新规则，不能声称跨旧应用有效。

新建 targetpolicy 的 `SuffixSettings`／`SuffixUpdateInput`／`SuffixPort`／`SuffixService`／`SuffixHandler`，复用身份、host、完整版本、strict object、gate 辅助。App 启动验证及独立 router 注入新资源；旧 DTO 不变，无新固定短码入口。SQLC queries 不变，但 schema 包含整个 migrations，仍按锁定 1.30 标准入口实际生成两次并核完整输入／输出零漂移，不手改生成物。

## 前端

独立 entity、query key、draft 和 editor，放在 AdminSettings 原 general form 外，精确黑名单之后。字段叫 suffixes，复用现有 host scalar／revision 校验，不建立通用 CRUD 框架。0–100 行、增加／删除／清空、显式保存和重载；编辑时不排序，保存后使用服务端 canonical 结果。说明包含自身和所有子域、宽范围配置、拒绝优先和仅今后新目标。

尚未成功加载前不可保存；普通失败保留草稿；冲突保留并阻写，仅显式重载成功后解除。当前账号身份 scope／generation 同步清掉旧私有数据，覆盖 load／save 每个 success、error、finally；edit revision 防读取覆盖新编辑。切号、同号重登录、撤权、卸载及 query cache 不闪回旧数据。权限不足清列表禁操作，服务端仍最终授权。

已有 `200121` 双语反馈和 unknown 优先级不变；新后缀受限应在实际单条、四批量和两编辑入口复验。产品版本在实施后更新 0.67.0；不改 manifest 依赖、lock 或 workspace，不安装包。
