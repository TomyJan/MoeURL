# v0.82.0 CSV 结构错误定位设计

## 意图与方案

现有严格 parser 对所有失败统一返回 `{success:false}`，用户不易定位结构错误。Agent 选择在浏览器本地增加受限诊断；相比任意可选列、手动映射或历史恢复，这一方案不扩协议、默认值或权限。范围见[scope](../product/scope-v0.82.0.md)。本设计在前版实际额度窗口内完成调研和自检，正式实施从 PR364 独立核验的 master 开始，不把草案当用户逐字段要求。

## 单一解析核心与兼容接口

保留 `parseBulkCreateImportCsv(text)`、`parseBulkCreateCsv(text)` 的精确旧输出，失败没有额外属性。新增 `parseBulkCreateImportCsvDetailed(text)`：成功沿用旧八种 union；失败为 `{success:false; issue?:BulkCreateCsvIssue}`。`BulkCreateCsvIssue` 只含 `kind:'header'|'syntax'|'width'` 和 `record:number`。旧入口包装详细核心并剥除失败诊断，不复制状态机。

诊断不带文件名、URL、输入片段、底层异常或字段值，不发网络、不持久化、不新增日志。`record` 只允许 1–21：表头为 1、首条数据为 2，引号内 LF／CRLF 不新增记录；不是物理行号或精确列号。

保持旧拒绝顺序，不承诺文件中位置最早的错误：先原 Unicode／65536 字节预检，再原状态机扫描及八字段／21 记录限制，扫描完成后核表头，再取首条宽度不符的记录，最后业务 schema。无效表头后还有未闭引号时，先返回扫描发现的语法问题；不为诊断额外扫描文件或放宽上限。

| kind | 触发与序号 |
| --- | --- |
| header | 扫描完成后表头不是标准序列前 N 列的完整集合，或表头扫描超过八字段；record=1。仍逐字匹配，不 trim、改大小写、猜别名或补列。 |
| syntax | 原状态机拒绝的引号位置、闭引号尾随字符、引号外裸 CR、未闭引号；record=当前已完整记录数+1。引号内原本允许的字符保持。 |
| width | 数据扫描超过八字段，或完成扫描、表头有效后第一条数据宽度不符；指向该逻辑记录。 |

当前记录号超过 21 时不给 issue；原记录上限、非法 Unicode／总字节、合法表头但无有效数据、URL／tags JSON／metadata／完整 wire 预算和其他业务 schema 失败，保持原通用失败。空文本／只有 BOM 在原顺序中是无效表头，返回 header／1；合法表头后的空记录先按原宽度规则，再交 schema。任何组合都整体失败。

原八种成功格式、数据顺序、字面值、空字段、BOM、引号和权限协议保持。详细入口不变成部分导入或错误收集器。

## 当前读取与界面

`useBulkCreate` 仅对本地文件改用详细入口，错误键仍是 `bulkCreate.csvInvalid`。内部存可空受信 issue，对外只读 computed 仅在该错误键时暴露，否则为 null。读取开始、成功、reset、clearImport 清值；所有迟到 success／error／finally 继续受原 current／sequence／generation／权限 epoch 守卫。

现有 alert 内以文本节点追加一个独立段落：表头“CSV 表头不符合标准列集合（第 1 条记录）。”；语法“第 {record} 条 CSV 记录的引号或换行格式不正确。”；宽度“第 {record} 条 CSV 记录的字段数量与表头不一致。”。英文对应 Invalid standard column set in CSV record 1 / Invalid quoting or line ending in CSV record {record} / CSV record {record} has a different field count from the header。帮助增加“按 CSV 记录计数，表头为第 1 条，单元格中的换行不另计。”及对应英文。

不覆盖手工／结构化草稿、预览或未知结果 UUID／payload；新文件、同文件重复选择继续走原 feedbackAttempt 聚焦，不新增异步 focus 队列或改变 actions 布局。其它错误不显示残留诊断，关闭换号、撤权恢复和旧 finally 不能复活旧内容。

## 验证与交付

先写具名行为测试；RED 可用将现有函数重导出为详细入口别名的最小可执行基线，让原状态机运行后只因缺诊断失败，不能把缺导出／类型／导入故障当 RED。GREEN 才迁移为唯一详细核心、旧包装剥除。全部旧成功／失败对象、八份模板及 65536／65537 边界保持，三种诊断、逻辑多行、1／21／22、拒绝优先级、秘密／HTML 不泄漏有字面量断言。

真实 File／parser／hook／组件覆盖草稿、同错误不同记录、成功／清除、重复焦点、迟到读取／权限恢复、未知重试和双语文案。完整前端四项 100%、types／lint／新旧 E2E strict／build；准确新 web 与守恒 app／Goose 组合的 smoke／所选扫描和中英1280／390／320布局浏览器、必要原图及同轮 runtime 分列实证。原后端、SQLC、race 仅按完整输入守恒保留原执行身份，不重跑或冒当前执行。

继承三组 Minor 在本次实际文档维护中澄清：RED两份／其余三份路径、五处有效量词、旧报告本机 ZIP／成员／获取边界。不是重写冻结原件或公共下载保证。活动4GiB／双根12GiB／Docker可回收6GiB；大操作先预算，恢复ZIP完整解压逐hash后再清用完副本及精确自有资源。唯一整分支终审、真实 CodeRabbit 和正常合并核验、全部裁决报告及恢复归档见[计划](../implementation/v0.82.0-plan.md)。
