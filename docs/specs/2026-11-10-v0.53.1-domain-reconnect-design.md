# 域名重连回归设计

## 现状和选择

已有域名排序场景通过真实管理员与普通账号覆盖排序、个人默认、手选和创建。前版改为焦点刷新后，永久真实重连覆盖缺失；临时诊断不能代替提交的测试。

复用同一个场景，以焦点刷新／网络重连两个明确模式运行 1280 px 和 390 px，避免复制大量数据库恢复逻辑。重连模式先让用户页面处于前台并等待已有网络请求结束，再用其 BrowserContext 的真实 offline 状态断网；独立管理员 API 在断网期间修改顺序，恢复网络后等待浏览器自身候选请求，不手动 refetch、不重载、不伪造在线事件。

## 可观察结果

打开真实候选菜单，断言自有三个域名的显示顺序；个人默认仍选第二个域名、手选仍选第一个域名。两轮均实际创建，断言请求 domainId 和返回短链 origin。管理员 API 仅用于另一会话修改，不能代替用户页面刷新断言。

如果取消 reconnect 查询，等待真实响应或菜单顺序断言必须失败；如果刷新覆盖个人／手选，选择值或实际创建断言必须失败。恢复网络放在 finally，所有既有 fixture 清理继续聚合错误。

## 证据边界

生产输入逐 hash／bytes 相同后复用前版准确产品镜像及成功门禁，不重建相同产品。新测试在独立快照、Compose project、数据库与输出目录执行。保留首次失败和原始日志，不将测试补验首次通过冒称产品 RED→GREEN。
