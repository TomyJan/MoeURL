## 资源与输入

FooterLink={label:string,url:string}；FooterLinks={links:FooterLink[]}。默认空数组，最多 5 项，顺序就是展示顺序，允许重复，不隐式排序／去重，无持久 ID、分页或通用菜单模型。

无 HTML／Markdown／CSS／脚本／上传／Logo／Favicon／备案号专有字段／翻译管理／Open Graph／图标编辑／嵌套导航／点击统计／服务器抓取。自定义目标是管理员声明，不是产品审核或安全认证。

## URL 精确合同

服务端永不 DNS 探测、访问或代理目标；只有用户主动激活后浏览器导航，无预取／预连接。允许 localhost、内网名称、私有 IP，支持自托管内部文档；不声称可达性或 SSRF 安全认证。

1. 只允许 ASCII RFC3986 的字母数字、未保留字符、保留分隔符和百分号。拒绝空格、反斜杠、原始非 ASCII、双引号、尖括号、反引号、花括号和竖线。Unicode 路径／查询用百分号编码，国际化域名用合法 ASCII punycode。
2. scheme 大小写不敏感，只允许有 :// 的 http 或 https，规范输出小写。拒绝 relative／protocol-relative／opaque、空主机、userinfo（含空用户名）、空端口、无效端口。
3. 主机为 DNS、标准十进制四段 IPv4 或括号 IPv6。拒绝 zone、authority 的百分号、尾点域名、空标签／下划线／首尾连字符；DNS 标签 1–63、总名至多 253 字节，仅字母数字及内部连字符，单标签内网名允许。普通 ASCII 标签允许内部连续连字符，包括第 3、4 位均为连字符的 ab--cd；仅对 xn-- 前缀的 ACE 标签逐标签使用已有 x/net/idna Lookup 校验 ASCII punycode，并要求规范结果与小写标签相同。不能对整个主机套用 IDNA 的 U-label 连字符限制，也不能关闭 ACE 校验；规范小写，不改 domain 模块的 Origin 合同。
4. IPv4 经 netip 校验且原始拼写等于标准十进制四段，拒绝整数／短式／八进制／十六进制／前导零四段。非 IP DNS 名的最后标签不能全为数字，也不能匹配大小写不敏感的 0x 加零个以上十六进制数，避免 WHATWG 隐式数值主机。
5. IPv6 经 netip 校验并规范压缩、保持括号；IPv4-mapped IPv6 整类拒绝，避免 Go 与 WHATWG 对映射地址的十进制／十六进制输出差异，内部 IPv4 可直接用标准四段地址。端口仅十进制数字，1–65535，去前导零；移除 http:80 和 https:443，其他端口保留。
6. path 为空或以 / 开始，query／fragment 可选。每个百分号必须有两位十六进制后缀；拒绝编码的 C0 字节和 DEL。不递归解码，不把 fragment 的 @ 当 userinfo。
7. 只规范 scheme 和 authority，保留 path／query／fragment 原字节与大小写；不靠原生 URL.href 重写整个地址。Go net/url 加同一词法限制，TS 先同一限制再原生 URL 校验协议／空凭据／规范 authority；返回 scheme+authority+原后缀。浏览器实际导航可正常处理 dot segments，不承诺请求路径逐字相同。
8. Go 与 TS 必须消费同一 testdata URL 样例及规范期望；任何 authority 分歧先修合同，不能放宽绕过。短链私网拒绝器和 domain.NormalizeOrigin 不能直接套用。

链接统一 target=_blank、rel=noopener noreferrer、referrerpolicy=no-referrer。只绑定严格校验后的服务端 URL，label 用文本节点，不 v-html。可见辅助图标和本地化屏幕阅读器说明新窗口，不改 label 字面内容。

## 样例与错误代价

正例：HTTPS://Docs.Example.COM:00443/help?A=b#FAQ → https://docs.example.com/help?A=b#FAQ；http://localhost:8080/docs；http://192.168.1.2/；https://[2001:0db8:0:0:0:0:0:1]:443/a → https://[2001:db8::1]/a；https://example.com/%E4%B8%AD?x=%2F#part；https://xn--bcher-kva.example/；https://example.com/a/../b 存储后缀保留。

反例：空、//example.com、/help、javascript/data/mailto scheme、https:example.com、https:///evil.example、user:pass@ 或 @userinfo、空／0／65536／字母 port、尾点／双点／下划线 host、2130706433、127.1、0177.0.0.1、0x7f.1、example.123、example.0x、IPv6zone、raw Unicode URI／反斜杠／Cc、%ZZ／单百分号／%00／%0A／%7f、2049 字节。fragment 中合法 @ 应通过，不能全串禁 @。

ROOT 裁决：5 项／40码点／2048字节约束布局与负载；代价是长文案和 IRI 要自行编码。允许内网的代价是目标可指向内部站点，靠管理员权限与点击边界而非假可达性保证。独立资源增加三个 endpoint／小服务，却避免旧 strict DTO 与 general CAS 相互覆盖。允许重复省去无价值规范去重；全文替换 CAS 确保排序原子。无 HTML／上传／自动抓取大幅减小注入、存储和联网面。

采用新协议局部 duplicate-key／Unicode 严格处理，是为避免 Go/JS 解析差异；不能顺带改旧 API。当前设计复杂度必须由共享语料、明确小函数和真实测试约束，不提前抽象。异常事务最早 rollback 用有界 context，不复制上一轮 Background rollback Minor。旧五类 Minor 仍延期，不称修复。

只读 Node 内置 WHATWG URL 的八例诊断已记录 footer-links-url-parser-probe.json：真实整数主机被规范为 127.0.0.1、映射 IPv6 变十六进制、dot-segment 被 URL.href 消除，支持上述保守限制／仅规范 authority 决定。它不是完整新 validator、Go 一致性或真实浏览器套件通过；没有联网请求。请求／响应所有字段名称区分大小写，错误大小写拒绝，不靠 Go 默认不区分大小写匹配冒严格协议。
