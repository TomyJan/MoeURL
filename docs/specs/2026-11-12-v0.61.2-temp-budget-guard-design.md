# v0.61.2 临时容量检查设计

## 取舍

采用原生 Node.js／ESM，与现有 `scripts/*.mjs` 一致，无新增依赖。相比继续复制每版 PowerShell helper，可复用入口更易保持同一口径；相比自动 prune 或系统配额，只读检查不会误删其他项目资源。采用此方案是 Agent 根据用户无人值守与数据安全要求作出的决定。

## 接口

`node scripts/check-temp-budget.mjs --root <worktree>/.tmp --root <main>/.tmp --active v0612-evidence --reserve-mib 256 --docker`

`--root` 可重复且至少一个；只能指定普通 `.tmp` 目录。`--active` 是一个直接子目录名，拒绝路径、`.` 和 `..`。`--reserve-mib` 默认 256，仅接受非负安全整数；`--docker` 可选，Docker 构建或扫描前必须使用。未知／重复单值选项、缺值或不安全数值拒绝。成功与超限分别退出 0／1，参数或盘点错误退出 2；均不创建、删除或更新文件。

导出 `inspectTemporaryFiles(roots, activeName)`、`evaluateBudget({ activeBytes, totalBytes, reserveBytes, dockerCacheBytes })` 和 `parseDockerReclaimable(output)`，供原生 `node:test` 验证真实目录行为与数字边界。CLI 仅组合这些接口。

## 目录与容量口径

对每个根先 `lstat`，拒绝链接与缺失根；经物理规范化去重，拒绝父子重叠。迭代遍历普通目录／文件，链接只计跳过数、不跟随；硬链接按路径保守计数。不吞掉读取失败或扫描中消失的路径。根下散文件、所有版本证据与共享缓存均计总量；只将第一层目录名等于活动名的后代计活动量，Windows 下活动名保守忽略大小写。每次求和须保持非负安全整数。

总量与活动量分别加同一预留后比较 12 GiB／4 GiB。Docker 使用无 shell 的 `docker system df --format '{{json .}}'`，必须恰有一个 Build Cache 行；只接受完整可回收数值与可选百分比，使用十进制 B/kB/MB/GB/TB，并加 16 MiB 舍入余量后与 6 GiB 比较。调用超时 30 秒，非零退出或格式异常拒绝。

## 验证与限制

真实小目录验证两根累计、活动归属、散文件、重复／重叠根、链接与读取错误；纯数字输入验证阈值等于、预留越界、负数／NaN／不安全整数，避免写入 GiB 大文件。CLI 子进程验证参数、退出码与只读不改文件；Docker 使用真实本机只读盘点，格式解析另测畸形输入。

后端、前端和产品字节不变时，复用准确旧执行证据，不重复 Go、浏览器、产品构建或扫描。脚本自己的完整原生测试必须通过。唯一末段独立审查和最终 head 真实 CodeRabbit仍须各自完成；不查 CI、不发布部署。
