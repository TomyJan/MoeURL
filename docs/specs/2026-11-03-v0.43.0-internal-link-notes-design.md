# v0.43.0 短链内部备注设计

## 意图与方案选择

在本人短链和全站短链行菜单中提供“备注”。打开时才读取一段内部纯文本；读取权限足够时可查看，额外写权限足够时可编辑。用于用途记录和交接，不作为密码存储。范围见[产品范围](../product/scope-v0.43.0.md)。以下具体实现选择由 Agent 按无人值守授权制定，不冒作用户逐项批准。

采用 `short_link.note` 与独立 `note_updated_at`。旧 metadata 是标题／标签整体替换对象，将备注混进去会让旧客户端误清；独立备注表对一段文本无必要。原单条、批量与软删的 `updated_at` 时钟策略不同，不扩大修改旧写入，备注只用自己的版本进行并发控制。

## 文本与数据

`note text not null default ''`，数据库约束 `char_length(note) <= 1000`；`note_updated_at timestamptz not null default now()`。不建索引、实体表或缓存汇总。数据库长度约束是第二层保护，规范化由服务完成。

两端共用语料钉住如下顺序：先验证 UTF-8／UTF-16 标量有效，CRLF 归一 LF；拒绝孤立 CR 和其他 Unicode Cc，允许 LF 与 TAB；随后按 Go `strings.TrimSpace` 等价集合裁剪两端；最后计算最多 1000 Unicode 码点。BOM 保留，不做 NFC／大小写变化，不使用 JS 默认 trim 偷换语义。空字符串表示清空；1000 emoji 合法，1001 拒绝，组合字符按独立码点计数。

## 独立 HTTP 契约

| 端点 | 请求 | 成功 data |
| --- | --- | --- |
| GET `/api/v1/short-link/note` | 唯一 `id=UUID` | `{id,note,updatedAt}` |
| POST `/api/v1/short-link/note/update` | 完整 `{id,note,expectedUpdatedAt}` | `{id,note,updatedAt}` |
| GET `/api/v1/admin/short-link/note` | 唯一 `id=UUID` | 同上，全站授权 |
| POST `/api/v1/admin/short-link/note/update` | 完整同上 | 同上，全站授权 |

UUID 必须规范小写且非零；版本按原始 RFC3339Nano 全精度收发，年份 1–9999、有效且非零。响应 `updatedAt` 专指备注版本，不能拿主列表的版本保存备注。所有响应 `Cache-Control: no-store`。

严格拒绝缺失／重复／未知字段、null、坏编码、非法 JSON Unicode 转义、尾随第二文档、重复／未知 query、无等号或空段。POST 必须 `application/json`（允许合法 charset 参数），原始 body 含 framing／空白最多 16384 字节，超出整体拒绝。不能仅靠 `encoding/json` 的替换字符容错接受孤立 surrogate。

官方前端所有备注 GET／POST 均携带打开时捕获的 `X-MoeURL-Expected-User-ID`；若有此 header，必须单值、规范 UUID 并等于 Cookie actor，否则 120001，且不读取备注、不进入写入。无 header API 保留当前 Cookie actor 语义；header 不授予身份或权限，不修改其他端点。

100001 输入无效；120001 无权限；200104 不存在、软删或个人越权资源；200116 备注版本陈旧；基础设施 HTTP500／900000。其他业务仍 HTTP200。Session 无效按现有 middleware 回退 guest 后拒绝；不改全局认证语义。日志仅 request_id、安全类别与错误类型，禁止备注正文、SQL、响应或字段前后值。

## 当前授权与原子写入

有效非 guest 账号按数据库当前组能力授权。个人读 `read_own`＋当前 owner，写再 `update_own`＋`set_metadata`；管理读 `admin:access`＋`read_all`，写再 `update_all`＋`set_metadata`。不能用客户端 group／owner 或旧 permission snapshot 代替当前数据库校验。

读取用当前账号、组和短链的同一 SQL 快照确认权限与归属，明确区分授权失败和资源不存在，不执行独立无授权文本查询。写入整个操作五秒期限，`WithAuditTx` 中锁序为账号共享锁→当前组共享锁→短链更新锁，锁后重查账号有效、当前权限、软删和 owner。并发账号修改与转移按数据库锁串行化，已先取得合法锁的事务可以完成，不承诺回溯取消。

先比较 `note_updated_at`，再判断同值 no-op；陈旧同值仍冲突。同值不写、不推进版本、不审计；实际变化只写 note 和 `greatest(clock_timestamp(), note_updated_at + interval '1 microsecond')`，原主版本、地址、设置、配额和事件不变。审计仅记录 `note` 字段名与真实 actor；触发器／审计失败时全部回滚。其他设置、单条／批量归属转移保留 note 与 note_updated_at，新 owner 后续按权限可读，旧 owner 后续被拒绝。

## 迁移与回退

新 `00035_short_link_note.sql` 增加两列和长度约束，更新 short_link 审计 trigger 白名单包含 note，版本列不作业务变更字段。Up 不授予权限，旧操作审计字段保持原集合。

Down 在同一 Goose 事务以 access exclusive 锁定 short_link，任何非空 note（包括软删）均安全拒绝且 schema／审计不变；全部为空才恢复原 trigger 并删除两列。必须验证全新 Up、空值 Down／再 Up、非空与软删有内容 Down 拒绝及安全重试。操作前备份，禁止清空用户备注来绕过 guard。旧应用保留新 schema 可继续旧字段操作，但不承诺旧二进制具备新功能。

## 前端状态与布局

固定 own/admin 包装共享一个专用 `ShortLinkNoteDialog` 和 controller；不向原 settings 表单、旧实体 DTO 或列表加载塞入备注。读写实体分别固定端点，缓存族隔离，key 包含账号 ID／epoch／link ID。使用现有父 auth 状态，不新增全局 observer；父页面保证可读当前列表及行／批量／导出／设置互斥，queued click 再核 live 身份和资源。

每次 load/save 的 success/error/finally 都绑定账号 epoch、权限代际、资源和打开轮次。关闭重开、A→B→A、同账号撤权恢复退休旧请求和缓存；新上下文不显示旧备注、错误或完成提示。保存期间禁用关闭；上下文失效可退休组件，旧结果不可恢复它。清空只改本地草稿，仍需保存。

后台读取不覆盖 dirty 草稿。冲突保留草稿、冻结保存，显式“重新加载（替换草稿）”才替换版本与内容；读取错误可重试。transport／5xx／畸形 success 视为结果未知，提示“保存结果未确认，请重新加载核对”，保留草稿并冻结再次保存到显式 reload，绝不自动重放写入。已知校验业务错误允许修改草稿后保存，权限／资源失败按当前身份刷新和关闭规则处理。

使用 Vuetify dialog／textarea，中英、码点计数、loading／error／empty／readonly／dirty／saving／conflict／unknown 状态明确。保留换行、长词换行，手机操作区可见，键盘可打开、输入、保存和关闭；不隐藏真实通知。界面常显转移提示，不暗示备注只属于个人。

## 验证与风险

真实 PG 验证预检后撤权／禁用／删除／改组、同版本竞争唯一赢家、审计回滚、转移与旧字段不变；同源 Unicode／framing 语料覆盖两端。真实 QueryClient 与受控 promise 验证所有迟到结果、脏草稿及未知保存恢复，不能仅验证 DOM 禁用。真实 Session E2E 验证本人／全站、只读、冲突、转移、双语言视口及原图几何；公开 Preview／302／CSV／主列表／统计均不泄露备注。完整门禁与审查按[计划](../implementation/v0.43.0-plan.md)执行，不借旧版本成功冒新输入结果。
