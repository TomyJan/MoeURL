# 测试资源清理诊断维护设计

## 目标与选择

前版独立终审记录 v0832-FR-M1：嵌套 finally 仍会尝试每项释放，但后面的错误可能遮住前面的错误。只做文案会保留故障诊断缺口；引入通用生产清理框架超出范围。因此只修 Node 测试夹具自身，保持产品 0.84.0 和真实 E2E helper 不变。

## 行为

fixture 在创建目录后继续立即登记 hook，顺序保持 server → handle → directory。每步独立 try/catch，将实际抛出的值无条件追加错误数组；最后有错则抛 AggregateError，errors 按原值和顺序保存。单错也聚合，不按 truthy 判断。原来成功路径、未获取资源跳过及准确目录回收保持。

测试 seam 为 options.afterRelease(stage)：仅在该步真实释放之后执行，用于可靠模拟释放报告错误；默认无此回调。返回 directory 和 serverListening 供测试观察，不新增生产 API。新测试捕获真实 hook 手动消费，三项各自单错、同时三错和 falsey 多错均断言 AggregateError 精确身份／顺序，以及服务不监听、句柄 stat 为 EBADF、目录访问为 ENOENT。外层清理关闭注入后再消费 hook，失败的 RED 也不能留下资源。原嵌套 finally 应以非聚合／较晚错误断言失败；再最小改成独立捕获。
