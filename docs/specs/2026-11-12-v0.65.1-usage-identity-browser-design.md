# v0.65.1 用量身份通知浏览器验证设计

## 意图与边界

PR317 已真实覆盖并交付，本维护单独解决原 Ruling25 的可选浏览器证据缺口。旧流程在 held usage 请求之后以 API 退出再整页导航，不能证明浏览器中的真实退出／登录通知接线。本版不修改生产实现或原冻结报告。

## 实现决定

保留现有四场景的真实创建、刷新、错误、撤权与布局断言。新增一次 window 自有字符串标记，整页刷新会丢失；先在旧 goto 后断言，从真实失败证明该守卫能识别旧漏洞。随后仅更换末段为 UI 退出和 UI 登录 B，消费既有 redirect 自动进入控制台；若正常回到首页，则点本人入口进入个人中心，再用侧栏 RouterLink。手机点击账号菜单，桌面点击侧栏退出，不调用内部 router 或 QueryClient。登录 URL 按 pathname 判断，保留合法 redirect 查询；退出后与 B 的界面允许按浏览器基线改变语言，身份断言不得依赖 A 的语言。

通过管理员独立 request 创建 B，A 在场景内已经真实创建一次且用量为 1，B 初始用量为 0。在 A 刷新时 route.fetch 取得真实响应并验证 expected-owner=A、payload.used=1，用 Promise 门闩截留；B 登录后的新读取验证 expected-owner=B、payload.used=0、卡片=0，才释放 A。保存准确 A Request，在捕获前注册 requestfinished／requestfailed，按对象身份匹配；等待 route 处理和该 Request 的真实网络终结。成功路径核 failure=null、准确 response.finished() 及真实 used=1；失败路径记录实际 failure.errorText。fulfill 异常不能一律当取消，异常须失败；调用返回另记，不作为投递 oracle。网络终结后跨两个 requestAnimationFrame 的浏览器渲染边界，再核卡片仍为 0 且 runtime 标记未变。旧请求若已取消，只记录实际失败，不冒成功投递。

该验证证明同一浏览器 JS 运行时的真实通知和跨账号读数整合；原卡片会在路由离开时卸载，同一未卸载 composable 的迟到成功／失败与同账号 epoch 仍由 v0.65.0 单元测试负责，不夸大浏览器覆盖。

## 隔离、清理及证据

使用新独立 Compose 项目及 18111／19111，PostgreSQL 全新卷，设置恢复注册早于首次修改。B 同 A 在 finally 禁用，短链删除并恢复 quota／deny／allow，最后关闭新 browser context。原测试超时与权限不变，不通过降低断言修复失败。

不重新编译或下载：v0.65.0 产品 94 成员逐 hash 与恢复映射核准后重新组装同一内容；源生产文件须与基线逐 hash 相等。构建出的镜像记录真实 ID，原编译及扫描只称原身份。保留原 RED、必要日志／退出码／输入清单／runtime；成功 trace 不保留，用完删除快照、重复 assembly、容器、卷、网络和本版镜像，保留共享五镜像。原报告只读。
