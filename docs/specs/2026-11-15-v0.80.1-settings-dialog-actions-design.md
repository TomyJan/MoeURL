# v0.80.1 访问配置操作可达性设计

## 原因与取舍

v0.80.0 解决了列表拒绝保存后密码被清空的问题；其两张移动表单图只显示密码区域，提示和按钮未进入图像。新需求是长表单操作和暂不可保存的原因应易于找到，不将现有 DOM 可渲染等同真实视口可达。

选择 Vuetify 现有 `v-dialog` 的 `scrollable` 行为：标题、状态提示与操作区不随正文滚动，`v-card-text` 是唯一表单滚动体。将现有 unavailable 提示移到正文之外、操作区之前的独立区域；正文 `min-height:0`，固定区不可压缩。沿用现有文本和中英翻译，不增加副本。相比绝对定位／全页 sticky，此方案遵循已有弹层布局，不让按钮覆盖字段；相比跳转焦点到提示，不打断正在编辑的原生密码输入。

## 行为边界

当前字段、权限、`canSave` 判定和同步最终保存守卫均不变。提示出现／消失只改变布局，不能 remount 或重置正文；焦点仍在当前字段，密码不进入响应式状态。pending 期间保留原禁用／关闭语义。内容高于可用空间时仅正文滚动，按钮仍完整位于视口内。最小验证视口为 320×500，目标按钮命中区域至少 44 像素高；不承诺实体手机键盘、任意缩放或全部弹层。

## 可验证结果

新增 `web/e2e/v0.80.1-settings-dialog-actions.spec.ts`，用真实隔离产品和已有管理员创建 own 测试短链。每种语言／尺寸打开全部访问字段，填目标与新密码，记录实际 viewport、dialog、正文、提示和按钮矩形及裁切交集。按钮及暂不可保存提示的可见交集须覆盖其完整矩形，至少保留 1 像素容差；正文滚动 top／middle／bottom 后均检查。使用 `expect.soft` 收齐基线诊断，并以真实几何失败形成 RED；不以测试框架 import／类型错误作为 RED。

用离线恢复触发真实列表 refetch，再暂扣真实服务响应，验证提示进入固定区、Save disabled、Cancel enabled、密码和 activeElement 不变；释放后 Save enabled，实际提交精确包含新目标和密码。另验证可取消且不提交。finally 删除 own 短链；所有场景 workers:1，原已有权限不改。新产品单轮 setup＋中英×三个尺寸，共 7 个身份，无 skip／retry／flaky，原始图与几何 JSON 全部核验。后端完整投影相同才复用原 app／Goose；新网页、产品和执行 SHA 分别记录。

## 交付

三项任务：真实基线浏览器 RED、布局实现和完整前端；准确新产品、GREEN 浏览器与精确清理；唯一 fresh 最强独立整分支审查、真实 CodeRabbit、正常合并独立核验与 whole-owned 可恢复归档。按用户无人值守授权自主收敛、沿用现有 linked worktree，不派 builder 或实现代理；只在版末派一次独立审查。旧证据冻结，前版量词 Minor 只改 tracked 文档，不改原 readback。
