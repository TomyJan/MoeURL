# v0.29.0 每域名默认跳转方式设计

## 1. 意图、授权与边界

对应 [范围](../product/scope-v0.29.0.md)。部署者可为不同短链域名提供合适的创建模式，例如分享域名倾向 confirmation，内部域名倾向 direct。这里只减少创建者重复选择，不增加强制访问策略或新的授权层。

这是 root 依长期自主设计授权作出的常规方案，不冒用户逐项批准。保持 Go／Chi／SQLC1.30／Goose／PostgreSQL、Vue／Vuetify4／TanStack Query；不新增依赖或权限。设计 builder check 只检查能否计划，不能冒实现终审。实施使用独立 worktree、root 原生 TDD，最后一次 fresh 最强独立完整实现终审及集中修复。

## 2. 现有事实与方案选择

当前 domain 的详情和排序共用 updated_at；旧 AvailableDomain 与 ManagedDomain 是前端 strictObject，不可直接增加字段。短链 createAccessConfig 在 RedirectMode 为空时固定 direct；面板目前初始化 direct、delay5，已有身份 epoch、域名手动／个人／组层级及显式模式权限。

比较三种方案：

1. 服务端重解释省略 redirectMode：改变旧客户端和脚本含义，拒绝。
2. 在旧 available／managed 响应加字段：破坏旧严格客户端，拒绝。
3. 独立配置动作／投影，只用于新面板初选：采用。保留旧请求与响应，显式 payload 继续走现有短链授权。

配置列直接放 domain，复用版本；不为单一三值属性另建策略表或多版本协调。不增 nullable／inherit，因为没有本版系统默认模式层；direct 是确切、可恢复的初值。

## 3. 数据模型、迁移与旧写入

00028_domain_default_redirect_mode.sql 为 domain 增加 default_redirect_mode text not null default 'direct'，CHECK 只允许 direct／intermediate／confirmation。域名数量属于小型配置集，不触及 short_link 大表；单次 Goose 事务添加、校验及更新 domain_audit trigger 字段清单。既有域名不改 updated_at，不补无意义审计；新初始化与旧 CreateDomain 通过数据库默认值得到 direct。

Up 在 v0.27 的 domain_audit 白名单末尾加入 default_redirect_mode，复用 record_business_audit；变化按既有 domain update 记录，仅字段名不含值。Down 先恢复原白名单 trigger，再删除约束／列；已有 audit_log 字段名历史保留，不清审计、短链、域名或偏好。回退会丢失此配置，再 Up 为 direct，必须在验收明确。

queries/domain_redirect_default.sql 定义独立查询及 CAS 更新，SQLC1.30 正常生成；旧查询显式列及旧 domainFromRow 不增 JSON 字段，旧详情／设默认／排序只写自己已有字段。共享版本意味着任一动作可令另一草稿陈旧，但不会静默覆盖配置。旧完整详情请求不必带新字段。

## 4. 管理接口与严格输入

所有接口 no-store；业务成功／失败 HTTP200，基础设施错误沿用500／900000。独立 RedirectDefaultPort／Handler 接入现有 domain Service，不扩大旧 Port 或要求旧测试替身实现新方法。

GET /api/v1/admin/domain/redirect-default 只接受单个 id 参数：小写规范非零 UUID，重复、未知、空值无效。返回 data.setting={domainId,redirectMode,updatedAt}，updatedAt 是 domain 完整 RFC3339Nano 版本，不返回旧 ManagedDomain。

POST /api/v1/admin/domain/set-redirect-default 接受唯一 JSON 对象 {id,redirectMode,expectedUpdatedAt}。字段全部必填且非 null；模式精确三值，不 trim／忽略大小写。拒绝未知字段、数组、重复字段、尾随第二 JSON／文本、错误 Content-Type，以及非规范 UUID、零 UUID、不完整时间。Content-Type application/json 可带合法 charset。版本语法与 v0.27 相同，保留数据库微秒，不能只比较展示时间。

成功仍 data.setting={domainId,redirectMode,updatedAt}。100001 为输入无效；120001 为无权；210102 为管理目标不存在／非短链域名；210103 为版本冲突；500／900000 为未知存储或审计失败。无新错误码。旧域名响应保持原字段集合。

GET 与 POST 都检查有效当前 DB 账号、builtin admin 组以及 admin:access＋domain:manage；不因入口 GroupKey／旧 Resolver 曾放行而跳过。管理者可以给停用或任意授权组组合的已有短链域名保存配置，不要求其自己拥有对应短链增强模式权限；这是管理设置权，不授予目标组使用权。

## 5. 写事务、版本、审计与竞争

POST 使用五秒 Context 和 WithAuditTx。锁序为现有 domain 全局 advisory 排他 → 当前 app_user 共享 → 当前 builtin admin 组共享 → 目标 domain FOR UPDATE。复用 authorizeDomainWriter 的锁后当前 DB 授权；当前账号被禁用、删除、迁组或撤权已在等待中提交时，新写入拒绝。不要增加先 target 后 actor 的逆序，不升级共享域名锁。

持锁后先比较完整 expectedUpdatedAt，不等即冲突，包括陈旧同值；再判断当前值：同值返回原版本、不 UPDATE、不审计。实际变化只写 default_redirect_mode 与 greatest(clock_timestamp(), updated_at + interval '1 microsecond')，返回新版本。UPDATE、审计或 commit 任一步失败全回滚。域名已删除按不存在；引用中的域名仍可改默认模式，因为已有短链永不被改写。与 delete／set-default／order／旧update 串行且共享 CAS。

管理 GET 使用五秒只读一致快照，当前 DB actor＋组权限和目标状态来自同一快照，不执行 FOR SHARE／UPDATE 的写锁查询。合法快照读不承诺撤回已经完成授权的在途响应。query 失败不回退为 direct 或旧版本。

## 6. 本人有效默认投影

GET /api/v1/domain/redirect-defaults 不接受任何 query 参数，返回 data.items=[{domainId,redirectMode}]，无 domain host／显示名／组权限／管理版本。调用者只能由 Cookie 当前身份确定，不接受 userId 或 groupKey。

同一五秒只读快照重新读取有效 app_user 的当前 builtin 非 guest 组及 permissions，并与启用的 purpose=short_link 域名授权交集关联；需要 short_link:create，默认域名需 domain:use_default，非默认需 domain:use_assigned。排序沿用 is_default desc、sort_order、created_at、id。无创建／域名资格但账号有效时 items=[]；不存在／禁用／非 builtin／guest 身份返回120001，不返回可枚举 UUID。

每项是有效默认：配置 intermediate 且无 short_link:use_intermediate，或配置 confirmation 且无 short_link:use_confirmation 时，返回 direct；不会自动换成另一种增强模式。direct 不需要新增权限。数据库约束损坏／无效枚举或解析失败是基础设施失败，不悄悄修复数据。响应数组 ID 唯一且模式三值；前端 strict schema 拒绝错误数据。

自动配置只是建议；短链创建提交时仍执行原 Service 当前授权。若配置读取后权限／域名角色改变，原120001／200114仍可能拒绝，刷新授权／域名／默认并由用户重新确认，不自动重试写入。

## 7. 创建面板状态合同

域名选择仍独立按有效手动 → 个人 → 组 → 全局 → 有序首项。将空字符串的全局选择解析为当前 available 中真实默认域名 ID；不能把空字符串当作无域名，也不能用旧已切换的默认 UUID。模式只读取该实际 ID 的有效默认项，且再次与 auth/me 当前能力取交集；不可因为另一域名的配置先返回就套用。

为草稿区分 manualMode: RedirectMode|null 与自动模式。用户点击任何模式（包括已选 direct）成为手动值；编辑倒计时隐式固定当前 intermediate 为手动，保留原3–10规则。未手动时，域名切换重新选取新域名默认，自动 intermediate 使用5秒；有手动时，域名切换与迟到默认不覆盖模式／倒计时。

自动配置在当前身份、实际域名的第一次成功读取或明确“使用域名默认”操作时绑定为本草稿快照。相同域名的后台 focus／online refetch 不无声改写已绑定模式；当保存配置已变时，可显示有新默认并提供明确重新采用按钮。域名切换、reset、创建成功、身份 epoch 改变或重新采用默认才重新绑定。手动模式一旦被当前权限撤销，立即清除该无权值并回 direct，同时提示重新确认；不能自动切为另一增强模式。身份变化同步清草稿、结果及 pending feedback。

自动默认尚未成功读取、读取失败或 selected ID 不在有效投影时，不把 direct 伪装成读取成功：禁用自动提交，提供可访问的重试和“本次使用直接跳转”。显式使用 direct 令 manualMode='direct'，单域名也可恢复；用户显式选其他有权模式同理。当前无任何增强模式权限时，可沿用 direct／省略原模式字段，不要求无意义默认读取。显式模式只绕过本版默认读取屏障，不绕过旧 personal／group／available 的域名资格屏障。

mutation pending 时模式、域名和默认采用动作全部锁定；固定本次 payload，不让异步数据改变在途操作。canSubmitRedirectMode 保持原权限含义：有增强模式配置能力时显式发送最终 redirectMode；没有时省略，后端仍 direct。仅 intermediate 发送 delay，自动5或当前手动值；confirmation／direct 不发送 delay。创建成功保留结果但清输入，重新读取／采用当前默认。

新 query 使用 useAccountIdentity 的 userId＋epoch 分区，不复用上个账号缓存；staleTime0、retryfalse、局部 refetchOnWindowFocus=true，不改变全局 QueryClient。旧 me 发布 guard 与卸载检查继续。默认结果只可填充当前 scope、目标 domain 及未手动／未绑定代次；迟到 mutation／toast 同样不得跨轮次。

## 8. 域名管理草稿协调

在现有详情表单和排序编辑器旁放 DomainRedirectDefaultEditor，仅编辑已保存选中域名；新增域名表单不新增字段，创建后以 direct 开始配置。编辑器通过独立管理 GET 取得模式与完整版本，不能把旧 managed 响应缺字段当 direct。

详情、排序、模式草稿互锁，存在任一未保存草稿时不允许另一编辑器写入；切换域名／新增须确认放弃所有本地草稿。共享 mutation pending、读取／访问失败和刷新屏障；保存模式后更新其响应版本并重新读取旧列表／该设置，两个读取都在当前身份且成功后才解除依赖写屏障。后台读取不得覆盖脏草稿，版本不同标记陈旧，必须明确重载，不自动重试 mutation。

读取 setting 失败时禁用默认模式编辑器及其写入，详情／排序不得把失败误当全局权限拒绝；已确认120001／401／403才进入现有访问恢复流程。无权或换号隐藏旧值／反馈；恢复需 fresh me＋list＋当前 setting。选中目标删除时保留脏草稿并显示已删除，不能写到后继第一项。迟到另一域名读取可入自己 query cache，但不能更新当前编辑器或当前版本。

保存消息分清本模式保存失败、210103版本冲突、普通读取失败和明确权限拒绝；包括中英双语、键盘、窄屏，不嵌套额外假卡片、不新增页面路由。可抽出小型专用协调 composable；不重写整个 AdminDomainsPage。

## 10. 裁决及错误代价

1. Ruling：默认只影响新面板初选，不改旧省略redirectMode=direct。若错，旧API调用者需显式模式而不能获得自动默认；比静默改访问行为更可控。
2. Ruling：独立三个API和strict DTO，不扩旧投影。若错，多一次小型配置读取；避免严格老客户端失效。
3. Ruling：domain非空列／共享版本／三值，不做inherit或另一策略表。若错，共享CAS会要求重载，但不会静默覆盖旧详情。
4. Ruling：管理保存只需双管理权限；使用时取增强模式权限交集。若错，管理员可以配置当前无人可用的模式，UI仍退direct，不扩大授权。
5. Ruling：自动intermediate固定5秒，无域名倒计时。若错，用户需在每次草稿调整3–10秒，避免扩配置维度。
6. Ruling：显式手动模式／delay跨域名切换保留；自动模式按域名绑定草稿快照。若错，已打开表单不会立刻追随管理员新默认，但不会无声更改用户已看过的配置。
7. Ruling：默认读取失败阻止隐式提交，提供显式direct恢复。若错，短暂读取失败增加一次操作，但不伪造已成功采用默认；无增强权限用户保持原路径。
8. Ruling：旧全局domain写锁及当前actor→group→target锁序复用，五秒界限。若错，小型管理写串行；低于排队后撤权仍可写或反序死锁的代价。
9. Ruling：复用现有审计白名单trigger，Down丢默认配置但留历史。若错，回退后再升级需重设模式；不丢短链／审计。
