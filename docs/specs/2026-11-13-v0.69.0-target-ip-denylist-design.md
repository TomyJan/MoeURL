## 协议与授权

key `security.target_ip_denylist`，默认 `{"addresses":[]}`。

- GET `/api/v1/admin/system/target-ip-denylist` 返回完整 `{addresses,updatedAt}`。
- POST `/api/v1/admin/system/target-ip-denylist/update` 接受 `{addresses,expectedUpdatedAt}`，返回同一完整资源。两个字段必须存在且非 null；未知／重复字段、类型错误、尾随 JSON、读取失败、查询参数和非 JSON 媒体类型整体拒绝。最多 32768 B，读至 32769 B 判断超限。
- 输入错误 `900220`、版本冲突 `900221`；基线源码初核均未占用。权限 `120001`、目标受限 `200121`、非法目标及基础设施 HTTP500／`900000` 沿用当前协议。所有响应 no-store，不记录地址、完整目标、原 JSON 或可能带值的数据库错误。
- `IPSettings{Addresses []string,UpdatedAt string}`、`IPUpdateInput{Addresses []string,ExpectedUpdatedAt string}`、`IPPort` 及独立 `IPService`／`IPHandler`，不扩四份旧 DTO 或通用系统设置 DTO。
- 当前有效非 builtin 账号、builtin admin 组、admin:access＋system:manage 双权限。Get 使用五秒内的一致读取快照重查；Update 在审计事务中取得 gate 后重查当前 actor 和 group，不信缓存或客户端声明。
- 复用完整 UTC RFC3339Nano 微秒版本解析；先 CAS 后 no-op，陈旧同内容仍冲突，真 no-op 不改版本不记审计，未来版本后仍单调增加。坏存储版本失败关闭。

## 地址规范与目标分类

`normalizeIPs(input []string) ([]string,error)`：nil 或超过100项拒绝；逐项先检查 UTF-8 与控制字符，再 trim 外侧空白，交给 `netip.ParseAddr`。拒绝 zone，使用 `Unmap().String()`；规范后重复整体拒绝，按文本排序。不能用浏览器自动接受的短 IPv4、前导零、八进制或十六进制输入代替标准地址。IPv6 方括号只属于 URL 语法，不属于管理列表输入。

| 管理原文 | 规范身份与结果 |
| --- | --- |
| `192.0.2.1` | `192.0.2.1` |
| `::ffff:192.0.2.1`、`::ffff:c000:201` | 同一 `192.0.2.1`；彼此或与IPv4重复时整体拒绝 |
| `2001:0DB8:0:0::1` | `2001:db8::1` |
| `::192.0.2.1` | IPv6 `::c000:201`，不能错误 Unmap 为IPv4 |
| `127.1`、`0177.0.0.1`、`0x7f.0.0.1`、`192.000.2.1`、尾点地址 | 拒绝 |
| zone、CIDR、URL、userinfo、带方括号／端口、控制字符 | 拒绝 |

`checkIPs(addresses,targets []string) error` 在空列表时立即返回，不增加原语法约束。非空时使用原 HTTP(S) URL／Hostname 分类：无 zone 且 `ParseAddr` 成功的地址，按 `Unmap().String()` 精确查列表；zone 拒绝为 `ErrInvalidTarget`。非地址分支复用 `targetHost`，其 IDNA／标签／数字尾标签错误不可当未命中放行。转换出 IP 的 Unicode／数字歧义仍按原 DNS 分类拒绝，不使用部分 IDNA 输出。原 URL 字节不重写。

端口、path、query 或 userinfo 不能隐藏实际 Hostname。`https://name@203.0.113.9/a` 必须按IP判断，而 `https://203.0.113.9@example.com/a` 的实际主机仍是DNS；原 URL 验证不因此放宽。基础私网／本机等拒绝先按原路径执行，不将其拒绝误归新 `200121`。新缺限制 RED 使用原基线允许的文档测试地址，不做外部访问。

新增前端 IP URL 分支先检查 trim 后的原文 authority，再使用 URL parser 验证完整语法，避免 WHATWG 先把 `127.1`、八进制／十六进制、全角或百分号数字改写成标准 IP 后放行。保留原 DNS 分支、合法 userinfo／端口／混合尾段 IPv6 及原文字节；不借此修复旧 DNS 分支的其他语法。后端基础 `isBlockedTargetIP` 在既有检查前执行 `Unmap`，使 mapped CGNAT 与零地址网段受同一限制；名单为空或不相关时仍拒绝为原 `200103`，公开 mapped 文档地址继续允许。这两项修复不新增 DNS 请求、网段或 SSRF 承诺。

前端 `normalizeTargetPolicyIP(raw:string):string` 只用于校验／比较，不改编辑行或请求原文。严格四段无多余前导零十进制 IPv4；IPv6 先拒控制／zone／方括号／非ASCII／非地址字符，含点尾段再核严格IPv4，使用平台 URL parser 的规范 IPv6 host，识别mapped后转IPv4。服务端仍为权威；请求／GET响应分别校验完整 shape，GET还要求规范、排序、唯一。共享字面向量必须证明Go与前端一致，不以诊断时浏览器的自动改写替代校验；不引入新IP库。

## 五资源、写入与锁

`CheckTargets` 在调用者持 shared gate 的同一事务先读取并严格验证全部五资源，再做 IP、精确DNS和后缀DNS拒绝，最后检查启用的两种DNS允许集合并集。空或关闭的资源也验证存储，不能短路绕过坏值。DNS允许启用时直接IP本来就不被允许；新资源不改变此语义，不给管理员或mapped地址开例外。

七协议仍为单条 create、batch-create、batch-create-with-titles、batch-create-with-metadata、batch-create-with-custom-slugs、本人update、管理员update。任一受限整批零链接、成功审计和新回执；当前授权后先恢复已提交同内容回执，异内容仍冲突。unknown 重试保留不变 payload/requestId，后继确定拒绝不能证明前次未提交。无权／不存在的编辑先走原错误；锁内原目标字节未变或省略时不读策略。历史 open／preview／unlock／continue 不读新资源。

共用双 int32 advisory gate `(0x4d4f4555,0x54504f4c)`：目标写 shared，五份策略保存 exclusive，均先于任何身份／业务行锁。五秒 deadline 包含gate与I/O。先进入reader可先提交，保存提交后进入的新writer必须看到新策略；无跨请求缓存，不承诺多个独立保存跨提交原子化。真实PG blocking PID和有界同步证明队列，不能用固定sleep或瞬时未完成代替。
