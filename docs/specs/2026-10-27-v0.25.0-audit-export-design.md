# v0.25.0 操作审计 CSV 导出设计

## 1. 意图与实现取舍

为既有审计页补齐路线图中的离线核对能力，复用现有 Go／Chi／SQLC／PostgreSQL 和 Vue／Vuetify，不增加依赖。选择管理员、同步、有界且单次快照；浏览器拼分页无法保持一致授权及保留时刻，无限后台任务则扩大存储和交付范围。接口、上限、列格式及实现方式是 Agent 的工程决定，用户没有逐项批准这些细节。

## 2. 接口和授权

新增 `GET /api/v1/admin/audit/export`。仅接受 `days` 或成对 `startDate`／`endDate`、可选 `actorId`、`resourceType`、`action`；沿用审计列表的规范非零 UUID、资源和动作枚举。日期默认 7 天，预设 7／30／90 天，显式日期最多 90 个 UTC 日、不含未来日。拒绝 cursor、pageSize、未知／重复／空参数、非法编码、混合／反向／非法日期；不通过分页 DTO 偷接收分页字段。

`audit:export` 属于 administration，与现有 `audit:read` 一致为受保护的管理员权限。只添加至 admin baseline，user／guest 和 restricted／basic／standard 不添加；不放宽现有“可配置权限等于 user baseline”的目录约束。每次导出同时要求 `admin:access`、`audit:read`、`audit:export`，在 Service.read 的同一 5 秒只读 repeatable-read 事务中重查 active／未删除／非 guest 用户和当前数据库组权限。快照开始前已提交的撤权生效；快照开始后的变化不将同一文件拆成多个授权时刻。UI 权限不替代数据库判断。

成功为既有业务 envelope 中 `{fileName,contentType,content}`，MIME 固定 `text/csv;charset=utf-8`，文件名 `moeurl-audit-{startDate}-{endDate}.csv`，日期取数据库实际范围。非法输入 `100001`、无权 `120001`、审计导出容量超限 `100002`（通用请求容量错误；不复用短链访问导出的 200120），基础设施 HTTP 500／900000。所有响应 no-store，日志沿用现有 insight 的安全诊断，不记录 SQL／SQLSTATE、筛选全文、CSV 或业务内容。

## 3. 查询、保留与资源

使用已有 audit_log 及 `(created_at,id)` 索引，日期为半开 UTC 范围，且 `created_at >= snapshot.now - 180 days`，与现有审计列表一致。先按 actorId／resourceType／action 过滤，再 `(created_at DESC,id DESC)` 排序，读取最多 1001 条候选；bigint ID 全程保持整数，在 CSV 中以完整十进制表示，不经过 JS Number。

候选 MATERIALIZED，只保存 ID、排序和文本长度元数据。原始读取预算包含当前 actor username、resource_type、resource_id、action 及 changed_fields 的完整 JSON 数组 UTF-8 文本；后者的引号、分隔符和 null 同样计入，防止大量空字段元素绕过预算。长度求和前转 bigint。先检查候选 count > 1000 或累计原文 > 8 MiB，超限只返回哨兵，不向 Go 回读大文本。预算通过才按候选 ID 回读，username 与业务字段都在同一快照；NULL actor／不存在账号保持原有 actor_id 与空 username 的区别，不将未知账号伪装成系统 actor。

最终 CSV 另有精确 UTF-8 8 MiB 预算，包含 BOM、表头、CRLF、JSON 数组及 CSV 引号扩张。超限、查询失败、取消或事务提交失败均整体拒绝，不返回部分内容。没有 count 全表、offset、N+1、服务器临时文件或新增索引。读取不修改版本、审计或任何业务数据，在线清理规则不变。

## 4. 文件契约

固定表头：

```text
start_date,end_date,time_zone,audit_id,occurred_at,actor_id,actor_username,resource_type,resource_id,action,changed_fields
```

每行重复实际日期和 UTC，audit_id 是完整十进制 bigint，occurred_at 为 UTC RFC3339Nano。actor_id 为空仅表示数据库中的系统 actor；有 actor_id 但账号缺失时保留 ID、username 为空。用户名延续现有列表的当前快照名称语义，不宣称历史名称。resource/action 使用机器值。changed_fields 为数据库数组的 JSON 文本（如 `["nickname","status"]`、空数组 `[]`），在 CSV 中作为一个单元格，不以逗号拼接损失结构。

复用标准 encoding/csv，BOM／UseCRLF；各文本单元格采用既有 Unicode 空白和 `= + - @`／tab／CR／LF 前缀公式中和。允许标准引号、逗号及 Unicode。将现有 insights 访问导出的有界 buffer 和中和逻辑小范围提为共享 `csv_export.go`，分别映射访问／审计公开限额错误，原访问导出行为与 HTTP 200120 不改变，不建设通用导出框架。空结果仍是 BOM 与完整表头。

## 5. 权限迁移和生成

新增 `00024_audit_export_permission.sql`，只给 builtin admin 补缺失权限，已拥有时不改变 updated_at。追踪本迁移追加及该权限存在性后续 UPDATE 修订，Down 只撤回本迁移追加且未独立编辑的权限；预先拥有、移除再授予、迁移后 INSERT 的组都保留。不给 user／guest 授权，不跟踪 INSERT，不删除审计日志。Up／Down 跟踪清理均使用 Goose 实际事务。

更新权限常量、admin baseline、受保护目录及两种语言标签；SQLC 1.30.0 和权限 fixture 走标准入口，验证完整生成集合与二次零漂移。新请求端口 `AuditExportPort` 与既有 AuditPort 独立，避免扩大列表测试桩及路由契约。

## 6. 前端行为

在 AdminAuditPage 的标题动作区使用标准 Vuetify 导出按钮及 1000 条／8 MiB 提示，无新增导航。显示要求三权限交集。仅当审计查询成功、不在刷新／错误、实际范围可用且 actor／resource／action 草稿与已应用过滤相同并合法时启用；空结果可下载，第二页仍请求全部筛选、不携带分页。range 使用加载响应的实际日期，浏览器验证日历／顺序／90 天，不凭本机时钟否定服务器日期。

固定已应用日期／过滤／父级同步 contextRevision 和账号轮次。pending 防重复；筛选或分页往返、未应用草稿、查询 pending／error／refresh、换号、同账号重新登录、同步 cache 撤权及卸载后，迟到成功／失败不得下载、Toast 或覆盖新状态。前后直接读取 auth cache 检查权限，不能只靠上次渲染。

当前拒绝 120001／401／403 清除旧授权，复用 v0.24 的跨组件 useAuthorizationRefresh 与 Shell 协调；旧身份的拒绝不动新号。100002 提示缩小范围或过滤，100001／普通故障保留输入可重试。没有下载时不创建 Blob URL；准备或保存失败仍清理临时节点和 URL。响应严格校验固定文件名／MIME／BOM／表头／UTF-8 字节上限，复用 downloadCsv。

## 7. 验证和交付

真实 PostgreSQL 覆盖三权限分别缺失、stale grants、guest／无效／停用／软删账号、固定日期及 180 天边界、系统与已删除 actor、bigint 超过 2^53、并列时间排序、0／1000／1001、两种独立字节预算、JSON 数组／多字节／公式／引号、快照并发写入／撤权、查询／提交故障／取消、无副作用及迁移 Up／Down／再 Up。HTTP 验证严格 query、envelope／no-store、业务码、安全日志与接线。共享 CSV 抽取须验证既有 visits 不回归。

前端真实 QueryClient／身份／下载边界覆盖已应用过滤／日期、未应用全部三种草稿、非首页、空结果、非法响应、所有失败与并发／账号生命周期；真实 Shell 拒绝恢复。E2E 独立 fixture 通过真实业务产生审计，桌面／手机实际下载并核对固定字段、过滤、隐私、完整页外结果、撤权和对象清理，不 mock 产品 API，不依赖跨测试顺序。

完整 Go／原业务 100%、前端四项 100%、静态／隔离构建、生成零漂移、完整 Playwright、Linux race／govulncheck、production smoke 与精确镜像扫描，不降低阈值或扩大排除。每轮实现／本地门禁／PR CI／真实 CodeRabbit／合并／发布分开。用户要求合并后 CI 不作为下一轮开发的等待门禁；后台继续跟进并优先修复真实失败，不宣称必然成功。

真实浏览器场景位于 `web/e2e/v0.25.0-audit-export.spec.ts`。每场独立 user／admin 账号，以实际创建、25 次标题编辑、停用和启用固定产生 28 条审计，动作及字段数组按字面量核对，只有 ID／时间取自独立列表 API。为验证超出 2^53 的真实业务 ID，仅在核实项目／容器／卷／数据库归属的专用 Compose 库推进 identity sequence，不插入或改写审计；整体数据库由本场专用 project teardown 清理。旧页面撤权通过另一管理员的真实改组 API 撤销全部会话，不能绕过 protected 权限编辑规则。定向后冻结完整 web／E2E、后端与部署输入，再在精确提交运行完整浏览器和 production 制品验证；各类镜像及后续纯文档提交分别归属，执行证据见[验收](../implementation/v0.25.0-acceptance.md)。
