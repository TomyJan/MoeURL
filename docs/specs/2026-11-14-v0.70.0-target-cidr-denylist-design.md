# 目标 CIDR 黑名单设计

## 意图与边界

管理员目前只能逐个列出 IP。新增独立网段列表，限制今后的字面 IP 目标写入；不解析 DNS，也不改变历史访问。[范围](../product/scope-v0.70.0.md)为权威。方案由 Agent 在长期自主授权内选择：扩展旧 addresses DTO 会破坏 strict 契约，通用规则引擎又超出当前需要，因此沿用现有独立资源模式。

## 网段与地址身份

Go 使用 `netip.ParsePrefix` 和 `Masked`；先拒控制字符／非法 UTF-8，再 trim，单个 `/` 后必须为 `0` 或非零开头的 1–3 位 ASCII 数字。拒绝 zone 和 `Addr().Is4In6()`。规范文本排序、重复整体拒绝，重叠不合并；空切片有效、nil 无效。存储必须已经规范且排序，不执行读取修复。

| 输入／目标 | 结果 |
| --- | --- |
| `192.0.2.129/24`、`192.0.2.0/24` | 同为 `192.0.2.0/24`，一起提交为重复 |
| `2001:0DB8:1234::9/48` | `2001:db8:1234::/48` |
| `192.0.2.1/32`、`2001:db8::1/128` | 单地址范围 |
| `0.0.0.0/0`、`::/0` | 分别拒绝全部新 IPv4／原生 IPv6 目标，允许管理员明确配置 |
| `::ffff:192.0.2.0/120`、`::ffff:c000:200/120` | 拒绝，提示使用 IPv4 CIDR |
| `192.0.2.0/024`、`/33`、IPv6 `/129`、缺 `/`、zone／URL／端口 | 拒绝 |
| mapped 目标 `https://[::ffff:192.0.2.9]/` | Unmap 为 IPv4，只按 IPv4 CIDR 匹配 |
| 兼容 IPv6 目标 `https://[::192.0.2.9]/` | 保持原生 IPv6，不错误转成 IPv4 |

新 `checkCIDRs(prefixes, targets []string) error`：空列表立即返回；非空规则解析为至多100个规范 Prefix。URL 解析保持现有 HTTP(S) 约束，取实际 Hostname；字面地址无 zone、Unmap 后用 `Contains`。非字面地址复用 `targetHost` 的 IDNA／数字歧义拒绝，普通 DNS 不做网络解析也不因 CIDR 命中。URL 原文字节不改写。新的列表不能放行原基础私网禁限或绕过 DNS 允许策略。

前端 `normalizeTargetPolicyCIDR(raw:string):string` 复用现有严格 IP 规范函数，映射型原文规范后变为 IPv4时整体拒绝，拒绝非规范前缀长度。以 BigInt 计算 IPv4／IPv6 主机位清零；IPv6 hextet 输出再由平台 URL parser 压缩，不能让 URL parser 先接受数字别名。原输入仅校验，不在编辑时改写。GET schema 要求规范排序唯一，POST 允许合法非规范主机位并保持原字符串。

## 协议、事务与集成

`CIDRKey`、`CIDRSettings{Prefixes []string, UpdatedAt string}`、`CIDRUpdateInput{Prefixes []string, ExpectedUpdatedAt string}`、`CIDRPort`、`CIDRService`、`CIDRHandler`，文件使用 `cidr_*`。GET 返回 `{prefixes,updatedAt}`，POST 接受 `{prefixes,expectedUpdatedAt}`；两字段必需且非 null，未知／重复字段、尾随 JSON、非 JSON 媒体类型、query 和超过32768 B均拒绝。复用已修复的原文／UTC年份、零值和微秒版本契约。

沿用五秒读快照和审计事务：当前数据库身份／双权限，gate→actor→group→setting锁序；先完整版本 CAS 后 no-op，no-op不改版本或审计。输入900222、冲突900223、权限120001、基础设施HTTP500/900000，返回no-store，日志不含规则、目标或原始数据库错误。

App启动验证第六份资源；router只注入独立port，无新前端固定路径。`CheckTargets`先读并验证全部六份资源，再CIDR／精确IP／精确DNS／后缀拒绝，最后保留DNS允许并集。共享gate先于身份锁，所有七写入口沿用原事务，无跨请求缓存或管理员绕过。回执恢复仍先于新策略判定；旧访问和锁内同字节编辑不读新资源。

迁移00046使用默认空和ON CONFLICT DO NOTHING，独立仅键名审计trigger/function；Down保留数据和历史，旧应用不会执行新限制。现有SQLC查询足够，schema变化仍标准生成两次核全输入／输出零漂移。

## 验证和运行安全

独立字面向量覆盖主机位、两族端点、mapped拒绝／目标Unmap、兼容IPv6、重叠、宽规则及数字歧义。真实App端点和插入设置后的创建行为先RED，非编译／fixture故障。真实PG验证锁序、撤权、同版本并发唯一赢家、审计回滚、六份坏存储、七个协议入口零部分写、回执优先和旧访问；迁移往返保留值及精确版本。

完整本地门禁、准确新app/web产品及必要浏览器和原图独立留证；未改变的Goose可按完整输入恢复并保留原归属。唯一独立终审后按实际CodeRabbit恢复时间及fresh no-running守卫请求；正常合并、独立SHA/tree/唯一父和恢复归档。不查CI、不发布部署；4/12/6GiB预算，生成与清理串行，准确归属清理。用户无人值守授权覆盖例行设计问答，设计与计划自行交叉检查，不新增builder审查席。
