# v0.68.0 可选 DNS 后缀白名单设计

## 意图与方案

精确允许只针对单个 DNS 主机，后缀拒绝已经具备标签边界语义；本增量为管理员提供同样明确的域名族允许策略。[范围](../product/scope-v0.68.0.md)是产品边界。基线 PR326/master fe36797f，当前实施与实际验证状态见[验收](../implementation/v0.68.0-acceptance.md)。

扩旧精确允许 DTO 会破坏 strict shape，独立两允许策略取交集则无法让新增后缀项允许新子域。Agent 选择独立默认关闭资源，启用集合取并集；拒绝仍优先。不开新授权层，不建通用 CRUD 框架，不引入公共后缀库、DNS 网络检查或 SSRF 承诺。

## 管理协议与存储

key `security.target_host_suffix_allowlist`，默认 `{"enabled":false,"suffixes":[]}`。

- GET `/api/v1/admin/system/target-host-suffix-allowlist` 返回 `{enabled,suffixes,updatedAt}`。
- POST 同路径 `/update` 接受 `{enabled,suffixes,expectedUpdatedAt}`，返回同一完整资源。三个字段必须存在且非 null；未知、重复、错误类型、尾随 JSON、查询参数、非法媒体类型及读取失败整体拒绝。上限 32768 B，读取至 32769 B 判超限。
- 新 `900218` 输入错误、`900219` 冲突，已在与基线同 tree 的候选查无占用；权限 `120001`、目标受限 `200121` 和基础设施 HTTP500/`900000` 沿用。所有响应 no-store，不记录列表、目标或原 JSON。
- 0–100 项，启用必须非空。沿用 normalizeHosts 的完整 ASCII／ACE、控制字符先拒后 trim、单尾点、小写、253/63 字节、禁 URL/port/userinfo/原始 Unicode/通配/IP/数字式尾标签、规范重复整体拒绝及 canonical 排序；父子冗余允许保存。读取拒绝非 canonical 存储，不暗中修复。
- 完整 UTC RFC3339Nano 微秒版本，先检查 CAS 再 no-op；陈旧同内容也冲突，真 no-op 不改版本不记审计，未来版本后仍单调前进。有限有效版本、合法键及值全部校验。
- 当前有效非 builtin 账号、builtin admin 组和 admin:access＋system:manage 双权限。Get 用有界一致快照；Update 用审计事务，在 gate 后重查当前身份和组。五秒 deadline 覆盖 gate、行锁与 I/O。

## 四种策略合并语义

先在调用者持 gate 的同一事务读取并验证四份资源，包含关闭策略；任一缺行、坏 JSON、非法版本或 I/O 均失败关闭。然后精确黑名单、后缀黑名单优先拒绝，最后检查启用允许集合。

| 精确允许启用 | 后缀允许启用 | 两种拒绝均未命中后的条件 |
| --- | --- | --- |
| false | false | 不新增目标分类或语法限制 |
| true | false | 有效 DNS 精确命中 hosts |
| false | true | 有效 DNS 自身或子域命中 suffixes |
| true | true | 有效 DNS 命中上述任一集合 |

关闭但非空的预配置项不能授权。任何允许策略启用时 IP 的空 DNS 分类必须拒绝。复用 targetHost 的 IDNA 和单尾点分类，错误不得用部分输出；完整目标 URL 原文不重写。

后缀按 `host == suffix` 或以 `.`＋suffix 结尾匹配，覆盖任意深度；badexample.com 和 example.com.evil.test 不命中 example.com。父子重叠允许，不自动删项。没有“注册域”推导，com 会允许全部对应 DNS 子域；卡片必须警示宽范围。

新 `SuffixAllowlistSettings`、`SuffixAllowlistUpdateInput`、`SuffixAllowlistPort` 和 service/handler 独立于原三 DTO；`checkAllowlistTargets(exact AllowlistSettings, suffix SuffixAllowlistSettings, targets []string) error` 为统一允许判定入口。复用当前身份、strict object、host、版本、审计及 gate 辅助，不在七个协议复制四策略逻辑。

## 写入、锁、迁移

既有 CheckTargets 继续承接单条、四种批量、本人和管理员实际改目标。当前授权先于已提交同内容回执恢复，策略后改不能破坏恢复；异内容仍冲突。无回执新批次有一项被拒则整批零链接、成功审计、回执。先 unknown 后确定拒绝仍 unknown，保留不可变 payload/requestId。

锁内原目标字节完全相同或省略目标的编辑不读取新限制；改变 path/query 仍是新目标。历史 open/preview/unlock/continue 不读规则，其他访问条件继续执行，无管理员绕过。

沿用双 int32 gate `(0x4d4f4555,0x54504f4c)`。目标写先 shared，再身份和业务行锁；策略保存先 exclusive，再 actor/group、对应 setting FOR UPDATE。无跨请求缓存；已进入 reader 可先提交，保存提交后才进入的新 writer 必须看到新规则。不同资源保存串行，不承诺多个独立提交原子化。真实 PG blocking PID 与有界同步验证，不用固定 sleep。

新增 `00044_target_host_suffix_allowlist.sql`，当前最后迁移为00043。Up 默认关闭、ON CONFLICT DO NOTHING，独立仅键名审计 function/trigger。Down 卸新 function/trigger，保留设置、版本、审计；再 Up 不覆盖。旧应用回退会忽略新 key：后缀允许原来独立承担的限制会失效；若旧精确允许仍开，旧应用仅按原精确允许限制，不能声称继续执行并集。必须明确回退差异。

App 启动校验第四份资源，router 独立注入新 port；无新前端固定路由，不改变短码保留集合。SQLC 查询不变，但 schema 含新 migration，仍按锁定1.30.0标准入口两次生成，完整输入／输出 hash/bytes 核零漂移，不手改生成物。

## 前端

新 entity/query key/draft/editor，字段 suffixes；独立卡片放在 AdminSettings 既有 general form 外，精确允许卡片附近。旧精确允许卡片新增并集说明。双语说明覆盖自身及所有子域、宽规则、拒绝优先和仅今后目标，沿用既有响应式输入行／按钮。

关闭保留列表和草稿，开启空表不能保存，清空不暗中关闭。成功加载前不可保存；编辑不排序，保存后才采用服务端 canonical。明确 900218 输入拒绝保草稿并允许修正重试；网络中断、HTTP 5xx、无效响应及其他未知保存结果保草稿，持久提示核对服务器设置并阻写。冲突同样保草稿并阻写；只有显式重载成功且被当前身份和编辑 revision 接受才解除，失败或被后续编辑淘汰的重载不能解除未知屏障。load/save 每个 success/error/finally 都核当前身份 scope/generation，edit revision 防读取覆盖新编辑；切号、同号重登录、撤权、卸载清列表并隔离 query cache。不增加管理写回执协议。

既有200121反馈和unknown优先级不变。product package版本在 Task2 更新0.68.0，依赖集合／版本、lock/workspace不变。仅版本metadata导致依赖image三文件校验失配时，可核依赖闭包完全一致后创建准确小派生层更新metadata；不重复安装或复制整store，不静默跳过manifest匹配，实际image及runtime另留证。
