# CSV 标签双重字节上限回归设计

本维护补 v0.55.0 独立终审 M1，协议不变：CSV 文件和未来完整 metadata JSON 请求各最多 65536 字节。当前 parser／schema 正确，不为制造 RED 改写产品；新测试直接通过属于补验，私有故障变体用于证明回归保护。

## 测试边界

- 使用真实三列 CSV、JSON 标签数组及 CSV 双引号转义，不 mock parser／schema。标签包含引号、反斜杠、逗号与 Unicode。
- 两个 LF／CRLF 场景：完整未来请求分别恰好 65536 和 65537 字节，CSV 两者均小于文件上限；前者完整接受并保留原文及标签顺序，后者整体拒绝。
- 四个 LF／CRLF × 无／有 BOM 场景：十个合法、互不重复的引号密集标签使 CSV 转义开销大于请求封装开销。文件分别恰好 65536 和 65537 字节，请求均小于上限；分别接受／拒绝，BOM 和换行纳入文件实际字节。
- 独立 TextEncoder 测最终完整字符串；使用多字节字符，证明字符串 length 不能代替 UTF-8 字节数。原始标题合法空白用作填充，归一化后的标题仍合法。
