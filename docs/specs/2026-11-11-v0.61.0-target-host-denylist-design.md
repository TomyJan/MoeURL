# v0.61.0 目标主机精确黑名单设计

## 范围选择

本版依据路线图自主选择 exact-host denylist。一起实现黑白名单会扩大优先级与自锁问题；在公开访问阶段封禁历史链接会改变已分发地址的可用性。因此只管今后的目标写入，空列表兼容当前行为。详见[范围](../product/scope-v0.61.0.md)。

## 管理协议

独立 key `security.target_host_denylist`，值 `{"hosts":[]}`。

- GET `/api/v1/admin/system/target-host-denylist` 返回 `{hosts,updatedAt}`。
- POST `/api/v1/admin/system/target-host-denylist/update` 接受 `{hosts,expectedUpdatedAt}`，返回同一资源。
- 当前有效、非 builtin 账号，所属 builtin admin 组，同时有 `admin:access` 和 `system:manage`。读取用有界一致快照重查，写入在审计事务内重查，不信客户端身份或权限缓存。
- 请求最多 32768 字节。必需非 null 字段、未知／重复字段、尾随 JSON、错误类型一律拒绝。空数组明确清空。
- 版本为可完整回传的 UTC RFC3339Nano、微秒精度；先比较版本再判断 no-op。陈旧版本即使内容相同也冲突；真正 no-op 不改版本、不记审计。
- 格式错误 `900210`、冲突 `900211`、目标受限 `200121`，权限沿用 `120001`。缺行、坏存储及 I/O 为 HTTP500／`900000`。所有响应 no-store；错误日志不含列表、目标 URL 或原 JSON。

## 主机规范化与匹配

管理列表最多 100 项。先拒绝原字符串控制字符，再用 Go trim 去外侧空白；trim 后每项 1–253 ASCII 字节，每标签 1–63，标签仅字母数字和中间连字符。小写后允许移除恰好一个终止点，残留空标签拒绝。禁止 URL、port、userinfo、Unicode 原文、通配符、IP 和数字／十六进制数字尾标签。普通 ASCII 双连字符允许；`xn--` 标签需通过现有 IDNA 校验。规范化后重复整体拒绝，成功按 ASCII 排序。

目标先通过现有 `validateTargetURL`，保存原文不重写。原 `netip.ParseAddr` 可识别的 IP 不由 DNS 黑名单匹配，既有 IP 校验不变。ASCII DNS 用显式标签规则；Unicode DNS 用现有 `idna.Lookup.ToASCII` 后再用标签规则。转换后统一小写，最后只去一次终止点，不能前后各去一次。IDNA 返回任何错误均拒绝，即使同时返回部分字符串。非 IP 原文转换成 IP／数字简写须拒绝为非法目标，不能作为未命中放行。非空策略下无法明确分类的目标以原非法目标错误拒绝；空列表不增加原 URL 语法限制。

只精确匹配规范 host，不含子域。scheme、port、path、query 和 fragment 不影响 host 比较。该机制不做 DNS 查询、重定向跟踪、外部信誉判断或 SSRF 防护。

## 写入及回执

单条 Create、统一批量 Create、本人 Update、AdminUpdate 四个 service 路径覆盖七个 HTTP 协议，无管理员绕过。批量任何一项受限整批回滚，无链接、成功审计或回执残留。

当前身份与权限检查后先查已提交回执；相同 key 同内容恢复原结果，之后才考虑新策略。相同 key 异内容维持冲突，不改原摘要算法、版本或重试 payload。前端将 `200121` 识别为确定拒绝，但此前已 unknown 的批次维持 unknown 与不可变 payload／key，不能用后续拒绝证明前次未提交。

Update 有目标字段时，在授权归属范围内锁定 link 并比较当前目标原文字节。省略目标不读策略；锁内完全相同也不读策略，允许修改其他配置。真正改变目标时才检查；变路径或 query 同样受限。无权／不存在先返回原错误，不泄漏其他用户的目标或黑名单命中。公开 open／preview／unlock／continue 不读新策略。

## 事务和锁

中立包 `internal/targetpolicy` 提供规范化、策略读取、gate 与管理资源，shortlink 调用它，不形成 system／shortlink 环依赖。

专用 PostgreSQL 事务 advisory gate 为双 int32 `(0x4d4f4555,0x54504f4c)`，SQL 显式 `$1::integer,$2::integer`。该键空间与既有 domain bigint、OIDC hash bigint 分离，提交／回滚自动释放，无进程缓存或 session 锁。实施前核全仓无相同双键。

| 路径 | 同一事务锁及行为顺序 |
| --- | --- |
| 单条创建 | policy shared → domain shared → 原授权 → 当前策略 → insert；slug 冲突每事务重新读 |
| 批量创建 | policy shared → domain shared → actor／group → 回执恢复 → 无回执时策略与全批校验 → insert／receipt |
| 有目标 Update | policy shared → 归属范围内 link FOR UPDATE → 原文字节变化时策略 → 原 SQLC 更新 |
| 管理保存 | policy exclusive → 当前 actor／group share → setting FOR UPDATE → 完整 CAS → 更新／键名审计 |

gate 必须先于任何业务行锁，不能先持 actor／group／link 再取 gate。仅 actor→group→policy 行锁不足：Create 的 owner FK 晚取锁可能产生反向锁序。五秒 deadline 覆盖 gate、所有行锁与 I/O。先进入的 reader 可以先提交，保存提交后才进入的 reader 必须读新策略。实际 PG 队列和有界条件证明顺序，不能用固定 sleep 或瞬时未完成冒证据。

## 存储、启动与回滚

迁移 `00039_target_host_denylist.sql` 插入空值，独立 trigger 只审计 key，不含 host 或目标。Down 卸载本版 trigger／function，保留列表、版本、历史；再次 Up conflict-do-nothing，不覆盖定制值。

读取只接受已规范、小写、排序、唯一的存储；结构正确但非 canonical 同样失败，不在读取时重排或默认补行。启动验证存储，后续请求仍逐次读取。旧应用回退不会执行新策略，该限制须披露。SQLC 只经锁定 1.30 标准入口生成，连续两次核完整输入和输出零漂移。

## 前端

AdminSettings 独立卡片、entity 和草稿，不扩 general form 或旧 strict DTO。0–100 个表单行，每行 host 与删除；可增加、清空、保存和显式重载，无表格或虚拟列表。编辑时不排序或移焦，保存后使用服务端规范结果。说明精确主机、ACE 输入、仅新目标与不含子域。

身份／权限 generation 同步使所有迟到 load／save success、error、finally 失效；edit revision 阻晚 load 覆盖已编辑草稿。切号、同号重登录、撤权、卸载都清旧数据，旧缓存不闪现；冲突保草稿，不自动重试写入。当前权限不足清列表并禁操作。

单条、四批量、本人和后台设置均将 `200121` 映射为明确双语受限反馈，保留输入。不与域名授权 `200114` 混淆，不触发无关权限恢复。批量确定拒绝集合增加新码；原 `unknown || newUnknown` 优先级保留。
