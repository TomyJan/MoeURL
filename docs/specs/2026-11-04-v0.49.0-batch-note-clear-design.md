# v0.49.0 设计：批量清空内部备注

状态：2026-11-04 从 PR263 已交付 master fa020805ed5499f40a9f437d710f3eb661247057 启动，Agent 根据持续无人值守授权选择本增量。后端已实现并通过最终 host 完整回归／vet／业务覆盖率 100% 及 Linux race／安全门禁；前端和交付尚待，实际结果见[验收](../implementation/v0.49.0-acceptance.md)。

## 目标与取舍

路线图的“备注批量编辑／历史”尚未实现。优先补最小闭环：本人和全站列表在当前页选择 1–100 条短链，先查看受影响数量，再显式确认清空内部备注。适用于清理一次性运营说明；不改变目标地址、标题、标签、状态、归属或公开访问。

不做批量替换／追加正文、备注历史、撤销、跨页全选、后台任务、导入导出备注或新权限。替换与追加会扩大文本处理、误写和正文暴露范围；历史需独立保留与隐私策略，不混入本版。没有数据库 migration 或新依赖。

风险为中：原子批量删除私密文本，主要危险是覆盖选择后新改的备注、越权或未知结果被自动重试。两个版本检查、全量预检和显式确认共同防护。

## 产品流程

列表沿用当前页选择和最多 100 条限制。工具栏新增“清空备注”／“Clear notes”，权限等同单条备注写入。新对话框与单条备注、访问设置、批量标签、转移、删除、创建及导出互斥，打开时固定目标 ID 与列表完整版本。

打开后只发预览请求，显示选择数、有备注数和已为空数，不读取或展示备注正文。预览失败可显式重试；发生版本冲突或资源变化时关闭本次确认，刷新列表后重新选择，不悄悄换目标。预览成功才显示“清空 N 条备注”的破坏性确认按钮；全部为空时只显示无需操作，不发清空请求。

确认期间锁定对话框普通关闭与其他写入口；发送一次，禁止自动重试。成功显示实际清空数／未变化数，清选择并刷新当前列表，保留筛选与每页大小。备注条件可能让成功清空的行退出结果集，这是正确行为。

网络中断、5xx 或畸形成功响应视为结果未知，保留原固定目标并禁用确认。用户可显式重新预览核对当前结果；核对成功只展示新数量，下一次写仍需重新确认，绝不自动重放旧请求。若主版本已变化，退出并要求刷新后重新选择。关闭不等于撤销服务端可能已成功的操作；提示仅说明无法确认结果，不展示请求／响应正文。

桌面／手机支持换行和滚动，按钮不被挤出；标题、计数、不可撤销提示、加载／失败／冲突／未知状态和无障碍标签均有中英版本。键盘可以打开、取消及确认，焦点恢复遵循现有 dialog 行为。

工具栏的危险操作使用既有 error 色与 tonal 样式；焦点初始落在取消按钮，不能默认聚焦破坏性确认。写入期间 dialog persistent，身份／权限退休仍可强制关闭。关闭后优先还原到原入口；入口因授权变化消失时回到当前列表可聚焦容器，不能把焦点移回旧身份元素。

| 状态 | 中文 | English |
| --- | --- | --- |
| 提醒 | 此操作会永久清空所选备注，无法撤销。 | This permanently clears the selected notes and cannot be undone. |
| 确认 | 清空 {count} 条备注 | Clear {count} notes |
| 全空 | 所选备注均为空，无需操作。 | All selected notes are already empty. |
| 未知结果 | 无法确认清空结果。请重新核对后再决定是否清空。 | We could not confirm the result. Check the current notes before deciding whether to clear them. |
| 未知结果只读动作 | 重新核对 | Check current notes |

未知状态不用“重试清空”或成功提示。重新核对失败继续显示未知；重新核对成功后仍须用户再次确认，服务端已清空的项目计入已空数。英文单数／复数沿用现有 i18n 计数规则，测试 0／1／100，不展示“1 notes”。

## API 与严格边界

复用 `/api/v1`、Cookie Session、业务错误码和 `Cache-Control: no-store`；固定本人／管理员端点，不接受客户端传 scope 或 actor。

| 动作 | 本人路径 | 全站路径 |
| --- | --- | --- |
| 预览 | POST `/short-link/note/batch-clear/preview` | POST `/admin/short-link/note/batch-clear/preview` |
| 清空 | POST `/short-link/note/batch-clear` | POST `/admin/short-link/note/batch-clear` |

预览输入恰为 `{items:[{id,expectedUpdatedAt}]}`，每项固定列表主版本。输出恰为 `{items:[{id,expectedUpdatedAt,expectedNoteUpdatedAt,hasNote}],nonemptyCount,emptyCount}`，保留请求顺序，ID 集合与输入完全一致。`hasNote` 严格等于数据库 `note <> ''`，BOM 也算非空；不 trim 或修改旧正文。版本输出为完整 UTC RFC3339Nano。

清空输入恰为 `{items:[{id,expectedUpdatedAt,expectedNoteUpdatedAt}]}`，不接收正文、hasNote 或客户端计数。输出恰为 `{changedCount,unchangedCount}`；两者为非负整数且总和等于输入长度。客户端严格验证输出字段、ID 集合／顺序、完整版本和计数一致性，拒绝额外正文。

预览响应的主版本必须与打开时固定的请求版本代表同一完整时刻。客户端先用共享 noteVersionSchema 验证语法，再按整秒与补齐九位的小数比较，不使用毫秒 Date 截断来比较 CAS；等价 offset 可以通过，相差 1ns 必须拒绝。清空沿用打开时主版本原字符串，只采纳本次实际预览的备注版本；服务端或畸形响应不能悄悄换掉主版本以绕过选择时的并发条件。

原始请求体上限 64 KiB；JSON 顶层／每项字段严格，拒绝未知字段、重复键、null、错误类型、尾随 JSON、无效 UTF-8 及未配对代理字符。items 为 1–100 个唯一非零规范小写 UUID。两个版本均复用备注严格版本解析，保留原字符串精度，不用 JS Date 重新格式化 CAS。预览不得悄悄替换过期的列表版本。

Content-Type 必须为 application/json，拒绝查询串。沿用可选 `X-MoeURL-Expected-User-ID` 与实际 Cookie actor 精确绑定；正式客户端始终发送，不能借 header 赋予身份。无效输入 100001，缺资源／不可见 200104，完整版本冲突 200116，无权限 120001；基础登录及基础设施状态沿用既有规则。响应和日志不含私密正文，错误不暴露单个失败 ID 或当前版本。

## 授权、事务和并发

预览与清空均要求当前账号 active、未删除且非 guest，并重查组当前权限。本人需 read_own＋update_own＋set_metadata；全站需 admin:access＋read_all＋update_all＋set_metadata。请求快照中的权限不足以授权。

总期限五秒。锁序固定为 actor 共享锁→当前组共享锁→按 UUID 排序的全部短链锁。预览使用短链共享锁，清空使用更新锁；两者都在同一事务快照核全部 live／owner／主版本，清空再核全部备注版本。先拿完整锁集合并完成所有预检，然后才执行任何写入；缺任一项、越权或任一冲突则整批零写入。与单条备注、批量标签及转移保持既有锁序，不使用固定 sleep 证明同步。

在已取得的全量行中先核集合完整与全部可见性，再核全部版本，最后才写入；不因输入顺序让可见 stale 项掩盖另一项不可见／缺失。READ COMMITTED 下等待资源锁后以实际取得的行版本为准；不把先前查询或客户端快照当锁后授权。预览用现有 WithTx 的普通事务，业务上只读且不设置审计 actor；不能开启 PostgreSQL READ ONLY，因为 SELECT FOR SHARE 行锁不允许用于该事务模式。清空才使用 WithAuditTx。

预览可通过新增 SQLC share 查询取得 ID、owner、updated_at、note_updated_at 及 hasNote，不返回正文。清空专用 update-lock 查询同样只需 hasNote，无需在 service 持有完整 note。对应 SQLC 查询走仓库标准生成入口并再次生成核零漂移，不手改生成物。

清空在 WithAuditTx 中执行，仅对非空项调用现有 UpdateShortLinkNote(note='')，从而推进 note_updated_at；主 updated_at 及所有其他字段不变。已空项仍须通过两个版本检查，随后 no-op：不推进任何版本，不写审计。现有数据库审计触发器每个真实变化只记录 actor、资源与 note 字段名，正文不进入审计；审计失败整批回滚。事务取消／连接失败不允许部分提交。

两个使用相同备注版本、至少含一条非空备注的并发清空至多一方真实写入；另一方冲突。全空且版本准确的两个请求均可 no-op 成功。单条备注编辑若先提交，旧预览清空冲突；批量先提交，旧单条保存冲突。转移／配置变化引起主版本变化后，旧预览不得继续清空，即使管理员仍有全站权限。

## 前端状态与缓存

新增独立 strict entity 和独立 controller/dialog，不把新写操作塞进旧通用批量 finally。作用域固定 own/admin；使用现有 useShortLinkAccess 的实时 read/tags 检查和账号 epoch。

每次打开捕获账号 epoch、权限签名、打开代际、操作编号和不可变目标快照。同步监听授权缓存变化，包括撤权后同 tick 恢复，立即退休上下文；卸载、身份轮换、筛选／页／大小变化亦退休。每个 success/error/finally、toast、cache 更新和失效请求均先检查同一 capture；晚到的旧请求不能清除新 pending、复活对话框或刷新新账号数据。普通关闭禁止打断在途写，但权限退休永远允许清私密状态。

预览不进共享列表缓存，不持久化 storage／URL；对话框销毁清除预览版本、目标和错误。若使用 TanStack Query，仅在独立、含账号 epoch／授权代际／打开代际的 key 下保留预览，并在退休时 cancel/remove；不让旧缓存绕过显式预览。未知结果后必须实际读回，不能用成功旧缓存解除冻结。

列表、CSV、公开 DTO 仍不增加 note、noteUpdatedAt 或 hasNote。列表入口只捕获已有 id／updatedAt，不把主版本当备注版本。新接口是私密管理用途，路由位于现有固定 API 下，不新增顶层短码保留字。

## 测试重点

- 边界 0／1／100／101，重复 ID、大小写／零 UUID、重复嵌套键、unknown/null、64 KiB 边界、尾随 JSON、损坏编码；两个版本共享人工严格语料，纳秒与等价 offset 不丢精度。
- 两种 scope 的当前授权、guest、普通用户访问 admin、跨 owner、已删除／失效账号；预览不写且不泄漏正文，清空之外完整行字段不变。
- 混合非空／空、全空、BOM 与多行私密 canary；准确计数、单项审计、全部无正文；后项 stale／缺失时前项也不改变。
- PG 阻塞队列验证账号禁用／改组、组撤权、主版本变化、单条备注写入、两个批量竞争及取消；审计拒写故障证明全部回滚。同步使用可观测锁队列、channel 或有界条件，禁止固定休眠冒证明。
- 客户端 malformed success、错 ID／重复／漏项／额外正文、版本失真、非整数或总数错误；错误不携带私密 response。
- UI 双击仅一次；延迟成功／失败／finally 遇到退出再登录同账号、权限撤回恢复、重开、卸载、筛选／页大小变化均不能污染新上下文；未知写保持冻结直到新预览实际完成。
- 手机／桌面中英、键盘、固定目标确认、批量动作互斥；筛选清空后的结果和页码归一化沿用既有行为，CSV 与公开访问回归。
