# v0.51.0 当前选择标签重命名设计

方案由 Agent 按无人值守授权选择；沿用 Go／SQLC／Vue／Vuetify。现有 add/remove 不能在同一事务改名，replace 会抹掉每条不同的标签；新增独立 rename，避免扩张旧协议。没有全局标签实体、跨页全选、自动重试、撤销、备注历史、新权限、依赖或 schema。

## 服务端契约

本人 `POST /api/v1/short-link/batch-tag-rename`；管理员 `POST /api/v1/admin/short-link/batch-tag-rename`。只接受单个严格 JSON 对象 `{items,fromTag,toTag}`，每项恰为 `{id,expectedUpdatedAt}`。1–100 个唯一规范非零 UUID；版本为完整非零、可回传年份范围的 RFC3339Nano。拒绝未知、重复、大小写别名字段、null、类型错误、尾随 JSON、无效 UTF-8／孤立代理项、query、不支持的 Content-Type；body 最多 64 KiB。

旧／新各先拒原始控制字符与无效 UTF-8，再 Go Unicode 空白裁剪；非空、最多 32 码点，大小写敏感，不 Unicode 规范化。trim 后相同拒绝 100001；大小写不同允许。BOM 保留。旧 normalizeTags 实际先 trim 再拒控制，新接口刻意先拒 raw，旧接口不改。

有旧无新：在旧位置替换。旧新都有：只移除旧，保持已有新标签位置与其余顺序。无旧：完全 no-op。每条最多 10 个标签不变。

本人需 update_own＋set_metadata 且当前 owner；管理员需 admin:access＋update_all＋set_metadata。前端预览另需对应 read，后端不误用备注权限函数增加 read 要求。五秒上下文，账号→组→UUID 锁序；锁后核当前账号、组、权限、归属、软删除和完整主版本，no-op 也检查。任一失败全批零写；仅改变 tags 的行推进主版本，字段名审计与写入同事务，审计失败全回滚。复用 SQLC LockBatchTagsShortLinks／UpdateBatchTags，无 SQL 变化不重生成。

响应只含 `{changedCount,unchangedCount}`，非负整数且总和等于 items 数量。复用 100001／120001／200104／200116 和基础设施 900000；全部 no-store，日志不含标签、URL、请求或失败目标正文。

## 页面与确认

两列表增加“重命名标签”，打开固定 ID／完整主版本／公开 URL／标签和身份轮次。旧名、新名各有名输入，展示逐条前后标签、预计变化和无旧数量，并写明“只影响本次选择，不是全局标签重命名”。全部预计 no-op 时不发送写入。

每次编辑退役批准。批准绑定当前预览对象、打开代际、草稿代际；A→B→A、旧 confirm 闭包、关闭重开、撤权后恢复都不能复活批准。所有入口及 success/error/finally、focus、toast、invalidate、清选择均同步复核当前身份／权限／auth 状态签名。后台刷新不替换固定快照。

与设置、二维码、备注、旧标签操作、批量备注、转移、创建、导出、筛选和分页双向互斥，queued handler 同样守卫。保存中禁重复、关闭和竞争动作。成功清选择，刷新相关列表／概览／统计／目录，保留筛选与页大小；旧标签筛选自然隐藏改名行。

冲突或目标失效退役旧确认，实际新列表读取成功且 fetch idle 前禁重开。明确普通拒绝保留草稿但要求重新批准。网络丢响应、5xx、畸形成功一律结果未确认，锁编辑和再写，只提供实际“重新加载并检查”；失败继续锁定，成功 idle 才清旧选择、关闭，不声称写失败、不推断原准确计数、不自动重发。中英计数无复数歧义；390px 下长标签和 URL 可换行，键盘和焦点安全。
