# v0.74.0 CSV 跳转方式导入设计

## 当前事实

CodeGraph 已定位 `bulk_create_custom_slug_service.go`、`bulk_create_service.go`、`bulk-create-csv.ts`、`bulk-create.ts` 和 `useBulkCreate.ts`。现有四列严格解码为 custom-slugs，事务先锁目标规则／配额／域名创建 gate、当前账号和组，重查权限后才读回执；旧 SQLC CreateBulkShortLink 固定 direct／5 秒。新模式必须在既有事务和回执内完成，不能先创建再逐条改。

## 线协议与规范化

独立外层 `requestId/items`，每项恰为 `targetUrl/title/tags/customSlug/redirectMode`；全部必填且类型严格，redirectMode 字符串只允许空、direct、intermediate、confirmation。不 trim／改大小写，拒绝 null、未知／重复键、孤立 surrogate、非法 UTF-8、尾随值及超 64 KiB；错误复用 100001。保留自定义短码 3–32 ASCII 字母数字／小写去重、保留字和全局唯一错误。

新 `BatchCreateRedirectModeItem`／`BatchCreateWithRedirectModesInput` 与原四 DTO 分离；normalize 函数复用四列规范检查但保留原文。摘要为 `SHA256("moeurl:bulk-create:redirect-modes:v1:" + Go JSON 原始有序 items)`。空模式和 direct 存储等效，原文摘要不同；跨五种格式共享 actor/requestId，不同协议重用键冲突 200120，不重放另一个端点。

## 内部事务

把私有 batchCreate 的两个布尔参数收为私有 `batchCreateOptions{Metadata, CustomSlugs, RedirectModes bool}`，四旧入口显式保持原组合；新入口三个 true。prepared item 追加 RedirectMode。原 DTO 的零值模式映射 direct，新协议空字符串同样映射 direct；未知值只能在服务规范化阶段拒绝，不能进入 writer。

当前账号／组锁后、回执查询前：先核原四项权限，再逐行核 `short_link:use_intermediate`／`short_link:use_confirmation`。direct 不额外要求增强权限，混合批任何一行无权整批失败 120001。所有历史协议继续按原权限，不读取个人或域名默认模式。

将原 `CreateBulkShortLink` 查询中的固定 direct 改为必填 `redirect_mode` SQLC 参数，各旧调用明确传 direct；intermediate_delay_seconds 仍固定 5，其他访问条件仍 null。通过仓库标准 SQLC 1.30.0 入口生成两次并核完整输入／生成物零漂移；不手改生成物，不新增 query／schema。固定查询改变需完整旧批量回归，不能只测试新接口。

既有锁序、五秒上下文、七项规则检查、原子配额、默认域名和全部指定短码预留不变。相同回执重放不消耗第二次配额，模式授权仍在重放前；目标规则和域名后续变化沿用既有成功回执语义，不隐式创建新对象。链接、审计、回执或配额失败必须一起回滚。

## 前端

现有 parser 增加严格第五列和 `redirect-modes` 区分分支；旧四种格式继续保留。新独立 strict schema/client，深冻每项和 tags；完整未来 JSON 体也核 65536 字节。第五个固定模板提供 direct、intermediate、confirmation 与空列示例，旧四模板内容不变。

`useBulkCreate` 扩充 Protocol／StructuredItem／Snapshot 和 dispatch，保留已有身份 generation、fileSequence、draftRevision、metadata/customSlug epoch。新增两模式各自的 permission epoch：文件开始读取时记录两值，解析后的实际行若使用该模式，当前权限和对应 epoch 都须匹配。无关模式权限丢失不退休 direct-only 草稿；五列始终依赖原四项权限，即使全部短码为空。已使用模式的权限丢失立即清整个五列草稿和快照；恢复权限不复活旧请求。预览和 mutationFn 同步再查当前 cache。

纯文本逐行预览保留原标题／标签、规范化短码／随机标识，新增本地化实际模式；空模式显示直接跳转，另说明中间页固定 5 秒。不渲染 HTML，不显示真实目标的安全保证。未知结果沿原账号／端点／UUID／完整原文快照显式重试；只有确认放弃后才可另建批次。任何迟到 success/error/finally 不得关闭或改写新身份的对话框。

## 验证风险

1. 旧四个端点的 direct／5 秒与摘要必须逐一回归；新字段不能使旧协议接受扩展。
2. 混合批最后一行无权限或触发规则／唯一冲突，必须没有任何部分链接、审计、配额、回执；权限撤回后的重放拒绝。
3. 空与 direct 等效存储但摘要不同，不能用规范化内容覆盖原文；五种格式双向键冲突。
4. 撤回／恢复模式权限间的迟到文件必须退休；未用该模式的草稿不受无关撤权影响。
5. 五列 CSV 引号、JSON 标签、Unicode、大转义、65536／65537双容量与 20 行手机预览都要有实际验证。

完整门禁保持现有阈值，不新增排除。准确新 app／web，Goose仅完整闭包相同时复用；真实 `/{slug}` 验证 direct／中间页／确认页及成功访问统计，不能把接口已保存当公开访问已验证。资源预算 4 GiB／12 GiB／Docker可回收6 GiB，产品／构建／浏览器串行，用完精确清理，唯一恢复档保留。只跑必要新输入；新模式涉及 Go/SQLC/前端，旧产品测试不能冒作当前验证。
