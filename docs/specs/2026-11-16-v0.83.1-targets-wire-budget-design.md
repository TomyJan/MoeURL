# v0.83.1 纯网址批量请求预算设计

## 根因与决策

`bulkCreateTargetsSchema` 被手工解析、标准单列 CSV 和 API 共用，但仅检查网址数组；JSON 的双引号和反斜杠转义及请求外壳尚未计入。新映射入口在 v0.83.0 单独修复，旧入口仍可接受无法提交的批次。Agent 选择在共同 schema 增加预算，而不是只在 API 拒绝或给三个界面分别加判断：后两种会遗漏先替换草稿的副作用，亦制造重复规则。

预算沿用现有服务端 65536 字节，不改 API 或数据库。数组校验在原单条、数量和去重约束之后，检查 `JSON.stringify({requestId:'11111111-1111-4111-8111-111111111111',targetUrls:values})` 的 UTF-8 字节数不大于 65536。有效请求 ID 始终为 36 个 ASCII 字符，因此占位值与实际 UUID 的字节开销相同；不能用空 UUID 或缩短占位。保持真实 API 的小写非零 UUID 校验。

原 `parseBulkCreateLines`、`parseBulkCreateImportCsvDetailed` 及 `batchCreateShortLinks` 自然消费共同 schema；不新增生产 helper、不引入循环依赖、不修改 hook。原映射的额外预算守卫保留，不为去重捆绑重构。七种结构化提交及它们已有的完整预算保持。

## 用户行为与边界

手工输入仍只去 ASCII 首尾空白和空行，保网址字面值与顺序。超额时原 `bulkCreate.invalid` 可见，草稿保持、没有预览快照或新 UUID、无法提交；普通合法输入仍可重新预览并原协议写入。

标准单列 CSV 在调用 `replaceDraft` 之前整体拒绝，显示原 `bulkCreate.csvInvalid` 通用错误，不伪造结构 issue。原手工或结构化草稿、模式、顺序均保留；拒绝本身不发送写请求。后续预览仍发送原草稿的精确协议。标题等七种标准格式、显式自定义映射和权限轮次不变。

文件预算与请求预算分开：原 20 条各 2048 字节网址及 24506 个转义双引号形成 65536 字节 CSV，却有 65593 字节完整 JSON。保留同一字面 fixture，唯一扫描器仍接受文件；高层 parser 本版开始因请求超额拒绝。这是有意收紧不可提交的旧行为，不是测试 fixture 故障。65537 字节文件仍先被扫描拒绝，不降低任一上限。

## 先测后修

新增 `bulk-create-targets-budget.test.ts`：独立字面网址集合分别产生完整 wire 65536／65537；断言数组、手工及标准解析；反斜杠扩张单独 fixture；真实 API 超额时原错误 100001 且零 fetch，边界合法时精确有序 payload／receipt。测试不用生产预算 helper 推导期望，不在测试名称打印巨大数组。

新增 `useBulkCreateTargetsBudget.test.ts`：真实 hook／QueryClient／HTTP 边界，只控制外部文件和网络。手工超额预览没有 UUID／snapshot；标准超额保留原手工和 titles 草稿，拒绝零 HTTP，随后能真实原协议提交；恰好预算预览与未知结果重试保相同 UUID／payload。已有身份、权限、读取竞态和八种格式完整回归继续执行。

真实浏览器从控制台入口覆盖中英三视口：超额手工不进入预览、标准单列超额不替换原草稿或发送请求，普通 targets 实际创建并读回。必要原图和实际运行时单独留证；不声明实体手机、其他引擎或 CI。
