# v0.83.0 CSV 自定义列映射设计

## 意图与取舍

外部表格即使只有网址、标题和多余说明列，也必须改成标准表头后才能导入。本版增加显式本地映射，Agent 决定先只接现有 targets／titles 协议，避免把“选择两列”扩成完整数据迁移。这是 Agent 的产品取舍，来自[路线图](../product/roadmap.md)和自主授权，不冒称用户逐字段批准。另一方案是猜别名或自动回退，会隐藏字段丢弃；全部八个字段的映射则增加权限和默认值组合。本版均不采用。

## 共用扫描与两个入口

将现有唯一 CSV 字符状态机原样移入 `bulk-create-csv-scan.ts`，导出 `scanBulkCreateCsv(text:string):CsvScanResult`、`BULK_CSV_MAX_BYTES=65536` 和原 `BulkCreateCsvIssue`。结果为 `{success:true;records:string[][]}` 或 `{success:false;issue?:BulkCreateCsvIssue}`。保留 Unicode／字节预检、一个开头 BOM、八字段上限、严格引号、引号外裸 CR 拒绝和原扫描提前返回顺序。

`bulk-create-csv.ts` 重新导出原常量／类型，标准详细入口消费同一扫描结果，再按原顺序核标准表头、首条坏宽度和原八种 schema。两个旧包装的成功与精确失败对象不变。特别保留 EOF 末条与扫描中超限的旧优先级，不因重构改变标准诊断。

新文件 `bulk-create-csv-mapping.ts` 的内部表读取消费扫描结果，显式要求总记录数 2–21，所有数据宽度等于表头。表头是任意合法 UTF-8 字符串，允许空名、重复名；不 trim、不匹配字段、不猜测。宽度错误仍返回 `width`／逻辑记录 2–21，其余非结构失败为通用失败。

- `inspectBulkCreateCsvMapping(text:string)` 返回 `{success:true;headers:readonly string[]}` 或原失败结构；只给头部，不暴露数据行。
- `parseBulkCreateMappedCsv(text:string, columns:{target:number|null;title:number|null})` 返回原 targets／titles 成功对象或精确 `{success:false}`。target 必须为范围内整数，title 为 null 或另一个范围内整数，拒绝相同、负数、分数、NaN、Infinity 及越界。目标文字和标题逐字交现有 schema，所选之外的列不参与 schema、不进入结果。标题 null 使用 targets；即使标题值为空，只要选择标题列就使用 titles 并要求 metadata。

应用时再次调用同一有界扫描和 schema，最多处理同一 64 KiB 两次；不缓存第二份完整单元格表，也不增加另一个解析器。采用现有严格校验和完整 JSON wire 预算，不制造“只要能选列就能写入”的旁路。原模板和标准接受集合完全保持。

## 文件读取、草稿和权限轮次

`useBulkCreate.importFile(file, mode:'standard'|'mapped'='standard')` 保持原默认接口。两种模式共用原读取序号、draftRevision、generation、身份和权限 epoch；先严格解码，才分支解析。读取开始退休旧映射，标准读失败也不回退映射。

mapped 成功只私有暂存 `{text,headers,titleEpoch}`，输出只读 `mappingHeaders` 和两个 `number|null` 选择 ref，默认都 null。原 draft、importedItems、mode、snapshot 不动。暂存期间隐藏旧草稿编辑／预览，仍可取消或选新文件；无样本、无网络、无持久化。原草稿的显式变化退休暂存及旧读取。

`applyMapping()` 当且仅当当前 opened、身份／基础权限有效、非 reading／snapshot／pending／unknown 且有暂存时执行。重新解析所选列；失败只显示 mappingInvalid，保留旧草稿和暂存。选择标题还核当前 metadata 权限及捕获的 titleEpoch，撤销后恢复不能复活旧读取授权。成功才按现有 targets／titles 流程一次替换草稿，冻结结构化项、清暂存／选择／错误并退休读取序号；随后原 preview 生成 UUID，原 submit／unknown 重试保持同一 payload。无标题时不要求 metadata。

`cancelMapping()` 清暂存／选择、退休当前读取并清本次错误，原草稿不变；关闭、重开、换号、卸载或失去基础权限走原 reset 并释放私有文本。失去 metadata 时，已选择标题的暂存按现有结构化隐私策略退休；未选标题的暂存可继续映射网址，但后选标题仍必须满足原 titleEpoch。新读取的旧 success／error／finally 不得覆盖或解锁新操作。

## 界面与隐私

原文件入口和帮助保持，增加第二个有清楚标签的文件入口。新 `BulkCreateCsvMapping.vue` 仅负责显示列选项、网址必选、标题可选、应用和取消，状态仍归 hook。使用既有 Vuetify 和 vue-i18n。列标签为“第 {column} 列：{name}”／“Column {column}: {name}”；空头显示“无表头名称”／“Unnamed header”。先替换 Unicode 控制类字符为替换字符，再按码点取前 60 个；超长加省略号。全程纯文本，无 HTML 渲染、完整原值 tooltip 或数据样本。

明确提示“仅导入所选网址和可选标题，其余列会被忽略。这不是历史数据恢复。”／“Only the selected URL and optional title are imported. Other columns are ignored. This does not restore historical data.”。标题无权时禁用并说明所需权限；必选无效、重复列和字段失败在原错误反馈区给安全通用文案，重复拒绝仍聚焦。应用前不能预览旧草稿。取消后原草稿及 mode 原样恢复。标题 null 不把空标题错误发送为结构化请求。

## 验证和保留边界

先写具体 parser 行为断言，以原严格入口重导出为两个新名字作可执行 RED 基线，让实际旧状态机因自定义表头拒绝而失败，不借缺模块／类型故障。GREEN 后统一扫描；既有标准诊断／模板／排列回归必须通过。

具名测试覆盖引号内换行、BOM、非法 UTF-8 文件、65536／65537、1／8／9 列、0／20／21 条数据、末条 EOF 及坏宽度／语法、任意与重复头、无效索引、未选字段不外传、完整 wire 和旧输出。真实 hook／组件覆盖手工与结构化草稿保留、取消、标题权限／撤销恢复、迟到读取、换号关闭、标准切换、同错误聚焦和未知 UUID／payload；只控制 HTTP／File 边界，不 mock parser 或 hook。

完整前端四项 100%、types／lint／十份 E2E strict／隔离 build；准确新 web 配完整守恒旧后端，smoke、所选扫描及中英三个视口浏览器验证从真实入口手选两列、实际保存／读回、targets／titles 两协议、非法选择保草稿、取消和无横溢／纯文本。原后端和 SQLC 按完整输入守恒复用原执行身份。继承 CR-L1 三处量词在实际文档维护中修正；IR-M1／IR-M2 原报告保留，非本版现存行为保证。

容量、唯一独立终审、真实 CodeRabbit、正常合并和恢复归档以[范围](../product/scope-v0.83.0.md)及[计划](../implementation/v0.83.0-plan.md)为准。
