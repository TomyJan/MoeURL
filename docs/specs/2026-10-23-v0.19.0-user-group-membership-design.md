# v0.19.0 用户组成员迁移设计

## 1. 意图与取舍

用户与认证、后台规格已有管理员调整用户组的目标，现有界面只能在创建时指定。本阶段补齐单账号主组变更，使用既有 `app_user.group_id` 与权限解析，不同时构建完整 RBAC。相比自定义组或单纯显示成员数，改组直接满足增设管理员及撤销其后台能力的管理需求，且可用现有事务审计保证追溯。

以下为 Agent 自主决定的范围：仅 `user`／`admin`；保护全部 builtin 账号和操作者自身。初始化创建的管理员不是 builtin，允许其他管理员调整其组，但操作者本人必须在事务内仍具管理权限，因此改组不会把最后一个可操作管理员降权；改组后强制全部旧 Session 失效；同组保存为 no-op。继续沿用 Go、SQLC、PostgreSQL 与 Vue／Vuetify，不新增依赖。

## 2. API 与错误

新增 `POST /api/v1/admin/user/change-group`，JSON 为 `{id, groupKey, expectedUpdatedAt}`。id 为规范非零 UUID，groupKey 严格为 `user`／`admin`，expectedUpdatedAt 为保留微秒精度的 RFC3339 时间。仅接受 JSON 媒体类型、单个 JSON 对象、已知字段；空值、尾随值和未知字段均拒绝。成功 `data.user` 为既有 UserSummary。列表与返回的 updatedAt 改用 RFC3339Nano，避免秒级截断使正常提交冲突。

HTTP 200 业务码：100001 无效请求，120001 无权限，300102 内置账号不可改，300103 账号不存在，300105 版本冲突，300106 不允许修改自己的用户组；保留既有 300104 账号偏好冲突含义。基础设施错误 HTTP 500／900000；日志不记录请求体、密码、会话或数据库诊断值。

## 3. 事务与并发

5 秒请求预算内，在 actor 绑定的审计事务中锁定操作者与目标 app_user 行，按 UUID 稳定顺序锁定，避免两个管理员互改的反向锁死。操作者必须当前存在、active、非 deleted、非 guest，且当前数据库组拥有 `admin:access`；生产使用同事务查询解码权限，不使用入口 actor.GroupKey 作为授权。锁定 group 行读取其权限（FOR SHARE），与权限更新协调。已有在途请求继续遵守各自既有事务边界，不承诺取消已授权请求。

校验目标存在、非 builtin、非自身，比较 expectedUpdatedAt。目标组必须存在且 builtin，未知组拒绝。同组且版本匹配直接返回当前记录，不撤销会话。实际变更只更新 group_id，并以 `greatest(clock_timestamp(),updated_at+interval '1 microsecond')` 生成新版本；事务内撤销目标所有未撤销 Session。已有审计触发器已包含 group_id，无需新 migration 或触发器；审计动作沿用 update、changedFields 为 group_id。

后续请求由既有 Session 校验拒绝旧凭据，新登录从数据库读取新组权限。OIDC 供应对已有绑定应保留既有组，不重新覆盖。短链所有者、域名、访问密码、额度、偏好及 external_identity 均保持不变。

## 4. 界面

沿用用户表格操作菜单，新增“调整用户组”，builtin／当前账号不提供操作。独立对话框保存打开时的账号快照、原始 updatedAt 与原组，选择 user 或 admin；显示目标用户名、提权／降权说明及需重新登录。必须改变组且明确确认才可提交，pending 时锁定关闭和重复提交。不得把列表自动刷新结果替换进已打开快照。

成功关闭并刷新用户列表。冲突保留提示、关闭旧对话框并刷新列表，必须重新打开最新账号再操作；读取失败保留现有页面重试，不自动重试写入。切换对话框目标时重置旧错误与草稿，异步成功不能操作后来打开的其他目标。中英双语及手机布局沿用标准组件。

## 5. 验证与交付

真实 PostgreSQL 验证双向改组、全部旧会话拒绝／重新登录权限、自己／builtin／guest／软删／无权／陈旧 actor、版本冲突、同组 no-op、审计失败原子回滚及并发同版本至多一次成功。Handler 验证 JSON 契约；前端验证快照、确认、pending、错误和冲突。真实浏览器覆盖增设管理员、重新登录获得后台权限、降权后会话失效、中英桌面／手机。保持 100% 业务覆盖率、标准 SQLC 生成零漂移。运行全仓 Go、前端门禁、隔离 E2E、Compose smoke 与适用静态／安全门禁，分别记录实际环境和候选，不用历史结果冒充当前证据。
