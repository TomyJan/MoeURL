# v0.23.0 批量短链标签整理设计

## 意图与取舍

让用户对一组已有链接做分类，而不逐条打开设置。选择当前列表有界批量标签，复用既有 tags 和多选；集中标签库需要额外的归属、合并和授权语义，通用批量编辑则会引入目标／密码误改风险，均留在本版之外。技术栈继续使用 Go／SQLC／PostgreSQL 与 Vue／Vuetify，无新依赖、表、权限或导航。以下细节由 Agent 自主设计，不记为用户逐项批准。

## API 契约

新增 `POST /api/v1/short-link/batch-tags` 与 `POST /api/v1/admin/short-link/batch-tags`。仅接受 `application/json`（允许合法参数）、一份严格对象，不接受未知字段或尾随 JSON：

```json
{"items":[{"id":"规范非零UUID","expectedUpdatedAt":"完整精度非零RFC3339Nano"}],"operation":"add","tags":["项目 A"]}
```

`items` 是 1–100 条互异的规范非零 UUID 和非零版本。`operation` 仅允许 `add`、`remove`、`replace`；`tags` 必须显式数组，add／remove 为 1–10 个，replace 为 0–10 个。拒绝缺失、null、类型错误、裁剪后重复或空标签、控制字符、无效 UTF-8、超过 32 个 Unicode 字符的标签。沿用 v0.11.0 的 Unicode 空白裁剪、大小写敏感与不做 Unicode 规范化规则。

add 保留原顺序，按输入顺序追加尚不存在的标签；已有同值标签不重复写入。remove 删除精确匹配的标签，保留其余顺序。replace 采用规范化后的完整数组，空数组清除。结果中任意链接超过 10 个标签则整批拒绝，不截断。返回 `{changedCount, unchangedCount}`，均为非负整数且合计等于请求条数；前端校验一致性，不自动重试写入。

个人要求 `short_link:update_own` 和 `short_link:set_metadata`，且全部链接当前属于自己。管理员要求 `admin:access`、`short_link:update_all` 和 `short_link:set_metadata`。未登录／guest 不可操作；前端另需对应读取权限来展示入口。业务失败使用 HTTP 200：`100001` 非法输入，`120001` 无权，`200104` 任一链接缺失／软删／个人归属不符，`200116` 任一版本冲突（复用“Short link changed”契约），`200119` 结果标签超过上限。基础设施 HTTP 500／`900000`，响应 no-store；日志仅 request_id、error_category、error_type，不含标签、SQLSTATE、SQL、请求正文或 URL。

## 事务与审计

入口先解析既有权限快照，再派生 5 秒期限，在同一 `WithAuditTx` 内按用户行 → 用户组行 → UUID 排序的短链行加锁。用户及组使用共享锁，重读当前账号启用／未删除／非 guest 状态和当前数据库权限；与改组、禁用、权限编辑、移交保持相容锁序。对全部未删除目标 `FOR UPDATE`，再在持锁状态检查数量、个人 owner、完整版本和每条运算后的标签上限，全部预检完成后才更新。

新查询只更新 tags 与严格递增的 `greatest(clock_timestamp(), updated_at + interval '1 microsecond')`；数组顺序相同的 no-op 不执行更新。复用现有 tags 审计白名单，仅实际变化写日志，错误则业务和审计一起回滚。锁定后个人归属检查防止旧 owner 等待转移完成后仍编辑。保留标题、owner、短码、域名、目标、状态、跳转方式、到期、密码／授权、额度／用量与全部事件；不改造现有单条更新协议。

## 控制台

在个人与全站当前列表多选工具条增加“整理标签”，要求身份就绪、相应读写和元数据权限，当前列表成功且未刷新、筛选已应用、未执行其他编辑／批量／导出动作。打开时复制 ID、完整版本、公开 URL、现有标签及登录轮次快照，后续后台刷新不替换待确认版本或用户草稿。

Vuetify 确认框包含数量、有限高度可滚动的链接／原标签摘要、操作选择、一行一个标签的输入、结果覆盖范围说明与显式确认。add／remove 不能空输入；replace 空输入显示清空警示，仍需确认。复用共享元数据校验与 vee-validate，不使用逗号拆分含空格标签。长标签和 URL 手机不横向溢出；pending 禁止重复和手动关闭，且与单条设置、启停、删除、归属转移、其他批量和导出双向互斥。

普通失败保留草稿、确认和当前有效选择；超量错误明确提示缩小标签集。版本冲突关闭旧快照并刷新，只有新列表成功且刷新结束才可重新打开，刷新失败不能用旧缓存。撤权或身份／登录轮次改变关闭对话框、抑制迟到提示与选择变更；成功即使对话框已卸载也失效归属相关列表／概览／统计／insights 缓存。当前身份成功关闭、清空选择并显示正确中英复数计数，标签筛选列表自然更新。

## 验证

真实数据库验证三种操作顺序、清空、混合 no-op、1／100／101、权限及数据库中途撤销、跨用户、归属转移等待、版本精度、过量整批回滚、相反输入并发、审计错误及连接／事务／查询失败；快照比较除 tags／版本外的记录和授权／事件完全不变。HTTP 覆盖媒体类型、未知／缺失／null／尾随值、no-store 与安全日志。新代码纳入原 100% 业务门禁，不扩大排除。

前端覆盖严格载荷／响应、三种输入、确认及 pending、快照、冲突刷新失败与恢复、撤权／换号／卸载迟到结果、筛选和双向互斥。真实 Compose E2E 用独立账号／链接验证本人及后台操作、跨用户拒绝、标签筛选、标题及访问配置保留和 390 像素布局。完整 Go、前端四项 100%、SQLC 标准生成零漂移、Linux race、安全检查、完整 Playwright、production smoke 与精确镜像扫描分别留证；实现、合并、CI 与发布状态分开记录。
