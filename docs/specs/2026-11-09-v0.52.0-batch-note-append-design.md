## 目标与取舍

本人／全站列表当前页选择 1–100 条，给内部备注末尾追加同一非空文本，保留原内容。路线图仍列备注追加未实现；现有清空、统一替换和标签重命名已交付。追加适合给一批链接补充一次处理说明，无需逐条打开或覆盖旧备注。

比较了完整备注历史、全匹配追加及当前选择追加。前两者分别扩大数据留存和操作范围，故只选当前页选择。沿用 Go／SQLC／PG、Vue／Vuetify／TanStack Query，不引入依赖、权限或新导航路由。不做历史、撤销、跨页全选、后台任务、备注正文导出或公开访问变更。不发布部署。

## 内容与预览

输入复用 normalizeNote：先 CRLF→LF，拒绝除 LF／TAB 外的控制字符，再 Go TrimSpace，非空且最多 1000 Unicode 码点；BOM 仍不是 Go 空白。追加规则唯一：旧正文为空则结果为输入；否则结果为旧正文 + 一个 LF + 输入。旧正文不再次 trim，不删改任何原内容。结果最多 1000 码点；任一目标超长就禁止整批写入，不截断、不跳过。

界面独立“追加备注”对话框，中英说明“保留原备注，在末尾换行追加；不能撤销”。只显示操作者新输入的文本，不读取或展示目标旧正文。实际预览显示选中数、可追加数和超长数；超长时没有提交入口。预览只读，不产生回执或审计。草稿任意编辑，包括改回原值，都同步退休旧预览与在途结果。

每次有效提交都会变化所有选中备注，即使末尾已有同样文本也不去重，因为重复说明可能是操作者有意再次追加。防止同一次网络重试重复追加必须使用数据库回执，不能用“末尾相同则跳过”代替。

## 四个独立 POST 接口

本人 `/api/v1/short-link/note/batch-append/preview`、`/api/v1/short-link/note/batch-append`；全站对应 `/api/v1/admin/short-link/note/batch-append/preview`、`/api/v1/admin/short-link/note/batch-append`。沿用 Cookie Session、身份绑定 header、no-store 与现有错误／基础设施 HTTP 边界，不接受 actor 或 scope 字段。

预览输入 `{items:[{id,expectedUpdatedAt}],note}`；结果 `{items:[{id,expectedUpdatedAt,expectedNoteUpdatedAt}],appendableCount,overflowCount}`，顺序与准确 ID 集合固定，两个计数为有界整数且和等于目标数，不返回正文或旧长度。写输入 `{requestId,items:[{id,expectedUpdatedAt,expectedNoteUpdatedAt}],note}`；结果 `{requestId,appendedCount}`，同一次重放返回同一结果，不返回其他资源信息。

strict JSON 64 KiB，拒绝 unknown／duplicate keys、null、尾随值、坏 UTF-8／未配对代理字符、非 JSON 媒体和 query。items 为 1–100 个唯一规范非零小写 UUID，完整主版本及备注版本沿用现有解析，不损失纳秒，等价 offset 表示同一时刻；requestId 同样为规范非零小写 UUID。无效输入复用100001、无权限120001、不可见200104、双 CAS冲突200116；同 requestId 不同规范内容复用既有200120并同步本功能文案，不改变旧功能语义。写入超长用100001、无单项ID或当前版本泄漏。

## 原子写入及回执

独立 `short_link_note_append_batch` 表，Goose00036：actor_id 外键、request_id、32字节 request_hash、appended_count1–100、created_at，复合主键(actor_id,request_id)。不保存新旧正文、ID清单或错误正文，无独立审计 trigger、无自动过期。Down在同一事务先取得回执表ACCESS EXCLUSIVE锁，再检查为空才删除；已有回执安全失败，不能在“查空→DROP”之间让并发写入的回执被删。回滚仍是维护操作，需停旧服务，不宣称在线无阻塞回滚。旧00033只为创建，不借来存新操作，也不顺带改写其历史migration。

规范摘要包含固定协议版本、own/admin、按输入顺序的ID及两个规范UTC完整时刻、规范化追加文本；使用结构化JSON编码再SHA-256，禁止易混淆的字符串拼接。输入先完整校验再开启五秒事务。锁序：当前actor FOR UPDATE→当前组 FOR SHARE→本actor回执→UUID排序目标FOR UPDATE。actor锁串行化同账号操作，回执唯一约束兜底；与旧创建/成员迁移/备注/标签锁序逐项核实，不能仅照抄不同模块。

事务内读取真实active、未删除且非guest账号与当前组，逐项验证本人read_own/update_own/set_metadata或全站admin:access/read_all/update_all/set_metadata。即使回执重放也必须当前有权。回执存在且hash相同：返回原数量，不再查目标或写备注、版本、审计；hash不同拒绝200120。无回执时完整核所有目标可见性，再核全部主版本及备注版本，再核全部追加后的长度，之后才改全部目标并插入回执。任一失败/取消/审计或回执拒写全部回滚。

SQLC锁查询不向service投影旧正文；只投影id/owner/主版本/备注版本及是否超长。真正追加在受锁SQL内拼接，已有UpdateShortLinkNote版本及审计语义须核实后复用或新增准确更新查询。note_updated_at推进、主updated_at和其他字段不变；每目标仅一条字段名审计，真实actor绑定；重放零新审计。预览用actor/group share及目标share，不宣称PG READ ONLY事务可加行锁。

并发同key同内容至多一次真实追加，其他请求取原回执；同key异内容唯一一方成功。不同key同双版本一方提交后另一方冲突。同key成功后即使目标被修改/转移/软删，当前仍有功能权限的同actor重放只返回原数量，不恢复目标或披露旧数据；这是既有批量创建回执一致语义。其他actor的相同key相互隔离。

## 前端与未知结果

新增独立entity/controller/dialog，复用现有文本与版本schema；不把非幂等追加塞入替换controller。输入、实际预览、显式确认三个阶段；确认时固定规范化文本、准确双版本和一个随机requestId。id由现有浏览器安全随机UUID入口产生，不以时间或用户文本构造。

保存时禁编辑及普通关闭，显示本地化保存进度和aria状态，双击及排队事件只能调用一次。网络失败/5xx/成功响应畸形均未知结果：冻结同payload/key，仅提供明确的“重试这次追加”，由用户手动触发同key写请求，不重预览、不换key、不自动重试。后端先查回执，因此已写但丢回执的重试不受旧版本冲突影响且不会重复追加。确定业务失败才允许修正并新预览；同key异内容不得用生成新key偷偷规避。放弃未知结果前显示操作编号与可能已完成警示，不声称取消服务端写入。

身份epoch、实时授权签名、打开/草稿代际、请求编号守卫全部success/error/finally/toast/cache/锁。撤权再恢复、ABA登录、关闭重开、卸载和分页筛选变化退休旧上下文，不能向新身份续发旧请求。私密正文不进入URL、storage、日志、错误meta、共享query缓存或持久化离线队列。复用当前页选择；与现有清空/替换/标签/转移/删除/创建/导出/QR/筛选分页双向互斥。成功清选择、真实刷新并按当前筛选校正页码。
