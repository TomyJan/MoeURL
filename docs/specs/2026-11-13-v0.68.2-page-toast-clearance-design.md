## 意图与选择

共享 AppToasts 在 modal 内已有正常流通知区；在 ConsoleTopbar 可见的页面，usePageToastClearance 按真实导航和展开菜单计算 bottom＋8。现实现将通知固定在该 top，长页保存后滚回卡片标题，标题仍可能落在通知下面。原图片已经明确该问题，`inViewport` 不能证明没有遮挡。

执行者根据无人值守授权选择只把现有受导航测量的页面通知区移到底部，沿用 Vue／Vuetify／vue-sonner，不安装或新增依赖。逐卡片 offset 会重复布局且只修特定滚动；把长页通知放在正文起点可能在保存时不可见，均不采用。桌面和无测量导航页面保留默认 Toaster 定位；modal 保持原正常流。此决定不是用户逐项批准的产品要求。

## 布局合同

AppToasts 继续唯一 Teleport、Toaster 和 live region。`target === body` 且 `pageTop !== null` 才进入原 `.app-toasts--page`；无需新 JS 断点、状态机或身份逻辑。usePageToastClearance 的观察、隐藏状态、菜单过渡、resize／scroll 和卸载清理不变。

页面 style 把已测量的 `pageTop` 作为 CSS custom property `--page-toast-clearance` 传给真实布局。CSS 撤掉页面区的 top 定位，`bottom: max(16px, env(safe-area-inset-bottom, 0px))`；保留 right、width、横向10px内边距、pointer 边界、消息正常排列和原生触摸规则。`max-height` 为 `max(0px, min(30dvh, calc(100dvh - var(--page-toast-clearance) - max(16px, env(safe-area-inset-bottom, 0px)))))`，使短视口和展开菜单不能把区域推入导航。高度上限同时存入 `--page-toast-max-height`，纵向内边距取 `min(10px, calc(var(--page-toast-max-height) / 2))`；避免固定上下padding把零高度撑回20px。没有空间时整个外盒保持零高度，关闭菜单或改变视口恢复；不通过隐藏个别业务消息规避失败。

六秒持续时间、五条可见通知、逐条关闭、文本安全、语言／主题、退出动画和消息 ID 均不改；迁移或 resize 不重建 Toaster，不清队列、不重播、不抢焦点。modal 的触摸 pointercancel／剩余时长和最高活动层逻辑保留。页面通知仍是浮层，不泛称其不会覆盖任意正文或虚拟键盘。
