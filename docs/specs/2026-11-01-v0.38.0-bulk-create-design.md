# v0.38.0 有界批量创建设计

## 意图与取舍

从[产品范围](../product/scope-v0.38.0.md)的导入方向切出一个可安全验证的小功能。比较三种方案：客户端循环单条 Create 会部分成功且响应丢失易重复；完整 CSV 恢复牵涉旧权限、归属、slug 与历史；本版选择目标网址小批量原子创建。沿用 Go／SQLC／PostgreSQL、Vue／Vuetify／TanStack Query，不加依赖。选择由 Agent 自主作出。

## 协议

`POST /api/v1/short-link/batch-create`，Cookie Session／既有 CSRF 和权限中间件不变，响应 `Cache-Control: no-store`。局部 handler 接受至多 64 KiB 的 UTF-8 `application/json` 单个对象，拒绝未知字段、重复字段、非字符串网址、null、尾随值及无效编码；不改旧通用 decoder。

输入：`{ requestId: string; targetUrls: string[] }`。requestId 为 canonical 小写非零 UUID；targetUrls 为 1–20 个不同的、1–2048 字节可打印 ASCII 字符串，必须通过现有 `validateTargetURL`。API 不隐式 trim 或重排，大小写与参数原样保留；界面裁剪规则见范围。

成功的 data 只有 `{ requestId: string; createdCount: number }`，数量为该批原数量。重放没有不同的成功语义，不返回别人的短链／历史目标。错误沿用 `100001` 无效请求、`120001` 无权限、`200103` 无效目标、`200114` 域名不可用、`200101` 短码冲突；新增 `200120` 表示 requestId 已被该账号用于不同内容。业务错误 HTTP 200，基础设施错误 HTTP 500；日志只记录请求标识、操作和错误类型，不写目标 URL、body 或底层错误正文。

## 原子性与锁顺序

独立 `Service.BatchCreate`，不在事务里调用已有单条 `Create`。前置规范化之后进入 5 秒上下文的 `WithAuditTx(actor.ID)`。锁序为现有域名创建 shared advisory → 当前账号行 FOR UPDATE → 当前组 FOR SHARE → 本账号回执／当前默认域名与授权行。当前账号必须 active、未删除且不是 guest；内置管理员沿用既有权限。当前组非 guest 且有 create 与 use_default，不能信任调用方旧 GroupKey。

先查 `(actor_id,request_id)` 回执：SHA-256 为固定版本前缀加有序 targetUrls 的 JSON 编码，规范化后的完整内容决定同一批。相同 hash 返回原数量；不同 hash 返回 200120；不存在才选当前已启用 short_link 默认域名及当前组授权。每条写 active、direct、5 秒、空 metadata、无到期／密码／限额，复用现有随机 slug 与保留路由检查；每条最多 8 次候选，用 SQL `ON CONFLICT DO NOTHING RETURNING` 避免唯一冲突把整个事务置为 aborted。任意生成、写入、审计或回执失败全部回滚。每条原审计 trigger 记录真实 actor；重放不再写审计。

账号锁把同账号的并发批次串行化，数据库唯一约束兜底；不同账号相同 requestId 不互相读取。已撤销权限时连重放也拒绝，不能借回执越权。域名不可用只阻止新创建，已提交回执重放不重新选择域名或创造短链。测试必须证明受控并发及撤权行为，不能靠 sleep 猜测。

## 数据库与回滚

新增 `00033_short_link_create_batch.sql`，表 `short_link_create_batch`：actor_id UUID 外键、request_id UUID、32 字节 request_hash、created_count 1–20、created_at timestamptz；复合主键 actor_id／request_id。无 URL 或结果快照，不为新表添加审计触发器；短链审计沿用原表。回执不自动过期，避免旧重试重新创建；本版无定时清理或额外后台。

Down 仅在回执表为空时删除表；存在任何回执安全失败，保留幂等历史和全部短链，不能先删回执后冒安全回滚。真实迁移测试覆盖空库 Up→Down→Up、已使用后 Down 拒绝及数据不变。SQLC 1.30 使用标准入口生成，完整 sources／generated 集合核零漂移，不手改生成物。

## 个人列表界面

入口只在个人列表且当前已认证、权限满足时出现；不加固定路由或管理员代创建。独立 feature 负责输入、文本预览、mutation 和 pending／unknown 状态。采用同一 schema 验证 API 边界，并使用单条创建已有目标 URL 规则再加本版 ASCII／字节／数量限制。明确提示默认域名／direct、不采用高级默认和不支持 CSV。

预览冻结 targetUrls 后生成 requestId；提交期间不能改输入或重复点。成功刷新个人列表／overview 并显示数量；服务器确定业务失败保留输入供修正，新内容才新建批次。超时、网络、500 或成功响应格式错误都视为未知结果：保留相同 payload/key，提供手动「重试这个批次」，不自动重试；关闭前明确警示重新建批次可能重复。页面刷新／离开不承诺恢复，requestId 显示为可选中的文本供记录，不把目标 URL 写 localStorage／sessionStorage。

只对此 mutation 使用 networkMode:always，不进入离线重连队列；捕获 payload、身份及 generation，在 mutationFn 真正调用 API 前再次检查身份／权限和组件存活。换账号、撤权、认证失败或卸载后不得续发旧批次。单次 AbortController 限制15秒，涵盖 fetch 与响应正文，finally 清计时器；到期进入 unknown，不断言服务端未提交，不自动重试或换key。共享 apiPost 可选signal不改变旧无signal调用的请求形状。

身份与授权的同步 generation 对所有异步 success／error／finally 生效，旧账号响应不能清理新账号输入、显示旧结果、刷新新账号列表。卸载后不发额外写入。单条创建、CSV 导出、批量编辑与默认域名初选行为不变。
