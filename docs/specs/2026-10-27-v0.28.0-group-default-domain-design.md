# v0.28.0 用户组默认短链域名设计

## 1. 意图、兼容与方案

补齐 domains 的个人→组→全局→排序层级，用于创建面板初始选择。明确手动选择仍优先于所有配置；组默认不是授权，不改变公开访问和已保存短链。保留 v0.8、v0.26 的后端创建契约：选项当前为全局默认时省略 domainId，其他选项传 UUID；提交时后端仍检查当前全局／显式角色及当前授权。管理配置在提交期间变化可导致原 200114，刷新后用户重选，不自动回退重发。

比较三个方案：浏览器保存无法跨设备且不能按组统一；给旧权限请求／严格 DTO 追加字段会破坏旧 z.strictObject 客户端并可能被旧完整保存清除；单独新表虽可隔离版本，却增加组配置的多版本同步、删除和审计映射。采用 user_group 可空列＋已有组版本，新增独立端点，旧 HTTP DTO／请求不变。共享版本意味着权限与默认配置的并发编辑会冲突，这是同一组资源的显式选择，不是独立版本承诺。

沿用 Go／Chi／PostgreSQL／Goose／SQLC 和 Vue／Vuetify／TanStack Query／zod，不增加依赖、权限或通用策略框架。guest 仍无创建能力，自定义组与默认跳转另行规划。

## 2. 数据和迁移

Goose00027 为 user_group 增加可空 default_domain_id，引用 domain(id)的默认 NO ACTION 外键；非 null 值必须非零 UUID 且当前行 builtin、key 为 user 或 admin。旧记录均 null，不修改旧组 updated_at／权限，不回填个人值。为非 null 域名引用建立小型部分索引，供清理及外键检查。

新增专属 AFTER UPDATE 触发器／函数，只在 default_domain_id 实际变化且事务启用审计时插入 user_group、资源组 UUID、action=update、changed_fields=[default_domain_id]；只记标识和字段名，不记域名或配置值。原 user_group_audit 继续只对权限集合变动记 permissions_change，不修改共享 record_business_audit，不双记。

所有原完整 user_group SQL 投影按标准 SQLC 生成适配新列，以继续返回完整生成模型；手写旧 UserGroup HTTP 映射故意不暴露新字段，保持现有严格响应。新专属 DTO 读取新字段。旧权限 UPDATE 不赋值 default_domain_id；新默认 UPDATE 不赋值 permissions。

Down 先 drop 新触发器和专属函数，再 drop 索引、约束和列；原权限 trigger、账号、权限、域名、个人偏好、组 updated_at、短链及全部历史审计保持。配置值会丢失，正式 Down 前需备份确认。旧镜像可保留列并忽略默认；它不会清理新 FK 引用，可能拒绝删除被组默认引用的域名，不能称策略／删除完全兼容。

## 3. API 与读取投影

新接口均在/api/v1，业务失败 HTTP200、统一数字 code，no-store；基础设施 500／900000，日志不含配置正文或数据库错误内容。

| 路由 | 输入 | 成功 data |
| --- | --- | --- |
| GET /admin/user-group/domain-default | 必须且仅一个 groupKey，guest/user/admin；拒绝未知、重复、空参数 | setting={groupKey,domainId 可 null,updatedAt 完整字符串,editable}及 candidates 数组 |
| POST /admin/user-group/set-domain-default | 严格 JSON 三个必填字段 groupKey、domainId 可 null、expectedUpdatedAt 非 null | 与上述管理读取相同的 setting 及 candidates |
| GET /domain/group-default | 不接受查询参数；当前 Cookie 账号，不收 userId 或 groupKey | selection={domainId 可 null,status=available/not_set/unavailable} |

管理 GET 的 guest 仅返回 editable=false、domainId=null 和空候选，展示只读边界；POST guest 返回 300203。未知 groupKey 或格式错误 100001；所需 builtin 目标组不存在 300201；完整组版本不匹配 300202；操作者无权或指定域名当前对目标组不可用统一 120001，含未知／停用／非 short_link／无授权。清除不要求目标组仍具备创建能力，但操作者仍须双管理权限。

写入要求 application/json（合法媒体参数允许）、恰好一个 JSON 对象，拒绝未知／缺失字段、尾随文档、错误类型。groupKey 写只支持 user/admin；domainId 非 null 必须规范小写非零 UUID；版本必须完整非零 RFC3339Nano。保留完整纳秒，不能因 PG 微秒编码截断变成匹配。

管理 GET 使用最多 5 秒只读 repeatable-read 事务：先从 actor.ID 重新读取当前 active／未删除账号及其 builtin admin 组和当前权限，再读目标组及候选，形成一个一致快照。要求 admin:access 和 domain:manage；不信 actor.GroupKey／Permissions。目标原始权限必须通过 DecodeSnapshot 校验，损坏数据返回基础设施失败，不能伪装为空候选。候选只含目标组有创建和对应 domain:use_default／domain:use_assigned 权限、已授权、启用 short_link 域名，按 v0.27 顺序返回 id／host／displayName／isDefault。保存值不在候选中时管理员能看见原 UUID 及不可用状态并清除，不补入无权候选。

本人 GET 以单条 SQL 快照读取当前有效非 guest 账号、builtin 主组、组保存值及当前域名／授权；服务端校验真实组权限。只有交集可用时返回 UUID，未配置为 not_set，已配置但不可用为 unavailable 且 domainId=null。无名称、地址、保存的不可用 UUID、目标组权限或其他账号信息。无创建权限也可读取不含元数据的不可用状态；无效账号／guest 返回 120001。损坏权限或数据库错误不伪造 not_set。

## 4. 写事务与锁序

所有新增默认设置在 5 秒 WithAuditTx 内，先规范 actor 非零 UUID，再 domain advisory 共享锁（复用 LockShortLinkCreation）→当前 app_user FOR SHARE→当前 builtin admin 组 FOR UPDATE→目标 builtin 组 FOR UPDATE。操作者组始终先取排他锁，即使目标是 admin 也不先共享再升级；目标 admin 复用已持锁行，user 随后锁定。重查 active／未删除／当前组及 admin:access、domain:manage，再检查目标与完整版本。

指定 UUID 时在持锁后按目标组当前权限和 grant 核实启用 short_link。domain 共享锁使该判断与域名配置写／删除互斥，目标组排他锁使权限并发更新无法穿过校验。先比较版本再比较值；当前同值直接返回当前表示，不 UPDATE／不推进版本／不审计。实际变化仅更新 default_domain_id 与 greatest(clock_timestamp(),updated_at+1 微秒)，同事务审计；事务内读回、模型校验或审计失败全回滚。HTTP 响应在提交后编码；其失败返回基础设施错误，不能撤销已提交写入，客户端必须重新读取再操作，不能自动重试写入。

旧 UpdatePermissions 保持入口快速授权、请求／旧 DTO、受保护权限规则和同集合仍推进版本的旧行为，但生产事务也采用相同 domain 共享→当前 user 共享→当前 admin 组排他→目标组排他前缀，最终只需其原 admin:access。排队期间账号禁用／删除／改组、admin 不再 builtin 或权限撤回均不能写。完整版本在持锁行上先用 Go 时间比较，再执行原条件 SQL，避免纳秒被编码截断。显式 actor 传入手写事务 store，不从审计 GUC 倒推身份、不扩公开 API；隔离 fake 保持测试边界，安全结论必须由真实 DB／HTTP 门闩回归证明。该旧写边界随本轮共享组版本一起补强，不借机改旧列表或其他模块。

成员迁移先锁用户再锁组，不请求 domain 锁；新旧组配置写都在 domain 锁后取 user，再按 admin→user 顺序取组。domain 旧写从 domain 排他开始，互斥发生在持组锁之前，不能引入组→domain 倒序。scope 不新增任意组锁框架。

## 5. 删除与资格变化

域名删除保留原版本、全局默认和任意短链引用检查。成功删除前，在原审计事务／domain 排他锁内清该域名的个人偏好，并清 user_group.default_domain_id、单调推进每个受影响组版本，再删除域名；任何清理或审计故障全回滚。组清理 SQL 先通过明确的 MATERIALIZED 数据依赖锁 builtin admin 行 FOR UPDATE，再按 admin 优先和 UUID 锁引用组并更新，不能先锁 user 组再升级先前共享的 admin 组。避免与成员迁移的 admin→user 共享组读取形成环。此新增清理及删除事务使用 5 秒期限；外键保留 NO ACTION 作为最后防线。

停用、移除 grant、撤销目标组创建或 default/assigned 权限、切换全局默认不清保存值或版本。本人使用时再次判断角色与交集，失效通用提示后回退；恢复资格后可再次选中。真正删除清空并推进版本，旧编辑器必须冲突，不能重建引用。既有短链、个人选择和域名排序不改写。

## 6. 管理界面

在 AdminUserGroupsPage 中为当前组增加独立默认域名区域，单一下拉、清除／保存、说明仅影响创建初始选择。guest 只读；没有双管理权限时新区域不开放。候选来自专属管理查询，不凭当前操作者自己的 available 列表替目标组决定。加载、空候选、读取错误／重试、已保存但不可用、保存、冲突及显式重新加载均有双语状态。

权限和域名默认各保留每组草稿；共享组版本有清晰说明。当前组任一草稿脏时禁用另一区域的编辑／保存，取消本区恢复另一区域。切 Tab 保留各组草稿，不自动放弃；任一写入 pending 期间阻止重复写及 Tab 切换。提交边界再次核当前身份、目标组、数据有效性与 pending，不只依赖按钮 disabled。

刷新不得覆盖脏草稿；共享组版本后台改变时标记陈旧并保留原快照，显式重载成功才采用新版本／放弃对应草稿。旧权限 API 的 300202 处理仍可按旧契约明确告知后重载该权限草稿；不得因新默认区域的普通后台 refetch 静默丢弃权限草稿。保存返回 setting 后等待必要组列表、默认配置及当前选择查询刷新，刷新失败显示重试并禁止后续写入，不以局部响应冒完整配置已就绪。

本页查询按 userId＋login epoch 分区，保留原 userGroupQueryKey 前缀失效；旧权限和新默认 mutation 都捕获 scope 与 groupKey，成功／失败／刷新前核仍为当前身份。退出、换账号、同 ID 新 epoch、卸载及迟到读取不能写新账号 cache 或反馈。当前权限同步失效即停写，恢复使用当前 me 验证后再刷新，不使用可能先污染身份的旧 refetch 结果。两个表单不嵌套。

## 7. 创建面板

useDomainPreference 及 available 原身份隔离保留，增加本人组默认 query，key 包含 userId＋epoch 且支持统一前缀失效；不把另一身份 placeholder 当当前结果，不保存到 localStorage。管理员设置／清除成功、权限保存成功及域名管理成功均失效相关管理、本人组默认和 available 前缀；本人组默认与授权候选查询局部启用焦点重读，不更改全局查询策略；其他浏览器通过焦点／online／显式重试读取最新配置，不宣称推送即时同步。

没有明确手动选择且个人偏好未成功读取时仍沿用原加载屏障；个人偏好已成功且有当前可用值时无需等待组默认。否则采用组默认前须其查询成功，或用户明确选择／点击使用系统选择。组默认加载／失败不伪造未配置；失败提供重试与明确系统兜底，即使只一候选也可恢复。明确使用系统选择是当前表单的手动 fallback，采用当前可用全局默认／有序首项，不能被迟到组默认覆盖，不清任何持久配置。

有效手动／个人优先，随后与 available 交集匹配的有效组默认，再原全局／有序首项。组默认 unavailable 提供不含域名信息的通用回退提示；不把其未知 UUID 补进选项。个人、手动或组层变化均不自动提交。预览依据当前选择；真实创建成功 URL 以响应为准；200114 刷新身份、available 及组默认并保留表单，用户重新确认，不自动重发。成功创建／重置清临时选择，再用最新已加载优先级。
