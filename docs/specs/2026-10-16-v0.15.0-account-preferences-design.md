# v0.15.0 账号偏好设计

## 1. 数据与 API

新增 `user_preference`，`user_id` 为关联 `app_user` 的主键，删除用户时级联删除。`language`、`theme` 为受数据库约束的可空文本，`updated_at` 为非空 `timestamptz`。不回填旧用户、不修改 `app_user.updated_at`，不新增权限。

`GET /api/v1/user/preferences` 返回 `{"preferences":{"language":null,"theme":null,"updatedAt":null}}` 表示尚未创建账号设置。已保存记录返回同结构及 RFC3339Nano 版本。`POST /api/v1/user/preferences/update` 必须提供 `language`、`theme`、`expectedUpdatedAt` 三项，均允许 `null`，拒绝未知字段、缺项、非法类型、枚举、版本及多个 JSON 值。

写入只操作 Cookie 所属、当前仍启用且未删除的非 guest 用户。`expectedUpdatedAt=null` 仅创建缺失记录；其他版本必须与现存记录精确匹配。并发首次保存只能有一个成功；陈旧版本返回 `300104`，不自动重试写入。非法输入沿用 `100001`，无权沿用 `120001`，基础设施错误为 HTTP 500／`900000`；业务响应为 HTTP 200。两个接口均 no-store。

SQLC 负责源查询及生成物；单条条件写入原子检查版本。版本每次成功写入严格递增。migration Down 仅删除新表，保留用户、会话和其他设置；回退会丢失本版个人偏好，部署文档须明确备份要求。

## 2. 偏好覆盖层

保留现有浏览器本地偏好与站点默认值规则。账号值只存在当前身份的内存覆盖层，不复制到访客 localStorage。身份改变时先恢复浏览器／站点基线，再加载新账号；未设置账号字段不覆盖基线。

应用入口观察共享 `auth/me` 查询，按用户 ID 和本地登录轮次隔离账号偏好查询键。每次成功登录都开启新轮次，包括未先退出而再次登录同一账号；清除旧覆盖及缓存后重新读取账号值。只在确认非 guest 后读取；读取失败保持可用界面，个人页提供重试，不伪造成功。自动加载不能覆盖该身份进入后用户主动执行的浏览器切换。迟到响应必须同时核对当前用户 ID 和登录轮次，退出后不恢复旧账号设置。

个人页显式保存成功立即应用返回值并更新对应查询；切换账号或组件失效后的写入响应不得改变当前界面或其他账号缓存。手动切换影响当前浏览器，下一次完整页面刷新或登录重新采用账号设置。`system` 表示跟随当前设备系统主题。

## 3. 编辑与恢复

个人页使用标准 Vuetify 下拉选项，包含「沿用浏览器设置」，与现有浏览器即时切换入口区分。请求成功前禁用保存；草稿脏时不被后台重取覆盖，保存使用编辑开始时的版本。

成功使用 Toast。失败保留草稿并友好提示；版本冲突提供显式重新加载操作，重新加载成功才放弃草稿并取得新版本。加载失败显示持久重试入口。正在保存、身份撤销及退出后禁止重复提交。

## 4. 验证与边界

真实数据库验证未设置、两用户隔离、合法枚举与 null、首次及后续并发冲突、禁用／删除用户、数据库故障和 migration Up／Down／Up。HTTP 验证严格解码与错误、缓存契约；生成零漂移。

前端验证 API 契约、未加载禁止提交、脏草稿、冲突／重试、身份切换、迟到结果、自动加载与手动选择竞态，以及退出恢复访客偏好。真实浏览器创建独立账号，在两个浏览器上下文验证保存与重新登录，覆盖中英文和移动布局，清理所有测试资源。100% 覆盖率不降低或扩大排除；Docker、目标 CI、Linux race 和生产证据按实际环境分开记录。
