# v0.87.1 标签映射交付状态设计

本轮从已独立核验的 PR377 合并开始，解决原审查登记的文档状态滞后，让阅读入口的用户知道标签映射已交付，而不是仍在设计。Agent 依据持续自主授权选择这一小增量，不冒称用户逐句批准。

## 当前与历史

- 当前产品为 0.87.0。只更新当前六处入口、开发能力表和路线图剩余缺口；标签映射复用 metadata 权限、严格 JSON 标签数组、空数组不降协议，其他字段映射与历史恢复继续未交付。
- 前版 scope、plan、tasks 同步完成状态；acceptance 追加独立交付补记，原“当前阶段”及后续候选记录完整保留，唯一允许的原文措辞变更是“四场景”补为“四个场景”。此处不改变测试数、运行时、命令、hash 或原执行时点。
- 前版候选 `56c971c1c0cbe3647fde158194975e6b74130623` 的真实审查不能借给本维护新 head。准确候选 tree 与合并 tree 相同，不意味着本维护已完成审查。
- PR377 两条 inline 合并为一个阶段摘要 Minor；六处 LanguageTool 措辞合为另一组。准确映射与事实守恒由本地检查负责，英文提示 Minor 继续明确延期。

## 内容与证据

文档改善限定为八份文件、四个场景、八份模板及八种协议和对应模板的量词／并列句。产品 package、模板、协议和权限均保持字节不变。旧16份证据、10份恢复成员及原 ZIP 保持 hash／bytes；只读复用，不重建、不覆盖。当前阶段简述使用“文档维护；交付状态以验收为准”，避免每个执行阶段反复改入口。
