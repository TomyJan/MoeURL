# v0.51.1 标签重命名保存进度设计

## 原因与方案

现控制器发出请求前立即清除 approved，模板因此切回禁用的“确认以上预览”，用户看不到正在保存。保留该安全行为，仅让模板在 saving 时继续呈现保存分支。沿用 Vue、Vuetify 和 vue-i18n，不新建状态机。

保存按钮使用 Vuetify 实际消费的 `#loader` 槽，同时显示局部导入的进度图标和本地化文本；明确 accessible name 和 `aria-busy=true`。中文为“正在保存…”，英文为“Saving…”。保存中的提示保持完整可读透明度，原生 disabled 和交互阻止仍保留。继续禁止取消、编辑、重复提交；不能让保存 UI 依赖已经退役的 approved。恢复分支仍只在请求结算后接管。

## 验证与边界

真实 QueryClient、控制器和 Vuetify 中，用受控 Response Promise 挂起保存。两种语言均检查 saving=true、approved=null、保存按钮仍存在且 disabled/busy、可见进度文本、旧审批按钮消失；实际 HTTP 请求数为一，不能靠 mock 控制器造保存状态。

用真实成功、普通拒绝、版本冲突、网络丢响应验证结算后的正常关闭或原恢复入口。切号、撤权、卸载后迟到请求不重开弹窗或改写当前身份。已有 controller 回归全部保留。

浏览器从本人和管理员实际入口验证，覆盖中文桌面及英文 390px、100 条选择；真实提交后暂缓响应，检查进度并实测至少取消与保存两个按钮的非零矩形、视口范围和不重叠。不得以“全部按钮 disabled 导致空集合”冒布局通过。

不改 API、数据库、生成物、依赖和导航，不自动重试，不恢复 approved，不把 CI 或旧版本证据冒作本版验证。
