# 可选目标 CIDR 白名单设计

基于 PR337 已完整交付且独立核验的 master `ff6a86bf9109e776e70aa6119fd2c4fc3ea52d1c`。方案由 Agent 在长期无人值守授权内选择，不代表用户逐项批准；[范围](../product/scope-v0.71.0.md)为权威。沿既有技术栈，无新增依赖。

## 为什么做

路线图已交付字面 IP 的精确/CIDR 拒绝、DNS 精确/后缀允许。已启用 DNS 允许集合时，管理员目前无法同时明确允许某个 IP 网段。下一项实际增量选独立、默认关闭的 CIDR 允许资源；不再为维护状态单独开一版“文档修文档”。原 v0.70.1 四个 Task1 计划框的延期 Minor 在该实际增量顺带同步。

## 备选与选择

扩展旧 DNS hosts/suffixes DTO 会破坏严格契约；把 CIDR 放进拒绝列表无法表达允许；通用规则引擎过重。选择现有模式的独立管理员资源，复用已审的 CIDR 解析及单事务 gate。

## 产品语义

默认 `{"enabled":false,"prefixes":[]}`。0–100 项，启用须 1–100 项，关闭保留列表；清空不能暗中关闭。合法 CIDR、主机位清零、规范排序/重复拒绝、mapped CIDR 拒绝及 mapped 目标 Unmap 与 v0.70.0 一致；重叠不合并。

三个启用的允许集合取并集，但按目标实际类型匹配：DNS 可命中启用的精确 DNS 或后缀 DNS；字面 IP 可命中启用的 CIDR。任一允许资源启用后，未命中任一启用集合的新目标拒绝。因此只启用 CIDR 会拒绝所有 DNS 新目标；只启用 DNS 时仍拒绝 IP。新 CIDR 关闭时严格保持全部旧行为。UI 必须明确这些影响。

基础地址禁限、DNS 精确/后缀拒绝、精确 IP 拒绝和 CIDR 拒绝仍先于允许判断；CIDR 允许不豁免基础私网禁限，不解析 DNS，不提供 SSRF/信誉或历史访问封禁承诺。`/0` 仅覆盖对应地址族且仍不能绕过任何拒绝。

## 后端契约

独立 `security.target_cidr_allowlist`；独立 GET `/api/v1/admin/system/target-cidr-allowlist`、POST 相同路径加 `/update`；旧 DTO/权限集合不扩展。strict 完整 JSON、32768 B、no-store、五秒事务、完整微秒 CAS、先 CAS 后 no-op、仅键名审计及当前有效非 builtin admin/双权限与既有资源一致。当前代码核查未占用的 `900224`/`900225` 分别用于本资源输入/冲突，目标拒绝仍 `200121`，基础非法目标仍原码；基线完整代码已核没有占用这两个码。

已通过 CodeGraph 两次核当前六资源 CheckTargets、旧 DNS 并集、CIDR 规范函数与共同 gate。新 `checkCombinedAllowlistTargets(exact AllowlistSettings, suffix SuffixAllowlistSettings, cidr CIDRAllowlistSettings, targets []string) error` 放在 `internal/targetpolicy/cidr_allowlist_model.go`：CIDR 关闭时直接委托旧 `checkAllowlistTargets`，原函数签名/测试保持。CIDR 启用时按原 URL 的实际字面地址匹配 `Unmap`；DNS 只有至少一个 DNS 允许资源启用时才委托旧 DNS 并集，否则拒绝。先把七份存储全部解码，再任何匹配，不能用早退遮蔽坏存储。管理模型/服务/严格 JSON/handler 使用 `CIDRAllowlist*` 独立类型，避免改旧 CIDRPort 的签名。

新目标写事务持 shared gate，先完整读取并验证七份存储（包括关闭的允许资源）再判策略；保存共用 exclusive gate，先于身份/组/业务锁。七入口、整批原子性、已提交同内容回执优先、异内容冲突、锁内目标原字节未变或省略的编辑、旧访问不追溯均保持原合同。迁移默认关闭；Down 只卸独立审计定义，保留内容/精确版本/历史，重 Up 不覆盖；旧应用回退忽略新允许约束，不宣称等价安全。
