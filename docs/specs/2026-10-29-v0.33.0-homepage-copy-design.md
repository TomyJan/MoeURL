# v0.33.0 首页文案设计

## 1. 意图与边界

首页现有 `home.heroTitle` 和 `home.heroSummary` 为固定双语文案。路线图允许后续配置首页介绍；本轮由 root 在自主迭代授权下选择仅开放这两个文本，沿用 Vue 3、Vuetify 4、TanStack Query、Go／SQLC／Goose。此选择是执行者裁决，不记为用户逐字段批准。范围权威为 [scope](../product/scope-v0.33.0.md)。

不修改首页短链权限、生成器、顶部导航、介绍区、站点名称、登录策略或已有设置表单。无新依赖或权限。

## 2. 文本与公开投影

`HomeContent` 为 `{title: string, summary: string}`。每个值先以 Go `strings.TrimSpace`／前端 Unicode 首尾空白规则裁剪，再按 Unicode 码点计数；标题 0–80，简介 0–200。拒绝 `unicode.IsControl` 对应控制字符，包括换行、制表和 NUL；检查原值中的控制字符后才裁剪，不能以 trim 静默接受它们。普通空格、中文、emoji、组合字符与可打印标点合法；不做 NFC 重写，码点不等同字素簇或 UTF-16 code unit。空字段独立回退默认，不以 title 为空清除 summary。

`GET /api/v1/system/home-content` 无需登录，仅返回两字段。设置读取失败、内容损坏或缺行由服务端报基础设施错误，不能伪造成功空值；首页在加载及失败状态显示既有当前语言默认值，绝不阻断创建入口。读取成功后空字段使用 `t('home.heroTitle')`／`t('home.heroSummary')`；自定义值直接渲染文本节点，语言切换保留原值，不把 `{name}`、`<img>` 或 Markdown 当指令。h1 和简介使用 `overflow-wrap:anywhere`，不截断文本。

所有新 API 都 `Cache-Control: no-store`，不进入 Service Worker／持久缓存。首页 query 在每次挂载重新读取，失败不显示旧缓存自定义值；不承诺已打开页面跨客户端实时同步。

## 3. 管理 API 与完整版本

- `GET /api/v1/admin/system/home-content` 返回 `{title, summary, updatedAt}`。
- `POST /api/v1/admin/system/home-content/update` 接收 `{title, summary, expectedUpdatedAt}`，三者均必填且非 null。解码前必须要求可解析的 `Content-Type: application/json`（允许合法参数与类型大小写），拒绝缺失、简单表单／纯文本及畸形媒体类型，不能以 Cookie／CAS 代替请求意图边界。拒绝未知字段、尾随 JSON、错误类型和超出 8 KiB 的请求体；原始请求必须是有效 UTF-8。标准 JSON 字符串解码后再执行业务验证。
- `updatedAt` 为 UTC RFC3339Nano，保留数据库微秒完整精度；`expectedUpdatedAt` 必须可解析、非零且含时区。不能通过 JS Date 来回转换后提交。
- 业务输入错误 `900204`、冲突 `900205`，HTTP 200；权限错误沿用 `120001`。登录态及基础访问失败仍依现有中间件返回 401／403，基础设施错误为 500 且不记录文案正文。

不扩展旧 `PublicConfig`、`Settings` 或 `UpdateSettingsInput`，旧严格前端 schema 和旧客户端完整提交继续工作。两个资源的版本独立：旧设置保存不覆盖文案，文案保存不改变旧 settings_revision。

## 4. 存储、授权与审计

`00029_home_content.sql` 在既有 `system_setting` 中以 `site.home_content` 保存规范对象 `{"title":"","summary":""}`，Up 使用 `ON CONFLICT DO NOTHING`。新应用启动验证此键存在且满足文档结构、文本和版本规则；不从不完整或损坏存储猜测默认。旧已知键清单忽略此键，兼容回退到旧应用。

新 `HomeContentService` 使用五秒 Context。管理读取在只读 repeatable-read 事务中重查当前有效、非 builtin、未删除账号、当前 builtin admin 组及两项权限，并在同快照读取配置；不信任 actor 中的旧组名。写入通过 `WithAuditTx`，按当前账号共享锁 → 当前 builtin admin 组共享锁 → `site.home_content` 行 `FOR UPDATE`，锁内重查状态／主组及 `admin:access`、`system:manage`。不借用 domain 的 advisory lock 或把 domain:manage 当系统权限。

先比较完整版本，再判断规范内容是否相同。相同则原样返回，无版本／审计变化；实际变更的版本严格大于旧值，以微秒精度保存，业务更新和审计任何一步失败均回滚。只使用 SQLC 查询；新 `queries/home_content.sql` 定义当前身份只读投影和账号／组锁，现有通用系统键查询仍复用。输入变化后用 SQLC 1.30 标准生成并验证第二次零漂移。

既有通用审计函数固定键白名单忽略新键。为新键增加一个专用、仅监听该键的 AFTER INSERT／UPDATE 触发器和小函数，不复制替换通用函数。只有显式 audit_enabled=on 且值实际改变才插入：resource_type=`system_setting`、resource_id=`site.home_content`、action=`settings_change`、changed_fields=`['site.home_content']`。不保存前后值、文案或请求正文，不能双记。迁移默认插入不启用业务审计。

Down 仅移除本版专用触发器及函数，保留配置行和全部历史日志；这不是撤销管理员内容的操作。旧应用忽略此键，重新 Up 保留已存内容。测试必须证明 Down／Up 后原内容不变，旧审计和其他设置不变。

## 5. 管理页面与身份隔离

在 `AdminSettingsPage.vue` 原 general form 外新增独立 `HomeContentEditor`，明确标题“首页文案”／“Homepage copy”，标题与简介两个有名输入框、码点计数、留空默认提示、保存及显式重新加载入口。与原普通设置、OIDC 管理无共享草稿／提交／版本。

仅同时拥有两项权限的当前账号可读写。query key 包含账号和身份轮次；关闭权限或换号时清草稿、错误、版本和挂起状态并递增 generation。每个异步成功、失败、finally 均验证当前轮次，不让旧结果重新填表、改 public cache 或提示成功。用服务端返回的新完整版本替换已提交草稿；重新编辑后到达的旧加载不能覆盖新草稿。冲突保留草稿并显示持久消息，不自动覆盖／重试；用户主动重新加载才用服务器值替换。

保存中禁用重复提交。成功只更新当前身份管理缓存并使公开首页 query 失效，不修改旧 public-config。错误保留可编辑草稿和重试能力。公共文案是全站公开内容；管理 draft／版本不能出现在公开响应。
