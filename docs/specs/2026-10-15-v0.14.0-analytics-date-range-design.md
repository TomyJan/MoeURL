# v0.14.0 统计日期范围设计

## 1. API 与兼容

复用 `GET /api/v1/short-link/statistics` 和 `GET /api/v1/admin/short-link/statistics`，保留 `id`。

- 不提供范围参数时默认为含今天的近 7 天。
- `days` 只接受 `7`、`30`、`90`；不能与自定义日期混用。
- 自定义日期同时提供 `startDate`、`endDate`，严格使用 `YYYY-MM-DD`，范围 1–90 天，结束日不晚于服务端 UTC 今天。无效输入返回现有 `100001`，不执行统计聚合。
- HTTP 入口拒绝重复的范围参数和显式空值，避免悄悄降级为默认范围。
- 响应新增 `range: {startDate, endDate, timeZone: "UTC"}` 和 `stats.rangeVisitCount`；其余字段保持原结构。
- `visitCount`、`todayVisitCount`、`lastVisitedAt` 仍为全生命周期指标；趋势、三类维度与 `rangeVisitCount` 限定为选择的区间。默认维度从原全生命周期改为近 7 天，页面明确标注，避免与总量混淆。

## 2. 时间与查询

服务端一次捕获 UTC 今天，纯函数验证并生成 UTC 午夜的半开区间 `[start, end + 1 day)`。SQL 使用类型化 timestamptz 边界，避免 `created_at` 上的过滤函数，使现有短链 ID／时间索引可用。每日序列按 UTC 日历生成，最多 90 点，空日补零；查询时区不改变结果。今日概览同样使用 UTC 午夜上下界。

维度先按范围过滤，再按数量降序和值升序排序，保留前 10 个，其他归入 `other`。仅统计 `redirect_response_sent`。区间访问量从已返回的连续每日计数求和，不增加一次扫描。既有全生命周期概览查询保留，不在本版引入预聚合表或缓存。

## 3. 权限与安全

沿用个人 `short_link:read_own`、管理员后台与全站读取检查；先完成授权、短链存在性与所属关系判断，再读取统计。不提供公开统计。响应继续 no-store；不增加事件字段，不改变异步事件写入。无 migration，可直接回退旧镜像。

## 4. 页面与状态

分析仍位于短链二级页，使用现有 Vuetify 风格。快捷选项近 7／30／90 天；自定义显示起止日期和应用按钮，草稿输入不触发请求，验证通过后才切换范围。标注 UTC 和实际服务端返回日期，新增「区间访问量」指标。趋势标题与维度说明不再固定写近 7 天。

查询键包含个人／管理上下文、短链 ID 和已应用范围；不同范围不复用错误的结果。切换期间显示加载状态，失败显示持久重试入口，不把上一范围图表误标为新范围。切换短链时重置日期草稿和已应用范围。语言、主题和响应式布局沿用现有实现。

## 5. 验证

纯函数覆盖跨月／闰年、1／90／91 天、无效日期、未来日期、混用和缺失参数。HTTP 测试检查两端点参数传递与错误契约。数据库使用独立库和固定 UTC 边界事件，覆盖首日午夜、尾日最后时刻、排除区间外和非跳转事件、非 UTC 数据库时区、补零与三类维度。验证原有权限和空结果。

前端覆盖请求编码、响应结构、快捷／自定义范围、无效草稿不请求、错误重试、快速切换和路由切换。真实 E2E 在隔离数据库创建自身短链并生成访问，验证范围切换与手机布局，不依赖其他场景的数据。完整 Go、前端覆盖率、静态检查、构建、SQLC 零漂移和分支独立审查必须执行；Docker、CI、Linux race 与生产环境缺失证据保留为待验证。
