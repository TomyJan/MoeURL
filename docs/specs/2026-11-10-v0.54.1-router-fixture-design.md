# 标题路由子测试隔离设计

## 目标与边界

消除 `TestBulkCreateTitlesRouter` 对其他子测试建立的回执及权限状态的依赖。使用既有 Go／testcontainers／PostgreSQL 工具，不增加生产代码、依赖或迁移，产品仍为 0.54.0。

## 方案

父测试保留五个原名称并逐一 `t.Run`；内部 helper 直接以当前子测试的 `t.Context()` 创建 `ProjectMigratedPool`、用户组、用户、默认域名和 Session，再执行对应场景。每个场景开始核准链接／审计／回执全空。helper 仅存在于测试文件，不成为生产接口，不增加通用 fixture 框架。

跨协议及撤权重放各自在本场景先通过真实标题 API 创建并确认两条链接、两条审计、一条回执。前者核同键跨协议冲突；后者在撤权后核真实已有回执仍拒绝，且旧协议保持可用。所有原 Unicode、元数据、身份和原子存储断言保留。数据库的权限无需向其他场景恢复，因为每个场景独立拥有数据库，清理由原测试工具生命周期负责。

不采用仅为两个场景补 seed 后仍共享数据库的方案，避免权限和后续场景继续产生顺序耦合；不实现通用参数化测试框架。

## 验证和归属

隔离副本已记录原单选跨协议失败：预期200120、实际0。修复后分别单选跨协议、撤权重放通过，完整 Go／vet 和 Linux HTTP race 通过。正式分支接入时必须逐 hash/bytes 证明测试文件准确移入、产品输入与原候选相同；原失败及副本执行身份保留，不将准备结果冒作提交后重跑。

唯一独立终审和最终 head 真实 CodeRabbit 另行验收；有效意见逐项核实并处置。正常 sha 守卫合并，独立 PR／commit API、fetch、SHA／tree／唯一父核准，标准任务和 whole-owned 恢复归档后才交付。不查、不等 CI，不发布或部署。
