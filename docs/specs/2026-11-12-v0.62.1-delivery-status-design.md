# v0.62.1 交付状态文档设计

## 意图

使维护者能区分本地验证、执行资源清理、源副本恢复、审查、合并和最终归档。PR311 已完成这些工作，仓库中的候选检查点仍保留“待完成”，容易造成重复执行或误判。

## 方案与事实

Agent 在持续自主授权内选择一次仅 Markdown 的维护，沿用既有技术栈和交付流程。修改六个入口与 v0.62.0 的四份范围／实施文档，不改冻结回执。前版最终候选 `00422ad0118463f7d803f441f7600b5615a8e700` 由唯一独立审查及真实 CodeRabbit 覆盖，正常 squash `8a9bc9ec6fe770a759e388031fc8988d80fc157c`，tree `d23e90e41f7ab32f29dac369bb427000aa18a5c8`，唯一父 `3e75148a9364af6853c9f2de8e187597fbb3c2dd`；三个标准任务、16 条完整裁决及 11 份文件恢复归档已经完成。

前版执行资源清理与三个 source 副本清理属于 Task2，整个 owned 目录最终归档属于 Task3。验收列表将这三种事实分行记录，勾选基于各自证据，不把本维护尚未完成的审查提前勾选。前版首次 313 项浏览器为 311 通过／2 失败，准确后继受影响 29 个场景加 setup 通过；组合去重覆盖 313 个身份，不能写成单次全绿。原图片、产品、执行提交和扫描边界原样保留。

## 文字与保留边界

只整理 v0.62.0 文档中的“五份文档”“六个文档入口”“三种尺寸”等量词；“补验”“补测”“补全”和相对 epsilon 保留原意。原正则误报拒绝和公开处置不改，不为文字触发产品测试。旧归档、报告及哈希不重写。

## 验证

私有只读校验器核完整非 Markdown 集合、十份修改文档事实、链接、diff、前版 ZIP 及 recovery／extract 每个成员。文档缺口先保存原 hash 和实际语句；这是事实纠正，不伪造产品 RED。新维护的审查和合并证据单独归属，不借前版 CodeRabbit 给新提交。
