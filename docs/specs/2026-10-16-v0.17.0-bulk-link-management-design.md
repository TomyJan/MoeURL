# v0.17.0 短链批量管理设计

## 1. 接口与权限

新增 `POST /api/v1/short-link/batch` 与 `POST /api/v1/admin/short-link/batch`，请求为 `{"ids":["UUID"],"action":"disable"}`。`action` 仅允许 `enable`、`disable`、`delete`；`ids` 为 1–100 个不同的非零 UUID，拒绝缺失、null、类型错误、未知字段、尾随 JSON 和规范化后重复 UUID。成功 data 为 `{"affectedCount":2}`，即本次匹配并处理的记录数；重复设置相同状态可成功，已软删除的记录不能再次处理。

个人启停要求 `short_link:update_own`，删除要求 `short_link:delete_own`；后台要求 `admin:access` 和对应的 `short_link:update_all`／`short_link:delete_all`。无读权限时 UI 不提供列表，API 最终仍按写权限检查。非法请求沿用 `100001`，无权限 `120001`，任一记录不在操作范围沿用短链不存在错误，不泄露其归属；基础设施错误为 HTTP 500／`900000`，其他业务响应 HTTP 200，两个接口均 no-store。

## 2. 原子写入

不新增 schema 或 migration。源 SQL 通过仓库锁定的 SQLC 入口生成。先用既有 Resolver 验证权限，再在单条 SQL 中锁定并检查当前启用、未删除账号及其当前用户组授权。对目标短链按 UUID 排序获取行锁，个人操作同时限制 owner。只有锁定记录数量等于请求去重后的数量才写入；否则零写入。当前账号或授权不可用与记录缺失分开返回。SQL 的锁、数量检查与写入处于同一语句事务，避免预检之后的删除、停用或撤权竞态以及不同批次反向锁定造成死锁。

启停仅写 `status`、`updated_at`；软删除仅写 `deleted_at`、`updated_at`。不清空访问授权、统计、短码、密码或额度，不写访问事件。启用不能绕过域名停用、过期、密码或已耗尽额度。沿用单条状态操作的显式赋值、最后提交生效语义，不引入未实现的列表版本协议。

## 3. 前端交互

使用 Vuetify 标准选择框与当前列表全选，工具条显示数量和可执行动作。选择仅限当前返回列表，不暗示全库／跨页全选。筛选、身份／登录轮次或页面改变后清除选择；刷新后移除已不存在的选择。查询失败、加载、其他写入或本次提交期间不能发起批量写入。

删除通过标准对话框固定保存所选 ID 快照；确认时不能改用后来的选择。启停也提交点击时的快照。失败显示友好 Toast 并保留仍有效的选择；不自动重试写入。成功清空选择并失效个人、后台列表及概览。迟到响应不得修改其他账号的选择或显示该账号的操作成功。权限决定可见动作，服务端仍为最终权威。

## 4. 验证

真实 PostgreSQL 覆盖三种动作、个人／后台权限、越权混合批次、缺失／已删除记录零写入、当前状态／授权撤销、并发反向批次、无关字段保留及故障。HTTP 覆盖严格解码、错误契约、no-store 和路由接线。前端覆盖选择、权限、确认快照、失败重试、过滤与身份隔离；隔离数据库 Playwright 覆盖个人与后台及移动端，不修改日常预览数据和 `web/dist`。100% 门禁不降低、不扩大排除。目标 CI、Linux race、Docker 和发布证据单独记录。
