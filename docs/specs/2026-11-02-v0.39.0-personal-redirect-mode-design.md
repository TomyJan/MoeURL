# v0.39.0 个人默认跳转方式设计

## 意图和取舍

延续[范围](../product/scope-v0.39.0.md)中的其他个人偏好方向。保持原 Go／Chi／SQLC／Goose／PostgreSQL 和 Vue／Vuetify／TanStack Query；不增加依赖。改变旧创建端点的省略含义会破坏旧客户端，扩语言主题 DTO 会破坏严格解析，因此选独立本人资源，只在单条创建面板解析初选。以下细节为 Agent 自主决定，不冒用户逐项批准。

## 数据与迁移

新增 `user_redirect_preference`：`user_id uuid primary key references app_user(id) on delete cascade`、`redirect_mode text null`，CHECK 仅 direct／intermediate／confirmation；`updated_at timestamptz not null default clock_timestamp()`。物理删除账号时清理该偏好，沿用既有个人偏好规则；软删除不删除保存值。不回填旧账号、不改其他表和偏好版本。未保存返回两个 null；首次清除仍创建一行并获得版本。Down 仅删除本表与其中个人值，须停应用并备份，旧短链、旧偏好和公开流程不变；再次 Up 是未保存状态，不能声称保留已回退的个人值。

SQLC 独立文件 `queries/user_redirect_preference.sql`；通过锁定 1.30.0 生成，不手改输出。保存按精确版本 CAS；`expectedUpdatedAt=null` 仅首次插入，后续即使同值也推进版本 `greatest(clock_timestamp(), old.updated_at + interval '1 microsecond')`，避免陈旧同值覆盖。带版本但记录不存在返回冲突，不隐式建新记录。

## 本人 HTTP 契约

| 动作 | 路径 | 严格数据 |
| --- | --- | --- |
| GET | `/api/v1/user/redirect-preference` | 不接受 query 参数；成功 data 恰为 `{preference:{redirectMode:null或三枚举,updatedAt:null或完整版本}}` |
| POST | `/api/v1/user/redirect-preference/update` | `application/json`（允许合法参数），body 恰为必需且可 null 的 `redirectMode`、`expectedUpdatedAt` |

两端点 no-store。POST 8KiB 上限（外层原全局 BodyLimit 不变），拒绝错媒体类型、顶层非对象、未知／缺失／重复解码键、大小写别名、错类型、尾随 JSON；模式不 trim、不接受空串。版本用既有 RFC3339Nano 完整精度规则，拒绝不可表示年份、零时刻和超过九位小数；纳秒非微秒倍数直接冲突，不能舍入成匹配。GET 拒绝 query 不泄漏任何其他账号或组数据。

成功和业务失败 HTTP200；输入100001、无权120001、冲突300104、基础设施HTTP500／900000。原认证中间件的401／403边界保持。错误日志仅request_id和error_type，不记录body／偏好内容或DB错误正文。

## 当前身份与权限

服务先拒绝 guest、空／非规范／零 UUID。GET 用当前 DB active、未删除账号与 builtin 非 guest 组的单条查询返回本人保存值；即使增强权限已撤回也可读旧值，不把它当有效创建策略。

Update 五秒事务按当前账号 FOR SHARE → 当前组 FOR SHARE → 偏好 CAS 写。账号共享锁后取得真实 group_id；组共享锁返回 builtin、key、permissions，等待后判定有效身份和实际对应模式权限。保存 intermediate 要求 `short_link:use_intermediate`，confirmation 要求 `short_link:use_confirmation`；null／direct 无额外创建权限要求。旧入口 GroupKey／旧 auth/me 不授予写权限。撤权、禁用、删除和改组与锁序一致，失败无部分写。个人初选没有新的审计需求或授权层。

## 独立前端编辑器

个人设置页新增独立 `RedirectPreferencePanel`，四项「跟随域名默认／直接跳转／倒计时中间页／确认页」。不可用增强选项禁选，已保存但已无权的选项显示明确提示并允许改为跟随／direct。加载完成前禁保存；失败有重试，草稿不被后台刷新覆盖，版本变化显示需重载；冲突保留草稿，显式重载才放弃。成功显示自己的回执并刷新本资源，不修改语言主题／域名／时区草稿。恢复认证时必须重新读取权威状态，不把旧错误永远锁死。

实体严格解析 data、preference 两层，仅两个字段；非 null 模式必须有非 null 版本。Query key 包含 userId＋登录 epoch，返回数据和错误携带所有者标记，避免 observer 转换同一 tick 的旧值短暂可见。退出同步清空旧账号缓存链；不写 localStorage／sessionStorage 或 Pinia。

所有读取、保存 success／error／finally／显式重载以 scope、组件 alive、generation 和 edit revision 判定归属；在真正发请求之前再次核 scope／当前授权，不让离线排队恢复后替另一身份写入。`retry:false`；失败只保留草稿和明确重试，不自动重放写入。

## 创建初选合同

当前草稿手动模式（包含手动点击当前 direct 或修改倒计时）优先；否则读取当前账号个人偏好，有权非 null 值优先；个人 null 或增强值当前无权，退回实际域名原有权默认，最后 direct。保持域名选择的手动／个人域名／组／全局／排序层级，个人模式绝不选择域名。

个人有权非 null 值已明确时，无需域名默认查询成功即可绑定；否则须等待域名有效投影。偏好失败或未知时不悄悄退 direct：提供重试和显式模式。无任何增强权限时无需额外读取，沿用 direct。手动值免于默认读取失败，但仍受原域名选择／当前权限屏障约束。

复用 `useDomainRedirectDraft` 的 bound／manual／reconfirm 机制，增加一个个人默认输入；自动快照仍绑定实际 domainId，后台任何配置刷新只提示有变化，不改已绑定模式与倒计时。切换域名清 bound，仅非手动草稿重算；创建成功、重置、身份 epoch 变化清选择并读取当前默认。自动 intermediate 倒计时固定5秒。当前模式权限撤回则回原 reconfirm 屏障，不自动重发创建；偏好编辑器中的旧值仍保留。

真正发送创建前核当前 identity 与权限；旧请求已发出时由原服务最终授权；旧请求晚到不得发布结果、清除或污染新身份草稿。只对本版触及的创建发送边界补必要守卫，不借机全仓重构。旧API省略仍direct，批量固定direct，公开Open／Preview／Continue、访问量和既有链接都不改。
