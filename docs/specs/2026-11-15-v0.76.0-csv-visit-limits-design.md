# v0.76.0 CSV 最大访问次数导入设计

## 决策与边界

在已有 linked worktree 内联实现，沿用 Go／Chi／SQLC／PostgreSQL、Vue／TanStack Query／i18n，不新增依赖。按持续无人值守授权自主收敛范围并提交、正常集成；仅版末一次 fresh 最强独立整分支终审，不派 builder 或逐任务审查。本设计是 Agent 的决定，不表示用户逐字段批准。

复用已有最大访问次数语义：`max_visits = null` 时无限额，只有最终服务端目标跳转才原子领取额度，公开 Preview 不返回额度数值。新协议只扩批量创建，绝不通过重放重建或更新既有链接。

## 线协议与摘要

新增 `BatchCreateVisitLimitItem`、`BatchCreateWithVisitLimitsInput` 和 `BatchCreateWithVisitLimits`。JSON 外层精确两字段；有序 items 每项精确七字段，tags 为非 null、最多 10 项的字符串数组，其余均为字符串。独立 strict handler 保留现有 UTF-8／surrogate、重复／未知键、尾随 JSON、64 KiB、20 行、唯一目标、标题／标签／自定义短码和过期时间规则。

新增 `parseBulkVisitLimit(value string) (pgtype.Int8, error)`：空值返回无效 nullable；否则先检查首字节 1–9、全部 ASCII 数字，再用有界整数解析并检查不超过 2147483647。所有非法值返回 ErrInvalidInput／100001。不依赖 ParseInt 对符号的宽松接受，也不通过浮点转换验证。规范文本与空值始终保留在公开 DTO 中。

`normalizeBulkCreateWithVisitLimits` 复用现有六字段验证，但采用独立 `SHA256("moeurl:bulk-create:visit-limits:v1:" + Go JSON 原始有序 items)` 摘要。空上限也仍是独立第七协议，不降级六列；原六种摘要完全保持。回执返回原 requestId／创建数量，不额外返回目标或原始上限。

## 事务、权限与持久化

私有 prepared item 增 `MaxVisits pgtype.Int8`，options 增 `VisitLimits bool`。只有新入口同时启用既有 metadata／custom-slugs／redirect-modes／expirations 与 visit-limits；原入口保持自身 flags，新字段零值。

1. 保持目标规则、配额、域名 gate、账号和组锁序。既有四项基础授权和实际行的模式／过期授权保持；新 flag 下有任一有效上限时，还要求当前 `short_link:set_max_visits`。
2. 权限必须在共享回执读取之前按当前数据库有效身份核验。传入的旧 actor 权限快照不能代替持锁后的当前权限，停用、删除、换组或撤权均不得借旧成功回执绕过。
3. 命中精确摘要的成功回执即返回，不读改旧链接，不重置用量；即使原链接现在耗尽或过期也可返回。不同内容或七种协议交叉使用同键一律冲突。
4. 新批次保持域名授权、七项目标规则、每日配额与锁后数据库时间检查。`CreateBulkShortLink` 查询把原 max_visits literal null 改成 `sqlc.narg(max_visits)`，旧六入口传无值；不写 visits_used，使用已有数据库默认 0。SQLC 1.30.0 仅从标准入口生成，第二次全生成物零漂移。
5. 链接、审计、配额和回执同一事务提交；任一验证、熵、存储或提交失败都不能留下部分写入。无新 DDL、权限、审计动作或部署配置。

## 前端生命周期

新增 `BulkCreateVisitLimitItem`／`BulkCreateVisitLimitsInput`、strict schema、client 与 `visit-limits` protocol，复用六字段类型但保留独立端点。CSV parser 只接受精确第七表头，旧六种逐字节保持。第七模板使用空上限、1、2147483647 示例；预览以纯文本显示原上限或本地化“无限额”，不混淆访问统计与额度用量。

完整请求含 items/tags 深冻，替换草稿前验证完整 JSON 65536 字节。为新格式增加独立 visitLimitEpoch：File 开始读取时捕获，解析后仅实际非空 cap 要求当前权限及 epoch 未变；撤权同步退休实际 cap 的导入内容和待发快照。空 cap、已放弃旧预览后形成的手动／低权限草稿保持，恢复权限不能复活旧读取。

新协议的基础自定义短码／元数据、实际模式、实际过期守卫继续成立，不能只核最大次数。preview 和 mutationFn 均在当前 auth 缓存下同步再核。所有异步 success/error/finally 继续检查身份 generation；未知结果保留原 UUID、端点和深冻 payload，仅允许明确原样重试，不因后继明确拒绝就把首次结果洗成失败。

## 验证与交付

先在真实 App 已登录请求新端点观察业务 RED，避免缺类型或编译失败冒 RED；随后验证三模式、空上限／1／上界、存储 usage0／一次审计回执。严格解码覆盖 null、JSON数字、重复键、Unicode、每个截断前缀、20/21 与双64KiB边界。

真实 PostgreSQL 验证授权在回执前、账号／组锁等待后撤权、空 cap 权限独立、同键并发唯一赢家、跨七协议冲突和原子回滚。实际最终跳转消耗 cap1 后原请求重放，确认 usage仍1、原链接仍耗尽；空cap继续无限额，不从事件统计推导用量。

前端 parser／hook 先行为 RED→GREEN，覆盖 strict cap 和旧格式、权限撤销／恢复迟到 File、替换草稿保护、未知重试、跨身份迟到 success/error/finally。完整 Go／业务100／vet、Linux race、必要源扫描、标准 SQLC、前端四100／lint／types／build／E2E strict 分别取证，不借原产品或原候选覆盖。
