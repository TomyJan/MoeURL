# v0.80.2 访问配置测试维护设计

## 目的与选择

v0.80.1 已正常交付，布局没有新增阻断问题，但其 E2E 只通过程序化滚动定位，保存请求是部分匹配，附件失败可提前退出 finally。Agent 选择维护现有测试边界，接续全部五项／组延期意见。产品实现和 0.80.1 版本号不改，不重新编译产品；已清理镜像仅从冻结 ZIP 重组，核对完整 /app 文件集合与 hash。

原生滚轮只放在既有英文最小视口，复用真实登录、own 短链和列表恢复；不复制六套滚轮测试。指针必须位于正文真实可见交集内，通过 mouse.wheel 让最后输入进入完整裁切区域，然后到达正文底部。轮询实际 scrollTop 和字段几何，不使用固定等待；末尾说明可能比正文高，因此字段进入可见与滚到底部分开验证。保留焦点／密码和原矩阵断言。

## 清理与请求契约

新增测试专用顺序清理工具，接受连接恢复、几何附件、删除短链和关闭 context 四个步骤及已有错误数组。逐项执行、逐项收集失败，任何一步失败不阻断后续步骤，也不覆盖已有错误。真实文件写入失败及真实文件删除／句柄关闭用 Node 测试证明；辅助工具不导入产品运行时。

完整请求预期直接写明 `{ id, targetUrl, redirectMode: 'intermediate', intermediateDelaySeconds: 10, password: { mode: 'set', value } }`，用 toStrictEqual 拒绝额外字段，避免计算预期值的自证测试。

## 负对照及来源

只在外置测试快照中将正文 overflow-y 强制 hidden，证明程序化滚动仍能发生但新增 wheel 断言失败；该控制是回归检测敏感性，不是实际产品故障。正常快照无注入，产品恢复自 v0.80.1 全量核验 ZIP；web／产品执行来源仍 2689602，app57712c0／Goose1efe1440，当前提交只归测试执行。严格输入集合、image、现场服务、原件和清理分列记录。

完整旧前端证据保持原执行身份；本版实际运行完整 Node 脚本测试、E2E strict、一个负对照场景＋setup及正常七身份。共享清理／请求断言影响六场景，因此正常矩阵整体执行一次有必要；无 skip／retry／flaky。原图和新滚轮几何核验，不把 CSS 覆盖率或原图冒新执行。
