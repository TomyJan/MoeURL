# v0.68.1 策略卡片保存结果核对设计

状态：设计完成，实施尚未开始。基线为 PR327 已核准 master `8457e3627690b31847095e8253acd0660c389c1a`；三个标准任务按[计划](../implementation/v0.68.1-plan.md)执行，未运行的验证保持未勾选。

## 意图与选择

旧精确主机允许、精确主机拒绝、DNS 后缀拒绝卡片把传输失败等未知结果显示为可重试失败。服务器可能已经保存，管理员会误解实际策略。本版选择把 v0.68.0 后缀允许卡片已验证的最小核对流程应用到这三张卡片，先于新增功能。该选择由 Agent 根据长期无人值守授权作出，不冒称用户逐项批准。

替代方案是继续保留误导提示，或建立通用 CRUD／服务端写回执协议。前者不能解决实际风险，后者扩大 API、数据库及测试范围；本版沿用独立草稿、已有 CAS、身份 generation 和编辑 revision。

## 行为合同

| 卡片 | 明确输入拒绝 | 版本冲突 | 字段 |
| --- | --- | --- | --- |
| 精确允许 | 900212 | 900213 | enabled、hosts |
| 精确拒绝 | 900210 | 900211 | hosts |
| 后缀拒绝 | 900216 | 900217 | wire suffixes，内部 row.host |

- 明确输入拒绝保留草稿，反馈保存失败，允许修正后再次保存；既有输入校验、最多 100 项和完整微秒 CAS 不变。
- 冲突保留原冲突语义和重载屏障。
- transport、HTTP500、无效 envelope、无效成功 data、其他未明确证明未写入的错误一律为 saveUnknown：保留草稿、持续显示结果未确认、禁止再次提交。程序化 submit 和 controller.save 同样阻止写请求。
- 失败重载不能把未知提示改成普通加载失败，不能解除屏障；编辑、删除、清空或开关变化不能清除未知提示和屏障。
- 只有当前身份、当前编辑 revision 接受的显式成功重载才能采用服务器状态并恢复保存。被新编辑淘汰的成功重载不能解除屏障或覆盖草稿。
- 当前 120001／401／403 仍走已有授权恢复，立即清私有草稿和缓存；切号、同号重登录、撤权、卸载均立即退休旧状态，迟到 success／error／finally 不污染当前卡片。
- 中英持久提示接入现有 v-alert，不使用短暂 toast 承载未知结果。建议文案与后缀允许保持一致，明确“保存结果未确认，请重新加载核对后再继续”。
- PR327 的 CR-M1 同时纳入：四张策略卡片在同一身份且所需双权限存在状态不变时，无关权限新增／移除不得清稿、消除 unknown／conflict 屏障、退休当前请求或触发自动 GET。只把签名缩到本资源实际所需权限；任一必需权限撤销、重新授予及身份变化仍维持原退休和 fresh load 规则。后缀允许卡片只改这一项，不重做已完成的 unknown 修复。

## 范围与非目标

生产改动为三份 draft 与三组 i18n，以及第四张后缀允许卡片的权限签名；必要调整三张 editor 的持久提示映射，保留独立资源。产品补丁为 0.68.1，只改 package version，不升级依赖。新建本版 E2E，完善四张卡片原单元测试。后端、API、权限目录、migration、策略匹配、回执协议与历史访问不变。PR327 的 CR-M2 十三处量词随状态更新收口，八处误报不改。手机成功 toast 的原 Minor 继续原归属，不借本版顺手重构。

## 验证与资源

三张旧卡片 unknown 和四张卡片无关权限保稿均先真实行为 RED，再最小 GREEN；不得把缺导入或环境失败当产品 RED。用当前既有 fixture 覆盖至少 transport／HTTP500／invalid envelope／invalid data／unknown code、明确拒绝、失败重载、被编辑淘汰重载、成功接受重载、当前与退休身份；四卡片逐一覆盖新增／移除无关权限时零自动 GET、草稿／屏障不变、当前 pending 继续按 generation／revision 完成。完整前端四项 100%、types／lint／build，严格 E2E types／lint。

准确 clean 新 web 配原核验后端二进制形成产品，smoke 和所选扫描独立留证。真实浏览器按三资源 × 中英 × 桌面／390px 覆盖：服务端提交后仅丢浏览器响应、独立 GET 核提交、未知持久提示、二次 submit 零请求、失败 reload 仍阻写、成功接受 reload 恢复。每资源至少一个真实身份退休场景；不把 reload 导航冒同 SPA 身份证明，不把 mock 错误冒真实服务端提交。

既有成功后端和旧 355 项浏览器证据按准确输入／产品归属复用，不冒新产品完整全套执行。标准三个任务、唯一最终独立审查、最终 head 真实 CodeRabbit、正常 squash、独立 API／fetch／SHA／tree／唯一父及 whole-owned ZIP 全解压逐 hash 完成后才交付。

活动版本 4 GiB、双根临时合计 12 GiB、Docker 可回收 6 GiB。大型步骤先预算并预留；串行生成与准确消费清理，保留失败、raw／exit／输入、LCOV／JSON、必要原图和恢复映射。不得全局 prune、删除 branch／worktree／automation、查或等待 CI、触碰 PR240／266／267、日常 DB／18080、发布部署。
