# v0.27.0 域名排序设计

## 1. 意图与方案

管理员需要整理已授权短链域名的候选顺序，现有两条列表查询只能使用 `is_default desc, created_at, id`。个人默认解决账号初始选择，排序补充未设置偏好或偏好失效后的可用候选顺序；它不是新的授权或服务器默认路由层。

采用独立单域名排序动作。把新字段混进既有完整保存会令旧请求意外清零，或让详情与排序失败时部分保存；全表拖拽还需集合版本、批量原子更新及额外可访问性。独立动作沿用域名版本、原事务与页面，范围更小。数值及方案由主控自主选择；技术栈维持 Go／Chi／PostgreSQL／Goose／SQLC 与 Vue／Vuetify／TanStack Query／zod，不加依赖。

## 2. 数据、顺序与兼容

Goose `00026_domain_sort_order.sql` 在 `domain` 增加 `sort_order integer not null default 0`，CHECK -10000 至 10000。既有域名读作 0，既有默认／创建时间／UUID 顺序不变；新域名也为 0。管理返回的 Domain 新增 `sortOrder`；可用列表仍只返回 id／host／displayName／isDefault，由 SQL 决定顺序，不为排序公开额外元数据。

两条列表统一 `is_default desc, sort_order asc, created_at asc, id asc`。全局默认固定优先，其余较小值优先，允许重复值，不改创建时间或 UUID。可用列表只对已启用的 short_link 且当前授权交集排序，guest／无创建权限仍无候选。后端创建的省略／显式语义完全保留，个人偏好和用户手动选择的优先级不变；没有可用全局默认时才由有序首项作 UI 兜底。

既有 create／update 不接收排序作为其写入字段；SQL INSERT 使用默认 0，旧完整 update 不赋值 sort_order。设默认／删除／域名偏好清理不重置它。新 web 的 managed schema 要求有效 sortOrder，所有 managed 返回路径都携带它；客户端和服务器按同一候选构建交付，不将新 web 对旧 server 的缺字段响应当合法成功。available schema 保持兼容。

Down 先把 domain_audit 恢复到旧白名单，再删除排序约束／列；历史审计字符串保留，账号、组授权、短链、个人偏好及其版本不删。排序写入所推进的 domain.updated_at 不回退。镜像回退可以保留列，旧应用忽略排序并按旧默认＋创建顺序展示；旧保存不会清空数据库的 sort_order，但不能承诺仍按排序展示。正式生产 Down 前备份并接受排序丢失，恢复核查在清理隔离环境之前进行。

## 3. API 与授权

新增 `POST /api/v1/admin/domain/set-order`，成功 `data.domain` 为包含 sortOrder 的完整 ManagedDomain。请求必须是 application/json（合法参数允许）、单个 JSON 对象，恰好三个字段：

```json
{"id":"00000000-0000-0000-0000-000000000727","sortOrder":-20,"expectedUpdatedAt":"2026-10-27T01:02:03.123456Z"}
```

三项必须存在且非 null。id 是规范小写非零 UUID；sortOrder 为 JSON 整数 -10000 至 10000，不接收字符串、小数或指数形式；expectedUpdatedAt 为含日期、秒及时区的非零 RFC3339Nano，保留完整精度。拒绝未知字段、错误类型、数组／null 顶层与尾随 JSON；不接受客户端指定 actor／group。超出 PostgreSQL 微秒精度的版本不能截断为匹配，合法但不匹配即冲突。

复用当前 no-store、Cookie／路由会话规则与错误 envelope。参数 100001；当前身份／权限不足 120001；目标不存在或非 short_link 为 210102；陈旧版本 210103；基础设施 HTTP500／900000。预期业务失败 HTTP200。请求路由不能仅凭 admin 页面放行。

Service 只从 actor.ID 确定操作者，要求规范非零 UUID；在最多 5 秒 WithAuditTx 内，先域名排他 advisory lock，再 active／未删除 app_user 共享锁、该用户当前 builtin user_group 共享锁，再目标 domain 更新锁。按数据库当前组权限逐项检查 admin:access 和 domain:manage，不信 actor.GroupKey／Permissions 的旧快照。非 admin 组不能获得受保护能力；guest／禁用／删除账号均不能写。读与写的查询、解析及审计故障返回原基础设施失败，不伪装为无权、未找到或成功。

此锁序保持与域名删除和本人偏好保存一致的 domain → user → group → domain row 前缀，不引入先锁组后等 domain 的倒序。域名当前为默认、停用或已被短链引用仍可排序；不改变 host／enabled／isDefault／grants／user_domain_preference／已有短链。比较版本先于值：版本相同且值相同直接返回当前表述，版本／审计不动；实际变化更新 sort_order 与 `greatest(clock_timestamp(), updated_at + interval '1 microsecond')`，与审计原子提交。

独立终审同时发现基线旧域名动作仅在等待锁前授权。真实门闩复现确认后，将旧 create／update／set-default／delete 纳入本轮有界安全修复：保留入口快速权限检查，在同一审计事务取得 domain 排他锁后，复用上述当前有效账号／builtin admin 组共享锁和双权限检查，再读写目标。排队期间账号禁用、软删除、改组、组非 builtin 或任一权限撤销，均返回无权且域名、版本、默认镜像、授权、个人偏好和审计不变。旧动作的请求字段及正常版本语义不变，无新权限、查询、迁移或依赖。

## 4. 审计

00026 Up 原位重建 domain_audit，保留原 host／display_name／purpose／enabled／is_default 白名单并追加 sort_order，沿用 record_business_audit。业务更新为 resource_type=domain、action=update、changed_fields=['sort_order']，只记字段名和 actor／资源标识，不记排序值或域名内容。创建仍正常包含新增字段名；不写额外手工审计，避免双记。

no-op 不发 UPDATE，因此不会推进版本或产生噪音；无效／陈旧／无权／失败事务也不留部分记录。故障注入验证审计 INSERT 失败时排序与版本均回滚，Down 后旧域名写仍能审计。审计列表／CSV 已支持通用字段字符串，不增加动作、权限或字段值输出。

## 5. 管理界面与异步

在现有选中域名的详情旁提供独立“排序”区域：整数输入、明确“较小值靠前；全局默认始终优先；同值保持创建顺序”提示、“保存排序”和“取消排序编辑”。沿用 Vuetify 和双语；默认显示当前保存值，不能只乐观改变本地数组顺序。字段空／非十进制整数／越界在前端明确提示，不能把空字符串转成 0。

普通详情和排序两个草稿互斥：详情有未保存改动时禁用排序编辑；排序有改动时禁用详情输入、详情保存、设默认和删除，提供取消排序以恢复。切换域名／新建须对任一脏草稿使用既有放弃确认，确认后才丢弃；不产生嵌套 form，也不让排序按钮触发旧详情 submit。排序请求期间阻止重复动作和选中切换。

排序成功只确认服务端返回的目标值／版本，保持当前选中 UUID，然后刷新 managed 列表及 available 前缀；服务器才是最终顺序来源。刷新失败显示错误与重试，在成功刷新前阻止后续写入，不能以局部结果假装完整顺序已加载。零值与负值按整数展示，不重排或修改其他域名版本。

冲突保留排序草稿和原完整版本；允许刷新列表看最新数据，但不自动覆盖／自动重试 mutation。显式“重新加载排序”成功后才放弃草稿并采用新值及版本。目标删除、加载失败和权限失效时不允许保存陈旧目标。其他错误保留输入，可由用户主动重试。普通详情原有冲突恢复不回归。

排序操作捕获 userId＋login epoch＋targetId；成功、失败和刷新前检查当前 scope，退出、换账号、同 ID 新 epoch、卸载及旧请求迟到不能写新账号 cache／反馈或刷新新账号数据。组件须在同步失权时阻止保存；服务端仍重查最终当前权限。

排序刷新只改变 available 数组，不清空个人偏好，不覆盖仍可用的明确手动选择。无手动或有效偏好时才重新采用全局默认／新的有序首项；真实 QueryClient 回归分别证明这三类优先级，不能只断言 invalidateQueries 被调用。
