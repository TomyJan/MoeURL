# v0.64.0 账号每日创建配额设计

## 意图与取舍

为自托管管理员提供可选的每日创建预算，防止单个有权账号无限消耗资源。先实现统一每账号上限，而非按组／套餐或个人覆盖，避免把数字配额耦合既有组权限和域名版本。默认 `null` 保持原创建能力。与按当前 owner 统计短链数相比，独立原创建账号计量不会被转移和删除绕过；与账号／日期无限增长的流水相比，每账号一行有明确存储上界。这些是 Agent 的设计决定。

## 独立策略资源

key `security.account_daily_create_quota`，默认 `{"dailyLimit":null}`。

- GET `/api/v1/admin/system/account-daily-create-quota` 返回 `{dailyLimit,updatedAt}`。
- POST `/api/v1/admin/system/account-daily-create-quota/update` 接受 `{dailyLimit,expectedUpdatedAt}`，返回同一资源。
- `dailyLimit` 必须显式出现，允许 `null` 或 `0`–`1000000` 的整数；不接受字符串、boolean、负数、小数或指数词法。null 不等于缺失。两个字段以外、重复字段、尾随 JSON、非法 UTF-8、媒体类型、查询参数和超过 `4096 B` 的正文整体拒绝。
- 完整 UTC RFC3339Nano 版本、微秒精度；先 CAS 再 no-op，陈旧同值冲突。真实 no-op 不改版本或审计。expectedUpdatedAt 非 null，沿现有有效年份边界。
- 当前数据库中非 builtin、active、未删除账号及 builtin admin 组，必须同时具备 `admin:access` 与 `system:manage`；不信任请求里的组或权限快照。五秒事务上限、no-store，日志只记请求标识。
- 管理错误 `900214`／冲突 `900215`，创建额度耗尽 `200122`；权限继续 `120001`，基础设施／坏配置／异常计量 `HTTP500/900000`。实施前核无占用。
- 审计只记 `security.account_daily_create_quota` 键，不记具体额度、用量、目标或完整 JSON。旧 general／公开 settings DTO 不变。

## 计量和事务

Goose `00041_account_daily_create_quota.sql` 新建 `account_daily_create_usage`：`actor_id uuid primary key references app_user(id)`、`usage_day date not null`、`used bigint not null check(used>=0)`。不按 owner 反推历史，不保存 URL，也不为每次创建增加一条计量历史。

创建锁序：目标策略 shared gate → 新配额 shared gate → 域名 shared gate → 当前账号／组 → 当前域名及目标检查 → 用量行 → 新链接／审计／回执。配额 gate 为双 int32 `(0x4d4f4555,0x4351554f)`，与现有 namespace 核无冲突。管理保存先取新 gate exclusive，再当前 actor／组和 setting。所有成功提交后才释放 gate，不缓存策略。

`Consume(ctx,q,actorID,count)` 在调用者持有 shared gate 的原审计事务中工作：

1. 读取并严格验证策略。调用者已经重新校验当前身份、必要权限、域名和目标。
2. 插入缺失的零计量行，初始日 `0001-01-01`；冲突不改原行。`FOR UPDATE` 锁定该账号行。
3. **取得行锁后**用 `pg_catalog.clock_timestamp()` 读取数据库 UTC 日期，不能用事务开始时间或等待前日期。日期有限且在公历合法范围；保存日大于当前日、负数或 bigint 加法溢出均安全拒绝，不倒拨清零。
4. 保存日早于当前日时有效已用量为 0，同日沿用原值。count 必须 1–20；有限额时先以减法检查余量，超额返回耗尽。无限额也递增。
5. 更新为当前日及新计数，后续创建／审计／回执任一步失败都随原事务回滚。并发不同账号独立；同账号争最后额度只有合法数量成功。

单条随机短码冲突会重开原审计事务，上一尝试的计量必须回滚。自定义短码冲突不扣。四种批量都在统一 `batchCreate` 内扣 `len(items)`，不修改各自 DTO、摘要或 UUID。先按当前身份和能力校验，再读取成功回执；同内容回执在配额检查之前恢复，不重复扣减，异正文同 UUID 仍冲突。新批次的任一项失败全部回滚。公开访问、本人／管理员目标编辑、配置编辑、批量转移／删除／禁用均不调用 Consume。

## 日界、关闭和回退

一天以数据库 UTC 日为准，与账号显示时区无关。上限调小到低于已用量只拦后续创建；null→有限额继续用当天计数。改组或短链所有权不影响 actor 行。不存在管理“重置用量”动作。

首次迁移只建立空账本；之前成功创建不冒已计入。新旧应用混跑、维护回退或直接数据库写入不属于完整配额执行环境。

Down 先取得同一 exclusive gate，再取数据库当前 UTC 日：存在 `usage_day>=today` 且 `used>0` 时安全失败，避免同日 Down/Up 抹掉用量。没有当日或未来非零用量才允许卸 trigger／function／计量表；保留策略值、版本及审计，Up 不覆盖。空账本和仅历史日用量应能 Down/Up；失败 Down 保持完整 schema 与数据。旧应用回退不执行新配额，不把安全 schema 回退说成持续执行配额。

## 结构和前端

新增 `internal/createquota/{model,json,service,consume,locks,handler}.go`，使用既有 SQLC／pgx／权限快照解析，不建立通用策略框架。新 `queries/account_daily_create_quota.sql` 包含当前管理身份、计量行及数据库日查询。SQLC 通过锁定 1.30 标准入口生成一次，再以相同完整输入二次生成核零漂移，不能手改生成物或把第一次合法新增文件当漂移失败。

App 启动验证独立资源，并注入独立 handler／router。两处创建 service 加 shared gate／Consume，两个真实 HTTP 响应分支映射 `200122`，不误改两种编辑路径。

前端新增 `entities/account-daily-create-quota/api.ts`、独立 draft／editor，放在 AdminSettings 旧 form 外。使用“限制每日创建数量”开关与整数输入：关闭发送 null；开启保留本地输入并要求 0–1000000，明确 UTC 日、0 禁止、管理员同样适用。加载／保存失败、冲突、无权限分别反馈；显式保存一次，冲突保草稿并只由成功显式重载解除。保存后仅由服务端响应更新字段及完整版本。

独立 query key、scope／generation 和 edit revision，切号、同号重登录、撤权、卸载同步清私有状态并使所有 load／save success/error/finally 失效；迟到 load 不覆盖编辑。单条及四批量保留原草稿并显示专用额度耗尽反馈；不把它误作目标受限或访问次数耗尽。首次确定拒绝可回编辑；先 unknown 后重试即使耗尽仍 unknown，原 payload／UUID 不改，不自动发新批次。
