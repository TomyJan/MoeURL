# v0.4.0 确认页访问设计

## 1. 背景与范围决策

v0.3.0 已经建立 `/go/{slug}` 公共访问页、同源预览、最终继续路由、密码解锁和短期授权。路线图中的确认页、最大访问次数和权限预设都可以作为下一阶段，但三者的工程边界不同。

本版本选择确认页访问，原因如下：

- 确认页直接复用现有公共访问状态机，不需要建立新的资源模型。
- 它能补齐产品总览长期目标中的第三种跳转模式，并与 direct、intermediate、password 形成完整组合。
- 最大访问次数需要把并发额度扣减与最终响应计量放入一致性设计，适合单独版本。
- 权限预设会同时扩展用户组写入、管理 UI 和初始化策略，也应保持独立边界。

版本号使用 v0.4.0，因为变更跨越数据库约束、权限、管理 API、公开预览契约和公共页面行为。

## 2. 方案比较

### 2.1 扩展现有跳转模式

在 `redirect_mode` 中增加 `confirmation`，复用 `/go/{slug}` 和 `/go/{slug}/continue`。公开预览显式返回模式，前端按模式选择自动倒计时或主动确认。

优点是数据模型和路由边界清晰，密码组合可以复用现有授权。缺点是需要调整当前把“可公开预览”等同于“中间页”的校验命名和测试。

### 2.2 把确认页作为独立访问条件

保留两种跳转模式，另加 `requires_confirmation` 布尔值。该方案会产生 direct + confirmation、intermediate + confirmation 等组合，但产品没有定义“倒计时之后再确认”或“确认后再倒计时”的顺序，容易形成无价值的状态爆炸。

### 2.3 新增确认令牌接口

点击确认后先签发令牌，再允许继续访问。确认页不是安全边界，令牌无法证明访问者理解了内容，只会增加 Cookie、存储和清理成本。

本设计采用方案 2.1，并明确不引入确认令牌。

## 3. 数据与 migration

新增 `00008_short_link_confirmation.sql`：

1. 删除旧的 `short_link_redirect_mode_check`。
2. 以 `NOT VALID` 添加允许 `direct`、`intermediate`、`confirmation` 的同名约束。
3. 使用可回滚跟踪表记录为内置 `user`、`admin` 新增的 `short_link:use_confirmation` 权限。

新增 `00009_validate_short_link_confirmation.sql`，独立执行 `VALIDATE CONSTRAINT`。Down 流程先把 `confirmation` 记录改为 `direct`，再恢复只允许 direct/intermediate 的旧约束，并只移除由 `00008` 实际添加的权限。

不新增确认文案、确认时间或确认令牌字段。确认页内容使用固定 i18n 文案，目标主机名从已存储目标 URL 动态提取。

## 4. 权限与管理契约

新增权限：

```text
short_link:use_confirmation
```

内置 `user`、`admin` 默认拥有，`guest` 不拥有。创建和更新遵循目标能力校验：

- `redirectMode = direct`：不要求高级跳转权限。
- `redirectMode = intermediate`：要求 `short_link:use_intermediate`。
- `redirectMode = confirmation`：要求 `short_link:use_confirmation`。
- 显式修改 `intermediateDelaySeconds`：始终要求 `short_link:use_intermediate`。

这意味着用户即使失去某项高级能力，仍可以把自己的短链切回 direct。管理员更新全站短链时仍先检查 `admin:access` 和 `short_link:update_all`，再按当前管理员用户组动态检查目标模式权限。

短链 Service 的生产权限解析器在每次业务操作开始时按 `GroupKey` 读取数据库中的 `user_group.permissions`，并在该操作内使用不可变权限快照。数据库撤权对后续请求立即生效，不依赖进程重启或编译期内置权限；权限读取失败按基础设施错误处理，不能降级为放行。短链模块的静态权限解析器只用于隔离测试。

短链响应继续返回 `redirectMode`，其 TypeScript 和 Go 枚举扩展为第三个值。列表使用独立的模式标签展示确认页，不把它显示为中间页或密码状态。

## 5. 公共访问状态机

### 5.1 初次打开

`Open` 先执行状态、软删除和过期检查：

- 设置密码：进入 `/go/{slug}?reason=password`。
- `direct` 且无密码：直接返回目标 `302`。
- `intermediate`：进入 `/go/{slug}`。
- `confirmation`：进入 `/go/{slug}`。

### 5.2 公开预览

`Preview` 只允许以下情况：

- 无密码的 intermediate 或 confirmation。
- 已持有有效路径授权的受保护 direct、intermediate 或 confirmation。

响应为：

```json
{
  "slug": "abc123",
  "targetHost": "example.com",
  "redirectMode": "confirmation",
  "intermediateDelaySeconds": null,
  "expiresAt": null
}
```

未受保护的 direct 通过预览接口返回既有错误码 `200110`，文案调整为“短链不使用交互访问页”。完整目标 URL、密码状态和授权状态都不进入响应。

### 5.3 密码组合

密码解锁成功后重新读取预览：

- direct：立即导航到 continue。
- intermediate：启动既有倒计时。
- confirmation：展示目标主机名和继续按钮，等待主动操作。

密码 Cookie、TTL、失效条件和限流规则不变。确认页不签发或延长访问授权。

### 5.4 最终继续

`Continue` 重新读取短链并检查状态、软删除、过期、模式和密码授权：

- 无密码的 intermediate 或 confirmation 无需路径授权即可继续。
- 受密码保护的 direct、intermediate 或 confirmation 都必须提供有效路径授权。
- 无密码 direct 不能通过 continue，返回 `not-interactive` 页面状态。

confirmation 请求在准备最终跳转前发出 `confirmation_clicked` 非统计事件。无论该事件记录是否失败，都不能阻断目标跳转。

## 6. 统计与事件

`confirmation_clicked` 用于描述确认页继续动作，但 v0.4.0 的数据库 Recorder 仍只持久化 `redirect_response_sent`。确认页进入、预览、点击、密码失败和访问条件拦截均不增加访问量。

最终目标响应仍由 Handler 先写出 `302`，成功写入响应体后异步记录 `redirect_response_sent`。因此 direct、intermediate 和 confirmation 使用同一统计口径。

## 7. 前端设计

创建面板和设置对话框根据当前权限组合构建模式选项：

- direct 始终存在。
- 有 `short_link:use_intermediate` 时增加 intermediate。
- 有 `short_link:use_confirmation` 时增加 confirmation。

倒计时滑杆只在选中 intermediate 时显示。创建面板的模式控件在至少拥有一项高级模式权限时显示，权限变化后立即把已失权选择归一为 direct，提交时再次校验当前模式。设置对话框在至少拥有一项高级模式权限，或短链当前仍是已失权高级模式时显示模式控件；后一种情况只提供 direct 降级入口。密码、过期时间和 pending 锁定行为保持不变。

`RedirectPage` 在获得预览后按 `redirectMode` 渲染：

- direct：不展示中间状态，立即进入 continue。
- intermediate：显示倒计时和“立即前往”。
- confirmation：显示确认标题、短码、目标主机名、可选过期时间、风险中性的说明、继续访问和返回首页，不启动计时器。

确认页沿用现有公共访问页视觉语言和响应式约束，不新增模板选择、卡片嵌套或装饰性页面结构。

## 8. 错误处理

- 不存在：公开入口返回 404，预览返回 `200104`。
- 禁用：进入 `reason=disabled`。
- 过期：进入 `reason=expired`。
- 非交互 direct 调用预览或 continue：进入或返回 `reason=not-interactive`，业务码沿用 `200110`。
- 密码授权缺失：进入 `reason=password`。
- Open 或 Preview 基础设施错误：返回 HTTP 500 或页面加载失败状态。
- Continue 基础设施错误：返回 `302 /go/{slug}?reason=continue-failed`；页面重新读取安全预览、展示失败状态，并让 direct、intermediate、confirmation 都等待访问者再次点击，避免自动重试循环。

继续操作失败保留在当前页并允许重试，不在客户端缓存目标地址。

## 9. 测试策略

- migration：升级、回滚、旧数据保持、confirmation 降级和内置权限可回滚。
- SQLC：创建、更新、读取和列表返回 confirmation，生成代码零漂移。
- Service：三种模式、数据库动态权限、运行中撤权、切回 direct、自定义倒计时权限和管理员路径。
- Redirect：Open、Preview、Continue、密码与三模式组合、二次状态检查、非统计确认事件和最终计量。
- Web：模式选项权限矩阵、权限变化归一、表单提交、列表标签、严格预览 schema、确认页元数据、无倒计时、密码后确认和 Continue 失败恢复。
- E2E：真实确认页、主动继续、Continue 失败重试、密码组合、禁用或过期二次检查、访问量，以及 `1280 x 720` 和 `390 x 800` 布局。

## 10. 决策记录

- 确认页是跳转模式，不是独立访问条件。
- 确认动作不产生令牌，不构成安全证明。
- 公开预览显式返回模式，避免前端从可空倒计时推断行为。
- 确认页展示短码、目标主机名和可选过期时间，不展示完整目标 URL。
- v0.4.0 不扩展风险审核、模板和最大访问次数。
