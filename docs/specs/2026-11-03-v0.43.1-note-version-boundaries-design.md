# v0.43.1 备注版本边界设计
方案由 Agent 按无人值守授权选择，基线为已交付 master 646656176ad961efb8876cb74acfd05096cb2b5e。

## 契约与最小实现
备注版本完整匹配四位本地年份、两位月日、大写 T、两位时分秒，可选点及 1–9 位数字，末尾大写 Z 或 ±HH:MM。offset 小时 00–23、分钟 00–59，时间与日历必须有效；本地年及 UTC 年均在 1–9999，绝对时刻不能是 Go 零时刻。拒绝逗号、一位小时、大小写替代、无秒、空小数、十位小数、尾随换行或空白。
后端仅在 parseNoteVersion 中先做严格词法检查，再保留 time.Parse 和现有零值／本地年／UTC 年检查。前端保留 Zod 严格日历校验，补 UTC 年份范围；去小数后的 Date 仅用于范围及零时刻所在秒判断，非零分数另按字符串判断。Date 不参与 CAS、不重格式化原字符串、不丢弃纳秒。
格式错误返回 100001，合法差 1ns 仍是 200116；等价 offset 同时刻且同值保存为 no-op。真实更新仍只有备注版本和一条 note 字段名审计，旧主版本不变。

## 测试与预期
独立人工 JSON 语料包含 input／valid／id，两个实现读取，不从被测代码生成期待值。
真实 Session／PG／生产 router 的本人和管理两个 scope：固定 DB 为 2026-11-03T00:00:00.123456Z，以 .1234560001Z 和不同内容保存，应为 100001，完整 link／audit 不变；原错误接受须实际 RED。合法 .123456001Z 为 200116；等价 +08:00 同值不写，规范当前版可以真实更新且恰一条审计。
service 语料当前版本固定 2030-06-15T12:34:56.654321Z，与全部合法语料不同；合法陈旧值期待 ErrTransferConflict，非法期待 ErrInvalidInput，完整状态不变。
真实 own/admin 客户端在请求中拒绝 UTC 越界且不 fetch，在 read/update 成功响应中拒绝畸形版本并报告 invalidNoteResponse；合法最大精度和最小非零纳秒逐字保留。
完整受影响后端、业务覆盖率 100、前端四项 100、真实浏览器、产品检查及独立终审继续执行。SQLC 无输入变化时只比全集，不重复生成。

## 风险与边界
主要风险是过严误拒合法官方版本及毫秒舍入把非零纳秒当零。边界语料、真实 HTTP 和原字符串断言分别防护。不扩其他资源解析器，不改权限、事务、迁移、依赖。v043 的历史 M1 和合同保持原件，修复由本版证据证明。
