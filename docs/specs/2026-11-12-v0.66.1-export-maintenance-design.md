## 目标与边界

## 测试选择

直接在 `web/e2e/global-visit-export.spec.ts` 比较 `ours` 的排序后短链 ID 数组与 `events.keys()` 的排序数组。Map 的键唯一，完整数组相等同时排除重复、遗漏和替换；不只比较 Set，否则重复可能被去重掩盖。继续逐行核对各自事件 ID、时间和匿名维度，允许同一隔离数据库前面场景留下的软删历史。

私有反例工具执行 E2E 中的实际断言片段：合法两 ID、倒序和无关历史应通过，重复 A／遗漏 B、缺行及未知替换应拒绝。先在旧片段观察重复反例漏检，再改断言验证拒绝；这是测试质量 RED→GREEN，不称产品 RED。随后使用不变的准确 0.66.0 制品运行四个真实浏览器场景和 setup。工具不进入生产代码。

路由测试只替换请求构造 API，沿用原四个真实路由拒绝场景；运行完整 HTTP 包，记录实际 Go 版本及容器清理。没有生产行为变化，不虚构该调整的行为 RED。
