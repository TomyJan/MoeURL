# v0.26.0 个人默认短链域名设计

## 1. 意图与边界

来源为 roadmap 的个人默认域名缺口，以及 domains 的个人优先规则。本轮交付“保存创建面板的账号初始选择”，不改变域名授权和创建 API 的服务器默认策略。用户在个人设置明确保存，创建时可随时临时改选；已有短链、组默认、域名排序和 DNS/TLS 不受本功能管理。当前后端已完成本地验证（e3286dcd），前端本地验证已完成，真实浏览器及完整交付尚待验证。

这是主控基于既有路线图作出的范围决定，不表述为用户逐项批准过的设计。技术栈沿用 Go／Chi／PostgreSQL／SQLC／Goose 和 Vue／Vuetify／TanStack Query／zod，不增加依赖。

## 2. 方案与选择

1. 浏览器 localStorage：不能跨设备，且容易跨账号继承，不采用。
2. 扩展语言／主题完整替换接口：旧请求会缺新必填字段，或者静默清空偏好；共享版本还会制造无关冲突，不采用。
3. 独立账号域名偏好资源：独立版本，复用已有个人设置、身份轮次与可用域名查询，采用。

新增 `user_domain_preference`，每个账号至多一行。它只保存域名选择，不建立通用偏好框架。账号语言／主题的表、响应及请求完全保留，互不写入版本。

## 3. 数据与删除一致性

Goose `00025_user_domain_preference.sql` 新建表：`user_id uuid primary key references app_user(id) on delete cascade`，可空 `domain_id uuid references domain(id)`，非空 `updated_at timestamptz default clock_timestamp()`。域名外键使用默认 RESTRICT／NO ACTION；为 `domain_id` 建索引，以便删除域名时定位引用。无旧账号回填，无新权限。

未保存账号返回两个 null；首次显式保存 null 也建立版本行。每次保存版本严格递增为数据库时钟和旧版本加 1 微秒的较大值。`expectedUpdatedAt=null` 只允许首次创建，非空版本精确匹配；超出 PostgreSQL 微秒精度的非零尾数不能被截断为匹配。解析使用已有严格时间规则，不接受不可规范化 UUID、nil UUID 或非法时间。

域名删除在原域名写事务和全局域名排他锁内，先完成原有默认／短链引用／版本检查，然后将该域名关联偏好设为 null、单调推进每行版本，再删除域名；任一步失败整批回滚。保存偏好使用同一域名共享锁，故不可能与删除形成悬空引用或在清理后重新写入被删域名。停用、默认切换或组授权变化不主动改偏好；使用时按最新可用列表重新判定。

Down 仅删除新表及索引，丢失个人域名偏好，不修改语言主题、账号、Session、域名、短链和历史审计。旧应用回退优先保留表；若需执行 Down，先备份并明确偏好丢失。升级、恢复文档补充新表核查，不执行正式生产演练。

## 4. 自有 API 与授权

新增 `GET /api/v1/user/domain-preference` 和 `POST /api/v1/user/domain-preference/update`，均 no-store，沿用统一响应。成功 `data` 为：

```json
{"preference":{"domainId":null,"updatedAt":null}}
```

保存请求要求 `application/json` 媒体类型（允许合法参数），必须且只包含 `domainId`、`expectedUpdatedAt`，两者均可 null；拒绝缺项、未知字段、错误类型、多个 JSON 文档。账号只能来自 Cookie 解析后的 actor，不接受任何指定用户参数。返回只含本人保存的域名 UUID／版本，不返回域名名称、地址或其他账号信息。

所有读取／保存重新核实当前数据库账号启用、未删除、非 guest。读取与清除不要求创建权限，保证撤权后可以移除偏好。指定 UUID 保存还要在同一事务中核实当前账号主组、该组当前权限、域名启用且 purpose=short_link，以及 domain_user_group 授权；当前全局域名要求 `domain:use_default`，其他域名要求 `domain:use_assigned`，两者均要求 `short_link:create`。不使用请求中 actor.GroupKey／Permissions 作为最终数据库授权。

事务最长 5 秒。锁序固定为域名共享 advisory lock → 当前 app_user 共享锁 → 当前 user_group 共享锁 → 目标域名／grant 共享锁 → 本人偏好条件写入。域名删除仍从域名排他 advisory lock 开始。用户／组锁顺序沿用当前成员迁移模式；清除没有目标域名，仍按相同前缀锁序核实账号。每次读只要求单一授权快照，不追溯撤销已完成读取；Session 解析仍使用既有中间件，不新建会话系统。

业务错误：无效请求 `100001`，账号不符或指定域名不再可用统一 `120001`（不区分未知域名与无权域名），冲突复用自有偏好语义 `300104`；基础设施 HTTP 500／`900000`。业务失败 HTTP 200。不存在记录与合法清空可区分为 updatedAt 是否为 null；数据库失败不能伪造为未设置。

## 5. 个人设置编辑器

在 ProfilePage 新增独立 Vuetify 区域，单一下拉与显式保存，字段使用 vee-validate／zod。选项首项“沿用系统选择”对应 null，其余仅来自当前身份的成功可用域名查询；可选择当前全局域名 UUID。说明偏好只影响初始选择，最终创建仍由服务端检查。

偏好和可用域名分别有加载／持久错误／重试状态，未加载偏好不能保存。可用域名请求失败时，不开放指定 UUID 保存，但已有偏好加载成功时仍允许明确选择清除。成功后更新当前身份对应 query，提示成功。失败保留草稿，冲突提供显式重新加载，重新加载成功才放弃草稿，不自动重放 mutation；后台 refetch 不覆盖脏草稿。

已保存 UUID 不在当前可用列表时，显示不含名称／地址的“已保存域名当前不可用”状态，保留其编辑快照，用户可选择可用域名或清除。不能把未授权域名补回下拉。保存成功应同步所有当前已挂载的创建面板，但不覆盖它们已经手动选择的值。

## 6. 创建选择与兼容

创建面板的状态应区分“没有手动选择”与“手动选择全局默认”。前者才采用已加载账号偏好，后者必须保持用户决定，不能再使用空字符串同时表示两种状态。

初始选择顺序为：当前表单明确选择的仍可用域名 → 当前账号偏好的可用 UUID → 当前可用全局默认 → 当前既有排序的首项。最后一项只复用现有 available 返回顺序，不新增域名排序策略。零项禁用。原手动选择或偏好失效时展示通用回退提示，不返回不可用域名元数据。

在偏好首次加载期间，不自动提交未知默认选择；用户可明确选择一个已加载的可用域名后提交。偏好读取失败提供重试与明确的“使用系统选择”动作，后者是本表单临时决定，不清空账号保存。只有一个域名时也要提供这个恢复动作，避免隐形阻塞。正常加载期间，输入目标 URL 无需禁用，但提交须等偏好就绪或用户明确选择。

序列化严格保留旧契约：当前选项 `isDefault=true` 省略 `domainId`，其他选项传 UUID；后端原创建服务与授权不因本功能修改。个人偏好不是固定域名路由承诺，选项为当前全局默认时仍采用服务端提交时的全局默认。若管理配置在提交期间改变，既有创建事务是权威；出现 `200114` 后刷新域名／身份并保留表单，提示重新选择，不自动回退重发 mutation。预览使用当前有效选项，创建成功的 URL 以实际响应为准。

成功创建或显式重置移除本表单临时选择，再采用最新已加载偏好。多个创建面板共享账号 query，不共享各自的临时选择。不保存目标 URL、临时选择或账号偏好到 localStorage。

## 7. 身份与异步

复用 `useAccountIdentity` 的当前用户 ID＋登录 epoch，偏好 query key 为 `['user','domain-preference',userId,epoch]`；可用域名沿用既有前缀并附相同身份维度，仍支持管理成功后的前缀 invalidation。拒绝 stale placeholder 复用上一身份的域名／偏好数据。

身份改变时同步清除面板原快照、临时选择、生成结果和反馈；取消并移除旧域名偏好 query，迟到读写不能写入新账号 cache、触发新账号通知或改变选择。保存与创建均捕获 scope；同 ID 重新登录也有新 epoch。已发起成功创建的迟到响应也必须通过 scope 检查，避免上一账号结果出现在新身份界面。服务端仍可完成已授权写入，前端丢弃迟到呈现，不宣称取消能撤回已提交业务。
