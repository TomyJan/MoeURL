## 本地用户系统

系统保留本地用户系统，用于支持基础账号、用户资料、用户组关系和权限计算。

v0.0.1 优先实现本地登录，并预留外部登录扩展入口。在没有可用外部登录方式前，不应提供禁用本地登录的配置，避免管理员误操作导致系统无法登录。

即使后续禁用本地登录，系统内部仍保留本地用户资料，用于绑定外部身份、记录短链归属、计算用户组权限和保存个人偏好。

## 登录流程

用户点击登录后，根据系统配置进入本地登录或外部认证流程。

登录成功后，系统创建或更新本地用户资料，并根据用户所属用户组计算权限。

登录后默认进入首页，因为最常用的生成链接功能就在首页。首页应根据登录状态和权限展示可用功能、禁用项提示和用户入口。

用户可以从首页进入用户中心、我的短链、统计分析和个人设置等页面。

## 登录页与登录结果页

登录页根据系统配置展示可用登录方式。

v0.0.1 阶段仅要求本地账号登录；外部登录入口在对应登录方式实现后展示。

完整目标形态可以包含：

- 本地账号登录。
- 已启用的 OIDC 提供商登录入口。
- 其他已启用的认证入口。

后续当至少存在一个可用外部登录方式时，管理员可以选择禁用本地登录。禁用后，登录页隐藏本地账号表单，只展示已启用的外部登录入口。

当配置了多个 OIDC 提供商时，登录页应展示清晰的提供商列表，例如「使用 GitHub 登录」「使用 Google 登录」「使用企业 SSO 登录」。

用户完成登录后，系统可以进入登录结果页，也可以直接跳转首页。

常见状态：

- 登录成功。
- 登录失败。
- 用户被禁用。
- 当前账号无权使用系统。
- 首次登录，需要补充昵称或偏好设置。

其中，「用户被禁用」表示本地账号状态不可用；「当前账号无权使用系统」主要用于外部登录场景，表示外部认证成功，但该账号没有匹配允许进入系统的用户组或访问规则。

## 个人密码修改

v0.13.0 增加已登录本地账号的自助密码修改，详细边界见 [设计](2026-10-15-v0.13.0-password-change-design.md)。用户证明当前密码后，服务端在单事务内更新 Argon2id 哈希并撤销全部已有 Session，随后重新登录。新密码为 8–128 个 Unicode 字符，保留首尾空格和特殊字符；纯 OIDC 账号不能借此设置本地密码，也不提供找回密码或账号合并。

该操作复用已有数据库失败窗口和认证并发保护，只作用于 Cookie 所属账号；本地登录开关不会被改密改变。状态和写入端点均 no-store，敏感字段不进入查询缓存、长期状态或日志。

## 用户组配置与默认域名

### v0.28.0 用户组配置共享版本

分支实现为 `user_group` 增加可空 `default_domain_id`，仅 builtin `user`／`admin` 可配置；与权限共享原 `updated_at`。默认域名新端点不扩充旧严格七字段组 DTO，旧权限请求也不写默认字段。默认写需要当前数据库的 `admin:access`＋`domain:manage`，旧权限写仍只需要原 `admin:access`；两个写事务都在等待锁后重查当前有效账号、builtin admin 组及权限，不能信旧会话中的组标识。

5 秒写入按 domain advisory 共享→当前账号共享→当前 builtin admin 组排他→目标组排他取锁，避免锁升级和组／域名反序；目标 admin 复用已锁行。默认写当前同值 no-op、陈旧同值冲突，旧权限同集合保存仍推进版本。域名删除在排他域名事务中清组默认，先锁 admin 再锁引用组，并记录独立 `default_domain_id` 字段审计；成员迁移和旧会话撤销契约保持。

管理页每组两个独立草稿共享版本，有一个脏草稿时互锁另一区域，写入期间禁重复及切组。后台新版本只标陈旧并保留原草稿；显式取消／重载才放弃对应草稿，刷新失败停写。查询和异步结果按账号＋登录 epoch 隔离，旧身份或卸载后的保存不发布新账号状态。边界与阶段分别见[设计](2026-10-27-v0.28.0-group-default-domain-design.md)及[验收](../implementation/v0.28.0-acceptance.md)，未增加自定义组、多组或批量能力。

## 外部登录扩展

v0.7.0 将登录方式扩展为：

- 一个或多个 OIDC 提供商登录。
- 其他后续可扩展的外部认证方式。

OIDC 不是一个简单的「启用 / 禁用 OIDC 登录」开关，而是一组可管理的身份提供商配置。v0.7.0 支持多个提供商的启用状态、显示名称、Issuer、客户端信息、固定回调地址和精确邮箱域名策略；作用域固定为标准身份声明，首次供应固定进入 `user`。图标、自定义声明映射和可选默认用户组仍属于后续范围。

配置 OIDC 提供商时，系统后续可以提供预置模板，帮助管理员快速填写常见平台参数。v0.7.0 使用标准 Discovery，不实现提供商模板。

v0.31.0 已将模板收敛为新建草稿的手动／Google／Entra UUID 单租户三种本地辅助，当前仅设计、尚未实现。明确应用才替换，脏草稿先确认并清旧凭据，不自动 Discovery／保存／启用；编辑现有身份命名空间不受模板影响。边界见[设计](2026-10-28-v0.31.0-oidc-provider-templates-design.md)，实际阶段见[验收](../implementation/v0.31.0-acceptance.md)。

## 首次初始化流程

自托管部署首次启动时，如果系统不存在管理员账号，应进入初始化流程。初始化完成前，普通登录、短链创建和管理后台应不可用。

初始化内容至少包括：

- 注册第一个用户，该用户加入内置 `admin` 用户组。
- 设置站点名称。
- 配置默认系统访问域名或确认当前访问域名。
- 配置默认短链访问域名。
- 选择默认语言。
- 写入固定内置权限模型。

初始化完成后，第一个用户默认属于 `admin` 用户组，并拥有系统最高管理权限。系统应同时创建内置 `guest`、`user`、`admin` 用户组，以及不可登录、不可删除的内置 `guest` 用户。

v0.0.1 初始化流程使用固定内置权限模型，不提供权限模型选择器。默认模型为：`guest` 用户组不能创建短链；`user` 用户组可以创建和管理自己的短链，并使用默认短链访问域名；`admin` 用户组拥有 v0.0.1 全部管理权限。

系统应禁止重复执行初始化流程，除非管理员通过明确的维护机制重置系统状态。
