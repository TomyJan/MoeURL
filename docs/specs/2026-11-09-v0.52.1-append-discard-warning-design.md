# v0.52.1 放弃重试风险提示设计

状态：设计已收敛，尚未实现与验证；见[范围](../product/scope-v0.52.1.md)、[计划](../implementation/v0.52.1-plan.md)和[验收](../implementation/v0.52.1-acceptance.md)。执行者自主选择小幅呈现维护，不把自主决定写作用户逐项批准。沿用 Vue3、Vuetify4、现有 controller 和测试工具，无新依赖。

## 意图和选择

v0.52.0 独立终审的两项 Minor 在原版延期。手机上确认放弃时，原编辑正文较长，新警示在下方，而放弃按钮已可点。原正文可滚动、默认焦点安全，因此原版未认定不可操作；此次维护让用户作出丢弃唯一内存重试入口的决定前，更容易看清后果。

比较三种方案：scrollIntoView 需要处理异步代际与焦点互相滚动；在滚动区外固定警示可能挤压窄矮视口；独立确认正文只显示当前决策所需信息，且重新挂载从顶部开始。选择独立正文，不引入滚动回调或计时器。

## 唯一呈现与状态边界

`BatchNoteAppendDialog.vue` 的 `discardRequested` 为真时，以独立 keyed `v-card-text` 展示原 `discardWarning` 以及原 `requestId`，后者保留可读的操作编号。非确认分支保留原编辑／预览／unknown 内容，确认期间不同时渲染编辑器与旧预览。两分支切换只销毁呈现，不修改 controller 内的草稿或冻结请求；不向 API 读取旧正文。

底部“保留”“放弃”按钮和既有受守卫回调不变，默认焦点继续在“保留”。点击保留恢复原未知结果视图，同一正文、双版本、requestId 仍可人工重试。点击放弃仅退休本地上下文，不声称撤销已经提交的服务端操作，不发取消请求。关闭、撤权、身份退休和卸载仍由原 controller 管理，呈现不得令退休状态复活。

复用原中英风险说明、操作编号文案、私密文本及 anywhere 换行规则。320×568 和390×844手机、桌面键盘路径须实际核警示、编号和动作与视口／滚动区的交集与命中区域，不以 DOM 可见代替首屏可见。超出这些有限布局、实机浏览器和读屏器不作验证承诺。
