# v0.60.0 可搜索账号显示时区设计

## 意图与兼容边界

从 v0.36.0 的九项显示偏好扩展为有版本的可搜索目录。范围由 Agent 在持续自主授权下选择；技术栈、Cookie 身份、CAS 和现有偏好协调器沿用，不代表用户逐项指定选项。正式基线为 PR304 已核 master a371588c8c2a43ebeedab1e8d9b7a4064891e0c6，详见[范围](../product/scope-v0.60.0.md)。

## 固定目录与来源

`internal/user/time_zone_catalog_v0600.json` 是唯一的 v0.60.0 目录源，包含 419 个唯一、排序、非空的标识：本机已有 Node v26.3.0／ICU 78.3／tzdata 2026b 的 Intl.supportedValuesOf('timeZone') 返回 418 项，加 UTC。目录一经交付即冻结，未来扩展创建新的版本文件，不覆盖原件。

这是一组受支持的 Intl 标识，不是全部 IANA 字符串。例如当前目录列 Asia/Katmandu，Intl 可识别的别名 Asia/Kathmandu 不在其中。本版只接受目录成员，不做猜测或自动别名替换；九个历史保存值均为目录成员。不能按运行时的 supportedValuesOf 动态扩大服务端合法集合。

Go 在启动时 embed 并解析这一文件为只读成员集合，异常目录安全拒绝启动；前端直接导入同一 JSON，不复制第二份手写枚举。解析校验拒绝非数组、空标识、重复值、无序值及缺失旧兼容值。服务端只校验成员，不用 time.LoadLocation 读取服务器文件或依赖 tzdata。前端的 Intl 不支持回退机制保留。

## 存储与迁移

新增 `migrations/00038_expand_time_zone_catalog.sql`，替换 user_time_zone_preference 上原九项 CHECK，不重写旧行、updated_at 或其他偏好。列和 SQLC 查询接口不变，null 仍合法。

`scripts/generate-time-zone-catalog.mjs` 只消费冻结的 v0600 JSON，机械生成这一迁移；支持 --check 只核字节，普通生成仅创建缺失文件或接受完全相同内容，遇不同既有文件拒绝覆盖。未来目录使用新文件及新迁移，不让生成器改写历史迁移。测试实际运行入口并验证输出／退出及拒绝覆盖行为，不以查源码代替测试。

Down 先在同一事务内锁表并确认全部非 null 值属于旧九项；如存在新值，明确失败，保留行与版本，不能悄悄清空或映射值。兼容时恢复旧 CHECK，Up／Down／Up 均保持账号和偏好值、版本不变。真正回退到旧应用前需用户显式改回兼容值，这是安全失败边界，不提供自动数据修改。

原 API 路径、严格两个字段、媒体类型、无缓存、当前身份、锁序、五秒事务、首次／后继 CAS、错误码和脱敏规则保持。SQLC schema 输入变更走锁定 1.30 标准生成和完整集合零漂移，不手改生成物。

## 搜索、编辑与显示

将现有独立面板的 v-select 换成受控 Vuetify 搜索选择。items 为跟随设备加固定目录；旧九项继续用已有双语标题，其余使用准确 IANA 标识。按可见标题及标识进行大小写不敏感搜索；匹配仅影响列表，提交仍要求精确目录值。未选中的搜索词不能被当作时区发送或清空原草稿；无匹配有本地化提示，键盘可选并退出，长标识在窄屏完整可读。

原始快照与搜索状态分离。后台重取不覆盖脏草稿；保存以原版本显式发一次请求，冲突成功重载后才替换草稿。成功、失败、finally、查询缓存和搜索清理都受同步身份 epoch／挂载状态保护。退出或新登录轮次立即回设备显示。无权限或加载前不能写，不自动重试写入。

选择仅改变七处现有控制台 instant 显示；不改变 datetime 属性、排序键、UTC 统计桶、range、CSV、游标、CAS、datetime-local 到期输入、服务端判断或公开页面。浏览器不能格式化某个已保存目录值时沿用设备回退及警告，不修改保存值；不以固定偏移伪造 DST。
