# v0.90.0 导出清单恢复设计

## 1. 意图与范围选择

让用户在数据库记录丢失、迁移到新实例或误删后，使用此前下载的 MoeURL 管理清单重建短链，而不把现有的单列网址导入、手动字段映射或所选 CSV 导出称为恢复。导入文件在浏览器本地读取并预览；确认后服务端将整批创建为当前登录账号的新短链。

这是从清单重放可重建配置，不是数据库备份／还原。新记录获得新 ID、创建／更新时间和零访问用量，全部归当前账号；不恢复原所有者、审计、统计事件或访问次数。不得更新、删除、复活软删除记录或重用已占用短码。文件里启用密码的任何行都整体拒绝，因为导出从不包含原密码。

由 Agent 依据路线图与现有导出／导入合同自主选择以下取舍：只接收 MoeURL 当前固定 17 列清单，不猜测外部表格表头；每次最多 100 行且全批原子提交；保留可解析的短码、目标 URL、标题、标签、状态和已配置访问方式／过期／访问上限。域名只能按清单公开短链的 host 精确匹配当前启用且调用方获准使用的域名，不做默认域名替换。管理员清单也只创建到当前调用者名下，不保留或模拟原归属。

## 2. 输入文件

- 只接受 v0.21.0 管理清单导出的精确表头、顺序和 17 列；支持一个开头 UTF-8 BOM、严格 UTF-8、标准 CSV 双引号与 CRLF／LF。拒绝未知、缺失、重复表头、重复列、额外字段、非矩形记录、裸 CR、无数据行和超过 100 行。源文件上限 8 MiB；最终 JSON 请求另行限制为 1 MiB。
- 表头为：

  ```text
  id,short_url,slug,target_url,title,tags,status,redirect_mode,intermediate_delay_seconds,expires_at,password_enabled,max_visits,visits_used,created_at,updated_at,owner_id,owner_username
  ```

- 所有 17 列均按导出协议严格验证；`id`、`owner_id`、`owner_username`、`created_at`、`updated_at`、`visits_used` 只用于确认输入结构与展示损失说明，不作为创建身份、归属、时间或用量写入。`short_url` 必须是无用户信息、查询和片段的 HTTP(S) URL，路径恰为 `/<slug>`；路径短码与同一行 `slug` 精确一致。URL origin 与当前启用域名的规范根 origin 精确匹配，分别验证 origin 与 slug，不混用两者。
- `password_enabled=true`、非法短码／URL／标签／状态／跳转字段、过期时间非规范格式、有限访问次数格式错误、域名无法精确解析或请求预算超限都会拒绝整个文件／请求；不得跳过坏行或生成部分恢复结果。
- CSV 公式防护属于现有导出协议。导入按 CSV 中实际序列化文本处理，不自动剥除前导单引号；标题／标签因此可能保留导出时用于防公式的前缀。UI 在预览和确认前明确说明不承诺原始文本逐字节往返，避免猜测性“反转”改变真实用户内容。

## 3. 创建语义与授权

- 新增仅个人路径 `POST /api/v1/short-link/manifest/restore`。请求包含规范非零 `requestId` 和 1–100 条严格结构化记录，不接受客户端提供的 ID、owner、用量、时间戳、权限、域名 ID 或 `password_enabled`。完整请求体 UTF-8 JSON 不超过 1 MiB；拒绝重复／未知键、非规范 UUID、重复 slug、非规范 UTF-8／代理项和尾随 JSON 值。
- 官方客户端附带 `X-MoeURL-Expected-User-ID`；Cookie 是唯一 actor 权威，绑定头只拒绝换号后的迟到意图。body-only API 客户端按 Cookie 当前本人语义处理。无写入／建链权限返回 `120001`。
- 只创建当前 actor 所有的记录。使用既有建链、字段、域名权限，不新增权限：创建本人短链；原短码需 `short_link:custom_slug`；标题／标签、跳转方式、中间页、过期和访问上限分别按当前权限目录校验；目标域名须满足现有默认／分配域名使用权限和组授权，origin 等于当前默认域名时按 `domain:use_default` 判定，否则按 `domain:use_assigned` 判定。所有权限、账号有效性、目标域名和短码唯一性在同一事务中重查。后端不信任前端权限快照。
- 一个 5 秒数据库事务处理整批：沿用建链路径的目标安全策略与账号每日创建配额，先完整规范与权限／冲突预检，再写入链接和既有创建审计；任一错误零记录写入。保留状态，因导入状态为 disabled 的行需要 `short_link:update_own`；不可用／不匹配的域名、已被活动或软删除资源占用的 slug、无权限字段、目标策略拒绝或配额不足均整批拒绝，不自动改码或回退到随机码。
- `requestId` 按现有不确定结果／同 key 同 payload 重试合同工作；同 key 不同内容拒绝。服务端事务最多 5 秒；官方客户端包含响应读取的 15 秒 deadline。成功响应只返回新建数量和不含目标 URL 的结果标识，不回显整批数据；响应 `no-store`。基础设施错误沿用安全日志分类，不写请求正文或短链目标。
- `visits_used` 不写入，恢复后的用量从 0 开始；原短链事件／趋势不会创建或回填。有限 `max_visits` 保持原上限，因此需显著提示恢复后可再次使用完整额度。这一语义是显式重建取舍，不称统计或限额连续性。

## 4. 前端交互与生命周期

- 在现有批量 CSV 创建区增加独立“恢复管理清单”入口，不替代当前网址导入、手动列映射、预览／确认或请求协议。恢复清单在独立面板解析；不在选择文件时自动提交，不把 17 列静默投影到普通 CSV 导入。
- 本地预览显示有效记录数量、源域名数量以及归属为当前账号、访问量重置、密码行不可恢复、公式前缀不反转等固定影响说明；不显示密码、访问事件或无关账号资料。预览只验证文件结构、字段格式和跨列一致性，不声称已确认实时账号权限、域名授权或短码可用性。若整体输入无效，只显示安全的行号和字段类别，不输出目标 URL／整行原文。
- 确认操作需要用户明确接受“创建新链接、不会修改现有数据、用量重置”的摘要。仅本地验证成功后发送一次原子请求；服务端在该单次事务内检查实时账号／权限／域名／短码冲突，任一失败整批不写入，并返回明确业务错误；不增加预检／dry-run API，以避免预检与提交间状态漂移及重复读取。服务端超时／结果未知必须保留同一 requestId 和完全相同 payload，仅用户显式重试；内容变化必须新建 requestId。明确业务错误保留原文件草稿并允许用户修正。
- 复用现有 File 读取、身份 generation、权限 epoch、草稿 revision、卸载和迟到结果守卫；每次开始读取、确认或重试都绑定当时 actor。换号、权限撤销、关闭、选新文件或组件卸载后，旧读取／请求的 success、catch 和 finally 不得替换草稿、下载或覆盖新反馈。
- 新增文案使用 vue-i18n，中英桌面和窄屏均可用；路径名、文件名和 CSV 单元格均按纯文本渲染，不使用 HTML。

## 5. 非目标与保护边界

- 不实现 SQL／数据库／实例配置备份，不恢复原 UUID、owner、创建时间、统计事件、访问用量或密码；不执行覆盖更新、软删除复活、slug 释放／复用、部分成功、自动改码、跨账号归属恢复、域名映射、XLSX、后台作业、跨页选择或任意 CSV 自动匹配。
- 不改变原 `/api/v1/short-link/export` 与 `/api/v1/admin/short-link/export` 字段、顺序、8 MiB 预算和访问权限；既有 targets／mapped CSV 导入保持兼容且语义独立。
- 不新增依赖；除新恢复 API 外不扩展公共读取／导出 API，不改访问统计或公开短链行为。若现有 SQLC 查询或交易能力无法在一次事务中满足全批授权、域名和唯一性原子预检，实施计划应把相关后端工作明确列出，不用逐行 API 拼装或声称原子性。

## 6. 验证与交付标准

- 解析测试按真实 exporter 输出覆盖精确 17 列、BOM／UTF-8／CSV 引号／换行、0／1／100／101 行、8 MiB 和 1 MiB JSON 边界、错表头／宽度／域名与 slug 不符、密码开启、公式前缀保留、非法枚举和全部字段格式；失败时不得产生请求。
- 后端真实 PostgreSQL 与 handler 验证 Cookie actor、请求头换号拒绝、各 field／domain permission 交集、禁用／软删除账号、域名关停／撤权、slug 活动／软删除冲突、100 条原子成功、任意行冲突／无效／撤权导致零写入、禁用链接、幂等同 payload 与异 payload、失败回滚及审计一致；迁移（若新增）验证 Up／Down／Up 和现存权限保留。
- 前端真实 QueryClient／File 读取与页面验证草稿保持、同文件重选、身份／权限轮次、撤权后恢复、关闭／换文件／卸载、迟到 success／error／finally、未知结果同 key 重试、重复点击保护、中英与手机可达性。
- 完成完整 Go 和前端本地门禁、业务及前端覆盖率合同、静态检查／构建、准确产品 smoke／所选扫描和真实中英文桌面／手机浏览器；复用准确依赖输入的已有证据时逐项冻结 SHA／bytes／运行时，不冒称本版重跑。真实 CodeRabbit 必须覆盖最终候选 head；正常合并后独立核验 API 与 fetch 的 SHA、tree、唯一父；最后 whole-owned 可恢复归档且逐项解压验 hash。禁止查或等 CI、安装依赖、发布／部署或触碰 PR #240／#266／#267。
