# v0.53.0 账号默认每页条数设计

状态：后端与前端实现及当前本地门禁已核验；真实浏览器、准确产品和审查交付尚待。v0.52.1 已完整交付，本版从已独立核实的 master `82355d63e2b7111912ac2d5eb6b067a3e1c14b5a` 启动。见[范围](../product/scope-v0.53.0.md)、[计划](../implementation/v0.53.0-plan.md)。

## 目标与范围

个人设置新增独立“默认每页条数”：沿用默认（20）、20、50、100。显式保存到本人账号，跨浏览器和重新登录保留。仅为“我的短链”和“全站短链”的页面首次加载提供初选，不改变列表权限、最多 100 条单页选择、批量命令、私密备注和全匹配 CSV。

列表内切换只是当前页面临时选择，不自动保存账号偏好。本人和管理员列表共用一个账号默认；不增加管理员代改、访客偏好、其他表格偏好、URL 参数或浏览器持久存储。

## 方案选择

1. 只存浏览器：简单，但不能满足账号跨设备保留，排除。
2. 扩旧通用偏好 DTO：接口较少，但会改变语言／主题等已有严格协议及版本竞争边界，排除。
3. 独立本人资源、独立 CAS、共用小型读取层：沿用默认跳转方式的既有模式，选择此方案。

列表初选考虑过“先 20、响应后随时改成偏好”，会造成二次请求、清空选择或打断确认，因此不采用。选择有界的首次准备：优先使用当前登录轮次已读值，否则最多等待 3 秒；成功使用保存值，失败或超时使用 20。初始化完成后，任何晚到结果、窗口聚焦、偏好保存、缓存失效都不再改变已打开列表的条数。

## 独立资源

- GET `/api/v1/user/list-preference`。
- POST `/api/v1/user/list-preference/update`。
- 严格响应 `{ preference: { pageSize: null | 20 | 50 | 100, updatedAt: null | string } }`。
- 严格更新 `{ pageSize: null | 20 | 50 | 100, expectedUpdatedAt: null | string }`，两个字段必须显式出现。
- 首次未保存为两个 null；清除已保存值保留真实版本，不删除行伪造首次状态。
- 严格整数，不接受字符串、其他数字、缺字段、重复字段、未知字段、尾随 JSON、过大请求。沿用现有 8 KiB 限制和完整精度版本解析；有效但不能精确匹配的纳秒版本必须冲突，不截断为微秒。
- 目标只取 Cookie 当前本人；`X-MoeURL-Expected-User-ID` 只作身份前提，不能指定其他资源。guest、非有效账号、当前不合法用户组拒绝。无新权限常量，不把偏好当授权。
- GET／POST 均 no-store，不写私密业务日志，不扩 auth/me 或旧偏好响应。

新 Goose migration `00037_user_list_preference.sql`（启动前已实核最新编号 00036）创建 `user_list_preference`：user_id 主键／账号 FK，nullable smallint page_size CHECK IN (20,50,100)，非空 updated_at。Down 只删除本版偏好资源，不改短链／审计／回执；必须明确记录这是有意丢弃本版偏好数据的回退边界。

SQLC 使用标准生成入口并检查零漂移。写事务按账号 FOR SHARE → 当前用户组 FOR SHARE → 偏好 CAS 的锁序，5 秒截止；核当前数据库状态，不信任旧 session 组。首次并发保存唯一赢家，已有行按完整版本更新，时间至少递增 1 微秒。冲突保留草稿，用户显式重新加载，无自动重试写入。具体业务错误码沿用或分配前先检查目录，不能凭空与旧码冲突。

## 前端与首次读取

独立 entity／query／editor／panel，不修改旧语言、主题、时区或跳转偏好草稿及 CAS。个人设置有加载、失败重试、未保存、保存中、成功、冲突、撤权和身份退休状态；选择不会立即写，清除也须明确保存。

缓存键含 userId 和 login epoch，所有异步 success／error／finally 均核 mounted、当前身份及操作代次；草稿修订防止旧加载覆盖输入。发送前重核在线和身份；保存成功取消旧读取后发布权威值，旧 GET 不能覆盖保存结果。

每个列表实例为当前 identity 建立一次初始化状态：

- 未完成前暂不发短链列表请求，显示现有加载状态；筛选仍可输入，首次请求使用当时筛选。
- 当前身份已有有效偏好立即就绪；否则等待成功、失败或 3 秒截止。null 使用 20。
- 用户主动选择条数即立即就绪并锁定该值，后来的偏好不能改写；手动操作不写偏好。
- 超时／失败只使本次列表使用 20，不伪称偏好保存值为 20；偏好编辑器仍能显示真实错误和手动读取。
- 查询关闭重试、聚焦重读；作用域退休、卸载时取消本消费者的定时器和回调。共享查询不能因为一个消费者退出就取消其他消费者仍需要的请求。
- `apiGet` 目前没有 signal 参数。正式实现如需取消 GET，只在末尾增加可选 AbortSignal 并透传 getJson/fetch，保留既有 headers 第二参数；测试默认请求不变及明确取消。首次超时的状态转移仍须独立成立，不能仅依赖 fetch 响应取消保证。
- 初始化后不再自动应用偏好，即使同账号在个人设置另存或浏览器恢复焦点；重新进入列表才应用当前默认。
- 身份变化同步清掉旧值、选择和私密筛选，开始新轮次；权限恢复重新初始化。撤权时隐藏数据，不能用偏好完成绕过现有 read 检查。
