# Go 安全补丁维护设计

## 取舍

沿用主机 Go 1.26 与生产 Go 1.27 两个既有分支，分别更新至官方修复版 1.26.11 与 1.27.4，避免同时提高语言基线或引入新的运行时分支。Docker web-build／go-build 两阶段保持一致。原前端与依赖、Go 生产源码、生成物及迁移不变；不把配置维护包装成业务功能。

源码扫描使用新主机工具链及已缓存 govulncheck 源码，保留 scanner 自报版本和数据库时间。完整解析所有记录及命中公告，单独判断 GO-2026-6859 是否消失；未命中该公告不自动推出其他漏洞不存在。原 required-only OpenPGP 风险独立记录，不能借补丁宣称所有模块安全。

## 实施与容量

官方元数据已实际确认两个稳定版本、文件大小与 SHA-256。归档只下载到本版准确目录，先核大小和哈希再安全解压；文件成员不得越界。解压后核实际 `go version`，消费完压缩包立即删除，保留官方元数据、归档哈希及恢复获取路径。采用进程级 GOROOT／GOTOOLCHAIN，容器源码只读，私有编译缓存用完即清理。既有运行时更新已获用户授权，不把它算作新增第三方依赖。

不添加仅断言版本字符串的永久测试。配置安全缺口由原准确工具链的扫描原件及本轮旧二进制 build info 证明，补丁后由新工具链扫描和真实产物证明；称配置安全验证，不伪造新的产品行为 RED。业务测试保持原断言和覆盖率标准。

Linux 原完整 race 及 10 次窄诊断均复现授权测试失败；诊断中授权创建时间比先写入的密码修订早 571610 微秒，而授权仍未过期，证明测试依赖的时钟先后关系失效。只修该测试数据：初始密码修订固定在过去，最后修订严格晚于数据库内授权创建时间 1 微秒；生产查询、权限及令牌逻辑不改。原失败、精确测试差异和补验分别归属，未变包及主机完整原件复用，受影响 Linux 包重验并补 vet、主机更新测试窄验。

## 兼容与证据

Task1 产出完整主机 Go 回归、业务 100%、vet、固定 Linux runtime 的完整 race 及源扫描合同。Task2 消费准确提交及新 runtime，重新生成 build metadata 对应的产品，执行 smoke、所选扫描和八个后缀场景加 setup；不把原 347 项浏览器结果写作本次重跑，前端完整 5080 项仅在完整输入相同后复用。

Task3 消费前两合同，唯一全新整分支独立审查后，最终 head 须真实 CodeRabbit reviewed／source=covered=head、success、无 running、有效 open0。正常 exact-head squash 后独立 API／fetch 核相同 tree 与唯一父。完整裁决和延期项随 whole-owned ZIP 全解压逐哈希核验，准确 leaf 可恢复迁出，用完 extract 删除；不删分支或工作区。

ROOT-M1 的路线图旧阶段句、CR-M1 的 28 条量词在当前 tracked 文档窄改，16 条误报保持原解释；旧独立报告、扫描失败和已封存原件不改。
