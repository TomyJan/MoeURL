# v0.41.0 我的标签设计

## 意图与取舍

现有标签保存在每条短链的 `text[]`，没有独立目录。用户必须记住标签名才能使用已有精确筛选。本版在我的短链内提供只读查找，不改变标签的数据模型和编辑流程。

三个选择：只从当前列表提取标签成本最低，但遗漏其他页；建立独立标签表可支持集中治理，但需要迁移、共享归属及写操作；按本人完整管理资源聚合能解决查找问题且不增加 schema。采用第三项是 Agent 的自主决定，依据既定持续开发授权，不代表用户指定过具体界面。

## 后端契约

新增 `GET /api/v1/short-link/tags`，独立 `TagCatalogPort`／handler，不扩已有 `Port`。挂在既有 CurrentUser 和 `NoStore` 业务路由中，由 App 注入原 shortlink Service。无新顶层前端路由或保留短码。

唯一可选参数 `q`。不接受客户端 owner、limit、状态、页码或 admin 范围；重复、未知、缺 `=`、畸形 URL 编码均 `100001`。`q` 先验证原始 UTF-8 与控制字符，再按 Go `strings.TrimSpace` 去空白；最多 32 个 Unicode 码点，可为空。搜索为 `strpos(tag,q)>0` 的大小写敏感字面子串，不解释通配符或做 Unicode 规范化。

成功 data 为 `{items:[{tag:string,linkCount:number}],hasMore:boolean}`；空 items 必须为 `[]`。每个 tag 沿用现有规范，linkCount 为引用它的本人未软删除短链数。聚合含所有管理状态，不叠加列表的关键词或状态，界面明确说明，因此点击后列表可以为空。返回数量最多 50，按 `linkCount DESC, tag COLLATE "C" ASC` 排序，查询 51 项判定 hasMore，不返回总标签数或完整短链信息。

Service 提前授权并设置 5 秒总超时；SQLC 单条只读语句在同一快照内再次确认 actor 当前未删除、active、组非 guest、数据库当前权限含 `short_link:read_own`，再限定 `short_link.owner_id=actor.id AND deleted_at IS NULL` 聚合。当前用户组名称不替代权限；管理员无全站例外。使用 `COUNT(DISTINCT link.id)` 避免存量重复数组元素放大计数。

语句保留授权 sentinel，即无标签时仍能区分“允许的空集合”和“无权限”。入口授权后被撤权、禁用、软删除、改组或转移的结果以该语句快照为准；完成后的并发变化不追溯撤销在途读取。稳定业务错误 HTTP 200：非法输入 `100001`，无权限 `120001`；基础设施 HTTP 500／`900000`，日志不带搜索正文、标签或数据库错误细节。所有响应 no-store；无写入或审计，无新 migration。

## 前端契约

独立 `PersonalTagBrowser.vue` 嵌入 MyLinksPage 的筛选区之后，默认折叠，展开才挂载查询内容；原列表和批量操作不等待目录。目录不是新导航或全站功能。

标题“我的标签 / My tags”，说明“统计你所有未删除短链，不受当前列表筛选影响”。搜索与原精确标签输入独立，按 250ms 防抖；原始控制字符和超过 32 码点时显示错误且不请求，搜索结果不能用旧关键词数据填补。每项是可键盘操作的按钮，纯文本标签及数量、长标签 anywhere 换行；点击只发 `select(tag)`，父组件修改现有 tagFilter，保留关键词和状态，并由原筛选机制清空批量选择。

目录只读要求 `access.canRead`；使用既有身份 scope 的 userId＋epoch，查询键归属于 `['short-link', 'tag-catalog', ...]` 以消费原创建、更新、删除、批量整理的族失效。每次打开实际重新读取，旧缓存不作为本次授权证据。关闭卸载，数据不持久化；账号／权限代际变化同步清搜索、折叠并丢弃旧状态，旧 promise 不得在 A→B→A 后显示。读取中、错误、失效和权限未知时不显示旧标签或旧数量；成功回到合法当前身份才显示。

区分加载、无标签、搜索无结果、可重试错误、非法搜索及 hasMore 提示。失败和重试不修改既有列表筛选，重试必须读取当前账号与当前有效搜索，不自动写入或重放业务请求。无新依赖、全局 query 策略、HTML、URL、公开预览字段或计数缓存表。
