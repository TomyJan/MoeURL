# v0.61.1 手机访问配置布局设计

## 意图和根因

访问配置在窄英文屏上须完整显示三种跳转模式，并允许键盘保存或取消。原手机规则只把外层 mode 容器改成列，Vuetify 内层按钮组仍保持固定高度、不换行；英文 390px 实测卡片 clientWidth 340、scrollWidth 405，320px 时 clientWidth 270。创建面板已有按钮组换行的同类方案。

## 最小方案

ROOT 选择复用该布局方式：在 `ShortLinkSettingsDialog.vue` 的现有 480px 媒体查询内，为 `.short-link-settings-dialog__mode :deep(.v-btn-toggle)` 设置 `flex-wrap: wrap`、`height: auto`、`max-width: 100%`，其直接 `.v-btn` 子项 `min-height: 44px`。不预先添加其他 grid 或宽度规则；只有真实几何仍失败时才评估最小补充。

不改模板、脚本、按钮顺序、ARIA、字号或文本。模式切换、权限降级、pending 和 emit 继续由原代码负责，浏览器测试通过真实服务验证 payload 与持久化。

## 验证设计

原设计探针只在旧产品看到英文两宽度、两入口共四项裁剪失败；独立样式注入实验恢复四项。这些是设计观察，不是源码 GREEN 或正式新产品证据。

正式测试不注入样式。八个场景使用独立账号、短链和浏览器 context，英文 320px 高度 568px，其余 900px。测量卡片 scroll/client 宽、按钮边界、文字 Range 边界及手机 44px 高度；短屏操作先聚焦、检查焦点与可见矩形，再 Enter。英文浅色、中文深色、桌面为对照。确认保存后重开，取消中间页和直接模式，再读服务端，断言只有一次更新。

原组件单测负责权限不足、失权降级 direct、pending 锁定和字段保留；完整前端回归保持四项 100% 与原阈值。后端全集路径／bytes／hash 相同则复用前版，不重跑 Go 或 SQLC。准确产品单独记录构建身份、smoke／扫描、浏览器和 ROOT 原图；不以全页无横向滚动代替内部检查。

## 风险和资源

换行占用纵向空间，因此 320×568 必须检查保存／取消可达；桌面媒体查询不命中，仍做真实对照。避免隐藏内容、缩字体或增加页面 overflow 掩盖问题。

使用现有锁定依赖、隔离数据库及精确 Docker image。单版本 4 GiB、两处项目临时总计 12 GiB；大操作先检查和预留，仅失败保留 trace，用后主动清理精确归属的可重建副本，保留日志、必要原图、合同及可恢复报告。不新增依赖、API、迁移、权限或部署行为。
