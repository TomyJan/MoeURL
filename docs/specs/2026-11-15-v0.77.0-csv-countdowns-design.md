# v0.77.0 CSV 中间页倒计时导入设计

## 决策与协议

沿现有 linked worktree 内联实现 Go／Chi／SQLC／PostgreSQL 与 Vue／TanStack Query／i18n。按持续自主授权收敛本版；不派 builder 或逐任务审查，仅版末唯一 fresh 最强独立终审。本设计由 Agent 作出；范围与非目标见[scope](../product/scope-v0.77.0.md)。

新增 `BatchCreateCountdownItem`、`BatchCreateWithCountdownsInput` 与 `BatchCreateWithCountdowns`，保留八个原文字段。独立 strict handler 逐 token 检查外层两键及项八键，继承 64 KiB、20 行、UTF-8／surrogate、非 null tags、未知／重复键及尾随 JSON 守卫。所有字段必须显式存在；无效请求不调用业务写入。

`parseBulkCountdown(value, mode string) (int16,error)`：空值返回 5；非空仅 `mode == "intermediate"` 且值逐字等于 `3`…`10` 时有效。不能依赖宽松整数解析。不修改原文字段；`normalizeBulkCreateWithCountdowns` 先复用原有七个字段的验证，再计算 `SHA256("moeurl:bulk-create:countdowns:v1:" + Go JSON 原始有序 items)`。空延迟也不降级旧协议；旧七种摘要完全不动。

## 共享事务与兼容

prepared `batchCreateItem` 增 `IntermediateDelaySeconds int16`，options 增 `Countdowns bool`。只有八列入口同时启用 Metadata、CustomSlugs、RedirectModes、Expirations、VisitLimits、Countdowns。新入口传严格秒数；共享写入在旧 flags 下明确选择 5，防止旧 DTO 零值写入 0。`CreateBulkShortLink` 中固定 5 换成 SQLC int16 参数；标准锁定 1.30.0 生成两次，第二次完整生成集合 path/bytes/hash 不变，不手改生成物。

沿现有锁序检查账号、组、域名 gate、目标规则和配额，当前授权先于回执。实际模式与非空 expiry/cap 分别检查原权限，倒计时不另增权限。命中同摘要只返回原 requestId/count，不读取再写旧短链；原倒计时被后续修改、访问耗尽或过期不影响授权回执恢复。不同内容或任意新旧协议同 actor/key 冲突 200120。四类业务存储失败整批零写入，提交失败仍保留既有结果未知语义。

公开 direct／intermediate／confirmation 行为、`/{slug}` 和 `/go/{slug}` 优先级、预览字段及最终跳转统计不变。不承诺服务端必须等够秒数，倒计时是既有浏览器访问体验。

## 前端输入与生命周期

entity 增 strict 八字段 schema、`BulkCreateCountdownItem`／`BulkCreateCountdownsInput`、独立 client 和 `countdowns` protocol。parser 精确识别第八列表头并保存原文；旧一列 consumer 不接受八列，旧七份模板逐字保持。CSV 与完整 payload 分别测量 UTF-8 65536 字节，替换草稿前必须都通过。第八份模板使用 3、10、空默认 5；八列预览显示真实秒数，旧协议仍显示默认 5，不出现矛盾帮助。

`useBulkCreate` 的八列模式接入所有原 metadata/custom-slug/mode/expiration/visit-limit 内容依赖和 epoch，不只切换 mutation 端点。异步 File 读取捕获身份、generation、草稿和权限轮次；只退休实际依赖已撤权限的内容，空 cap/expiry、手动替代草稿不误清。恢复权限不能让旧文件复活。提交冻结原始 items/tags 和 UUID；未知结果只能原端点／原 payload 重试，后来明确拒绝也不抹掉首次可能已提交的事实。success/error/finally 都受当前身份及请求轮次守卫。
