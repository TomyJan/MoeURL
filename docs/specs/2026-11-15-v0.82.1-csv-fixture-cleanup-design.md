# v0.82.1 CSV 测试初始化清理设计

## 根因与选择

`v0.82.0-csv-issues.spec.ts` 先创建临时 admin，再创建浏览器 context。旧 finally 将账号禁用包在 `context && user` 中，因此 `newContext` 失败后账号仍启用，直到外层独占 Compose teardown 销毁数据库。PR365 的成功运行没有实际遗留，但该失败路径需要收紧。

Agent 选择把原 fixture 的生命周期移入测试专用 `web/e2e/csv-issues-fixture.ts`，spec 直接调用，最后只将禁用拆到独立 `if (user)`。单纯改条件最短，却无法直接运行该闭包的初始化失败路径；源码提取／字符串断言与通用资源框架都不采用。模块只有类型导入及 Node 标准库运行依赖，不进入产品 bundle、不新增包。

## 精确行为

`runCsvIssueScenario({ browser, page: manager }, use, info, adminCredentials, touchPages): Promise<void>` 保留原管理登录、随机账号创建、语言／视口、context、页面登录、runtime 附件及 `use({ page, user })` 顺序。使用原有密码常量的可抛弃测试账号，只存在独占测试库。

共享的 `csvIssuePost`、`csvIssueLinks`、`csvIssueAttach` 供 fixture 和 spec 消费，保留 HTTP 200／业务 code 0 校验和完整数据；类型、原字段和业务断言保持。`touchPages` 仍是 spec 独占的 WeakSet，手机操作继续 tap，桌面继续键盘。

所有权只有收到成功 create 的用户对象才登记。原错按原值加入 errors，包括 undefined／null／0；随后 context 存在时列出并逐个删除自有短链，user 存在时禁用，context 存在时关闭。每步捕获后继续；删除一个失败仍尝试其他已列短链。无错 resolve，有错抛一个 AggregateError，按原错、列表／各删除、禁用、关闭的顺序保留原对象，不 flatten 或字符串化。不在 finally 新增未经捕获的拒绝。

## 验证与归属

先移动原逻辑、不修条件，并加入 Node 行为测试，运行实际模块，以 context 创建的拒绝导致账号仍 active 证明 RED；不是缺失 import／类型错误。测试在回环随机端口启动自有 HTTP fixture，真实读写账号及短链状态；只有浏览器与外部 API 故障在边界受控注入。断言服务端账号 disabled、自有短链删除及实际文件句柄关闭，不能只断言替身调用次数。用 test finally 关闭服务与句柄并删除准确临时目录。

具名覆盖初始化失败及禁用失败、场景和多重清理失败、列表失败、逐项删除失败、禁用失败仍 close、无用户、正常路径及假值拒绝。GREEN 后运行完整 Node 脚本、lint 和九份 E2E strict。产品与 0.82.0 的完整投影守恒，原 6569 项／四项 100%、smoke 与所选扫描只按原执行身份复用；不冒本版重新执行。
