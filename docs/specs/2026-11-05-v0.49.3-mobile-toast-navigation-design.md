## 根因和方案

页面 Sonner fixed top-right 的 z-index 为 10000，手机 sticky header 为 15；旧测试使用 focus＋Enter 绕行，不能证明触摸可用。整体移到底部会挡分页，写死高度无法适配字体和菜单；单改 offset 仍有绝对定位长消息溢出。选择只在 body 目标且手机 header 实际可见时启用有界固定页面区域。

ConsoleTopbar 根加 `data-toast-page-header`，只测其自身和内部可见 `role=menu`。接受有限、与视口相交的实际矩形；排除隐藏祖先、inert、aria-hidden、无 client rect、离屏及 detached 节点。top 为最大 bottom＋8 px，不扫描其他业务菜单，不复制 900 px 断点。关闭中的菜单在实际退出动画结束后释放避让。

区域 right 16 px、padding 10 px 保护关闭按钮，border-box 宽 `min(376px, 100vw - 32px)`，最大高 `100dvh - top - 16px`；原生滚动。复用 modal 静态列表规则，仅新页面 class 启用。modal 仍为 30dvh；空 modal 脱流逻辑不扩展到页面。桌面／首页／无 header 恢复原 Sonner 定位。

## 职责与生命周期

新增 `usePageToastClearance(isPage: () => boolean, isActive: (element: HTMLElement) => boolean)`，返回 `{top: ShallowRef<number | null>, refresh: () => void}`。hook 只测量、订阅和清理，不拥有消息队列。AppToasts 在 syncTarget 后 refresh，复用现有 MutationObserver，不增加第二个。ResizeObserver 仅观察当前 header／菜单，替换时 unobserve；resize、capture scroll、transitionend 重新测量。只在数值变化时赋值，避免自身 style 造成反馈循环；不永久轮询或 requestAnimationFrame。卸载清监听和 observer，晚回调不写入。

原生 touch capture 扩展到新页面区域，保留已验证 pointercancel 处理。单实例／原节点迁移、六秒总生命周期、五条可见、焦点、安全文本不改。

唯一终审发现真实短 drawer 的非空通知会被纵向 flex 挤成细条，因此只在 ConsoleShell 的真实 drawer 直接子通知区域禁用 flex 收缩；仍保持 30dvh 上限和区域原生滚动，drawer 外层负责导航所需的整体滚动，其他 modal 的 flex 收缩不变。共享静态 page／modal 行均设 z-index0，避免 Sonner 负层级将指针关闭交给 OL；桌面原绝对堆叠路径不变。真实320高正文 Range 可视范围、drawer 通知 tap 关闭和三 modal 五条真实 click 作为回归，不再用键盘关闭代替指针命中。
