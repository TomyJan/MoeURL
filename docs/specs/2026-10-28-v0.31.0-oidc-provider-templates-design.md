# v0.31.0 OIDC 提供商创建模板设计

## 1. 现状与目标

现有 `AdminAuthenticationPage.vue` 已管理列表、新建、版本化编辑和删除；`entities/oidc/api.ts` 只有既有七字段创建 DTO。Secret 保留在短期 draft 与 mutation 的 WeakMap，不进入普通 mutation variables。模板仅降低新建时 issuer 等字段的输入成本，不重写后端 OIDC 或解释既有身份命名空间。入口仍是 `/admin/setting` 的认证区域。

## 2. 模板目录与协议兼容边界

| 模板 | key | displayName | issuerUrl | enabled |
|---|---|---|---|---|
| 手动空白 | 空 | 空 | 空 | true（保留既有默认） |
| Google | google | Google | https://accounts.google.com | false |

目录在本地代码中，不请求远端模板或第三方脚本。所有模板的 Client ID、Client Secret、allowedDomains 都为空。key 和显示名仍可在创建草稿中手工修改，issuer 仍可用既有表单编辑；模板不是不可变配置或安全授权。

初稿曾选 Entra UUID 单租户，实施前进一步核真实 `protocol.go`／`identity_resolver.go`：首次供应严格要求 `email_verified=true`。[Microsoft ID Token 官方文档](https://learn.microsoft.com/en-us/entra/identity-platform/id-token-claims-reference)列出可选且可变的 email，没有承诺该标准已验证邮箱 claim。不能据正确 issuer 字符串宣称兼容，因此收窄为 Google＋手动，不交付 Entra 预设，不改变后端验证。不主张任何定制 Entra 部署绝对不可能；其互通须另有真实凭据与 token 契约设计。官方响应完整原件／hash 和本地协议hash存于本轮 `provider-compatibility.json`。

## 3. 交互与整体草稿替换

创建表单上方放置有名称的模板选择组、帮助文字及独立 type=button 的“应用模板”。初始选择手动；选择仅改变 picker 私有非秘密状态，不改任一业务字段，不保存或联网。帮助文字明确首次登录需要提供商确认邮箱已验证且在允许域名内。

点击应用产生不含凭据的规范模板值快照。父页只在 creating=true 且 mutation 非 pending 时接受。若任一字符串字段非空（包括空格和 Secret），或 enabled 不等于原始 true，先打开明确的“替换创建草稿”确认，提示清除 Client ID／Secret／域名；取消保留原 draft 逐字段完全相同。确认应用快照后一次 Object.assign 完整草稿，清旧凭据及白名单，不进行拼接或保留旧 issuer。干净初始草稿可直接应用。

打开确认后选择改变会使待应用快照失效；取消创建、切换既有 provider、保存完成离开创建也同步清除。确认 handler 再检查当前 creating 与 mutation pending，阻止陈旧事件。写入期间 picker 全禁用且 handler 运行时拒绝；确认期间保存 handler 拒绝，防止同时保存旧 draft。picker 只在创建期挂载，退出时其私有状态被销毁。组件卸载销毁 confirmation 与 draft；不新增长期存储或 Query 缓存。

## 4. 既有保存与安全边界

创建请求仍仅包含 key、displayName、issuerUrl、clientId、clientSecret、allowedEmailDomains、enabled；没有 templateId 或 tenant 字段。仍由原 API client 发送，响应保持 strict／无 Secret。手动填充完毕后的保存、失败清 Secret、后台列表更新、乐观并发、已有 identity 的 issuer/clientId 保护均复用旧逻辑。模板不修改已有 provider，编辑状态既无入口也无应用 handler 路径。

测试用真实 QueryClient／Vuetify／i18n／API client，仅在 fetch 边界控制服务器；断言真实表单、HTTP 请求七字段及清凭据行为，不断言 API mock。E2E 使用本轮隔离真实服务和既有本地签名 IdP 验证手动草稿保存；不使用生产 Secret，不声称外部 Google 互通已验证。

## 5. 验证与交付

先从旧生产页面的可见模板入口行为写 RED，不以缺文件导入报错充当 RED。目录纯函数测试覆盖手工预期 issuer、完整默认与每次新快照；真实父页集成覆盖不隐式更改／不联网、整体替换、确认取消、Secret-only 脏状态、禁用默认、切换失效、pending 拒绝与 strict 七字段请求。中英字典和既有 OIDC 全测试回归，完整前端四项 100% 门槛不变。新增行为 RED 明确不展示未证明兼容的 Entra 预设。

真实浏览器分别 1280×720 英文、390×800 中文；新建选择／覆盖确认／应用后草稿各一张，共六原图逐张 root 读回。完整 E2E、新 clean 精确 image、18178 smoke、同 image Trivy HIGH,CRITICAL／ignore-unfixed=false、正常 DB update／原 notice 与 owned 清理分别留证。Go、SQLC、migration 输入未变则核完整集合，不重跑旧长 suite；本版 PR／master CI 独立证明目标环境。

## 6. root 裁决与错误代价

1. Ruling: 从 roadmap 选择创建模板，不扩组模型／头像／时区 — 复用已稳定 OIDC 契约且范围可审查 — 如果错了代价是本版优先级及有限前端返工。
2. Ruling: 只给新建表单应用模板 — 不重新解释现有 issuer/clientId 的身份命名空间 — 如果错了代价是编辑时需继续手工操作，后续可以独立设计。
3. Ruling（初稿，已由第 10 项收窄）: Google 固定 issuer，Entra 仅 UUID 单租户 — 避免把多租户 token issuer 兼容性冒作现有严格协议能力 — 如果错了代价是部分组织仍需手动配置，不放宽后端。
4. Ruling: 明确应用、脏草稿整体替换并确认 — 避免拼接不同提供商凭据与静默丢失 Secret — 如果错了代价是一次额外确认和重填；取消必须零丢失。
5. Ruling: 具体模板默认禁用，手动空白沿用 true — 明确准备状态同时避免改变旧手动默认 — 如果错了代价是管理员多一次启用动作，不能自动启用弥补。
6. Ruling（初稿，已由第 10 项取消租户输入）: 租户仅 trim／规范 UUID／小写，不加版本限制 — 租户标识是格式约束，不是本地随机 UUID 生成策略 — 如果错了代价是后端 Discovery 拒绝无效租户，不能绕过后端验证。
7. Ruling: 模板私有状态不持久化，应用快照无 Secret — 防止增加 Secret 副本或模板缓存 — 如果错了代价是离开创建后需重选模板，不能保存凭据解决。
8. Ruling: 仅重验受影响前端与新 browser／产品；未变 Go／SQLC 输入核完整集合 — 节省重复运行且保留执行归属 — 如果错了代价是遗漏输入变化，故必须完整 set/hash/bytes 比较并由独立本版 CI 再验证。
9. Ruling: root 自主内联设计实现，最终一次 fresh 最强整分支审查 — 用户长期授权覆盖常规选择，不额外派重复 builder 或实现者 — 如果错了代价是前期设计盲点，靠具名反例和唯一终审集中修复承担。
10. Ruling: 取消 Entra 预设，保留 Google＋手动及严格 verified-email 供应边界 — 当前真实协议与 Microsoft 官方 claim 契约未证明 stock Entra 可完成首次供应，不能靠改 issuer 或放松验证冒兼容 — 如果错了代价是少一个快捷配置入口，管理员仍可在有独立互通证据时手动配置；不改变认证安全。
11. Ruling: metadata-only 版本改动在完整依赖相符后显式禁止 pnpm 检查／自动安装 — pnpm11 的 workspace fingerprint 包含 package version，旧 0.30.0 身份使 error 策略在工具启动前拒绝，而默认 install 会无必要 relink — 如果错了代价是陈旧依赖影响门禁，所以每次先比较除 version 外的完整 manifest 及 lock／workspace 与已通过 Task1 的 ae5e852，再使用进程级 verify-deps-before-run=false；不改全局配置、不安装或放松测试，三个原基础设施失败完整保留。
