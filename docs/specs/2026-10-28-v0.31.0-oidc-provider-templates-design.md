# v0.31.0 OIDC 提供商创建模板设计

## 1. 现状与目标

现有 `AdminAuthenticationPage.vue` 已管理列表、新建、版本化编辑和删除；`entities/oidc/api.ts` 只有既有七字段创建 DTO。Secret 保留在短期 draft 与 mutation 的 WeakMap，不进入普通 mutation variables。模板仅降低新建时 issuer 等字段的输入成本，不重写后端 OIDC 或解释既有身份命名空间。入口仍是 `/admin/setting` 的认证区域。

## 2. 模板目录与租户约束

| 模板 | key | displayName | issuerUrl | enabled |
|---|---|---|---|---|
| 手动空白 | 空 | 空 | 空 | true（保留既有默认） |
| Google | google | Google | https://accounts.google.com | false |
| Microsoft Entra ID | microsoft | Microsoft Entra ID | https://login.microsoftonline.com/{tenantUUID}/v2.0 | false |

目录在本地代码中，不请求远端模板或第三方脚本。所有模板的 Client ID、Client Secret、allowedDomains 都为空。key 和显示名仍可在创建草稿中手工修改，issuer 仍可用既有表单编辑；模板不是不可变配置或安全授权。

Entra 输入外侧 trim，接受大小写十六进制的 `8-4-4-4-12` UUID，输出小写。输入字段最多 64 字符，构建函数同样检查原始长度，拒绝空、缺连字符、花括号、域名、URL、common／organizations／consumers；不额外限制 UUID version／variant，也不将 UUID 当成秘密。无有效租户时应用禁用，并给出字段级说明。Google／手动不消费租户输入。既有后端完整 issuer Discovery 与安全检查仍是权威。

## 3. 交互与整体草稿替换

创建表单上方放置有名称的模板选择组、Entra 租户输入、帮助文字及独立 type=button 的“应用模板”。初始选择手动；选择／输入仅改变 picker 私有非秘密状态，不改任一业务字段，不保存或联网。

点击应用产生不含凭据的规范模板值快照。父页只在 creating=true 且 mutation 非 pending 时接受。若任一字符串字段非空（包括空格和 Secret），或 enabled 不等于原始 true，先打开明确的“替换创建草稿”确认，提示清除 Client ID／Secret／域名；取消保留原 draft 逐字段完全相同。确认应用快照后一次 Object.assign 完整草稿，清旧凭据及白名单，不进行拼接或保留旧 tenant／issuer。干净初始草稿可直接应用。

打开确认后选择／租户改变会使待应用快照失效；取消创建、切换既有 provider、保存完成离开创建也同步清除。确认 handler 再检查当前 creating 与 mutation pending，阻止陈旧事件。写入期间 picker 全禁用且 handler 运行时拒绝；确认期间保存 handler 拒绝，防止同时保存旧 draft。picker 只在创建期挂载，退出时其私有状态被销毁。组件卸载销毁 confirmation 与 draft；不新增长期存储或 Query 缓存。

## 4. 既有保存与安全边界

创建请求仍仅包含 key、displayName、issuerUrl、clientId、clientSecret、allowedEmailDomains、enabled；没有 templateId 或 tenant 字段。仍由原 API client 发送，响应保持 strict／无 Secret。手动填充完毕后的保存、失败清 Secret、后台列表更新、乐观并发、已有 identity 的 issuer/clientId 保护均复用旧逻辑。模板不修改已有 provider，编辑状态既无入口也无应用 handler 路径。

测试用真实 QueryClient／Vuetify／i18n／API client，仅在 fetch 边界控制服务器；断言真实表单、HTTP 请求七字段及清凭据行为，不断言 API mock。E2E 使用本轮隔离真实服务和既有本地签名 IdP 验证手动草稿保存；不使用生产 Secret，不声称外部 Google／Entra 互通已验证。

## 5. 验证与交付

先从旧生产页面的可见模板入口行为写 RED，不以缺文件导入报错充当 RED。目录纯函数测试覆盖手工推导 issuer、非法租户与完整默认；真实父页集成覆盖不隐式更改／不联网、整体替换、确认取消、Secret-only 脏状态、禁用默认、切换失效、pending 拒绝与 strict 七字段请求。中英字典和既有 OIDC 全测试回归，完整前端四项 100% 门槛不变。

## 6. root 裁决与错误代价

1. Ruling: 从 roadmap 选择创建模板，不扩组模型／头像／时区 — 复用已稳定 OIDC 契约且范围可审查 — 如果错了代价是本版优先级及有限前端返工。
2. Ruling: 只给新建表单应用模板 — 不重新解释现有 issuer/clientId 的身份命名空间 — 如果错了代价是编辑时需继续手工操作，后续可以独立设计。
3. Ruling: Google 固定 issuer，Entra 仅 UUID 单租户 — 避免把多租户 token issuer 兼容性冒作现有严格协议能力 — 如果错了代价是部分组织仍需手动配置，不放宽后端。
4. Ruling: 明确应用、脏草稿整体替换并确认 — 避免拼接不同提供商凭据与静默丢失 Secret — 如果错了代价是一次额外确认和重填；取消必须零丢失。
5. Ruling: 两个具体模板默认禁用，手动空白沿用 true — 明确准备状态同时避免改变旧手动默认 — 如果错了代价是管理员多一次启用动作，不能自动启用弥补。
6. Ruling: 租户仅 trim／规范 UUID／小写，不加版本限制 — 租户标识是格式约束，不是本地随机 UUID 生成策略 — 如果错了代价是后端 Discovery 拒绝无效租户，不能绕过后端验证。
7. Ruling: 模板私有状态不持久化，应用快照无 Secret — 防止增加 Secret 副本或模板缓存 — 如果错了代价是离开创建后需重选模板，不能保存凭据解决。
8. Ruling: 仅重验受影响前端与新 browser／产品；未变 Go／SQLC 输入核完整集合 — 节省重复运行且保留执行归属 — 如果错了代价是遗漏输入变化，故必须完整 set/hash/bytes 比较并由独立本版 CI 再验证。
9. Ruling: root 自主内联设计实现，最终一次 fresh 最强整分支审查 — 用户长期授权覆盖常规选择，不额外派重复 builder 或实现者 — 如果错了代价是前期设计盲点，靠具名反例和唯一终审集中修复承担。
