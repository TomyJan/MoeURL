# v0.34.0 站点强调色设计

## 1. 意图、备选与边界

[范围](../product/scope-v0.34.0.md)落实路线图中的可配置主题色。任意 CSS／色值会引入注入、不可读组合与配置恢复负担；完整主题包把背景、语义色和布局一起扩大。本版选择三个固定主强调色，复用现有 Vuetify 4 token、Go／SQLC／Goose 和独立设置资源模式，无新依赖。

默认 `iris` 精确保留当前视觉。只覆盖下面四个 token；其他颜色、圆角、布局、动画及语义含义保持。预设是站点公共配置，深浅模式是浏览器／账号偏好，两者独立，不把预设写入个人偏好或 localStorage。

## 2. 固定目录与应用

| --- | --- | --- | --- | --- | --- |
| `iris` | light | `#5c4dde` | `#ffffff` | `rgba(92, 77, 222, 0.09)` | `rgba(92, 77, 222, 0.38)` |
| `iris` | dark | `#b9adff` | `#272047` | `rgba(185, 173, 255, 0.07)` | `rgba(185, 173, 255, 0.44)` |
| `ocean` | light | `#075eae` | `#ffffff` | `rgba(7, 94, 174, 0.09)` | `rgba(7, 94, 174, 0.38)` |

| `forest` | light | `#236744` | `#ffffff` | `rgba(35, 103, 68, 0.09)` | `rgba(35, 103, 68, 0.38)` |
| `forest` | dark | `#8dd9a3` | `#0d3923` | `rgba(141, 217, 163, 0.07)` | `rgba(141, 217, 163, 0.44)` |

前端固定目录是颜色唯一来源，服务端只保存枚举。使用现有 `moeurlLight`、`moeurlDark` 两个主题的响应式定义应用这四项，不能改写当前模式名称或重置账号／浏览器选择。切换后再切深浅模式仍使用对应配套色。目录不接受服务端任意 CSS，不改变二维码本地外观预设。

应用入口新增独立公开 query。首次加载使用 iris；本次读取成功才应用其标识，读取失败使用 iris，不能把失败伪装成功或写回服务器。后台重新读取期间保留最近成功值，失败后回安全默认；App 重新挂载必须实际读取，不能只靠旧缓存。保存成功仅发布经当前管理身份守卫的服务端结果并更新／失效该公开 query，防止旧在途公开读覆盖刚提交的值；取消旧读或使用读取轮次实现此约束。跨浏览器无推送承诺，重载可读取最新值。

## 3. 独立协议

`Appearance = {accentPreset: "iris" | "ocean" | "forest"}`。

- `GET /api/v1/system/appearance` 公开返回 Appearance，恰一字段，不含管理版本。
- `GET /api/v1/admin/system/appearance` 返回 Appearance 加 `updatedAt`。
- `POST /api/v1/admin/system/appearance/update` 完整提交 `accentPreset`、`expectedUpdatedAt` 两字段，成功返回管理投影。

写入先解析并要求 `application/json`，允许合法参数和媒体类型大小写；严格拒绝缺失／null／未知字段、尾随 JSON、错误类型、无效 UTF-8、未知枚举与超过 8 KiB 的正文。版本使用非零、可回传的完整 RFC3339Nano 时区字符串，不经 JavaScript Date 截断。

全部接口 no-store，不进入 Service Worker。输入业务码 `900206`、版本冲突 `900207`、无权限 `120001`，业务 HTTP 200；会话／基础访问中间件语义保持，基础设施错误 HTTP 500／900000。日志只记录安全操作类别和请求 ID，不记录配置正文。旧 public-config、settings、home-content、preferences 的字段与版本保持独立。

## 4. 持久化、当前授权与审计

`00030_site_appearance.sql` 在 `system_setting` 插入 `site.appearance = {"accentPreset":"iris"}`，`ON CONFLICT DO NOTHING`。此行 `updated_at` 是独立并发版本，应用启动验证行存在、严格结构／枚举和合法版本；缺失／损坏不能由服务端静默补默认。公开查询使用五秒期限。

新 AppearanceService 的管理读在五秒只读 repeatable-read 事务中重查有效、非 builtin、未删除账号、当前 builtin admin 组及两项权限，再读配置。写使用五秒 WithAuditTx，账号共享锁 → 当前 builtin admin 组共享锁 → 配置行排他锁；持锁重查当前授权，不能信任旧 actor 组快照。

先比较完整版本，再识别同值 no-op；同值原样返回且不推进版本，陈旧同值仍冲突。实际变化只更新本键，版本严格递增。新 `queries/appearance.sql` 定义管理投影及两锁查询，复用通用系统键查询；SQLC 1.30 标准生成和二次零漂移，不手改生成物。

旧审计白名单忽略新键；增加仅监听本键的专用 AFTER INSERT／UPDATE 触发器及小函数。仅 audit_enabled=on 且值实际变化时写一条 system_setting／site.appearance／settings_change／changed_fields=['site.appearance']，不保存色值或前后正文，不双记。业务／审计失败全回滚。Down 仅删除本版专用触发器／函数，保留配置和全部历史；旧应用忽略独立键，再次 Up 保留管理员选择。

## 5. 管理交互与身份

AdminSettingsPage 的原表单外新增独立 AppearanceEditor。Vuetify 有名选择器列出三项双语名称，不靠颜色区分；小色样仅辅助识别。选择草稿不应用全站、不写服务器；保存中禁重入，成功采用返回的新完整版本并应用预设。重新编辑清旧成功反馈。加载失败持久重试；保存失败保草稿；冲突保草稿与显式重新加载，不自动重放写请求。

管理 query key 包含账号与身份轮次，权限变化同步递增 generation 并清草稿／版本／错误／挂起状态；每个 load/save success/error/finally 必须核同一当前轮次。卸载后旧结果不能填表、发布公共预设或提示成功。显式重新加载期间的新编辑不能被迟到读取覆盖。仅双权限可见，后端仍是最终边界；不重构旧 general、首页文案或 OIDC 表单。
