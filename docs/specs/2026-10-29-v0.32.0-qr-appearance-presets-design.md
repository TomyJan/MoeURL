# v0.32.0 二维码外观预设设计

## 1. 现状与取舍

roadmap 将二维码样式列为未开发扩展。当前 `ShortLinkQrDialog.vue` 已复用在创建结果和两类列表，浏览器动态加载 `qrcode` 生成公开 URL 的 PNG，320 像素、M 纠错、margin=2，使用 generationId 丢弃旧 URL 的异步结果。本版仅扩大该共享组件的本地显示能力。

比较任意色彩编辑器、固定预设和服务端持久样式：前者必须建立颜色验证、低对比度和透明度策略，后者新增数据与权限生命周期；采用固定预设，不建立没有消费者的通用模板系统。root 自主选择此边界，不冒用户逐项批准。

## 2. 目录与界面

`features/short-link-qr/appearance-presets.ts` 导出只读三项目录 `qrAppearancePresets`，每项 `key`、`labelKey`、`dark`。值由范围文档固定，背景只用 `#FFFFFF`；不接受服务端或用户动态颜色。

沿用现有对话框，在预览上方放有本地化名称的操作组，三个 Vuetify 按钮暴露 `aria-pressed`，各自显示文字与装饰性色块。按钮 `type=button`，Tab／Space／Enter 可操作；不伪造需要方向键协议的 radiogroup。默认黑白按钮也承担恢复默认操作。对话框有真实本地化可访问名称，正文说明“仅本次预览；重新打开恢复黑白”，不向使用者展示工程细节。

图片始终保留白色背景，宽度不超过可用空间；操作组允许换行。下载仅在当前编码成功时出现，文件名仍 `moeurl-${slug}.png`。不添加表单保存或后台写入。

## 3. 生命周期与异步

选中目录项只存组件 `ref`。同步监听 `open/slug/url` 身份变化，把选择恢复目录第一项；异步编码 watcher 监听同一身份和选中项，立即递增 generationId 并清 dataUrl/error/loading，再按 open 和非空 URL 决定是否生成。Vue 调度合并同一轮身份重置，避免为旧颜色多编码。

编码固定 `{width:320,margin:4,errorCorrectionLevel:'M',color:{dark:preset.dark,light:'#FFFFFF'}}`。颜色只影响渲染，载荷仍完整 `props.url`。成功、catch、finally 都核对本次 generationId。当前失败不显示旧预览或旧下载，换选项触发新尝试；旧失败不能显示在新选择下，旧 finally 不能提前清当前 loading。

close、URL 清空、slug 改变、同一 URL 重开都要核真实可见结果。已卸载组件的 Promise 不产生 DOM 或持久状态，不增加后台任务。

## 4. 权限与兼容

复用已有链接读取／创建结果入口；二维码本身是已获知公开 URL 的本地派生，不新开数据读取能力，不发 API 或记录访问。无新增权限、后端、SQLC、migration、依赖、存储、路由或 Secret。暗色应用主题仍输出同一白底 PNG，防止把透明背景误认为可扫码对比度。

静区由 2 调整为标准 4 模块，属于本版输出契约变化；PNG 像素不承诺与旧版本相同。固定深色对白底的颜色数值可核验，但真实扫描器、纸张和光照仍需部署者自行验证，不把浏览器像素断言冒作实体扫码互通。

## 5. 验证与交付

组件测试用真实 PNG 编码验证三个输出不同、始终公开 URL、下载与当前预览相同；仅在可控并发／失败测试中替换编码边界。具名反例：颜色选择缺失、同 URL 重开、slug-only 变化、URL 变化、旧成功／旧失败／旧 finally、当前错误切色恢复、关闭期间结果返回、长 URL 和空 URL。

真实父入口回归覆盖创建成功区、个人列表、管理列表。浏览器在两种语言及双视口选择每个预设，检查 selected 状态、白底与目标色 PNG 像素、真实 download 文件和预览字节、重开与换链接复位、操作区可达和无横向溢出。六张原图每视口各三预设；保存原文件并逐张实读，几何与视觉不足分别记录。

完整前端覆盖率四项100／lint／types／build；新 clean 候选完整 E2E、新精确产品／同镜像扫描；未变后端完整集合对 master 比较，不重复旧长 suite。证据逐命令记录 cwd、显式 env、继承未全捕获、完整输入 set/hash/bytes、HEAD dirty、raw/exit，不能转移执行身份。远端与最终归档按四任务计划。

## 6. root 裁决与错误代价

1. Ruling: 选择二维码固定三预设而非头像／时区／新权限模型 — 接续 roadmap 的样式方向，复用成熟共享组件，风险和验证边界有限 — 如果错了代价是该轮优先级及少量前端返工。
2. Ruling: 仅本次会话，身份变化恢复黑白 — 避免其他链接或下一用户继承意外样式，不增加持久数据 — 如果错了代价是每次需重新选择，不能靠偷偷保存偏好补救。
3. Ruling: margin=4 与不透明白底为三预设共同契约 — 保留标准静区，禁止任意低对比度或透明色 — 如果错了代价是二维码有效模块区域稍小，必须用当前长 URL 像素／浏览器验证，不冒实体扫码保证。
4. Ruling: 不新增二维码权限 — 已有入口只处理当前已可见的公开 URL，颜色不开放新资源 — 如果错了代价是未来服务端模板收费／授权需独立设计，本版不提前铺模型。
5. Ruling: 起始旧 upstream 解析失败是已删除远端引用的诊断，保留原输出而不声称成功 — 旧本地分支和其 origin/merge 配置仍存在，fresh master、无 open PR、clean、no-track 新分支均另有实际 exit0 — 如果错了代价是误读旧跟踪状态，必须将该原失败与成功 fetch/switch 分开记录，不能恢复或删除旧远端。
6. Ruling: root 内联设计实现与一位 fresh 整分支终审 — 沿用用户已授权自主多轮，不派重复 builder／实现者或模型计划审查 — 如果错了代价是前期盲点，由具名反例、完整门禁和唯一独立终审承担；普通取舍不再次询问。
7. Ruling: 六张初始原图不能视作无遮挡视觉验收，待当前 full 结束后仅在 E2E 中通过真实本地化关闭按钮消除创建成功提示并等待其移除，再留新 clean 证据 — 原 toast 属于正常创建反馈，不能靠 DOM 隐藏、固定睡眠或改产品通知修补拍摄；保留全部旧图／原通过功能断言 — 如果错了代价是一次新的定向捕获及变更输入相应验证成本，不得把旧 full／image 重归属新 head，不能提前 Task2 complete。
8. Ruling: README 当前主分支及最近合并版本仍称 v0.30.0，按已核 PR229／c6712051 修正为 v0.31.0，保留原 v30 验收段落与全部冻结制品 — 入口的当前状态必须与自身下方 v31 最终事实一致，不能让历史段落覆盖最新完成状态 — 如果错了代价是读者误判发布进度，因此只同步合并事实、不宣称正式发布或替换旧运行身份。
