# 短链

## 短链访问形式

MoeURL 使用简洁的路径型短链访问形式，例如：

```text
https://xxx.com/abcd
```

其中，`xxx.com` 是系统中已配置并启用的短链访问域名，`abcd` 是短码。访问者打开该地址后，系统根据访问域名和短码识别对应短链，并按短链配置执行跳转、展示中间页、展示确认页或要求输入访问密码。

短码在全系统范围内全局唯一，不随短链访问域名变化而重复。也就是说，同一个短码不能在不同短链访问域名下重复使用。

短码统一保存和展示为小写字母数字，访问查找按小写规范化。默认随机生成 6 位；v0.12.0 的自定义输入先验证原始值为 3–32 位 ASCII 字母数字，再转小写，不能通过 Unicode 大小写转换或去空格接受非法输入。

系统固定路由优先于短链路由。随机与自定义创建共享保留路径集合：`api`、`assets`、`icons`、`setup`、`login`、`profile`、`console`、`link`、`links`、`analytics`、`admin`、`go`。带点的静态文件名不符合自定义短码格式；新增固定入口时须同步检查保留路径。

## 未登录访问首页

未登录用户进入首页时，系统以 `guest` 身份判断可见内容和可用功能。

首页的短链创建区域作为核心组件应保持展示。若 `guest` 拥有创建短链权限，则表单可直接使用；若 `guest` 没有创建短链权限，则表单置灰，并展示清晰提示和登录入口。

## 创建短链流程

创建短链功能默认放在首页。用户也可以从其他页面通过快捷入口回到首页进行创建。

完整目标形态下，系统根据权限动态控制可用字段。v0.0.1 创建短链只要求输入目标链接，系统统一使用全局默认短链访问域名、6 位小写字母数字随机短码和直接跳转；域名选择、自定义短码、跳转方式、跳转页模板和高级选项属于后续能力或仅保留扩展点。

v0.2.0 在既有目标链接输入下增加折叠的高级设置，支持选择直接跳转或中间页跳转，并可在权限允许时设置固定过期时间。中间页倒计时范围为 3 至 10 秒，默认 5 秒；既有短链和未提供高级设置的新短链继续使用直接跳转。

v0.8.0 新增可用短链域名选择：拥有 `domain:use_default` 且获得默认域名授权时，默认选择沿用旧请求、不带 `domainId`；`domain:use_assigned` 仅允许显式选择获授权的非默认域名并传其 UUID，不能用于展示或选择当前默认域名。服务端在创建事务中同时校验用户组权限、域名授权与启用状态。短链保存的 `domain_id` 是之后所有列表、更新和统计响应公开 URL 的来源；全局默认域名变化不会修改已发布 URL，现有短链也不能通过编辑迁移到其他域名。

完整目标基础流程：

```text
输入目标链接
  ↓
选择可用域名
  ↓
选择短码生成方式
  ↓
选择跳转方式
  ↓
选择跳转页模板（如适用）
  ↓
填写模板元数据（如适用）
  ↓
配置可用高级选项
  ↓
生成短链
  ↓
复制或继续管理
```

页面需要做到：

- 对常见核心字段，无权限时优先置灰并说明原因。
- 对高阶或不相关字段，可根据权限隐藏。
- 常用字段默认展开。
- 高级设置默认折叠。
- 创建成功后提供复制、打开、继续创建和返回我的短链列表入口。v0.0.1 不实现独立短链详情页。

## 批量管理

批量管理在 v0.17.0 实施：当前个人／全站列表可多选启用、停用或软删除，一次最多 100 条，沿用对应写权限且整批原子执行；不跨页全选、不改变目标和访问配置。完整接口、错误与交互规则见 [批量管理设计](2026-10-16-v0.17.0-bulk-link-management-design.md)。

## 清单导出

v0.21.0 设计个人与全站清单 CSV 导出：独立 `short_link:export` 叠加对应读取权限，按当前已应用的状态、关键词和单标签筛选读取全部匹配记录，最多 1000 条／8 MiB，超限明确拒绝，不截断。保留原短链域名、目标、标题／标签和管理配置；不含密码、哈希、令牌或原始事件。服务端同语句快照重查当前授权与归属，前端隔离筛选和登录轮次，边界与实施状态见 [设计](2026-10-24-v0.21.0-link-list-export-design.md) 及 [验收](../implementation/v0.21.0-acceptance.md)。

## 归属转移

v0.20.0 允许具备管理和全站更新权限的管理员将单条未删除短链转给启用的 user／admin 账号。仅 owner_id 和完整精度版本变化；URL、slug、domain_id、目标、元数据、访问条件、授权 Cookie、额度和全部事件保持原值。历史统计随短链移交；旧所有者后续的个人列表、更新、删除及统计按新 owner_id 判断，已授权完成的在途读取不追溯撤销。新所有者接收既有链接不要求额外域名创建授权，其后续操作仍受本人当前权限限制。转移与 owner_id 审计同事务提交，冲突不覆盖，同 owner no-op，详见 [设计](2026-10-23-v0.20.0-link-ownership-design.md)。

v0.22.0 批量归属转移将相同规则应用于当前列表最多 100 条：全量锁定及版本预检后原子更新，任何错误整批回滚；同 owner 仍检查版本但不写入或审计。新旧所有者权限和全部历史保留规则与单条一致，不提供跨页全选或部分成功。详细契约及当前实现／验证状态见[设计](2026-10-25-v0.22.0-batch-ownership-design.md)与[验收](../implementation/v0.22.0-acceptance.md)。

## 批量标签整理

v0.23.0 独立分支已实现个人与全站当前列表 1–100 条标签添加、精确移除、全部替换和清空。个人需 `short_link:update_own`、`short_link:set_metadata` 和当前 owner；后台需 `admin:access`、`short_link:update_all`、`short_link:set_metadata`。界面另需相应读取权限。使用每条完整精度版本，全量锁定、当前授权与结果上限预检后同事务写入；任一失败整批零写入。

添加保留原顺序并按输入顺序追加，移除保留剩余顺序，替换采用输入顺序；每条结果最多 10 个标签，每个沿用 32 个 Unicode 字符、大小写敏感及首尾 Unicode 空白裁剪，不做 Unicode 规范化。no-op 不推进版本或写审计；仅 tags 与严格递增 updated_at 改变，标题、owner、地址、访问配置、密码授权及历史事件均保留。个人私有列表新增 `updatedAt` 响应字段供精确版本提交；创建、单条更新和统计响应未赋值时省略，公开预览不增加该字段。接口与错误详见[设计](2026-10-26-v0.23.0-batch-tags-design.md)，本地／CI／合并／发布状态见[验收](../implementation/v0.23.0-acceptance.md)。

## 自定义短码

v0.12.0 创建接口支持可选 `customSlug`：省略或 `null` 保持随机生成，显式空字符串不合法。只有拥有 `short_link:custom_slug` 才能指定，且创建事务内重查当前用户组权限。前端空输入省略字段，预览小写完整短链地址；格式错误或冲突使用友好 Toast，冲突保留草稿。

全局唯一约束是并发权威，跨域名及软删除记录仍占用短码。指定值只尝试一次，冲突返回 `200101`，保留路径返回 `200102`，格式错误返回 `100001`，缺权限返回 `120001`；不回退随机值，也不提供可用性探测接口。创建后不允许编辑、释放或复用，详细规则见 [v0.12.0 设计](2026-10-15-v0.12.0-custom-slugs-design.md)。

若入口快照通过后授权在事务前被撤销，创建查询统一返回 `200114`（域名或授权不可用），与既有创建行为一致，且不写入记录。

## 标题与标签

标题与标签的管理契约见 [v0.11.0 设计](2026-10-13-v0.11.0-link-metadata-design.md)：只在授权管理接口展示，不影响公开预览、访问条件、目标跳转和统计。创建和更新使用可选 `metadata` 整体替换对象，省略保留，空标题与空数组用于清除；列表支持关键词与单标签筛选。

## 最大访问次数

v0.10.0 允许拥有 `short_link:set_max_visits` 的用户设置 1 至 2147483647 的上限。创建省略 `maxVisits` 表示无限额；更新省略 `visitLimit` 保持配置，`limited` 调整上限并保留已有用量，`unlimited` 清除上限及用量。无限额重新设限从 0 开始，历史统计不回填。

仅最终外部跳转签发前领取一次额度。预览、密码解锁、中间页和确认页入口不消耗；Continue 重新校验访问条件和额度。有限额使用数据库行锁及条件更新，多实例争抢最后名额时最多一次成功；提交后不退款，因为响应头可能已经送达。默认无限额保持只读解析和既有访问快照语义。

管理响应包含 `maxVisits`、`visitsUsed`、`visitsRemaining` 和 `exhausted`；剩余量最低为 0。用量允许超过降低后的上限，此时立即耗尽。公开页面只显示耗尽状态，Preview 不暴露这些字段。禁用和过期不重置额度，提高或清除上限可恢复未被其他条件阻止的访问。

`visitsUsed` 与异步 `stats.visitCount` 口径不同，不能相互替代。详细契约见 [v0.10.0 设计](../superpowers/specs/2026-10-13-v0.10.0-max-visits-design.md)。

## 目标链接安全校验

目标链接在创建和编辑时必须通过基础安全校验。

v0.0.1 至少应要求目标链接是合法 URL，并默认只允许 `http://` 和 `https://` 协议；禁止 `javascript:`、`data:`、`file:` 等不适合作为跳转目标的协议。

系统还应预留目标链接审核状态和拦截点，便于后续加入黑名单、白名单、外部安全数据源、人工复审和风险链接强制确认页。

v0.0.1 默认不开放 `guest` 创建短链。若后续开放公开创建能力，需要增加更严格的目标地址风险校验，包括内网地址、localhost、私有 IP 段、当前系统管理路径、控制字符、不可见字符和 URL 最大长度等边界。

系统应预留避免明显短链循环的校验入口，例如短链直接指向自身。v0.0.1 不要求完整实现跨短链循环检测；是否允许短链指向其他短链，可以由后续风控策略进一步限制。

## 访问短链流程

访问者打开短链后，系统按以下顺序处理：

v0.8.0 中，识别域名必须比较真实请求 `Host` 与短链保存的启用域名；错误 Host 或停用域名按不存在返回。公开预览、路径作用域预览、解锁和继续访问同样重新校验，不信任客户端提供的转发头；恢复启用后旧地址重新可用。

```text
识别域名和短码
  ↓
查找短链
  ↓
预留 `short_link_opened` 事件记录点
  ↓
检查短链状态
  ↓
检查访问条件
  ↓
根据检查结果调用事件记录接口记录 `redirect_blocked` 或继续处理
  ↓
按跳转方式展示或跳转
  ↓
调用事件记录接口预留 `redirect_initiated` / `redirect_response_sent` 等事件
```

可能结果包括：

- 直接跳转到目标链接。
- 展示中间页后自动跳转。
- 展示确认页，等待用户点击后跳转。
- 要求输入访问密码。
- 显示短链不存在页面。
- 显示短链已禁用页面。
- 显示短链已过期页面。
- 显示访问次数已达上限页面。

所有访问页都应支持多语言、自动深色模式、响应式布局，并使用系统主题和页脚配置。

## 短链状态模型

系统应为短链定义统一状态，避免访问流程、管理后台和统计口径各自判断。

v0.0.1 必须实现的最小状态包括：

| 状态 | 说明 |
| --- | --- |
| `active` | 启用中，可以按配置访问。 |
| `disabled` | 已禁用，不允许访问目标链接。 |

软删除通过 `deleted_at` 表达，不作为普通业务状态复用。删除后普通列表默认不展示，访问时按不存在处理。

访问时还可派生以下状态，`pending` 和 `rejected` 仍属于远期预留：

| 状态 | 说明 |
| --- | --- |
| `expired` | v0.2.0 已实现：已过期，不允许访问目标链接。 |
| `exhausted` | v0.10.0 已实现：访问次数已达上限，不允许访问目标链接。 |
| `pending` | 待审核，预留给后续风控和人工审核。 |
| `rejected` | 审核拒绝，预留给后续风控和人工审核。 |

访问短链时，应先识别短链，再根据状态决定继续检查访问条件、展示状态页或返回 404。

### 过期时间

v0.2.0 支持可选的短链过期时间：

- 过期时间使用服务端可比较的绝对时间保存。
- 未设置过期时间表示不设置固定期限。
- 创建或编辑时，过期时间必须晚于服务端当前时间。
- 过期不写回 `status`，访问时根据当前时间动态判断。
- 过期短链不跳转目标 URL，也不记录 `redirect_response_sent`。
- 禁用状态和过期状态互不替代，恢复启用不会清除过期时间。

### 二维码

v0.2.0 的二维码只编码短链公开 URL。二维码在浏览器中即时生成，可预览和下载，不写入数据库，不包含目标 URL、账号信息或统计数据。二维码样式编辑、Logo 合成、批量生成和服务端图片存储不属于基础能力。

后继 [v0.32.0](../product/scope-v0.32.0.md) 已实现三个固定深色／不透明白底PNG预设，320像素、M纠错与4模块静区；关闭重开或slug／URL变化恢复黑白，不存储、不发API。Task1–2标准完成，原完整前端与clean459cddd自身浏览器／六图／产品证据见验收；独立终审及远端交付待完成。不改变v0.2.0基础范围，不含任意颜色编辑、Logo或实体扫码兼容承诺。

## 删除策略

删除策略采用软删除，便于审计，并防止短码被复用造成误导。

v0.0.1 删除短链采用软删除。删除后普通列表默认不展示，访问时按不存在处理，短码永久保留占用，不进入自动复用池。v0.0.1 不提供短码释放、恢复或复用能力。
