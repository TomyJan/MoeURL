# v0.30.0 批量用户组成员迁移设计

## 1. 意图、现状与方案

对应[范围](../product/scope-v0.30.0.md)。现有 v0.19 单账号改组已经提供原始版本、当前 DB 授权、Session 撤销和审计；管理员处理多名成员仍需反复确认。当前用户页仅显示前 20 项，不能把“批量”解释为整个数据库或自定义组管理。

比较三种方案：浏览器循环调用旧接口会部分完成；后台批次任务需要进度、恢复和审批模型；本版采用 1–100 项有界单事务、新独立接口和当前列表确认。沿用 Go／SQLC／PostgreSQL、Vue／TanStack Query／Vuetify／zod／i18n，不新增依赖、权限或 migration。所有下列常规选择由 root 自主决定，并非用户逐项批准。

## 2. API 与严格输入

新增 `POST /api/v1/admin/user/batch-change-group`，JSON 为：

```json
{
  "items": [
    { "id": "00000000-0000-4000-8000-000000000001", "expectedUpdatedAt": "2026-10-28T00:00:00.123456Z" }
  ],
  "groupKey": "admin"
}
```

仅 JSON 媒体类型、单个非 null 对象、已知字段；items 非 null 数组且 1–100 项，每项为非 null 对象，两个字段必填非空，拒绝未知字段／错误类型／尾随文档。ID 必须规范小写非零 UUID，重复 ID 整批无效，不去重。groupKey 严格 user／admin，不能省略／null。时间须严格 RFC3339，秒及 0–9 位小数、Z 或合法 offset、非零；按 time.RFC3339Nano 解析，不四舍五入到毫秒或秒。复用全局 1 MiB BodyLimit；100 项并非替代字节上限。JSON 同名字段沿用 Go decoder 既有规则，不承诺新增重复 JSON key 检测。

成功使用既有 envelope，`data={"changedCount":1,"unchangedCount":0}`，两个非负整数之和等于 items 数量；不返回账号资料、Session、逐项成功或完整请求。前端用 strict zod 校验计数及总和，不把无效响应当成功。当前同组项合法，API 允许全 no-op；界面要求至少一项实际变化，防止无意义确认。

业务 HTTP 200 沿用已有码：100001 无效输入或目标当前不属于 builtin user／admin；120001 当前 actor 无权；300103 任一缺失／deleted；300102 任一 builtin；300106 选择自身；300105 任一完整版本冲突。不给出失败账号 ID 或部分计数。基础设施 HTTP 500／900000，no-store 覆盖成功和全部错误，旧单账号 DTO／路径／业务码不变。

错误优先级：入口身份中间件故障依旧先处理；Service 先规范 actor ID（无权），再完整语法校验（无效），事务内当前 actor 授权，再按类别统一检查全部 target：缺失／deleted → builtin → self → 当前组不受支持 → 版本冲突。不同请求顺序不能改变混合错误类别。读取组配置缺失／不为 builtin 属无效配置请求；数据库异常／损坏权限解码为 500，不能降级授权。存储权限必须为数组，合法空数组表示无权，整个 JSON null 或数组解码失败属于配置损坏；此检查仅限本版 batch，不扩大共享 decoder 的行为。基础设施错误随实际发生点返回，不伪装业务冲突。

## 3. 事务、锁序与版本

从 Service 开始建立五秒 context，在 `appdb.WithAuditTx` 绑定真实 actor。一次事务完成以下步骤，不逐项调用 `ChangeGroup`：

1. 复用 `queries/user.sql` 的 `LockGroupChangeUsers`，一次传 actor＋全部唯一 target，SQL `ORDER BY id FOR UPDATE`，包含 deleted 记录以便保护分类。最多 101 行，不由 HTTP 输入顺序决定锁序。
2. 从已锁账号验证 actor 存在、active、未 deleted、非 builtin。先 `GetGroupChangeGroup("admin") FOR SHARE`，校验 actor 当前 GroupID 确为此 builtin 组并从其当前数据库 permissions 解码 `admin:access`；不信入口 GroupKey／Permissions。缺 actor／当前组不符／无能力拒绝。再 `GetGroupChangeGroup("user") FOR SHARE` 并校验 builtin。两个共享锁固定 admin→user，保留到提交，覆盖目标组及目标当前组的稳定性。
3. 全量执行上述保护、当前组及版本预检。目标允许 active 或 disabled，不改变状态。逐项时间与已锁 row 的完整时间相等才接受，**版本校验先于 no-op**；同组旧版本仍使整批冲突。
4. 按 UUID 顺序对实际变化的账号复用 `ChangeAppUserGroup`，更新 group_id 与 `greatest(clock_timestamp(), updated_at + interval '1 microsecond')`。逐账号复用 `RevokeGroupChangeSessions`，撤销当前所有未撤销 Session。其余同组项不写入、不动版本、不撤销、不审计。
5. 全部成功后单次提交才返回计数。任一写、撤销、审计失败都回滚全部；不把已写但未提交的计数发布。客户端断连／commit 网络故障可能让客户端无法确定提交结果，不承诺分布式“恰好一次”；不自动重试写，需刷新后重新确认。

锁关系已核对：旧单账号改组／短链归属转移也先按 UUID 锁账号再读组；组权限／组默认写先锁当前账号再 admin 排他、目标组排他，domain advisory 在其账号锁之前。批量不拿 domain／short_link 锁，且不在组锁后追加账号锁，避免新增反序。两个管理员 A→B 与 B→A 以同一账号集合顺序串行，后者等锁后按 DB 当前身份拒绝，不能凭旧 actor 权限双双降权。重叠批次同版本至多一个实际变更成功，其余冲突。锁超时按基础设施失败，不能自动扩期限或重试。

当前查询已足够，预期不改 SQLC 输入／生成物；若实际必需新查询，仅改源 SQL，经锁定 SQLC 1.30 标准生成及零漂移验证。不手改 generated 文件，不增加通用批处理框架。

## 4. Session、授权与审计边界

沿用既有身份与 v0.19 含义。真实变化账号的**提交前已经持久化的旧 Session** 在同事务撤销；下一次请求按实际会话及 DB 当前组拒绝或授权，新登录取得当前组。Local login 的账号 FOR SHARE 与这里 FOR UPDATE 串行；OIDC resolver 与 Session 创建是既有分离流程，提交后才创建的在途 OIDC Session 仍使用后续 DB 当前组，不承诺取消外部登录或所有已授权在途请求。不得用此机会重构认证协议或声称完全冻结全部登录。

审计 trigger `00021_audit.sql` 已对白名单 group_id 的真实变化记录 `resource_type=user`、action=update、changed_fields=[group_id]；一名变化账号一条，actor 均是真实管理员。No-op 不新增，失败整批无新增。无批次 ID／批次审计行，不存前后值、密码、Cookie、OIDC subject 或请求体。HTTP 日志仅固定事件、request_id、timeout／canceled／infrastructure 分类及 `%T` 类型，不能打印数据库诊断、目标清单或原始 error。

短链 owner、统计、域名授权、个人／组默认、密码与 external_identity 均不变。初始化管理员不是 builtin，可由其他管理员迁移；self 保护加锁后当前授权保证至少保留执行者，不另建“最后管理员”计数竞态。

## 5. 当前列表选择与确认

`AdminUsersPage` 增加 checkbox 列与轻量选中工具条：仅当前显示的非 builtin、非自身、当前组 user／admin 可选，disabled 状态账号仍可选。全选只覆盖当前可选行，提供准确 checked／indeterminate／可访问标签，最多 100，不新增分页或搜索。首个选择进入批量模式并关闭已有展开面板但保留昵称草稿；选择非空时阻止打开账号编辑／更多操作。用户可“清除选择”恢复单账号操作。

“批量调整用户组”打开时深拷贝当前可见选中对象（id、username、group、updatedAt），不复用可变列表对象。对话框滚动展示全部用户名及当前组，目标选择初始为空，明确 user／admin；显示会改变／不变数量，admin 有提权警示、user 有降权警示，并明确仅实际变化账号需重新登录。目标改变清除确认勾选；至少一项变化且明确勾选才可保存。后台列表刷新不会替换 snapshot 或版本；目标在后台被改／删由提交 CAS 整批拒绝，不偷偷缩小批次。

pending 期间禁止关闭确认、切目标、改勾选、重复提交、单账号改组／昵称／启停／重置密码与新建账号入口。已有单账号 update/reset/group 请求未完成时，不能开始选择／打开批量；已有单账号 dialog 时也互斥。不宣称跨浏览器互斥，服务器版本负责竞争。普通取消丢弃确认草稿，只保留当前列表仍可调整的选择；冻结期间离开列表或变为保护项的账号不继续占用选择计数和竞争写锁，全部移出时不能打开空确认。后台读取不能因此修改已经打开或在途的冻结快照。页面离开可卸载，不能以导航阻止或取消机制冒数据库回滚。

## 6. 身份、读取与失败恢复

使用已有 `useAccountIdentity` 的用户 ID＋epoch，auth/me 必须成功且有 admin:access 才启用当前用户列表和操作。列表 query key 使用 `['admin-user', userId, epoch]`，不以旧不分身份的 `['admin-user']` 缓存作为新页面数据；prefix invalidation 仍兼容旧单账号成功刷新。返回结果应用前检查 scope，按当前 canRead 决定显示，退出／换账号／同号新登录及撤权立刻清选择／确认／展开面板／昵称和密码草稿并隔离旧读写。只清本页目标缓存，不扩整个系统状态管理。

每次提交绑定 opening scope、revision 与组件 alive；旧结果不 Toast、不关闭后来对话框、不 invalidation 新身份查询。pending 的真实存续由请求 finally 管，不用 clear 误放开同一个仍在途请求；新身份可独立重建其状态。卸载后仍允许服务器按既有事务完成，但不更新界面。

成功：提示实际计数，关闭确认并清选择，进入 read barrier，等待当前 scope 的列表**实际成功读取**后才恢复选择及竞争写；不能拿 invalidate promise 已完成但 query 失败冒刷新成功。冲突／缺失／builtin／self／无效当前组：说明整批未应用，关闭旧确认、清选择，同样等待成功新读后重新选择确认。120001 或 HTTP401/403：撤销旧确认，重查当前身份，停写直到有效授权和列表读取恢复。普通 500／网络失败：保留相同 snapshot、目标和确认上下文，显示失败／结果可能需刷新确认，允许显式取消或手动再尝试；无自动 retry。读取失败显示持久重试，不能解锁 barrier；成功写后重读失败也不显示“写失败”。

HTTP 200 的坏 JSON／无效计数也属于结果不确定，保留确认上下文，不能以客户端解码的 100001 声称服务端未应用；只有真实服务端业务拒绝才清除快照并进入成功读取屏障。后端仍是最终授权。界面互斥和 guard 只保证可理解的操作，不把旧 user 列表或 auth/me 缓存当跨请求授权。

## 8. 自主裁决与如果错了的代价

1. 采用 1–100 条单事务，界面当前 20 项，不扩分页；若错，大名单需多次操作，但不会隐式选择看不到的账号。
2. 独立 POST 与计数响应，旧单账号不改；若错多一个小接口，以真实 App 契约避免旧 DTO 漂移。
3. 全批按类别错误优先级、先完整预检再写；若错管理员需刷新定位问题，换取不泄漏逐项信息及确定的零部分完成。
4. admin→user 共享组锁和 UUID 账号锁；若错长批次短暂阻塞组配置，五秒上限且真实并发回归约束，不扩超时。
5. active／disabled 目标均允许但只限当前 builtin user／admin；若错需先单独维护状态，批量不偷偷激活账号或支持未来自定义组。
6. 同组按原始版本校验后 no-op，只撤销实际变更账号旧 Session；若错管理员可能需再次确认，避免无意义踢出未变化用户。
7. 复用现有 SQLC 和审计，不建批次 schema；若错缺少批次级关联，但逐行 actor／时间和事务原子性可审，不增加不可回退模型。
8. 当前列表改为按身份／epoch 读取，竞争写与刷新 barrier 一并落在本页；若错既有测试 fixture 需同步真实查询契约，不为 fixture 在产品回退到共享旧缓存。
9. 普通错误保留快照且不自动 retry，不承诺 commit 断连恰好一次；若错多一次手动刷新，胜过静默重放提权操作。
10. 不重构 OIDC 供应或取消既有在途授权；若错登录完成时机仍有既有窗口，后续请求必须重查当前组，不把此版宣称完整会话冻结。

## 9. 留给实现者的常规细节

可自行命名私有 composable／测试 helper 和 CSS，选择等价 Vuetify 摘要布局；不能改变输入、数量、锁序、权限、错误优先级、no-op、会话、身份 guard 或 read barrier 合同。可在计划时补充确定测试名字／文件位置。设计 builder 只审可计划性，不替代实现终审或运行证据。
