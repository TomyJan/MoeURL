# CSV 测试夹具资源维护设计

## 意图与选择

用户要求限制临时资源并主动清理。ROOT 选择先处理已有审查记录中的小型资源窗口，再扩展产品；只做文案不能消除窗口，扩大生产清理框架则超出问题。这是自主授权下的 Agent 决定，不冒称用户逐项批准。

只修改 `scripts/csv-issues-fixture.test.mjs` 的测试夹具。保留真实回环 HTTP 和真实文件句柄，添加可传入的目录创建边界以构造真实占位冲突；默认调用仍创建相同前缀的唯一目录。创建成功后立即通过 `t.after` 登记清理，随后才打开文件、启动服务。清理使用嵌套 finally，使关闭服务失败仍尝试关闭句柄，句柄关闭失败仍删除准确目录；未获取的资源不关闭。产品生命周期 `web/e2e/csv-issues-fixture.ts` 不改。

## 行为证据

新增 `releases its directory when context handle initialization fails`：目录中预建 `browser-context`，真实 `open(wx+)` 拒绝为 EEXIST；消费捕获的测试清理回调后，该目录应不存在。旧夹具晚登记会保留目录，测试必须以行为断言失败。测试外层 finally 仍删除准确目录，RED 不泄漏。只在目录创建边界控制输入，不替换 open、rm 或服务端实际行为。

原有聚合四项错误的用例继续真实执行两个删除、停用和关闭；期望顺序为原首错、actual=7003/expected=0 的 AssertionError、actual=7004/expected=0 的 AssertionError、原关闭错误。单独初始化停用失败和列表失败补验 actual=7004、7002；这些已有行为首次通过就记补验。成功路径仍观察账号停用、短链清空和真实句柄 EBADF。
