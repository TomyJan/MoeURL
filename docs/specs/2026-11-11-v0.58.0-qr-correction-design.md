# v0.58.0 二维码纠错等级设计

## 选择与边界

在已经具备固定三色和 SVG 的共享弹窗上增加三个有限编码等级，复用现有 qrcode，不扩成模板系统。相比账号默认外观或上传 Logo，不引入身份资源、CAS、迁移或媒体安全面。此选择由 Agent 在持续开发授权内作出，用户没有指定等级目录；默认保持 M。正式转移必须在 PR300 真实审查、正常合并及恢复归档后进行。

## 状态与输出

新增本地固定目录 error-correction-levels.ts，key 仅 M／Q／H，labelKey 接入双语。selectedCorrection 初值 M；三个按钮置于单独具名 group，原颜色 group 不变。每个按钮有 aria-pressed，帮助文案说明较高等级可能让图案更密且不保证设备表现。

身份 watcher 同步恢复 classic 和 M，编码 watcher 读取 open／slug／url／preset／correction 的同一快照。等级变更和颜色变更各保留另一选择。每轮递增 generationId，清两种制品、错误和加载；PNG toDataURL 和独立 generateSvg 都显式传同一快照等级。generateSvg 不在 await 后读取可变选择。原 success／catch／finally 与卸载守卫继续生效，不允许旧 SVG 或 PNG 最终状态污染新选择。

保持完整 URL、320／白底／四模块静区、现有文件名和安全编码下载。PNG 编码失败显示既有错误、不调用 SVG；不能按失败自动降低等级或截断载荷。用户主动选择 M 或其他预设可重新生成。SVG 失败继续只影响其自身，PNG 不等它。

## 验证

新增组件 correction.test.ts，先在未实现组件的真实输出上确认缺少选择器与等级制品，不能用缺模块导入冒 RED。默认与原 M 输出相同；三等级各三颜色解析真实 SVG、对照独立按明确选项生成的 PNG，证明等级同时传给两格式。旧 PNG／SVG tests 保留。

使用真实 qrcode 作制品测试，只有异步时序和错误注入才替换编码阶段；明确每个测试抓住的破坏。受控 promise 验证旧 success／failure／finally 不发布制品、错误或结束新 loading；颜色／等级互相保留，slug-only／URL-only／关闭重开恢复 classic／M。长载荷真实触发高等级失败后主动回 M 恢复，不为 fixture 降低安全边界。

新增四组合浏览器场景覆盖双语和桌面／手机，三个真实入口，M→Q→H／颜色保持、两种实际下载、PNG／SVG按选择等级的模块一致性、无新产品请求及键盘。原整套浏览器身份完整收集，受影响原图与新图逐张ROOT读。此证据不冒实体扫码／打印、Firefox／Safari或读屏语音认证。
