# v0.22.0 批量短链归属转移设计

## 意图与设计选择

账号离职或资源误建时，管理员需要移交一组链接，保持已经分发的地址和历史统计。当前单条转移与列表多选均已实现；本版只补足管理后台已有规划中的批量归属转移。Agent 自主决定沿用 Go／SQLC／PostgreSQL 与 Vue／Vuetify，无新依赖、schema 或权限；不引入后台队列、跨页选择、个人赠送或部分成功协议。

## API 与权限

新增 `POST /api/v1/admin/short-link/batch-transfer`，仅接受媒体类型 `application/json`（允许合法参数）的一份严格对象：

```json
{"items":[{"id":"规范非零UUID","expectedUpdatedAt":"非零RFC3339Nano"}],"newOwnerUsername":"准确用户名"}
```

`items` 为 1–100 条不同的规范非零 UUID，每条必须含完整精度非零时间；拒绝缺失、null、未知字段、类型错误及尾随 JSON。用户名沿用单条转移：非空、精确匹配，不裁剪首尾空白、不折叠大小写、不额外限制既有合法长名。禁止自动重试写入。

要求当前账号启用、未删除、非 guest，且当前组同时具备 `admin:access` 和 `short_link:update_all`。接收账号必须启用、未删除，属于 user 或 admin；允许管理员本人及内置 admin，允许从已禁用账号移出。前端权限只控制入口，服务端为最终权威。

成功 data 为 `{transferredCount, unchangedCount}`，两者均为非负整数且合计等于请求数量；前端验证该一致性。业务失败 HTTP 200：非法请求 `100001`、无权 `120001`、任一链接不存在／软删 `200104`、任一版本冲突 `200116`、接收人不可用 `200117`。基础设施使用 HTTP 500／`900000`，日志仅请求 ID、安全 error_category 和 error_type，不记录 SQLSTATE、查询、密码、URL 或请求正文。响应 no-store，沿用现有登录中间件及严格媒体类型防跨源简单请求边界。

## 事务、锁序与数据保留

入口仍走既有 Resolver；随后派生 5 秒上下文并在同一 `WithAuditTx` 中执行：

1. 按 UUID 顺序锁定 actor 和精确用户名对应接收人的用户行。
2. 读取并 share-lock actor 当前组，从数据库快照重查授权；核对接收人当前状态与组。
3. 按 UUID 顺序锁定全部未软删目标短链。先比较数量，再检查每条当前 `updated_at` 与输入时间一致，完成全部预检之后才写入。
4. 相同 owner 计入 unchanged，不更新版本、不生成审计；即使相同 owner，陈旧版本也必须拒绝。
5. 其余仅更新 `owner_id`，以 `greatest(clock_timestamp(), updated_at + interval '1 microsecond')` 推进版本，每次实际 owner 变化由现有触发器原子审计。

任何失败都回滚全部变更及审计，不能在循环中逐条提交。锁序与单条转移、改组、批量写入一致；相反输入顺序不得造成死锁。已完成授权的在途读取不追溯撤销，后续个人读取／编辑／软删／统计必须按新 owner 判断，等待转移行锁的旧 owner 写入不能在移交后成功。

不更改公开 URL、短码、域名、目标、状态、到期、跳转模式、密码摘要／授权、额度与已用量、标题／标签或历史事件。新 owner 接管全部既有匿名统计；接收人创建域名权限不参与历史链接移交。现有单条转移 API 与错误契约不变，避免复制大块参与者校验逻辑，只提取确实共用的事务内逻辑。

## 控制台交互

只在全站当前列表的多选工具条提供「转移归属」，无独立导航。仅当前身份就绪、具有读写权限、列表成功且未刷新／出错、筛选已应用、无其他编辑或批量动作时可打开；无选中条目不可发起。打开固定 ID、完整版本、公开 URL、原 owner 和身份轮次的不可变快照。

确认框显示数量、链接／原 owner 摘要、准确接收用户名与“管理权及全部历史统计一起移交”的后果确认。列表摘要可滚动，长名和 URL 不导致手机横向溢出。确认前不得提交；提交期间禁止重复和关闭。对话框存在时阻止单条设置／启停／删除／转移、批量启停／删除及导出交叉操作。

身份／登录轮次变化或撤权应关闭并忽略迟到完成；成功结果不得清除新身份的选择或显示旧账号 Toast。普通失败保留输入、确认和有效选择，允许明确重试。版本冲突关闭旧快照并刷新列表，只有查询成功且刷新结束后才允许重新打开和确认，不能自动替换待确认版本；刷新失败仍禁止使用旧缓存再次转移。

成功显示正确中英复数计数、关闭、清理同身份选择，失效个人／全站列表、个人概览、统计及全站 insights。继续使用现有 Vuetify 标准交互、主题、动画和 reduced-motion 规则。

## 验证与边界

真实 PostgreSQL 覆盖 1／100／101、混合同 owner、全量版本预检、缺失／软删／授权撤销／接收人变化、反向批次并发、旧 owner 等待写入、审计与数据库故障原子回滚及全部未改字段／统计／授权保留。HTTP 验证单文档、媒体类型、no-store、路由和安全诊断。

前端验证严格计数、快照、确认、pending、普通失败、冲突刷新失败／成功、迟到事件、身份切换和撤权、当前选择清理及入口互斥。独立 fixture 的桌面／手机真实浏览器验证两条移交、新旧 owner 权限、历史统计、访问配置、同 owner 与冲突零写入。Go 业务与前端阈值维持 100%，SQLC 标准生成零漂移。

建造者已检查设计决策，没有剩余重要歧义；这是 Agent 的方案，不记为用户逐项批准。实现、本地门禁、目标 CI、合并和正式发布必须分开记录。
