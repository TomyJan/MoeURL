# v0.5.0 用户组权限管理范围

## 目标

v0.5.0 在现有 `user_group.permissions` 动态权限数据源之上，交付内置用户组权限管理闭环。管理员可以查看 `guest`、`user`、`admin` 三个内置用户组，按能力分类调整 `user` 和 `admin` 的可配置权限，并通过权限预设快速形成常见权限组合。`guest` 保持只读和无业务权限，避免在访客短链归属尚未实现时展示无法执行的假能力。

本版本不扩展完整 RBAC。用户仍只属于一个主用户组，权限预设只用于生成具体权限集合，不成为新的授权层。权限更新后的业务请求继续由后端从数据库解析当前用户组权限，不能依赖前端状态或进程重启。

## 范围决策

路线图在 v0.4.0 之后首先列出权限预设模型，控制台也已经保留用户组管理入口。当前数据库、Session 身份和各业务 Service 已统一使用 `user_group.permissions`，因此本版本选择补齐管理入口和写入边界，不同时引入自定义用户组、成员迁移或多用户组模型。

该范围可以独立形成生产闭环：管理员能看见当前真实权限、通过预设或逐项编辑生成新集合、处理并发冲突，并验证撤权对后续请求立即生效。

## 必须实现

- 将 `/admin/user/group` 从规划中占位页升级为真实用户组权限管理页，并从控制台导航移除“规划中”状态。
- 只列出 `guest`、`user`、`admin` 三个内置用户组，展示名称、标识、描述、内置状态、是否可编辑、当前权限和更新时间。
- `guest` 固定使用 `restricted` 且不可保存权限变更；`user` 和 `admin` 可以编辑可配置权限。
- 以稳定权限目录展示当前已实现的权限，不从数据库中的任意字符串动态生成可选项。
- 按短链基础能力、访问增强能力和管理能力分组展示权限；用户可配置权限使用复选框，受保护权限以只读状态展示。
- 提供 `restricted`、`basic`、`standard` 三个权限预设。套用预设只更新编辑草稿，管理员确认后再保存。
- 保存时由后端校验权限标识、重复项、内置用户组边界和受保护权限，不信任客户端提交的目录或保护状态。
- 使用 `updatedAt` 作为乐观并发前置条件；服务端检测到数据已被其他请求修改时拒绝覆盖，前端提示冲突并重新加载最新值。
- 权限更新成功后刷新用户组查询和 `auth/me`。当前操作者所在用户组被修改时，新的前端能力状态和后续后端请求都立即使用最新权限。
- 覆盖加载、空数据、权限不足、输入无效、并发冲突、保存失败和保存成功状态，并提供中英文文案与桌面/移动布局。

## 权限目录与预设

### 可配置权限

- `short_link:create`
- `short_link:read_own`
- `short_link:update_own`
- `short_link:delete_own`
- `short_link:use_intermediate`
- `short_link:set_expiration`
- `short_link:set_password`
- `short_link:use_confirmation`
- `domain:use_default`

### 受保护权限

以下权限固定属于 `admin`，不得从 `admin` 移除，也不得授予 `guest` 或 `user`：

- `admin:access`
- `short_link:read_all`
- `short_link:update_all`
- `short_link:delete_all`

保护管理权限可以避免管理员自锁，也避免把依赖 `admin:access` 的无效权限组合写入普通用户组。业务逻辑仍必须检查权限，不因固定保护策略改为按用户组标识硬编码放行。

此外，v0.5.0 固定 `guest` 权限为空。当前匿名身份没有可持久化的用户 ID，短链所有权和配额也未定义；访客业务能力必须在建立完整归属与滥用防护后单独开放。

### 权限预设

- `restricted`：不包含可配置业务权限。
- `basic`：包含创建、查看、更新、删除自己的短链以及使用默认域名。
- `standard`：包含全部可配置权限，与当前内置 `user` 的默认能力一致。

预设只适用于可编辑的 `user` 和 `admin`，只替换可配置权限；受保护权限始终按目标用户组的固定基线保留。`guest` 只展示 `restricted` 状态，不执行保存。预设不持久化为用户组字段，数据库仍只保存最终权限字符串数组。

## API 契约

```text
GET /api/v1/admin/user-group/list
  data.groups: UserGroup[]
  data.permissions: PermissionDefinition[]
  data.presets: PermissionPreset[]

POST /api/v1/admin/user-group/update-permissions
  groupKey: "user" | "admin"
  permissions: string[]
  expectedUpdatedAt: RFC 3339 Nano string，保留数据库完整小数秒精度

  data.group: UserGroup
```

`UserGroup.permissions` 返回完整的规范化权限数组，包括受保护权限；`UserGroup.editable` 明确当前组能否通过本 API 保存。权限定义返回稳定的权限标识、分类和是否受保护；名称和说明由前端 i18n 提供。预设返回标识、适用用户组和可配置权限数组。

业务错误继续使用 HTTP `200` 和统一数字 `code`：

- `120001`：当前用户没有 `admin:access`。
- `100001`：请求格式、权限标识或权限数组无效。
- `300201`：目标内置用户组不存在。
- `300202`：`updatedAt` 已变化，拒绝覆盖并发更新。
- `300203`：请求试图修改只读 `guest`，或改变受保护权限的固定归属。
- 基础设施错误使用 HTTP `500` 和 `900000`。

## 数据与一致性边界

- v0.5.0 不新增表或字段，不创建 Goose migration。
- 增加 SQLC 查询以列出内置用户组，并按 `key + updated_at` 条件更新权限。
- 保存前将权限按服务端目录顺序规范化，保证 JSON 数组稳定，未知项和重复项直接拒绝。
- 更新语句只允许修改 `user` 或 `admin` 两个内置目标组，并使用单次条件更新完成并发检查。
- `permission.DatabaseService` 继续按业务操作直接读取数据库，不增加跨请求缓存。
- `auth/me`、短链 Service 和用户 Service 保持同一数据库权限来源；前端权限控制只负责体验，后端授权仍是安全边界。

## 暂不实现

- 创建、删除或重命名自定义用户组。
- 修改用户所属组、批量迁移成员或一个用户加入多个用户组。
- 单用户权限例外、组织角色、团队空间或多租户权限。
- 域名级授权、配额、每日创建数量和默认有效期等参数化策略。
- 自定义权限标识、第三方插件权限注册或在线编辑权限目录。
- 访客创建短链、访客短链归属、访客配额和滥用防护。
- 权限变更审计日志、审批流、版本历史和一键回滚。
- OIDC、系统设置、主题配置和域名管理。

## 完成标准

- 管理员可以从真实页面查看三个内置用户组及其当前数据库权限，`guest` 明确保持只读。
- 逐项编辑和三个预设都能形成规范权限集合，保存前不会修改数据库。
- 未知、重复和受保护权限变更不能绕过后端；非管理员无法读取或更新用户组权限。
- 两个管理员基于同一旧版本编辑时，后提交者收到并发冲突，不能静默覆盖先提交结果。
- 撤销 `user` 或当前 `admin` 的可配置权限后，后续 `auth/me` 和业务请求立即反映变化；受保护管理能力保持固定。
- 后端测试、前端测试、覆盖率、lint、类型检查、生产构建和 Playwright E2E 全部通过。
