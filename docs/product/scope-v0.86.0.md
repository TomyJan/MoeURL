# v0.86.0 产品范围：CSV 标准字段子集

## 当前阶段

设计已确定，实施与验收按[计划](../implementation/v0.86.0-plan.md)和[验收](../implementation/v0.86.0-acceptance.md)分别记录。基线为 PR373 合并提交 `67d26fdf315540f6acc94bdc891366237d7fab17`，已交付运行产品仍为 0.85.0。

## 目的与取舍

用户准备批量短链时，应该能删除不需要的标准列，而无需为标题、标签等字段手工保留空列。复用原八种创建协议，按最高出现字段选择协议并补齐缺省；不扩展严格后端 DTO、授权或幂等模型。只放开标题／标签不能解决只填短码、过期或上限的相同问题，故一次支持八个标准字段的所有合法子集。

## 必须实现

- 必须恰有一个 `target_url`，其他七种标准字段任选、各最多一次、任意排列；逐字匹配，未知、重复、大小写或空白变体拒绝。
- 真实行宽先校验，缺失先行字段再补原缺省；不静默修复已提供的非法单元格，不改变字面值或行序。
- 复用原八协议、原权限链和后端缺省。非空秒数仍需显式 `redirect_mode=intermediate`，不能猜测方式。
- CSV 和补齐后完整 wire JSON 各最多 65536 字节；导入失败或权限不足保留原草稿。
- File 序号、身份与权限 epoch、未知结果相同请求重试、旧一列 consumer 和独立手动列映射保持。
- 中英帮助说明缺省及原权限要求，原八模板／示例逐字不变；真实桌面／手机验证。
- 顺带处理 v0.85.1 两组已登记文档 Minor，并准确补记其完成状态。

## 不纳入

别名、忽略未知列、Excel、远程上传、密码／备注／owner／历史列、完整恢复、批量编辑、持久草稿、新 API／权限／数据库／依赖、自动重试、发布部署。
