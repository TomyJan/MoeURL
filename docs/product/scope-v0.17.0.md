# v0.17.0 短链批量管理

## 目标与状态

从已核验的主分支 `bd4c2625`（PR #191，v0.16.0 聚合统计导出）开始，在独立分支补齐原路线图中的批量管理。当前产品代码候选为 `1c6df4a`，包含 `f4fbd632` 的 JSON 媒体类型安全修复；`33f287ec` 的完整门禁结果仅为安全修复前证据。截至 `1c6df4a` 的原始本地记录，修复后尚未完整重跑全仓 Go、Playwright 和前端门禁；后续 CI 及测试修正工作树的复验另见 [验收记录](../implementation/v0.17.0-acceptance.md)。目标 CI 全绿、合并和发布仍待完成。

## 必须实现

- 我的短链与全站短链通过标准表格多选当前列表记录，支持批量启用、停用和软删除。
- 每次接受 1–100 个不同的短链 UUID。整批原子执行，任一记录不存在、已删除或不属于可操作范围时不写入任何记录。
- 沿用个人更新／删除权限；后台另需 `admin:access` 及对应全站更新／删除权限，不新增授权或修改内置组。
- 数据库写入前重查当前账号状态及数据库授权。只修改状态或软删除标记，不覆盖目标、访问配置、元数据和额度。
- 选择不跨筛选、身份或页面；删除前明确数量与不可恢复提示。请求期间禁止重复操作，失败保留当前选择并允许刷新后重选，成功刷新相关列表和概览。
- 双语、移动布局、加载／错误状态、真实数据库原子性、覆盖率及隔离浏览器验证形成闭环。

## 不纳入

跨页全选、后台任务、导入导出、归属转移、批量编辑目标或访问配置、永久删除、撤销和回收站。

## 取舍

自定义用户组涉及管理权限和成员迁移的新安全模型；个人默认域名要扩展账号偏好与创建回退规则。当前先完成日常管理中的重复操作。采用有界同步请求和全有或全无语义，不让客户端循环单条写入形成难以恢复的部分成功。
