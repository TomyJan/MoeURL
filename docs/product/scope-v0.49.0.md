# v0.49.0 批量清空内部备注范围

2026-11-04 从完整交付的 PR263 master fa020805ed5499f40a9f437d710f3eb661247057 启动。Task1–3 已标准完成；唯一终审的成功后焦点问题已修复，对话框名称与英文单复数同步补齐。修复后 3239 项前端测试／四项 100%、types／lint／build、完整 191 项浏览器／58 张原图及精确产品验证通过；原执行与历史失败保持归属，Task3 本地归档与标准收尾完成，PR264 远端交付进行中。本版没有发布或部署；实际结果见[验收](../implementation/v0.49.0-acceptance.md)。

## 目标

在本人／全站短链列表清理当前页已不需要的内部备注，避免逐条打开保存。新增能力限于清空；不改变短链公开行为和其他业务字段。

## 必须实现

- 当前页选择 1–100 条，沿用现有选择边界；本人／全站使用固定作用域，不允许客户端声明 actor 或 scope。
- “清空备注”先实际预览，只显示选择数、非空数与已空数，不显示备注正文。全部为空时无需操作，不发清空请求。
- 用户明确确认后只发送一次清空请求；操作不可撤销，不能把关窗描述成取消服务端写入。
- 预览固定列表主版本，清空同时检查主版本与预览所得备注版本；全部目标授权、存在性和版本检查完成后才原子写入。
- 只清非空备注并推进其独立备注版本；空串 no-op 保留两版本、无审计。BOM 算非空，不改变单条备注规范化。
- 整批失败零业务写入、零新审计；真实变化按现有事务审计记录 actor 与 note 字段名，绝不记录正文。
- 身份、授权、页／筛选／大小及打开代际退休后，所有晚到结果均无私密状态、提示、缓存或锁的副作用。
- 网络或成功响应无法确认时冻结旧确认，用户必须实际重新预览并再次确认；无自动重试写入。
- 现有编辑、标签、转移、删除、创建、导出、QR、筛选和分页双向互斥，包括排队事件。成功保留筛选／条数，按真实刷新结果归一化页码。
- 中英、桌面／手机、键盘与焦点恢复，完整状态和错误反馈；列表、CSV、公开 API、URL 与 storage 不新增备注私密字段。

## 接口与权限

本人 `POST /api/v1/short-link/note/batch-clear/preview` 与 `POST /api/v1/short-link/note/batch-clear`；全站使用 `/api/v1/admin/short-link/note/` 同名路径。现有 Cookie Session、身份绑定 header 和 no-store 不变。

预览和清空均按单条备注写权限检查当前账号／组。本人要求 read_own、update_own、set_metadata；全站要求 admin:access、read_all、update_all、set_metadata。不新增权限。

1–100 个规范唯一非零 UUID，原始 JSON 上限 64 KiB，严格字段／重复键／Unicode／版本语法，总事务期限五秒。具体输入输出、错误码、锁序和纳秒比较以配套设计为准，不接受客户端计数或正文。
