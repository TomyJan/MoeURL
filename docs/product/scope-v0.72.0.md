## 必须实现

管理设置页在旧 general form 外提供独立中英卡片：输入一个完整 http/https 目标并显式检查。使用当前已保存的七份规则，不使用其他卡片未保存的草稿。结果仅为“当前规则允许”“目标格式或基础地址不允许”“被目标规则拒绝”。输入每次改变立即清除旧结果；失败保留输入，不自动请求或重试。

`POST /api/v1/admin/system/target-policy/check` 只读，严格 JSON 恰含 `targetUrl` 字符串；该接口独立上限为 2048 UTF-8 bytes，空、超限、控制字符、非法 UTF-8 和错误 JSON 返回业务码 `900226`。不改变旧创建接口的长度语义。合法载荷但 URL／基础地址不允许返回 `invalid_target`；策略拒绝返回 `restricted`；当前规则放行返回 `allowed`。HTTP200／code0 的 data 恰含 `outcome`，不回显 URL、查询、命中规则或账号信息。请求不允许 query；响应 no-store。

当前有效非 builtin 管理员及 `admin:access`、`system:manage` 才能检查。授权在数据库重新读取；不信任旧会话权限。五秒有界只读 ReadCommitted 事务先取得 shared policy gate，再授权、基础校验、完整读取并验证七份存储；对基础有效的目标，任一存储错误必须基础设施失败，不能变成允许或策略拒绝。基础非法不读取七存储，仍须先授权。完整策略复用原 `CheckTargets`，拒绝优先于三个允许集合的并集。

不写链接、审计、配额或回执，不解析 DNS，不访问目标。结果仅代表检查时点的目标准入，不检查短码、配额、其他创建权限或可达性，不表示安全认证或保证后续创建成功。
