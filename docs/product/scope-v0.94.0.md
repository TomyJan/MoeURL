# v0.94.0 多组补充授权范围

## 阶段与目标

v0.94.0 在不改变账号主组语义的前提下，允许普通持久化账号同时加入多个自定义补充组。每个账号仍保留一个主组，补充组只叠加已有可配置权限和明确的域名授权；不引入拒绝规则、组优先级或第二套身份模型。

该范围接续 v0.92.0 自定义组与 v0.93.0 自定义组批量主组迁移，解决一个团队账号需要组合多份可配置权限、但主组只能选一份的问题。v0.94.0 的产品决策依据是既有权限目录、fail-closed 自定义组约束和路线图的多组成员缺口。设计与实现仍需按独立 migration、API、UI 和验收切片推进；不改变显示产品版本，不表示发布。

## 范围决策

- `app_user.group_id` 保留为唯一主组，继续承担既有 `group` API 字段、主组默认域名和兼容行为。
- 新增用户与自定义组之间的补充成员关系。仅可加入非 builtin 自定义组；guest、user、admin 不作为补充组，admin 权限仍只能由主组 builtin admin 提供。
- 目标资格按 `app_user.builtin` 判断：只拒绝 builtin 账号记录，不因普通持久化账号的主组为 `admin` 而拒绝；仍拒绝操作者本人。
- 有效权限为主组与全部补充自定义组的并集。自定义组仍不得拥有任何 protected 权限；不实现权限拒绝、组顺序优先级或用户级权限例外。
- 主组和补充组的域名权限与显式域名 grant 取并集。用户个人默认域名仍按当前规则优先；之后仍只使用主组默认域名，再回退全局默认。补充组的默认域名不改变默认选择。
- 成员关系变更必须基于完整精度用户版本进行 CAS，按当前数据库身份重新授权；真实变化撤销目标全部 Session 并在同一事务写一条不含前后值的审计记录。准确同值仍先检查版本，再作为无写入 no-op。

## 必须实现

- 使用 Goose migration 建立账号与补充自定义组的关系表；保存稳定 UUID 外键及唯一性，删除账号时关联可安全清理，删除用户组时由 Service 检查主组及补充成员均为空。migration Down 遇到仍存在的补充成员数据时安全拒绝，不丢弃数据。
- 新增严格 `POST /api/v1/admin/user/update-group-memberships`：按用户 ID、补充组 key 完整集合及原始完整精度 `expectedUpdatedAt` 原子替换补充组集合；拒绝未知、重复、builtin、guest、primary 重复 key、builtin 账号、自身目标或不完整请求。沿用现有统一错误 envelope、状态码与 no-store 约定。
- 用户列表为每个用户返回主组及稳定排序的补充组 key／名称；`auth/me` 保留原 `group` 主组字段，并以新增字段返回补充组 key。旧单组客户端仍可读取原字段。
- 权限解析改为从当前数据库账号及主／补充组读取权限并形成单次调用不可变快照。既有业务授权路径按账号 ID 解析，不依赖登录态、列表缓存或编译期权限；任一组缺失、权限 JSON 无效或读取故障均失败关闭。
- 自定义组 memberCount 与删除保护统计主组及补充成员且不重复计数。所有短链权限检查与域名可用性判断使用主／补充组权限及 grant 并集；主组默认域名和既有个人默认、全局 fallback 顺序保持明确。
- 管理用户页面可查看、添加和移除补充组；使用当前身份组目录，目标组冻结并显示名称，变更期间禁重复提交。失败需重新读取，不自动重放写入。保留现有单账号主组迁移和 v0.93 主组批量迁移的 API 语义。
- 为 migration、权限 Resolver、用户创建／身份读取、主组及补充组权限组合、域名 grant/default、审计／Session 撤销、CAS、删除竞态和桌面／手机 E2E 提供真实回归。

## 非目标与反目标

- 不允许一个账号有多个主组；补充成员仅指自定义附加授权组。
- 不支持组嵌套、拒绝规则、优先级、自动 OIDC 组映射、OIDC 声明同步、访客持久化、个人权限例外或多租户。
- 不改变既有 primary group API、权限目录、protected 权限归属、短链归属、默认域名优先级或公开 URL。
- 不自动迁移用户主组；migration 对现有账号补充成员集合为空。
- 不新增依赖、审批系统或异步批处理，不降低 coverage 门槛。

## 主要风险

| 风险 | 控制与验收 |
| --- | --- |
| 主／补充组权限合并漏在某条授权路径 | 全面盘点 Resolver 与 SQL 直接权限查询；所有生产 Service 改为按账号解析，补 permission matrix 和 fail-closed 测试 |
| 补充组意外授予管理权限 | 补充成员只接受自定义组，protected 权限仍拒绝写入且仅主组 admin 能提供；HTTP／Service／真实数据库均覆盖 |
| 用户组删除留下外键或错误 memberCount | 同一用户行锁顺序下检查两类成员关系，删除与添加并发以真实 PostgreSQL 锁步验证 |
| 域名默认值因多个组出现歧义 | 仅主组参与组默认域名回退；补充组只参与权限与显式授权并集 |
| Session 或权限缓存延迟撤权 | 权限 Resolver 每个操作读取当前数据库；实际成员变化同事务撤销全部旧 Session |
| Down 丢失补充成员 | 有关系行时 Down 安全失败并保留表数据，验证 Up/Down/retry 分支 |
