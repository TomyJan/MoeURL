# v0.13.0 个人密码修改

状态：设计与实施中；基线为已合并 v0.12.0 的 `17e1f766`。功能、本地门禁、CI 和生产发布分别记录。

## 目标与决策

补齐个人设置中已有规划的本地密码自助修改。相比账号绑定和自定义用户组，该能力有明确的账号边界，且不需要扩展身份或权限模型。只修改当前登录账号已有的本地密码，不能为纯 OIDC 账号建立本地凭据。

## 必须实现

- `/profile` 提供独立的密码修改区域，先读取服务端可用状态，失败可重试；有本地密码才开放表单。
- 当前密码必须正确，新密码为 8–128 个 Unicode 字符，且不得与当前密码相同；密码按原值处理，不裁剪、不转义、不归一化。
- 校验、更新密码、清除失败状态和撤销全部现有 Session 在同一事务中完成。成功后清除浏览器 Cookie、敏感草稿和用户缓存，并进入登录页。
- 已登录非 guest 用户仅能修改自己的凭据，不需要管理员权限；禁用、删除、失效 Session 和内置 guest 均拒绝。
- 复用登录的数据库失败窗口与并发槽位；当前密码错误计入同一账号的 10 次／15 分钟限制，客户端取消不得绕过计数。
- 登录读用户时持有共享行锁至 Session 提交，改密使用排他行锁；改密事务在锁定用户后重新检查请求 Session，避免旧凭据和旧 Session 的并发竞态。
- 本地登录开关只控制新的本地登录，不禁止已登录用户修改已有密码；页面明确提示修改密码不会开启本地登录。
- 中英文、桌面和手机状态完整，操作反馈使用既有堆叠 Toast。

## 不纳入

找回密码、自助注册、首次设置 OIDC 账号密码、管理员重置行为改造、账号绑定、会话列表、头像和服务端偏好。没有新增权限、环境变量或 schema migration。

## 接口与验收

新增 `GET /api/v1/auth/password/status` 与 `POST /api/v1/auth/password/change`，沿用 Cookie Session 和 no-store。详细契约见 [设计](../specs/2026-10-15-v0.13.0-password-change-design.md)。后端事务、真实数据库故障与并发、前端敏感数据边界及真实浏览器闭环必须验证；目标 CI、race、完整容器和生产证据缺失时保持待验证。
