## 必须实现

- 支持八种既有完整列集合的任意排列。标准序列为 `target_url,title,tags,custom_slug,redirect_mode,expires_at,max_visits,intermediate_delay_seconds`；合法集合只能是该序列的前 1 至 8 列，列位置可变。例如 `title,target_url` 合法，`expires_at,target_url` 不合法。
- 表头仍逐字匹配、区分大小写，不 trim、不识别别名；重复、未知、缺列、额外列、行宽不一致均整体拒绝。保持 UTF-8、单个起始 BOM、严格引号／CRLF、1–20 行及 CSV／完整 JSON 各最多 65536 字节的既有边界。
- 按表头位置关联原值，只调整对象字段对应，不调整数据行顺序，不 trim、解析重编码或修改字段内容。tags 仍为原来的 JSON 数组单元格，所有业务字段继续由原 schema 校验。
- 列集合决定原有 mode／端点／DTO；同一有序内容无论表格列序如何，得到相同完整对象和字面值。旧模板逐字不变、旧规范顺序仍合法，旧一列 consumer 仍只接受 targets。
- 文件读取、身份和权限 epoch、旧草稿保留、预览冻结、未知结果原 UUID／payload 重试全部复用；新增回归必须穿过真实 parser 和 hook／组件，不能只测重排辅助方法。
- 双语格式帮助说明“标准列名可调顺序，但每种格式不能缺列或多列”，示例和下载模板继续给规范顺序。手机帮助可读，不新增配置表单。
- 本地完整前端四项 100%、types／lint／相关 E2E strict／隔离构建；准确新 web 与守恒后端组合产品、真实中英文桌面／手机浏览器及原图。最后唯一 fresh 独立终审、真实 CodeRabbit、正常合并核验和可恢复归档。
