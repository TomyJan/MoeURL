# v0.2.0 范围

## 目标

v0.2.0 完成短链访问体验与生命周期闭环：在既有直接跳转、短链管理和统计链路之上，提供中间页跳转、可选过期时间、二维码和可编辑的访问配置，让短链从「创建后只能直接跳转」推进到「可以按用途配置、展示和管理」。

主线为：

```text
访问配置建模 → 权限化创建与编辑 → 中间页访问 → 过期拦截 → 二维码使用 → 自动化验收
```

## 版本策略

本阶段使用 v0.2.0，而不是继续追加 v0.1.x 小版本。原因是本版本会同时扩展数据库 schema、短链 API、访问路由、权限模型、创建组件和管理流程，属于跨模块的访问能力升级。

本版本不直接进入 v1.0.0。域名管理、用户组权限编辑、访问密码、安全限流和系统配置仍未形成完整生产闭环，继续使用 v0.x 可以保持版本承诺与实际能力一致。

## 必须实现

- 通过 Goose migration 为短链增加跳转模式、中间页倒计时和可选过期时间。
- 支持 `direct` 和 `intermediate` 两种跳转模式，既有短链默认保持 `direct`。
- 中间页倒计时默认 5 秒，可配置范围为 3 至 10 秒。
- 中间页展示目标主机名、剩余时间、立即前往和返回首页操作，不向预览 API 暴露完整目标 URL。
- 只有最终向目标链接写出跳转响应后才记录 `redirect_response_sent`；进入中间页不计入访问量。
- 过期短链在访问时被拦截，不写入成功访问事件，并返回明确的过期状态。
- 新增 `short_link:use_intermediate` 和 `short_link:set_expiration` 权限；内置 `user`、`admin` 用户组默认拥有，`guest` 默认不拥有。
- 创建短链组件提供折叠的高级设置，按权限控制中间页和过期时间选项。
- 我的短链和全站短链展示跳转模式与过期信息，并提供访问配置编辑入口。
- 创建成功区、我的短链和全站短链提供二维码入口；二维码在浏览器中按短链 URL 即时生成，不写入数据库。
- 新增固定前端路由 `/go/:slug`，并同步更新后端静态路由和短码保留规则。
- 修复退出登录 E2E 的异步竞态，新增中间页、过期拦截、配置编辑和二维码 E2E 覆盖。
- 后端与前端业务覆盖率门禁继续保持 100%，生产构建不新增大分块警告。

## 数据与权限边界

- `redirect_mode` 只允许 `direct` 或 `intermediate`。
- `intermediate_delay_seconds` 必须在 3 至 10 秒之间；直接跳转模式下保存默认值但不参与访问流程。
- `expires_at` 使用 `timestamptz`，为空表示不设置固定过期时间；设置时必须晚于服务端当前时间。
- 过期不复用 `disabled` 状态，也不修改短链记录；访问时根据 `expires_at` 动态判断。
- 只有拥有对应权限的用户才能创建或编辑中间页和过期配置；管理员编辑全站短链时仍走现有管理员权限边界。
- 二维码只编码当前短链公开 URL，不包含目标 URL、用户信息、统计数据或其他私有字段。
- 中间页预览 API 只返回短码、目标主机名、倒计时和过期时间，不返回完整目标 URL。

## API 与路由

- `POST /api/v1/short-link/create` 接受跳转模式、倒计时和可选过期配置。
- `POST /api/v1/short-link/update` 与管理员更新接口支持修改访问配置；未提供的字段保持原值。
- `GET /api/v1/public/short-link/preview?slug=...` 返回中间页所需的最小公开信息。
- `GET /{slug}` 对直接模式写出目标跳转，对中间页模式进入 `/go/{slug}`。
- `GET /go/{slug}/continue` 重新检查短链的 `status`、`deleted_at` 和 `expires_at`；仅对仍启用、未软删除且未过期的短链写出目标跳转并记录 `redirect_response_sent` 成功访问事件。软删除短链按不存在处理，不得跳转或记录成功访问事件。
- 业务错误继续使用统一数字 `code`；公开短链的不存在、禁用和过期状态沿用适合浏览器访问的 HTTP 响应。

## 暂不实现

- 访问密码、密码尝试限流和短期访问授权。
- 确认页跳转。
- 自定义短码、标题、备注和标签。
- 最大访问次数。
- 二维码样式、Logo 合成、批量下载和服务端图片存储。
- 中间页模板管理、自定义背景图和自定义文案。
- 用户组权限编辑、权限预设和自定义用户组。
- 完整域名管理、用户默认域名和用户组默认域名。

访问密码不与本版本捆绑。该能力需要同时设计暴力尝试限流、代理来源信任、短期授权和多实例一致性，单独规划可以避免交付一个表面可用但安全边界不完整的实现。

## 完成标准

- 既有直接跳转短链在 migration 后保持原行为。
- 有权限的用户可以创建和编辑中间页短链与过期时间，无权限用户不能绕过后端校验。
- 中间页在桌面端和移动端完整展示，并可等待倒计时或立即继续。
- 过期短链不会跳转到目标 URL，也不会增加访问量。
- 二维码可以生成、预览和下载，编码内容等于短链公开 URL。
- 我的短链和全站短链能正确展示和维护新增配置。
- 数据库迁移可升级、可回滚，SQLC 生成代码与查询测试通过。
- `go test ./...`、`go vet ./...`、后端覆盖率、前端 lint、类型检查、测试、覆盖率、构建和 Playwright E2E 全部通过。
