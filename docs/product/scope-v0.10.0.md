# v0.10.0 短链最大访问次数闭环范围

状态：设计和实施计划已建立，功能尚未实现，所有工程与发布门禁保持待验证。

## 目标

v0.10.0 在现有短链访问条件、权限目录和最终跳转统计之上，增加可选的最大访问次数。有限额短链在最终外部跳转前通过 PostgreSQL 原子领取额度，达到上限后展示统一耗尽状态；默认无限额短链保持现有访问性能和行为。

## 必须实现

- 新增 `short_link:set_max_visits` 权限，默认授予内置 `user` 和 `admin`，不授予 `guest`。
- 创建短链时可以设置 1 至 2147483647 的最大访问次数，默认无限额。
- 编辑有限额短链时可以调整上限并保留当前额度用量；清除限额结束当前额度周期，再次设置时从 0 开始。
- direct、intermediate、confirmation 和访问密码组合只在最终目标跳转时消耗额度。
- 最后一个名额必须通过数据库条件更新原子领取，多实例并发下不得超发。
- 达到上限后，公开入口、预览、解锁和继续访问使用统一 `exhausted` 状态，且不泄露额度数值或目标 URL。
- 我的短链和全站短链列表展示有限额短链的已用量、上限、剩余量和耗尽状态；现有访问统计继续保持独立口径。
- 创建面板和设置对话框覆盖权限、输入校验、清除周期和降低上限后立即耗尽的反馈。

## 数据与接口影响

- 新增 Goose migration，为 `short_link` 增加 `max_visits` 和 `visits_used`，并追加权限。
- 创建请求新增可选 `maxVisits`；更新请求新增可选 `visitLimit` 模式对象。
- 短链管理响应新增 `maxVisits`、`visitsUsed`、`visitsRemaining` 和 `exhausted`。
- 公开 Preview 不返回额度字段，只通过既有公开状态流程表达耗尽。
- 不新增环境变量、部署服务或外部依赖。

## 暂不实现

- 每日、每月或自定义周期自动重置。
- 独立手动清零、一次性链接快捷模式和额度历史。
- 按访问者、来源、域名或用户组拆分额度。
- 额度告警、通知、批量设置和额度报表。
- 把异步访问事件改造成强一致计费流水。

## 完成标准

- migration Up、Down 和再次 Up 保持数据与权限回滚语义。
- 有限额短链在多实例等价并发测试中严格不超发；无限额短链不执行额度写入。
- 所有访问模式、密码、禁用、过期、域名和软删除组合保持既有边界。
- 后端、前端、权限目录、生成文件、E2E、Compose smoke 和文档门禁通过。
- 本地实现证据、目标 CI、安全扫描和生产发布证据分别记录；缺失时不得声称版本已发布。
