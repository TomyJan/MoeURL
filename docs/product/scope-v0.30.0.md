依据 [路线图](roadmap.md)、[进度清单](development-status.md)及 v0.19.0 单账号改组基础，root 按长期自主设计授权选择此有界版本；具体常规决策及错误代价见[设计](../specs/2026-10-28-v0.30.0-batch-group-membership-design.md)，不声称用户逐项批准。设计经一次 fresh builder check 后形成完整计划，再由 root 原生 TDD 实现；实现后仅一次 fresh 最强完整终审，root 集中修复。

## 目标

管理员从当前用户列表选择其他非内置账号，一次确认将其主用户组统一设置为内置 `user` 或 `admin`。整批成功或整批零写入，实际变更账号的全部旧会话撤销与既有审计同事务提交，避免连续单账号操作的部分完成及权限确认遗漏。

## 必须实现

- 一个独立严格 no-store 的 `POST /api/v1/admin/user/batch-change-group`；1–100 个唯一规范 UUID 和逐项原始完整版本，统一目标 `groupKey`。不扩旧单账号请求或返回 DTO。
- 五秒审计事务，actor 与全部 target 的账号行按 UUID 顺序加排他锁，然后锁当前 admin／user 组共享行；等待后重查当前 DB 账号及 `admin:access`。不信入口旧组名或旧权限。
- 保护自身、全部 builtin、已删除／缺失及非内置 user／admin 成员；允许 active／disabled 的既有目标，状态不变。全批保护和版本校验完成后才写；陈旧同组仍冲突，当前同组 no-op。
- 返回 `changedCount`／`unchangedCount`，实际变化只改 `group_id` 和单调 `updated_at`，逐账号撤销旧 Session、同事务记录 `user/update/group_id`。任何 SQL／审计／撤销或事务失败不留下部分变更；不增加批次表或新的审计动作。
- 当前列表多选／全选仅选可操作目标；现有页面继续展示前 20 项，不增加分页、搜索、跨页全选或后台任务。API 上限与既有批量规范一致，界面不能选不可见账号。
- 确认对话框冻结选中账号／组／完整版本，滚动摘要、统一目标、实际变化及不变数量、提权／降权与重新登录警示；明确确认且至少一项变化才能提交。pending 禁重复与竞争的账号写入。
- 列表读取与确认按用户 ID／登录 epoch 隔离，切换身份／撤权／卸载后迟到结果不得反馈或发布新身份状态；后台刷新不替换已开快照。成功／冲突后明确读屏障，成功刷新才允许重新选择；普通失败保留草稿、不自动重试写。
- 保留旧单账号改组及用户昵称／状态／重置密码的 API 含义；中英双语、桌面和手机真实使用。完整 Go／业务 100、前端四 100／静态／隔离构建、真实 DB／HTTP／并发／故障、完整 browser／当前截图与精确新 image／标准 smoke／同 image 安全门禁分别记录。

## 非目标与反目标

不提供自定义组、多组、OIDC 映射或绑定、批量启停／删用户／重置密码、账号导入、跨页选择、个人赠送、头像／时区、审批或撤销。不得用逐个调用旧 Service 的多个事务冒全批原子性，不取消已授权的其他在途请求，不将登录响应中的旧权限当作后续请求授权，不追溯改变短链归属／统计／域名或偏好。不正式部署、打 tag 或发布。
