# v0.1.1 范围

## 目标

v0.1.1 完成控制台概览闭环：将 `/console` 从规划中占位页替换为基于当前用户真实数据的工作台，让用户登录后可以快速了解自己的短链规模和访问表现，并继续进入短链管理或访问分析。

主线为：

```text
用户短链聚合查询 → 权限 API → 概览指标与最近短链 → 控制台入口 → 自动化验收
```

## 必须实现

- 新增 `GET /api/v1/short-link/overview`，返回当前用户的短链总数、启用数、总访问量和今日访问量。
- 聚合查询只统计当前用户拥有且未软删除的短链；访问量只统计 `redirect_response_sent`。
- `/console` 展示四项真实指标和最近创建的 5 条短链，不展示推测值或伪造趋势。
- 最近短链复用既有短链列表 API 和列表项统计，不增加重复的数据契约。
- 页面提供「我的短链」和「访问分析」入口，并覆盖加载、局部错误、空数据和移动端状态。
- 控制台概览导航移除「规划中」标识，中英文文案保持完整。

## 数据与权限边界

- API 使用 `short_link:read_own` 权限，管理员进入个人概览时同样只查看自己的数据。
- 禁用短链计入短链总数，但不计入启用数；软删除短链不计入任何指标。
- 总访问量和今日访问量包含当前用户全部未删除短链的成功跳转事件，不受短链当前启用状态影响。
- 今日边界沿用 PostgreSQL 当前日期，与既有列表和单短链统计口径一致。
- 聚合查询失败返回基础设施级 `500`；业务权限不足返回 HTTP `200` 和统一业务错误码。

## 暂不实现

- 系统级管理员仪表盘、用户数量、全站短链指标和系统健康状态。
- 全局近 7 天趋势、跨短链来源/设备/地区聚合和任意日期范围。
- 在概览页新增第二套短链创建表单。
- 访问明细、导出、访问密码、过期时间、二维码、中间页和确认页。

## 完成标准

- 聚合 SQL、权限服务、HTTP API、前端 API 和概览页均有自动化测试。
- `/console` 使用真实数据，并可进入既有短链管理和访问分析流程。
- `go test ./...`、`go vet ./...`、后端覆盖率门禁，以及前端 lint、类型检查、测试、覆盖率和构建全部通过。
