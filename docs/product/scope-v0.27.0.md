# v0.27.0 域名排序

## 目标与阶段

本轮后端与前端实现、任务完成契约及完整本地门禁已通过。候选 `6a46a48a0890a39a8b3cb2dca7b94ccfc795503d` 完整浏览器 99 项通过，Linux race／安全与新精确生产镜像 smoke／扫描通过；独立终审、归档及远端交付仍待，尚未推送或创建 PR。逐候选运行时与证据见[验收](../implementation/v0.27.0-acceptance.md)。独立分支 `feat/v0.27.0-domain-order` 从 v0.26 PR #224 的合并提交 `60b36fec2d063785a8c97855d5a6d38a950c4ad3` 起步。上一轮最终 PR 和合并 CI 已分别取得真实 9 项成功，实际 CodeRabbit 已覆盖最新候选；这些结果不替代本轮验证。

补齐 roadmap 中的域名排序：管理员为短链域名设置排序值，用户只在自己已获授权的候选中看到稳定顺序，个人偏好和临时明确选择继续优先。当前全局默认固定排在候选首位；排序不改变服务器省略 `domainId` 的全局默认语义。

## 必须实现

- 域名新增整数排序值，范围 -10000 至 10000，默认 0，较小值优先。同值继续按创建时间、UUID 稳定排序；当前全局默认始终优先。
- 管理列表与授权可用列表使用同一顺序。授权、启用及用途过滤在排序前执行；不返回无权限域名，available 响应无需暴露排序值。
- 管理页提供独立排序保存，复用 `admin:access` 与 `domain:manage`、当前数据库账号／组校验及域名完整精度版本。支持默认、停用和被短链引用的域名调整排序，不改变其他属性或授权。
- 旧创建、域名更新／设默认／删除及账号偏好接口的请求语义不变，省略排序字段的旧保存不能重置排序值；旧语言／主题和个人域名偏好不被覆盖。
- 排序同值且版本当前时 no-op，不推进版本或审计；陈旧版本即使值相同仍冲突。实际变化只更新排序与单调版本，审计只记字段名 `sort_order`，失败全事务回滚。
- 双语的整数校验、加载／权限／错误／冲突及明确重载、身份轮次隔离、草稿保护和排序后服务器顺序刷新形成闭环。排序与普通详情编辑互斥，避免隐式重放或未保存字段丢失。
- migration Up／Down／再 Up、标准 SQLC 零漂移、真实权限／数据库／并发／审计、前端有效回归、桌面与手机浏览器及完整门禁形成可追溯证据。

## 不纳入

用户组默认域名、默认跳转方式、全表拖拽或批量重排、跨账号个性排序、短链归属或域名迁移、公开短链解析规则修改、自助域名绑定、自动 DNS/TLS、新权限和新依赖。
