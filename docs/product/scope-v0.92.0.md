# v0.92.0 自定义用户组

## 当前状态

功能实现已在 `feat/v0.92.0-custom-user-groups` 完成本地 Task 1–5 并提交；Task 6 文档、生成物漂移和整体验收仍在进行。该分支尚未创建 PR、合并或发布；产品版本号不因本范围文档而改变。准确验证及待办见 [v0.92.0 验收](../implementation/v0.92.0-acceptance.md)。

## 目标

- 管理员可以查看、创建、编辑和删除自定义用户组。创建时服务端生成不透明、稳定 UUID key；客户端只传组名称和描述。
- 自定义组权限初始为空。可配置权限来自既有 catalog；protected 管理权限只能由 builtin `admin` 持有。
- 每个用户仍只有一个主组。管理员可创建用户或将单个非 builtin 账号迁入、迁出自定义组；现有批量迁组继续只接受 builtin `user`／`admin`。
- 自定义组可获明确的域名授权、配置其组默认域名，并据当前组权限使用短链功能。
- 组权限、名称、描述、域名授权及默认域名沿用完整精度并发版本；组权限变更立即影响后续请求，不引入权限缓存。
- 删除自定义组须在事务内确认没有任何账号引用。组关联域名授权随删除级联清理，域名本身和已有短链保持不变；成员仍存在时拒绝删除。
- 组管理、用户创建／迁组、域名授权和权限选择器消费服务端组列表；前端不硬编码自定义 key。

## 权限与一致性边界

- 所有组管理和成员管理写入由当前 Cookie 身份授权，事务内重新读取 actor、builtin admin 组及 `admin:access`。
- 配置域名授权或默认域名还需要 `domain:manage`，且必须在同一事务验证目标域名启用、已授权并符合组权限。
- `guest` 持久化组保持只读空权限，不可创建或迁移 guest 用户；builtin admin、自身改组和管理员自锁边界不变。
- 单账号组迁移继续使用完整版本、审计及实际组变化时的 Session 撤销语义。同组 no-op 不写审计或撤销会话。
- 失败关闭；权限或配置冲突不自动覆盖或自动重试写入，身份 epoch 变化和迟到响应不得污染新账号状态。

## 非目标

- 多主组、权限并集／交集、拒绝规则、个人级权限例外、组织／租户、模板市场、自动 OIDC 组映射。
- 新权限目录项、新会话模型、新依赖，以及自定义组的批量成员迁移。
- guest 资源归属、域名/DNS/TLS 供应、公开短链 URL 或已保存短链的域名迁移。
- CI、发布或部署状态不由本地验收推断；均不属于本范围的默认实施动作。
