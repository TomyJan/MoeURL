# v0.6.0 生产就绪闭环范围

状态：设计和实施计划已于 2026-08-29 确认，代码实现与生产验收尚未完成。

## 目标

v0.6.0 将 MoeURL 从「功能闭环完整」推进到「可按明确边界生产部署和维护」。目标部署形态固定为单机 Docker Compose，TLS、证书续期和公网入口由同机或外部反向代理负责；MoeURL 应用与 PostgreSQL 只暴露完成该拓扑所需的最小网络边界。

本版本不新增短链产品功能。实现重点是进程生命周期、HTTP 防护、健康检查、初始化与登录保护、Session 清理、Compose 安全默认值、备份恢复说明和最小安全 CI。所有生产声明必须由可重复的命令、真实运行环境和验收记录支撑。

## 当前能力结论

截至 v0.5.0，v0.0.1 至 v0.5.0 范围文档中的核心必须实现项均有对应代码和自动化测试支撑。产品总览、稳定规格和路线图还描述了完整目标形态及远期能力，因此「文档中出现」不等于「当前版本已经实现」。

当前状态分为三类：

| 类别 | 状态 | 说明 |
| --- | --- | --- |
| v0.0.1 至 v0.5.0 已完成范围 | 已实现 | 初始化、账号与权限、短链管理、统计、个人概览、访问配置、密码、确认页和内置用户组权限管理均有实现与测试。 |
| 历史验收记录 | 判定入口已校正 | v0.5.0 的 Node.js 26.x CI 证据已回填；v0.0.1 验收清单保留原始未勾选状态并标明历史性质，不能作为当前功能缺失清单。 |
| 路线图和稳定规格中的远期能力 | 未纳入当前实现 | 系统设置、完整域名管理、OIDC、自定义用户组、多用户组、审计日志、最大访问次数、模板、风险审核、批量导入导出和 Webhook 等仍需独立版本设计。 |

v0.6.0 只修正文档判定入口和生产工程缺口，不把远期产品能力改写为已完成，也不为追溯性美化而批量勾选缺少原始证据的历史验收项。

## 部署边界

生产拓扑固定为：

```text
互联网
  ↓ HTTPS
外部 TLS 反向代理
  ↓ HTTP，仅主机回环或受控容器网络
MoeURL App
  ↓ Docker 内部网络
PostgreSQL
```

责任边界如下：

- 反向代理负责 TLS 终止、证书续期、HSTS、公网入口访问日志和基于来源地址的端点限流。
- MoeURL 负责请求 ID、panic 恢复、安全响应头、请求体限制、应用级登录保护、健康检查和优雅退出。
- PostgreSQL 不在默认生产 Compose 中映射宿主机端口。
- MoeURL 宿主机端口默认只绑定 `127.0.0.1`，部署者必须通过反向代理提供公网 HTTPS。
- 生产数据库密码必须由部署者显式提供，不允许使用仓库内默认密码。

## 必须实现

### 应用生命周期与 HTTP 边界

- 进程监听 `SIGINT` 和 `SIGTERM`，在有界超时内停止接收新请求、等待在途请求、停止后台清理任务并关闭数据库连接。
- HTTP Server 配置读取、写入、空闲和 Header 超时，以及明确的 `MaxHeaderBytes`。
- Router 增加可追踪的请求 ID、panic 恢复、安全响应头和全局 JSON 请求体上限。
- 请求日志包含请求 ID、方法、路径、状态、响应大小和耗时；panic 和未知基础设施错误使用同一注入 logger 记录，不向客户端泄露内部错误。
- 应用启动时验证数据库连接，数据库不可用时启动失败。

### 健康检查

- 提供 liveness 和 readiness 两类端点。
- liveness 只判断进程是否仍能处理 HTTP 请求，不依赖数据库。
- readiness 使用短超时探测 PostgreSQL；依赖不可用时返回 HTTP `503`，不得报告就绪。
- 保留 `/api/v1/health` 兼容入口，并让它使用 readiness 语义。
- 应用容器增加 healthcheck，Compose 以 readiness 判断服务健康。

### 初始化与登录保护

- `MOEURL_ENV=production` 时必须配置高熵初始化 Token；缺失或不满足最低长度时应用拒绝启动。
- 未初始化系统的 setup 请求必须提供正确 Token。Token 不写入数据库、不进入日志、不在任何响应中返回。
- 开发环境允许不配置初始化 Token，保持本地和 E2E 初始化效率。
- 登录对已存在和不存在的用户名执行等价的密码哈希验证路径，降低账号枚举的时间差异。
- 登录失败状态保存在 PostgreSQL，并按规范化用户名的不可逆摘要聚合，保证多进程状态一致且不新增明文用户名副本。
- 同一用户名在 15 分钟窗口内失败 10 次后阻断 15 分钟；成功登录清理该用户名的失败状态。
- 登录事务脱离客户端请求取消并受独立期限约束，客户端断开后仍完成一次密码校验和失败状态提交；基础设施失败必须回滚，回滚使用独立的有界清理 Context。
- 后台任务每轮最多删除 500 条 `updated_at` 已超过完整 15 分钟窗口、且当前不在阻断期的陈旧登录失败状态；任务启动后立即执行一轮，随后每 15 分钟执行，单轮失败记录安全错误后继续下一轮，并可由应用生命周期取消。
- 登录响应不区分用户名不存在和密码错误；反向代理还必须对登录、初始化和公开解锁端点实施来源级限流。

### Session 生命周期

- 后台任务分批删除已经过期或撤销的 Session，避免表无限增长。
- 清理使用独立数据库操作、固定批量上限和可取消 Context；失败只记录日志，不中断在线请求。
- 登录失败状态清理不是 Session 清理；两者使用不同的删除条件和 SQLC 查询，不能共用数据保留口径。
- 应用退出时等待登录失败状态清理、Session 清理和既有短链授权清理任务结束，且不超过统一关闭期限。

### Compose 与运维文档

- 默认 Compose 移除 PostgreSQL 宿主机端口，应用端口默认绑定回环地址。
- 数据库密码改为必填部署变量，`.env.example` 只提供变量名和生成说明，不提供可直接用于生产的弱密码。
- 应用容器使用非 root 用户、只读根文件系统、临时目录、健康检查和明确重启策略。
- 提供单机 Compose 部署、外部 TLS 反向代理、备份恢复、升级前备份、失败恢复和灾难恢复演练说明。
- 备份恢复验收必须在隔离数据库完成，不允许用生产数据库直接试验恢复命令。

### CI 与发布证据

- 在既有测试门禁之外增加 Go race 检查、Go 漏洞检查和最终容器镜像漏洞扫描。
- 固定新增工具或 Action 的版本，不使用浮动 `latest`。
- 保持现有 Go 业务源码和前端覆盖率门禁，不通过降低阈值或扩大排除范围换取通过。
- 生产 Compose 必须完成配置解析、构建、健康启动、首次初始化、重启保留数据和清理验证。
- 验收记录分别记录本地结果和目标 CI 结果；引用 CI 时包含提交 SHA、运行链接和任务结果。

### 文档状态同步

- 回填 v0.5.0 在 Node.js 26.x 下已经通过的 CI 证据。
- 在产品总览、路线图和文档索引中把 v0.6.0 标为当前设计与实施入口。
- 明确历史验收清单、已完成版本范围和远期规格的不同用途，避免把远期目标误判为实现承诺。
- 删除技术基线中没有实现依据的建议环境变量，环境变量清单只保留真实契约和本版本新增配置。
- 修正默认 Compose「生产语义」描述，使文档在生产硬化实现前后都与实际行为一致。

## 数据与 API 影响

- 新增登录失败状态表、`updated_at` 清理索引及对应 Goose migration 和 SQLC 查询。
- Session 表结构保持不变，只增加分批清理查询。
- 初始化请求增加可选的 `setupToken` 字段；生产环境必填，开发环境可省略。
- 新增 `/api/v1/health/live` 和 `/api/v1/health/ready`；`/api/v1/health` 保持兼容。
- 登录限流增加稳定业务错误码，仍使用 HTTP `200` 表达可预期业务失败。
- readiness 依赖失败属于基础设施状态，使用 HTTP `503`。

## 暂不实现

- 多主机、高可用、自动故障转移和 PostgreSQL 流复制。
- Kubernetes、Helm、Docker Swarm 或云厂商专用部署模板。
- 内置 ACME、证书管理或由 MoeURL 直接监听公网 TLS。
- Prometheus 指标、分布式追踪、集中日志平台和完整告警系统。
- 事件表聚合、归档和保留策略。删除历史事件会改变累计访问量，必须先独立设计聚合基线。
- 在线备份调度器、对象存储上传、备份加密管理和 Web 管理页面。
- 基于客户端 IP 的应用内限流。MoeURL 不在本版本信任未经验证的代理来源头。
- OIDC、自定义用户组、系统设置、完整域名管理、审计日志和其他路线图产品能力。

## 完成标准

- 一台干净主机可以按文档用 Docker Compose 启动 MoeURL，并通过外部 TLS 反向代理安全访问。
- PostgreSQL 不暴露宿主机端口，MoeURL 默认仅监听宿主机回环地址，弱默认数据库密码不再存在。
- 数据库不可用时 readiness 和容器健康状态失败，数据库恢复后可重新就绪。
- 收到终止信号时应用完成有界优雅退出，不遗留后台任务或异常数据库连接。
- 生产环境不能绕过初始化 Token；登录恒定失败路径和数据库限流通过并发及时间边界测试。
- 客户端取消不能绕过登录失败计数；陈旧登录失败状态按 500 行单批、立即执行和 15 分钟周期安全回收，清理失败不终止后续调度。
- 过期和撤销 Session 可以分批清理，清理失败不影响在线请求。
- 备份可以在隔离环境恢复，并验证 schema 版本、管理员登录和短链数据。
- 既有 v0.0.1 至 v0.5.0 核心流程、覆盖率和 E2E 不回退。
- race、漏洞、镜像扫描、Compose smoke test 和既有全部 CI 门禁通过，并在验收记录中提供目标提交证据。
