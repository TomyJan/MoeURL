在个人设置中明确保存一个当前可用的短链域名，之后在其他浏览器登录时，创建面板优先选择该域名，减少重复选择。该偏好只决定界面初始选择，不新增域名授权，不改变既有创建 API 省略 `domainId` 使用全局默认的语义。

## 必须实现

- 本地和 OIDC 的启用账号可查看、保存或清除自己的域名偏好，guest 不可访问；Cookie 决定账号，不接受请求中的用户 ID。
- 个人设置提供“沿用系统选择”和当前已获授权的启用域名，独立显式保存、独立版本和冲突恢复，不与语言／主题的保存请求相互覆盖。
- 保存指定域名必须同时满足当前数据库账号／组、`short_link:create`、该域名对应的 `domain:use_default` 或 `domain:use_assigned` 以及组授权。无创建能力仍可读取／清除本人已有偏好。
- 首页 inline、桌面创建对话框和移动创建面板共用同一初始选择规则；手动选择优先于迟到偏好，成功创建／显式重置后重新采用最新已加载偏好。
- 偏好域名不可用时，回退到可用全局默认，再到现有可用列表的首项；提示已回退，不暴露失去授权域名的名称或地址。没有可用域名继续禁用创建。
- 域名被删除时同事务清除关联偏好并推进其版本，不能让陈旧编辑覆盖清理；停用或撤权不删除偏好，重新可用后下次加载可恢复。
- 身份轮次隔离所有偏好及可用域名数据；退出、同账号重新登录、换账号和迟到读写不得继承上一轮选择、结果或通知。
- migration 往返、标准 SQLC 生成及零漂移、真实数据库／并发／HTTP、前端有效回归／覆盖率、双语双视口真实浏览器、完整门禁及独立审查形成闭环。

## 不纳入

用户组默认域名、域名排序管理、自助域名绑定、自动 DNS/TLS、既有短链迁移、用户默认跳转模式、头像／时区、后台代改个人设置、推送同步和程序化接口鉴权。旧客户端忽略偏好仍按原创建 API 执行；本版不把偏好升级为强制路由策略。
