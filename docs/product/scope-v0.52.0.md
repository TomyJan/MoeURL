# v0.52.0 批量追加内部备注范围

状态：实现、本地门禁、224 项完整浏览器、准确产品及唯一独立终审通过，两个 Minor 延后；标准合同收尾与远端审查／合并／归档继续。基线为 PR279 已交付的 master `636cefd6f4b38cec884f6658807044279728c0c3`；分支 `feat/v0.52.0-batch-note-append`。执行者根据路线图及无人值守授权自主选择，见[设计](../specs/2026-11-09-v0.52.0-batch-note-append-design.md)、[计划](../implementation/v0.52.0-plan.md)和[验收](../implementation/v0.52.0-acceptance.md)。

## 目标与必须实现

- 本人／全站短链列表当前页选择 1–100 条，保留旧内部备注，在末尾换行追加同一非空文本；旧备注为空时直接写入新文本。
- 沿用 CRLF 规范化、控制字符先校验及 Go 空白语义；每条结果最多 1000 Unicode 码点，任一超长就整批拒绝，不截断或跳过。
- 四个独立 POST 端点，主版本／备注版本双 CAS、事务内当前权限与完整目标预检；只返回版本和计数，不返回旧正文或长度。
- 独立永久摘要回执，让同一 requestId 的网络重试只追加一次；不同内容复用 requestId 明确冲突，重放仍要求当前权限。
- 真实预览后显式确认；保存中显示反馈，未知结果冻结同 payload／key 并仅手动重试；身份、授权、草稿及所有异步阶段隔离。
- 本地真实 RED→GREEN、完整门禁、浏览器与原图、准确产品及唯一独立终审；最新 CodeRabbit 真实覆盖和正常守卫合并、独立核验与可恢复归档。不等待或伪称 GitHub CI。

## 非目标与选择理由

批量清空和替换已经交付，追加可避免逐条编辑并保留已有说明。完整历史、撤销与跨页全选会扩大数据留存和误操作面，故不纳入。已有相同末尾文本不会自动去重，防重只针对同一次 requestId，不改变用户明确再次追加的意图。

不增加权限、依赖、顶层导航、公开字段、备注正文导出、后台任务、全匹配操作或自动重试。不改旧清空／替换／单条编辑协议；新增的数据库表仅保存追加回执，不保存备注正文。已有回执时回滚安全拒绝。不发布部署、不触日常数据或 PR240／266／267。
