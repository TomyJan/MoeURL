# v0.7.0 多提供商 OIDC 登录范围

状态：功能实现与本地可执行门禁已完成；目标 CI、race、外部 OIDC 互操作和生产发布验收待补。

## 目标

v0.7.0 在现有本地账号、Cookie Session 和数据库权限模型之上补齐多提供商 OIDC 登录闭环。部署管理员可以配置多个标准 OIDC 提供商；符合提供商访问策略的外部身份首次登录时创建受控的本地 `user` 账号，后续继续使用 MoeURL 既有 Session、用户状态和权限判断。

本版本的重点是身份协议、安全边界、账号供应和可运维配置，不把系统品牌、通用系统设置或完整企业身份治理一并实现。

## 必须实现

### 提供商管理

- 管理员可以查看、新增、编辑、启停和软删除多个 OIDC 提供商。
- 提供商包含稳定键、显示名称、Issuer URL、Client ID、Client Secret、允许的邮箱域名、启用状态和乐观并发时间戳。
- 保存或启用提供商时通过 OIDC Discovery 校验 Issuer、授权端点、Token 端点和 JWKS 地址。
- Client Secret 使用部署密钥加密后保存；列表与详情 API 只返回是否已配置，不回传明文或密文。
- 软删除保留既有外部身份归属，提供商键不得被另一提供商复用。
- 管理操作继续受 `admin:access` 保护，不新增与现有权限目录重叠的授权层。

### 登录协议

- 登录页读取当前可用登录方式，并展示所有已启用的 OIDC 提供商。
- OIDC 登录使用 Authorization Code Flow、PKCE S256、随机 `state` 和随机 `nonce`。
- 登录尝试保存在服务端，`state` 和浏览器关联令牌只保存摘要，PKCE verifier 加密保存，且只能消费一次。
- 回调严格校验发起浏览器、提供商、Issuer、唯一 Audience、可选 `azp`、签名、过期时间、`nonce` 和一次性状态。
- 登录完成后签发现有 `moeurl_session` Cookie，并只恢复经过验证的站内相对路径。
- 提供商停用、登录尝试过期或重放、用户禁用、声明不完整和外部协议失败均关闭失败，不泄露 Token、Secret 或底层响应。

### 外部身份与首次供应

- 外部身份以 `(provider_id, subject)` 唯一绑定本地用户，不根据邮箱自动绑定既有本地账号。
- 首次登录必须提供经过验证的邮箱，并匹配管理员配置的精确邮箱域名白名单。
- 首次登录创建非内置、启用的本地 `user` 账号；不得通过提供商配置自动创建 `admin`。
- 本地用户名由提供商键和 `subject` 的不可逆摘要稳定生成，避免保存外部用户名作为认证标识。
- 昵称优先使用标准 `name`、`preferred_username` 和邮箱本地部分，并执行现有长度与非空约束。
- 重复登录复用既有绑定；邮箱变化不隐式迁移或合并账号，本地用户禁用后外部登录立即失效。

### 配置与运维

- 新增 `MOEURL_PUBLIC_BASE_URL`，用于生成固定 OIDC 回调地址；启用 OIDC 时必须为无用户信息、无查询和片段的绝对 HTTPS 地址，开发环境允许回环 HTTP。
- 新增 `MOEURL_OIDC_ENCRYPTION_KEY`，使用 Base64 编码的 32 字节密钥；存在 OIDC 配置时缺失或非法应使相关能力关闭失败。
- 既有未配置 OIDC 的部署可以继续启动并使用本地登录。
- 新增有界的过期 OIDC 登录尝试清理任务，并纳入应用退出等待。
- 部署文档说明回调地址、反向代理可信 Host、密钥备份和密钥丢失后果。

### 前端与体验

- 登录页保留本地登录表单，并在存在启用提供商时展示外部登录入口。
- `/admin/setting` 从纯占位页升级为本版本的“身份认证”管理页面，但不开放其他系统设置表单。
- 管理页覆盖加载、空状态、保存、冲突、发现失败、停用、删除和 Secret 保留/替换状态。
- 页面支持简体中文和英语，并适配桌面与移动端。
- Client Secret 不进入长期响应、查询缓存、Mutation variables 或可复用响应对象；提交完成后立即清空输入并释放短期载荷。

## 数据与 API 影响

- 新增 `oidc_provider`、`external_identity` 和 `oidc_login_attempt` 表及必要约束、索引和清理查询。
- 新增公开登录方式接口、OIDC 开始与回调路由。
- 新增管理员 OIDC 提供商列表、创建、更新和删除接口。
- 既有 `app_user`、`session` 和权限数据模型保持兼容；OIDC 成功后复用现有 Session 与 `auth/me`。
- migration Down 仅在尚无外部身份绑定时允许删除 OIDC schema；已有绑定时安全失败，避免不可逆丢失登录归属。

## 暂不实现

- 禁用本地登录。
- 用户主动绑定、解绑或合并本地账号与外部身份。
- 根据邮箱自动绑定既有账号。
- 自动授予 `admin`、组映射表达式、多用户组或组织同步。
- OIDC 提供商预置模板、图标上传或自定义字段映射。
- OAuth 2.0-only 提供商、SAML、LDAP、SCIM、设备码登录或 Passkey。
- Client Secret 在线轮换历史、部署密钥在线轮换和外部密钥管理服务集成。
- 系统品牌、页脚、主题、域名和其他系统设置。

## 完成标准

- 管理员可以配置至少两个标准 OIDC 提供商，并在登录页看到稳定、可区分的入口。
- 一个符合邮箱域名策略的新外部身份可以完成首次登录、创建本地 `user`、获得 Session 并访问既有控制台。
- 同一身份再次登录复用同一用户；状态重放、错误 nonce、错误 issuer/audience、未验证邮箱和禁用用户均被拒绝。
- Client Secret 不出现在 API 响应、日志、前端缓存或数据库明文中。
- OIDC 配置冲突不会静默覆盖，已软删除提供商不能继续登录。
- migration、SQLC、后端单元与集成测试、前端测试、构建、覆盖率和 Playwright OIDC 主流程通过。
- 既有本地登录、用户管理、权限、短链、公开访问和生产部署门禁不回退。
