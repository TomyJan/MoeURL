# v0.93.0 自定义组批量成员迁移实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 executing-plans 逐任务原生实现此计划。按仓库约定原子提交并逐任务验证。

**目标：** 将现有有界原子批量改组端点扩展至 v0.92 可分配的自定义组，并让当前管理员列表可安全选择这些组。

**架构：** 保留现有 API 和结果协议；服务层通过现有自定义组排他锁和可分配规则固定目标，按现有账号 UUID 锁、授权、CAS、审计与会话撤销完成单事务。前端以当前身份作用域的组目录补足可选 key/name，并冻结提交快照。

**技术栈：** Go、pgx、现有 SQLC 查询、PostgreSQL；Vue 3、TanStack Query、Vuetify 4、zod、vee-validate、vue-i18n。无 schema、生成物或依赖改动。

**规格：** `docs/product/scope-v0.93.0.md`、`docs/superpowers/specs/2026-11-25-v0.93.0-custom-group-batch-design.md`

## 全局约束

- 沿用 1–100 个唯一规范 UUID、逐成员完整 `updatedAt`、五秒审计事务及现有结果和错误 envelope。
- 目标和每个源组必须是当前数据库可分配组；guest／builtin 约束、当前事务内 admin 授权不放宽。
- 全批锁定、校验后才写；陈旧同组冲突，当前同组 no-op；失败全回滚。
- 真正变化的成员才更新时间、撤销旧 Session 和记录 `user/update/group_id` 审计。
- 前端目录和账号快照不得跨身份 epoch；读屏障未完成前不得再次写。
- 不新增迁移、API 路由、依赖、缓存、跨页选择或发布动作。

## 审查重点（Review Focus）

1. 自定义目标与并发删除交错：账号锁和目标排他锁决定唯一先后；不得把已提交成员留在删除组，也不得静默写入已删除目标。由真实 PostgreSQL 双方向同步测试覆盖。
2. actor 等待锁期间权限撤销或账号禁用：必须在获得锁后按数据库当前状态拒绝整批，不信旧 Cookie／组快照。由受控锁竞争测试覆盖。
3. 混合 builtin、custom、deleted、self 和 stale 成员且打乱请求顺序：首个保护错误保持既有稳定优先级；全批无更新、撤销或审计。扩展 `TestBatchChangeGroupErrorPriority`。
4. 第二项更新、会话撤销或审计失败：首项也回滚，旧 Session 保持有效、计数清零。扩展 `TestBatchChangeGroupRollback`。
5. 当前身份变化或目录刷新失败／过时：不能向新身份提交旧批次或以旧组名确认；须显式成功读回后重试。
