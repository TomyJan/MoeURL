# v0.92.0 自定义用户组实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 在保留单主用户组模型的前提下，交付可安全创建、配置、分配和删除的自定义用户组。

**架构：** 扩展现有 `user_group`／`app_user.group_id` 模型，不增加多组关联表。新增组管理能力复用当前权限目录、组版本和管理事务；自定义组使用不可变 UUID key，初始权限和域名授权均为空。先完成数据库与 usergroup API，再把成员迁移、域名授权／默认值和前端改为读取动态组列表。

**技术栈：** Go、Chi、PostgreSQL、Goose、SQLC 1.30.0、Vue 3、TypeScript、Vuetify 4、TanStack Query、Zod、现有 Playwright E2E。

**规格：** `docs/superpowers/specs/2026-11-23-v0.92.0-custom-user-groups-design.md`

## 全局约束

- 每个账号仍只有一个 `app_user.group_id` 主组；不实现多组并集、交集或拒绝规则。
- 自定义组 key 为服务端生成 UUID 字符串且不可变；组名规范化后在全部组中大小写不敏感唯一，名称最多 64 个 Unicode 字符，描述最多 500 个 Unicode 字符。
- 自定义组只能拥有非 protected 权限；`admin:access` 和其他 protected 权限仍只属于 builtin `admin`。
- 新自定义组 fail-closed：权限为空、域名 grant 为空、默认域名为空。
- 组删除只允许无 `app_user` 引用的非 builtin 组；内置组不可删除。
- 普通非 builtin 账号沿用 v0.19 边界，可迁移到 `user`、`admin` 或自定义组；builtin 账号和当前操作者自身仍受保护。
- API 使用 `/api/v1`、严格 JSON、统一 envelope、业务失败 HTTP 200／数字 code、基础设施失败 HTTP 500。
- 新增 SQLC 代码只能由仓库锁定 SQLC 生成，不能手工编辑生成文件；提交前运行 `git diff --check`。
- 不查 CI、不部署、不发布、不触碰 PR #240、#266、#267；所有独立资源用后精确清理。

## 审查重点（Review Focus）

- 重名组在大小写／首尾空白归一后必须被拒绝，而不是产生两个不可区分的组。
- 自定义组提交 protected 权限必须拒绝并保持数据库和版本不变。
- 删除竞争：组在检查后被分配成员时必须安全拒绝或回滚，不能留下孤儿用户。
- 组权限、成员迁移和域名授权并发时必须遵守既有锁序并用完整精度版本拒绝陈旧写入。
- 自定义组撤权后，后续请求必须从数据库读取新权限；不能继续使用旧 Cookie、前端缓存或静态 admin 判断。
