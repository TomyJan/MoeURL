# v0.91.0 短链跨页手动选择设计

## 意图

用户在本人短链或全站短链的分页列表中逐页检查记录时，希望保留自己明确勾选的记录，并在同一筛选结果里跨页执行既有批量操作。当前列表翻页会清空选择，用户必须反复操作或改变筛选范围才能凑齐一批。

## 目标

- 本人和全站短链列表均允许跨页保留用户逐行手动选择的 ID。
- 沿用现有批量工具栏、确认快照、动作授权、100 条 API 上限及服务端原子写入。
- 当前页表头的全选／半选只表示当前页；全选只添加当前页，取消全选只移除当前页，不能静默清除其他页的选择。
- 同一已应用筛选结果中的手动选择最多 100 条。若新增当前页全选会使唯一 ID 总数超过 100，整次全选不生效并显示双语上限提示；不部分选择。
- 当前已确认页在后台刷新后，只剔除刷新前该页存在、而刷新后已不存在的所选 ID；不得把其他页所选 ID 当成缺失记录清除。
- 筛选草稿／已应用条件变化、身份或登录轮次变化、权限集合变化时，清空选择与删除确认快照。

## 非目标

- 不提供“全选所有筛选结果”、跨页全选、选择跨筛选结果、选择持久化、后台任务或部分成功。
- 不新增 API、数据库、权限、依赖或批量动作；不改变短链排序、分页大小、CSV、导出或其他批量编辑契约。
- 不把分页期间并发新增／删除定义为跨请求快照。服务端仍以提交时的当前授权、目标范围与原子批量接口为最终权威。

## 交互与状态边界

- 选择集合按用户交互顺序保留唯一 ID；工具栏计数反映所有页的已选记录，并明确说明范围是当前筛选下手动选择的记录、最多 100 条。
- 表格表头状态仅由当前页 ID 计算：当前页 ID 全选才为全选；至少一个但非全部当前页 ID 被选才为半选；其他页的选择不影响表头状态。
- 当前页全选将当前页所有 ID 与已有选择合并。若合并后超过 100 个唯一 ID，维持全选前的原集合并提示上限。当前页取消全选只删除该页 ID。
- 已选 100 条时，行内仍允许取消已选项；未选行继续沿用表格现有禁用态，不产生额外 toast。调用层即使收到越限选中事件也必须拒绝新增，不能溢出上限。
- 切换页码或每页条数保留所选集合。成功读回同一页时，将该页刷新前的 ID 与刷新后的 ID 比较，只清除刷新前属于该页且已消失的选中项。新页读取完成不将其与旧页比较。
- 继续沿用过滤期间的操作锁、身份轮次守卫、异步结果隔离和冻结的删除目标快照；筛选、身份或权限改变时，旧请求只能完成原网络操作，不得对新上下文显示反馈或清除其选择。

## 实现决定

- 在 `useShortLinkBatch` 中将完整选择集合与当前页 ID 分开处理；由页面提供稳定的页身份（页码与每页条数）及读回就绪信号，保证刷新收敛只针对同一页。
- 页面提供的 selection filters 不包含页码和每页条数；身份单独由现有 identity scope 管理，权限变化由完整当前权限集合的稳定签名识别。
- 既有表格组件沿用其 checkbox 视觉与交互；只调整当前页状态计算、全选增删语义及工具栏范围提示。
- 上限拒绝使用既有 toast 反馈模式新增本地化文案，不安装依赖。

## 验收

- hook 测试证明跨页保留、当前页全选与取消、页头全／半选局部语义、同页刷新仅剔除本页消失 ID、过滤／身份／权限重置、恰好 100 条接受及超过上限原集合不变并提示。
- 本人和全站页面测试各自从第一页勾选后翻到下一页，确认计数与选择保持、页头状态局部、提交仍只调用既有动作 API 且使用被选 ID。
- 现有分页、批量删除确认快照、错误重试、过滤和身份竞态测试保持通过。
- 运行仓库既有前端测试、类型检查、lint 与生产构建；不查 CI、不发布或部署。
