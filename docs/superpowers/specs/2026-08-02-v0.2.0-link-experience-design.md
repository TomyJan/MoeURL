# v0.2.0 短链访问体验与生命周期设计

## 1. 背景

MoeURL 已完成初始化、登录、短链创建与管理、基础统计、访问分析、控制台概览和个人设置。当前短链仍只有直接跳转一种访问方式，创建后也不能配置过期时间；二维码没有正式入口，访问配置无法在列表中查看或维护。

路线图列出了中间页跳转、访问密码、短链过期时间、二维码、权限预设和管理配置等增强能力，但尚未定义下一版本边界。本设计根据现有实现、风险和可验证性，将下一个跨模块版本确定为 v0.2.0「短链访问体验与生命周期」。

## 3. 方案比较

### 3.1 访问体验与生命周期闭环

一次完成中间页、过期时间、二维码和配置编辑。四项能力共享短链创建、访问和管理边界，可以使用一组分阶段 migration、一套 API 扩展和一组前端设置组件交付。该方案直接改善核心短链流程，风险可以通过现有测试体系覆盖。

### 3.2 访问密码优先

访问密码用户价值高，但生产实现不能止于保存哈希和校验密码。还必须处理暴力尝试限流、反向代理来源信任、短期访问授权、重复提交和多实例一致性。若与其他能力一起交付，会让版本的安全风险和验收成本显著增加。

### 3.3 管理配置优先

域名、用户组、权限预设和系统设置能增强管理能力，但会同时改动权限计算、初始化数据、后台信息架构和多个资源模型。该方案范围过宽，也不能直接改善普通用户最常用的创建与访问流程。

本设计采用方案 3.1。版本号使用 v0.2.0，因为变更跨越 schema、API、公共访问路由和控制台管理；暂不进入 v1.0.0，因为安全访问和完整管理配置仍未闭环。

## 4. 目标与非目标

### 4.1 目标

- 保持既有短链默认直接跳转且无需人工迁移。
- 让有权限的用户创建和编辑中间页短链与过期时间。
- 让中间页进入、最终跳转和统计事件之间有清晰口径。
- 让用户从创建结果和列表生成、预览、下载二维码。
- 完成桌面端、移动端、错误状态、覆盖率和 E2E 验收。

### 4.2 非目标

- 不实现访问密码、确认页、最大访问次数或自定义短码。
- 不实现中间页模板、图片背景、自定义文案或广告能力。
- 不实现二维码样式编辑、批量生成或服务端存储。
- 不实现域名管理、用户组管理、权限预设或系统设置表单。

## 5. 数据设计

新增 Goose migration `00004_short_link_experience.sql`，原子增加字段、未验证约束和内置权限：

```sql
alter table short_link
    add column redirect_mode text not null default 'direct',
    add column intermediate_delay_seconds smallint not null default 5,
    add column expires_at timestamptz;

alter table short_link
    add constraint short_link_redirect_mode_check
        check (redirect_mode in ('direct', 'intermediate')) not valid,
    add constraint short_link_intermediate_delay_check
        check (intermediate_delay_seconds between 3 and 10) not valid;
```

同一 migration 为内置 `user` 和 `admin` 用户组条件追加以下权限，已有值不重复写入：

- `short_link:use_intermediate`
- `short_link:set_expiration`

`00005_validate_short_link_experience.sql` 在独立事务中执行 `VALIDATE CONSTRAINT`。这样新增约束立即约束后续写入，历史数据扫描又不会把 v4 的强锁保持到验证结束。完整 Down 流程由 v4 删除新增权限、约束和字段；约束验证本身不做无意义的反向操作。

既有记录通过默认值保持 `direct` 和 5 秒，不改变原跳转行为。`expires_at` 为空表示不设置固定过期时间；过期是访问时的动态结果，不写回 `status`。

## 6. 权限与业务规则

- 创建中间页短链要求 `short_link:create`、`domain:use_default` 和 `short_link:use_intermediate`。
- 设置过期时间额外要求 `short_link:set_expiration`。
- 编辑自己的访问配置继续要求 `short_link:update_own`，再叠加对应能力权限。
- 管理员编辑全站短链继续要求 `admin:access` 和 `short_link:update_all`，并按内置管理员权限获得新增能力。
- `guest` 默认不获得新增权限。
- 直接跳转是既有创建能力的默认行为，不增加新的直接跳转权限，避免破坏已部署实例的兼容性。
- 二维码只是公开短链 URL 的另一种展示形式，不引入独立权限。

服务端是过期判断的权威来源。创建或编辑时，非空 `expires_at` 必须晚于服务端当前时间；访问时 `expires_at <= now()` 即视为过期。

## 7. API 契约

### 7.1 创建与更新

创建请求扩展为：

```json
{
  "targetUrl": "https://example.com/docs",
  "redirectMode": "intermediate",
  "intermediateDelaySeconds": 5,
  "expiration": {
    "mode": "at",
    "expiresAt": "2026-08-10T12:00:00Z"
  }
}
```

`redirectMode` 缺省为 `direct`，`intermediateDelaySeconds` 缺省为 5。`expiration` 缺省或 `mode = "never"` 表示不设置固定过期时间。

用户和管理员更新接口接受相同访问配置。更新请求未提供 `redirectMode`、`intermediateDelaySeconds` 或 `expiration` 时保持原值；显式发送 `expiration.mode = "never"` 时清除过期时间。这样既有只更新状态的请求不会意外清空访问配置。

短链响应增加：

```json
{
  "redirectMode": "intermediate",
  "intermediateDelaySeconds": 5,
  "expiresAt": "2026-08-10T12:00:00Z",
  "expired": false
}
```

### 7.2 公开预览

新增：

```text
GET /api/v1/public/short-link/preview?slug=abc123
```

仅为有效的中间页短链返回：

```json
{
  "slug": "abc123",
  "targetHost": "example.com",
  "intermediateDelaySeconds": 5,
  "expiresAt": "2026-08-10T12:00:00Z"
}
```

接口不返回完整目标 URL。不存在、禁用、过期或非中间页短链使用稳定业务错误码；数据库错误返回 HTTP `500`。

### 7.3 公共访问路由

```text
GET /{slug}
  direct       → 302 目标 URL，并在成功写出响应后记录访问
  intermediate → 302 /go/{slug}，不记录成功访问
  expired      → 200 明确过期状态，不记录成功访问

GET /go/{slug}
  → 返回前端 App Shell，由 RedirectPage 加载公开预览

GET /go/{slug}/continue
  → 重新检查状态与过期时间，成功时 302 目标 URL 并记录访问
```

进入中间页时记录 `short_link_opened` 和 `access_condition_checked`。只有继续路由准备返回目标链接时记录 `redirect_initiated`，且响应成功写出后才记录 `redirect_response_sent`。如果倒计时期间短链被禁用、删除或过期，继续路由必须拒绝跳转并记录 `redirect_blocked`。

## 8. 后端结构

- `internal/shortlink/model.go` 承载访问配置、公开预览和响应字段。
- `internal/shortlink/service.go` 负责创建与编辑时的权限、模式、倒计时和过期校验。
- `internal/shortlink/redirect_service.go` 分离初次打开、公开预览和最终继续三个读取动作，但共用状态与过期判断。
- `internal/shortlink/redirect_handler.go` 负责内部中间页跳转、公开预览响应、最终目标跳转和事件写出时机。
- `queries/short_link.sql` 返回新增字段，并确保更新请求可以区分「未提供」与「清除过期时间」。
- `internal/http/router.go` 先注册 `/go/{slug}` 与 `/go/{slug}/continue`，再注册低优先级 `/{slug}`。

不创建新的跳转模块。新增行为仍属于 `shortlink` 的创建、管理和访问职责，拆出独立模块只会增加跨模块数据搬运。

## 9. 前端设计

### 9.1 创建组件

`ShortLinkCreatePanel` 保留目标 URL 作为首要输入，在下方增加默认折叠的高级设置：

- 跳转模式使用选项控件，提供直接跳转和中间页。
- 中间页倒计时使用 3 至 10 秒的整数滑杆，仅在中间页模式显示。
- 过期时间使用开关和本地日期时间输入，关闭时表示长期有效。
- 无对应权限时不展示高阶字段，后端仍执行权威权限校验。

创建成功后继续提供复制、打开和继续创建，并增加二维码图标操作。

### 9.2 列表与编辑

短链行新增可扫描的模式与过期信息。更多操作菜单增加「访问配置」和「二维码」：

- `ShortLinkSettingsDialog` 复用在我的短链和全站短链，编辑目标 URL、跳转模式、倒计时和过期时间。
- 用户页调用个人更新 API，管理员页调用管理员更新 API。
- 保存时显示局部加载和错误，成功后刷新对应 TanStack Query 缓存。
- 状态启停操作不携带访问配置，避免覆盖已有设置。

### 9.3 中间页

新增公共 `RedirectPage.vue`，路由为 `/go/:slug`。页面包含：

- 目标主机名。
- 稳定尺寸的倒计时与进度显示。
- 立即前往按钮。
- 返回首页按钮。
- 加载、预览失败、已失效和继续失败状态。

倒计时结束或点击立即前往时，浏览器导航到 `/go/{slug}/continue`。页面不通过 `fetch` 获取目标 URL，也不在客户端自行拼接外部跳转。

### 9.4 二维码

使用成熟的 `qrcode` 库在浏览器生成 PNG Data URL。`ShortLinkQrDialog` 展示二维码、短链文本、下载和关闭操作。生成失败时显示明确错误，不保留空白图片。文件名使用 `moeurl-{slug}.png`。

二维码对话框是单条短链工具，不嵌套在其他卡片中。桌面端和移动端使用稳定尺寸约束，避免图片加载导致布局跳动。

## 10. 生产质量与既有 E2E 修复

基线验证发现现有 Playwright 流程在点击异步退出按钮后立即执行 `page.goto('/')`。失败截图仍显示 `Admin`，说明新导航抢在 `POST /auth/logout` 完成前发生；此前首页版本会等待 `guest`，入口迁移到控制台后丢失了条件等待。

测试应在点击退出时等待登录页 URL 或退出响应完成，再进入首页断言 guest 权限。修复只调整同步条件，不增加固定超时。

生产构建使用路由级懒加载隔离统计图表、中间页和二维码依赖。最终构建不得新增超过既有阈值的大分块警告；若现有主包仍超限，按依赖边界拆分稳定 vendor chunk，不通过提高警告阈值掩盖问题。

## 11. 测试策略

### 11.1 后端

- migration 升级、默认值、权限数据和回滚测试。
- SQLC 创建、读取、列表与更新新增字段测试。
- Service 覆盖默认直接模式、权限拒绝、倒计时边界、过去时间、清除过期和状态更新不覆盖配置。
- Redirect Service 覆盖直接、中间页、禁用、删除、过期、预览与继续时二次检查。
- Handler 覆盖内部跳转、公开预览、最终跳转、业务错误和事件写入失败不阻断响应。
- 路由测试覆盖 `/go` 固定路由优先级和保留短码。

### 11.2 前端

- API 与模型测试覆盖创建、更新和公开预览契约。
- 创建组件按红绿循环覆盖高级设置、权限和校验。
- 设置对话框覆盖初始值、清除过期、保存成功与失败。
- 中间页覆盖加载、倒计时、立即前往、清理计时器和错误状态。
- 二维码对话框覆盖生成、下载、失败和移动端尺寸。
- 路由与 i18n 测试覆盖中英文键和公共访问路径。

### 11.3 E2E

- 既有直接跳转与退出流程保持通过。
- 创建中间页短链，确认初次访问进入 `/go/{slug}`，公开预览不暴露完整目标 URL，继续路由返回目标 `302`。
- 编辑短链为过期状态后，确认访问被阻止且访问量不增加。
- 从创建结果或列表打开二维码，确认图片已实际加载且编码 URL 正确。
- 桌面端与 390 x 800 移动端验证中间页和设置控件无重叠。

## 12. 假设与决策记录

- 中间页倒计时用于访问体验，不是安全等待机制；直接请求继续路由不构成权限绕过，因为目标 URL 本身不是受保护资源。
- 目标主机名属于中间页需要公开的信息，完整目标 URL 仍只由服务端最终跳转响应提供。
- 二维码是短链 URL 的派生展示，不需要数据库记录或独立权限。
- 访问密码必须在单独版本中与限流和授权一起交付，本版本不预留不安全的半成品字段或入口。
