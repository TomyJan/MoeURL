# v0.10.0 短链最大访问次数闭环设计

## 1. 背景与范围

MoeURL 已经支持直接跳转、中间页、确认页、访问密码、固定过期时间和最终跳转统计，但访问条件仍缺少稳定规格中已预留的最大访问次数。现有 `redirect_response_sent` 事件在响应写出后异步、尽力记录，适合匿名分析，不适合作为并发额度的事实来源；事件可能因为进程退出、写入超时或并发保护被丢弃，基于事件聚合判断额度会在多实例部署下超发。

v0.10.0 交付可选的短链最大访问次数：有权限的用户可以在创建和编辑短链时设置或清除限额，有限额短链只在最终外部跳转阶段原子消耗一次额度，到达上限后所有访问入口都展示统一的 `exhausted` 状态。默认不设置限额，既有短链的数据和访问性能保持不变。

本版本不实现每日或每月重置、定时额度窗口、手动清零、一次性链接快捷模式、按用户或来源分配额度、额度告警、批量设置、配额报表和访问事件强一致化。

## 2. 方案比较与决策

1. 从 `short_link_event` 聚合已访问次数：可以复用统计数据，但事件是异步尽力写入，无法提供并发安全的严格上限，也会让最终跳转依赖聚合查询。
2. 所有短链都同步维护生命周期总访问计数：模型直观，但会把数据库同步写和热点行竞争施加到默认无限额短链，破坏当前轻量访问路径。
3. 仅对有限额短链维护独立额度计数器：有限额链路使用条件更新原子领取额度，无限额链路保持只读解析；统计事件继续承担分析职责。

采用方案 3。`max_visits` 和 `visits_used` 共同描述当前额度周期，不从统计事件反推。首次从无限额切换为有限额时开始新的额度周期，`visits_used` 从 0 开始；修改已有上限保留已用次数；清除限额会结束当前周期并把已用次数归零，再次设置限额开始新周期。

## 3. 产品语义

### 3.1 额度周期

- `max_visits = null` 表示无限额，此时 `visits_used` 必须为 0。
- 创建短链时设置限额，当前额度周期从创建成功开始。
- 对已有无限额短链设置限额时，历史统计访问不计入新额度周期。
- 修改已有有限额短链的上限时保留 `visits_used`。新上限小于或等于已用次数时短链立即耗尽；提高上限后可以恢复访问。
- 清除限额时同时将 `visits_used` 归零。重新设置限额建立新周期。
- 本版本不提供独立的重置操作，也不保存历史额度周期。

### 3.2 计数边界

一次额度消耗只发生在服务端已经完成以下检查、准备返回最终目标 `302` 时：

- 短码和真实请求 Host 匹配已启用的短链域名。
- 短链存在、未软删除且状态为 `active`。
- 短链未过期。
- 需要密码时存在与当前密码版本匹配的有效访问授权。
- direct 模式通过公开短链入口进入最终跳转；intermediate 和 confirmation 模式通过 `/go/{slug}/continue` 进入最终跳转。

打开中间页或确认页、读取预览、输入密码、密码失败、签发访问授权、确认按钮展示和被其他访问条件拦截均不消耗额度。confirmation 的点击事件仍可记录，但额度只在最终跳转领取成功时消耗。

额度领取必须在写出 HTTP 响应前完成，否则多个并发请求可能同时越过最后一个名额。Go 的 `ResponseWriter` 不能证明客户端实际接收响应，因此产品契约定义为“服务端成功签发的最终跳转额度”，而不是网络层已被访问者接收。Handler 明确检测到响应正文写入失败时可以尽力归还本次额度，但进程崩溃或连接状态不可观测时不承诺自动补偿。该边界保证不会超过配置上限，优先于极端故障下绝对不少计一次。

### 3.3 状态优先级

访问状态按以下顺序判断：

```text
不存在、软删除、域名不匹配或域名停用
  → disabled
  → expired
  → exhausted
  → password required / interactive flow
  → final redirect
```

`exhausted` 是运行时派生状态，不写回现有 `status` 字段。禁用、过期和耗尽互不替代；重新启用不会重置额度，提高或清除限额可以解除耗尽状态。

## 4. 数据模型与迁移

新增 `00015_short_link_max_visits.sql`：

- `short_link.max_visits bigint null`。
- `short_link.visits_used bigint not null default 0`。
- 检查约束要求 `max_visits` 为空或处于 1 至 2147483647；`visits_used` 处于 0 至 2147483647；无限额时 `visits_used = 0`；有限额时允许 `visits_used >= max_visits`，以支持降低上限后立即耗尽。
- 把 `short_link:set_max_visits` 追加到内置 `user` 和 `admin` 权限，`guest` 不获得；权限目录归入 `short_link_access`，`basic` 预设不包含，`standard` 预设包含。

迁移不会根据历史 `short_link_event` 回填额度用量，所有既有短链保持无限额。Down 删除两个字段和检查约束，并只移除本迁移添加的权限；短链、事件及其他访问配置保持不变。migration 测试覆盖全新 Up、既有自定义权限、Down、再次 Up 和权限数组无重复。

## 5. 原子额度领取

新增 SQLC 条件更新，以短链 UUID 为键执行：

```sql
update short_link
set visits_used = visits_used + 1,
    updated_at = updated_at
where id = $1
  and deleted_at is null
  and max_visits is not null
  and visits_used < max_visits
returning visits_used, max_visits;
```

`updated_at` 不因公开访问变化而推进，避免访问流量持续制造管理编辑的乐观并发冲突。SQL 只在有限额时执行；无限额短链不写数据库。

最终跳转解析分为两步：

1. 读取并验证短链、域名、状态、过期、模式和密码授权。
2. 若存在限额，执行条件更新领取额度；返回零行时重新读取最小额度状态，区分已耗尽、短链并发删除或基础设施错误。

初始读取只能用于快速判断和页面展示，最终条件更新才是并发权威。并发访问最后一个名额时最多一个请求领取成功，其他请求得到 `ErrShortLinkExhausted`。多实例不依赖进程锁。

Handler 成功写出最终跳转后继续通过现有 Recorder 记录 `redirect_response_sent`。若 Handler 明确获得写入错误并且本次结果携带额度领取标记，则调用有界补偿接口，按短链 ID 将 `visits_used` 减 1，但不能低于 0。补偿失败只记录安全日志，不向已经开始写出的响应暴露数据库错误。该补偿不参与正常成功路径，也不改变异步事件记录行为。

## 6. 创建、更新与权限

新增权限：

```text
short_link:set_max_visits
```

创建请求新增可选字段：

```json
{
  "maxVisits": 100
}
```

省略表示无限额。更新请求使用显式模式，避免省略与清除混淆：

```json
{ "visitLimit": { "mode": "limited", "maxVisits": 100 } }
{ "visitLimit": { "mode": "unlimited" } }
```

更新时省略 `visitLimit` 保留现有配置。`limited` 要求 `maxVisits` 为 1 至 2147483647 的整数；`unlimited` 不接受额外数值。没有 `short_link:set_max_visits` 时，创建请求不能携带 `maxVisits`，更新请求不能携带 `visitLimit`；省略字段仍可编辑其他有权限的设置。

用户和管理员更新路径继续分别要求既有 own/all 权限，再单独检查限额权限。管理员不能仅凭管理身份绕过功能权限。数据库写入与目标 URL、状态、模式、过期、密码等现有更新位于同一事务；任何字段失败都不得部分提交。

短链响应新增：

```json
{
  "maxVisits": 100,
  "visitsUsed": 42,
  "visitsRemaining": 58,
  "exhausted": false
}
```

无限额时 `maxVisits` 和 `visitsRemaining` 为 `null`，`visitsUsed` 为 0，`exhausted` 为 `false`。这些字段用于管理列表和编辑，不进入公开 Preview API；公开访问者只获得耗尽状态，不获得额度数值。

## 7. 错误与公开访问

新增领域错误 `ErrShortLinkExhausted`。公开访问 Handler 把它映射到 `/go/{slug}?reason=exhausted`，页面展示本地化的“访问次数已达上限”，不返回目标 URL、上限或已用次数。direct、intermediate、confirmation 和密码保护组合使用同一状态。

管理接口继续使用现有短链错误码范围：非法限额输入映射为统一无效请求；缺少功能权限映射为现有权限不足；并发更新和基础设施错误沿用当前契约。本版本不新增可由客户端重试的额度错误码。

公开 Preview 和 Unlock 在初始读取时拒绝已耗尽短链，避免继续展示目标主机或执行 Argon2；最终 Continue 仍重新领取额度，处理页面打开后额度被其他访问消耗的竞争。所有耗尽响应继续应用现有公开路由缓存和安全头策略。

## 8. 前端交互

复用短链创建面板和设置对话框的高级设置区域：

- 只有当前用户拥有 `short_link:set_max_visits` 时展示“最大访问次数”。
- 使用开关控制无限额或有限额；启用后显示整数输入，范围 1 至 2147483647。
- 创建默认无限额。编辑已有有限额短链时显示上限、已用和剩余；已耗尽时提供明确状态文案，但不增加独立重置按钮。
- 降低上限至已用次数以下时在表单内提示“保存后短链将立即耗尽”，允许用户确认保存。
- 清除限额提示将结束当前额度周期；以后重新启用会从 0 开始。
- mutation pending、查询错误或权限状态不确定时禁止提交；失败保留草稿，可重试且不泄露密码输入。

我的短链和全站短链列表在有限额时显示紧凑的 `已用 / 上限`，无限额不增加视觉噪音。现有 `stats.visitCount` 仍表示成功写入的统计事件数量，不能用它替代 `visitsUsed`，文案和类型必须区分“访问统计”与“额度用量”。

公开跳转页新增 `exhausted` 状态及中英文文案，沿用系统品牌、主题、页脚和响应式布局。页面不提供登录或绕过入口。

## 9. 安全、性能与运维

- 默认无限额短链不执行额度更新，保持现有公开访问数据库读路径和异步统计写路径。
- 有限额短链每次最终跳转增加一次同一行条件更新，严格串行化同一短链最后名额；不同短链互不阻塞。
- 不使用内存计数、缓存计数、客户端上报或未经验证的代理 IP，保证多实例一致。
- 所有算术由数据库约束保护，服务端使用 `int64`，前端只接受不超过 2147483647 的整数，避免 JavaScript 精度问题。
- 额度字段不包含个人信息，不改变现有匿名分析数据边界。
- 备份恢复自然包含额度配置和已用次数；回滚到旧版本会丢弃限额字段，因此升级文档必须要求回滚前确认该产品语义可接受。
- Compose、环境变量和部署拓扑不增加新配置。

## 10. 测试与验收

- migration：既有短链保持无限额，约束边界，内置权限追加，保留自定义权限，Down 和再次 Up。
- SQLC：条件领取成功、最后一个名额并发只有一次成功、已耗尽返回零行、无限额不调用更新、补偿不低于 0、生成代码零漂移。
- Service：创建和更新的省略、设置、修改、清除、降低上限、权限组合、事务回滚和管理 own/all 路径。
- Redirect Service：direct、intermediate、confirmation、密码、过期、禁用、域名不匹配和页面打开后并发耗尽；Unlock 在耗尽时不验证密码。
- Handler：`exhausted` 状态映射、公开响应不泄露额度、成功写出后记录事件、明确写失败触发补偿、补偿失败安全日志。
- 前端：严格 Schema、创建和编辑校验、权限隐藏、已用/剩余展示、立即耗尽提示、清除周期提示、错误保留草稿及双语。
- E2E：创建有限额 direct 短链并耗尽；中间页和确认页只在最终 Continue 消耗；密码失败不消耗；提高上限恢复；清除后无限额；两个并发请求争抢最后一个名额不超发。
- 门禁：migration 往返、SQLC 零漂移、Go 全量、vet、race、目标覆盖率、前端测试与覆盖率、lint、typecheck、build、Playwright、Compose smoke、`git diff --check` 和干净工作区。目标 CI、安全扫描和生产发布证据与本地结果分开记录。
