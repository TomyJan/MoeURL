# v0.1.1 控制台概览设计

## 1. 背景

MoeURL 已完成短链创建与管理、统一控制台 Shell、列表基础统计和单短链分析闭环，但 `/console` 仍是 v0.0.3 留下的规划中占位页。用户登录后缺少一个可以快速确认个人短链规模、访问表现和最近工作的真实入口。

本设计以现有数据能力补齐个人控制台概览，不把它扩展为系统级管理员仪表盘，也不通过当前分页列表在浏览器中推算不完整的统计结果。

## 2. 设计目标

- 登录后首先看到当前用户自己的真实短链指标。
- 用一条后端聚合查询准确返回全部未删除短链的概览数据。
- 复用既有短链列表展示最近 5 条工作记录。
- 提供进入「我的短链」和「访问分析」的清晰路径。
- 沿用现有控制台 Shell、「雾蓝石墨」主题、双语和响应式基线。

## 3. 非目标

- 不实现全站管理员仪表盘、用户统计或系统运行状态。
- 不实现跨短链趋势、来源、设备或地区图表。
- 不新增数据库字段、migration 或持久化模型。
- 不在概览页复制短链创建表单；创建动作继续使用控制台 Shell 已有入口。
- 不实现访问明细、导出、访问密码、过期时间、二维码或跳转模式。

## 4. 方案选择

### 4.1 仅聚合当前前端分页

该方案无需后端变更，但只能汇总已加载页面中的访问量，短链超过一页后指标失真，因此不可采用。

### 4.2 新增个人概览聚合 API

该方案由 PostgreSQL 对当前用户全部未删除短链一次聚合，结果准确，权限边界集中在服务端；最近短链继续复用列表 API，避免概览接口承担两种职责。本设计采用该方案。

### 4.3 前端拉取全部分页

该方案会随短链数量增加产生更多请求和传输，仍可能受到分页上限影响，扩展性差，因此不可采用。

## 5. 后端设计

### 5.1 API 契约

新增：

```text
GET /api/v1/short-link/overview
```

成功响应：

```json
{
  "code": 0,
  "message": "OK",
  "data": {
    "totalLinkCount": 12,
    "activeLinkCount": 9,
    "visitCount": 840,
    "todayVisitCount": 31
  },
  "meta": {}
}
```

接口不接收用户 ID。用户身份只从 Cookie Session 对应的请求上下文读取，避免调用方选择任意所有者。

### 5.2 权限

- 服务层检查 `short_link:read_own`。
- 未登录且无权限的 `guest`、已登录但无权限的用户返回 HTTP `200` 和 `code=120001`。
- 管理员调用个人概览时仍按自己的用户 ID 聚合；全站管理概览应由后续独立 API 和页面承载。

### 5.3 聚合口径

SQLC 查询接收当前用户 ID，并返回一行：

- `total_link_count`：所有 `deleted_at is null` 的当前用户短链数量。
- `active_link_count`：上述短链中 `status = 'active'` 的数量。
- `visit_count`：上述短链关联的 `event_type = 'redirect_response_sent'` 事件数量。
- `today_visit_count`：上述事件中 `created_at >= current_date` 且 `< current_date + interval '1 day'` 的数量。

查询使用条件聚合或预聚合后左连接，必须保证没有短链和没有访问事件时均返回零值。禁用短链的历史成功访问仍计入访问量；软删除短链及其历史事件不计入个人概览。

### 5.4 错误处理

- 权限不足映射为统一业务错误。
- 数据库查询失败映射为基础设施级 HTTP `500`。
- 接口没有输入参数，不增加新的参数错误码。

## 6. 前端设计

### 6.1 数据流

新增 `getShortLinkOverview()` 及对应 TanStack Query key。概览页并行发起：

```text
getShortLinkOverview()
listShortLinks({ page: 1, pageSize: 5 })
```

两条查询分别负责聚合指标和最近短链。任一查询失败时，另一部分的成功内容仍可展示，并在失败区域提供重试操作。

### 6.2 页面结构

页面保持安静、紧凑的工作台布局：

1. 页面标题和一句当前用户视角说明。
2. 四列指标带：短链总数、启用短链、总访问量、今日访问量。
3. 最近短链区域：展示短码、目标地址、状态、访问统计和创建时间。
4. 页面级入口：进入「我的短链」和「访问分析」。

指标使用同一无嵌套表面，不堆叠装饰卡片。最近短链沿用现有控制台数据行语言，桌面端便于扫描，移动端纵向排列。

### 6.3 页面状态

- 聚合加载：指标位置显示稳定尺寸的 skeleton，不引发布局跳动。
- 最近短链加载：列表区域显示行级 skeleton。
- 聚合错误：指标区域显示简短错误和重试按钮。
- 列表错误：最近短链区域单独显示错误和重试按钮。
- 空数据：四项指标显示 `0`，最近短链区域提供使用已有「新建短链」入口的引导，不渲染不可用表单。
- 部分成功：保留可用区域，不用全页错误遮蔽真实数据。

### 6.4 导航与占位清理

- `/console` 路由改为 `ConsoleOverviewPage`。
- 控制台导航的概览项移除 `planned` 标记。
- `ConsolePlaceholderPage` 仅保留用户组与系统设置占位类型。
- i18n 删除概览占位配置，新增真实页面所需中英文文案。

## 7. 测试策略

### 7.1 后端

- SQL 集成测试覆盖零值、启用与禁用、软删除、成功与非成功事件、今日与历史事件。
- 服务测试覆盖权限检查、所有者 ID 传递、查询结果映射和数据库错误。
- Handler 测试覆盖成功响应、权限业务错误和基础设施 `500`。
- 路由测试确认固定 API 路径已注册且优先于短码路由。

### 7.2 前端

- API 测试确认请求路径和响应类型映射。
- 页面测试覆盖并行加载、成功、空数据、两个局部错误、重试和导航入口。
- 路由测试确认 `/console` 加载真实概览页。
- Console Shell 测试确认概览不再显示规划中标识。
- i18n 与覆盖率门禁继续执行。

## 8. 验收标准

- 当前用户的四项指标与数据库事实一致。
- 管理员个人概览不包含其他用户数据。
- `/console` 不再显示规划中占位内容或伪造数据。
- 最近短链最多展示 5 条，并可进入管理和分析流程。
- 加载、局部错误、空数据、浅色、深色和移动端布局均可用。
- 后端和前端全部质量门禁通过。
