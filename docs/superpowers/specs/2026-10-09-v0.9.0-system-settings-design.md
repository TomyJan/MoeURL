# v0.9.0 系统设置与站点品牌基础闭环设计

## 1. 背景与范围

MoeURL 初始化时已经把站点名称、默认语言和默认主题写入 `system_setting`，前端也已经具备本地语言、主题偏好和 OIDC Provider 管理能力，但初始化完成后没有统一的设置读取和更新流程。`/admin/setting` 当前只承载 OIDC Provider 管理，本地登录永久启用，站点名称和页脚仍由前端静态值决定。

本版本复用现有设置表和权限模型，交付站点名称、默认语言、默认主题、简单页脚及本地登录开关的完整闭环。关闭本地登录必须以可用 OIDC Provider 为安全后备；Provider 管理与登录策略变更必须在数据库中串行化，不能只依赖前端提示或先查后写。

本设计不实现媒体上传、主题编辑器、自定义 HTML/CSS、部署环境变量在线修改、OIDC 模板、账号绑定、审计日志和其他通用后台配置。默认短链域名继续由域名管理管理，系统访问域名继续由初始化及部署配置管理。

## 2. 方案比较与决策

1. 新建单行通用设置表：聚合更新简单，但与现有 `system_setting` 重复，需迁移并维护两套事实来源。
2. 继续使用独立设置键，并增加统一修订行：兼容初始化数据，更新可在一个事务中完成，修订行可以提供单一乐观并发版本。
3. 仅在前端保存品牌与登录开关：无法约束后端登录和 Provider 并发，不具备安全性。

采用方案 2。设置值继续按稳定 key 保存，`site.settings_revision` 行的 `updated_at` 是整个可编辑设置集合的版本。所有管理写入先锁定该行，再比较 `expectedUpdatedAt`，随后在同一事务中写入所有字段并推进修订时间。

## 3. 设置模型与校验

本版本管理以下设置键：

| key | 类型 | 默认值 | 规则 |
| --- | --- | --- | --- |
| `site.name` | string | `MoeURL` | 去除首尾空白后 1 至 64 个 Unicode 字符。 |
| `site.default_language` | string | `zh-CN` | 只允许 `zh-CN`、`en`。 |
| `site.default_theme` | string | `system` | 只允许 `system`、`light`、`dark`。 |
| `site.footer_text` | string | 空字符串 | 去除首尾空白，最多 200 个 Unicode 字符，按纯文本渲染。 |
| `site.show_powered_by` | boolean | `true` | 控制共享页脚是否展示 MoeURL 品牌文案。 |
| `auth.local_login_enabled` | boolean | `true` | 控制新的本地账号密码登录，不撤销 Session。 |
| `site.settings_revision` | integer | `1` | 不作为业务配置返回；其 `updated_at` 是统一并发版本。 |

后端使用单一设置模型完成 JSON 解码、缺失值补全和业务校验。数据库中的未知设置键保持不变；管理更新不执行整表替换。初始化完成后，任何已知键缺失、类型错误或值非法都视为运行配置错误，管理读取返回基础设施错误，应用启动执行相同校验并关闭失败，不能悄悄使用不同默认值掩盖损坏数据；初始化尚未完成时允许 Setup 使用安全默认值建立完整设置集。

公开配置读取在系统尚未初始化时返回安全默认品牌，避免初始化页依赖尚未写入的设置；初始化完成后若配置损坏则记录安全日志并返回基础设施错误。前端网络失败时可以使用编译时默认值继续渲染，但不得把该 fallback 写回服务端。

## 4. 数据迁移与回滚

新增 `00014_system_settings.sql`：

- 使用 `INSERT ... ON CONFLICT DO NOTHING` 补齐 `site.footer_text`、`site.show_powered_by`、`auth.local_login_enabled` 和 `site.settings_revision`。
- 对早于初始化完成的空数据库也写入安全默认值；初始化仍覆盖站点名称、默认语言和默认主题，并保证全部本版本设置存在。
- 把 `system:manage` 追加到内置 `admin` 权限，保持目录顺序；`guest` 和 `user` 不获得该权限。
- Down 从 `admin` 权限移除 `system:manage`，使旧二进制的权限目录仍可校验；设置行保留，避免回滚及再次升级丢失管理员配置。旧版本忽略这些额外设置键，本地登录按旧行为保持启用。

迁移不创建新的设置表，不修改 OIDC Provider、外部身份、本地用户、密码或 Session。Up、Down 和再次 Up 必须验证权限数组不重复、设置值保留及旧代码可回退语义。

## 5. 权限、API 与错误契约

新增受保护权限 `system:manage`，固定属于 `admin`。权限目录、默认 `AdminPermissions`、初始化写入、migration、用户组页面 fixture 和生成契约同时更新。系统设置和 OIDC Provider 管理 Service 均要求权限快照同时包含 `admin:access` 与 `system:manage`；Handler 或前端守卫不能替代 Service 的最终授权。

新增接口：

```text
GET  /api/v1/system/public-config
GET  /api/v1/admin/system/settings
POST /api/v1/admin/system/settings/update
```

公开接口返回：

```json
{
  "siteName": "MoeURL",
  "defaultLanguage": "zh-CN",
  "defaultTheme": "system",
  "footerText": "",
  "showPoweredBy": true
}
```

管理读取额外返回 `localLoginEnabled` 和 `updatedAt`。更新请求提交所有可编辑字段及 `expectedUpdatedAt`，服务端不接受部分更新，避免多个独立草稿产生隐式覆盖。成功响应返回完整最新设置。公开与管理读取均使用 `Cache-Control: no-store`，防止登录策略和品牌配置被中间缓存长期保留。

继续使用项目统一的 `120001` 表示权限不足。系统设置业务错误使用系统范围中的稳定错误码：

| 错误码 | 含义 |
| --- | --- |
| `900201` | 设置输入无效。 |
| `900202` | 设置版本冲突。 |
| `900203` | 关闭本地登录时没有可用的 OIDC Provider。 |
| `110104` | 当前不允许本地账号密码登录。 |

未知数据库、加密或事务错误只记录请求 ID、操作名和安全错误分类，响应使用既有 `900000`，不得记录设置正文、Client Secret 或 Provider 密文。

## 6. 本地登录策略与 OIDC 并发

“可用 OIDC Provider”定义为未软删除、已启用、持久化 Issuer 与端点通过现有运行时 URL 校验、允许域名 JSON 可解析且 Client Secret 能用当前 `MOEURL_OIDC_ENCRYPTION_KEY` 解密的 Provider。Provider 的创建、启用或协议参数修改仍需现有 Discovery 成功；切换本地登录不额外依赖上游网络瞬时可达性。

`auth.local_login_enabled` 行同时承担认证策略互斥锁。设置更新、Provider 更新和 Provider 删除采用固定锁序：先 `SELECT ... FOR UPDATE` 锁定本地登录策略行，再锁 Provider 行或执行 Provider 写入。这样可以保证以下检查与写入位于同一事务快照：

- 从启用改为停用本地登录时，最终 Provider 集合至少有一个可用项。
- 本地登录已经关闭时，Provider 更新、停用或删除后的最终集合仍至少有一个可用项。
- 修改最后一个 Provider 的 Issuer、Client ID、Secret 或端点时，候选配置已完成 Discovery 和本地运行时校验，事务内再对最终持久化集合执行校验。

Provider 创建不会减少登录入口，但仍按现有唯一键、Discovery、Secret 加密和权限规则执行。Provider 网络校验在事务外使用有界上下文完成；事务内只使用已经验证的候选值并重新检查受锁数据，避免持有数据库锁等待外部网络。

应用启动读取全部设置和已启用 Provider。若本地登录关闭且最终集合没有可用 Provider，启动返回明确的安全配置错误。已启用 Provider 的现有启动校验继续执行；本地登录启用时，没有 OIDC Provider 仍是合法部署。

`auth.Service.Login` 在获取登录并发槽位、创建事务、查询用户或执行 Argon2 验证前读取本地登录策略。策略关闭时统一返回 `ErrLoginMethodUnavailable`，Handler 映射为 `110104`，对任何用户名保持相同行为。关闭开关不会撤销现有 `moeurl_session`，`Me`、`Logout` 和管理员已登录操作继续工作。初始化完成前的 Setup 不经过 Login，仍可创建首个本地管理员。

`GET /api/v1/auth/methods` 读取相同设置快照，`local.enabled` 不再硬编码为 `true`。数据库不变量保证响应不会同时出现本地登录关闭和 OIDC 列表为空；读取失败返回基础设施错误，不伪造登录方式。

## 7. 前端结构与偏好优先级

新增公共配置实体和 TanStack Query，不把服务端设置长期复制到 Pinia。应用使用编译时安全默认值立即渲染，并异步加载公开配置；成功后更新站点名称、页面标题和共享页脚。公开配置失败不阻塞首页、登录页或跳转流程，可在需要的位置提供非侵入式重试。

语言优先级为：

```text
浏览器本地保存的手动选择 → 浏览器语言 → 系统默认语言
```

主题优先级为：

```text
浏览器本地保存的手动选择 → 系统默认主题
```

现有本地存储值保持权威，系统默认更新只影响没有本地偏好的浏览器。`system` 主题继续跟随操作系统。公开配置返回不支持的值时后端已拒绝；前端类型守卫仍关闭失败并使用编译时默认值。

`/admin/setting` 改为 `AdminSettingsPage`，包含“常规设置”和“身份认证”两个区域。现有 Provider 管理页面逻辑抽成可复用区域组件，保留 Secret 清理、脏草稿、冲突和删除快照语义。常规设置使用独立草稿；后台 refetch 不覆盖未保存内容，版本冲突显示最新数据和显式重新加载操作，不自动重放 mutation。

路由守卫、路由 meta 和控制台导航同时要求 `admin:access` 与 `system:manage`。权限被动态撤回后，后端拒绝后续操作；前端刷新 `auth/me` 后隐藏入口并离开不可访问页面。

登录页先读取登录方式：本地登录启用时保持现有账号密码表单；关闭时不渲染本地表单，只展示 OIDC Provider。登录方式查询失败显示现有可重试错误，不能因为公开配置 fallback 而重新显示本地表单。

共享页脚把 `footerText` 作为文本节点渲染，并按开关显示 Powered by MoeURL；不使用 `v-html`，不接受链接或脚本。页脚接入首页、登录页、控制台、跳转页和错误页；Setup 在未初始化时使用安全默认品牌。站点名称接入首页、登录页、控制台品牌区和 `document.title`，不改变 PWA manifest 的静态安装名称。

## 8. 测试与验收

- migration：已有初始化数据、空数据库、Up、Down、再次 Up、权限不重复、设置保留和旧权限目录兼容。
- 设置 Service：全部字段边界、Unicode 长度、非法枚举、损坏 JSON、权限组合、事务回滚、版本冲突、修订时间推进和公开字段最小化。
- 登录策略：关闭前无 Provider、不可解密 Secret、有效 Provider、并发关闭与 Provider 停用/删除/更新、启动不变量和本地登录在密码验证前被拒绝。
- OIDC：Provider 创建、更新、停用和删除继续覆盖 Discovery、绑定保护、乐观并发及最后登录入口保护；不得新增网络调用持锁。
- Handler/路由：`Cache-Control: no-store`、稳定业务码、请求体单值 JSON、权限上下文和基础设施日志脱敏。
- 前端：公开配置 schema、默认值、已有偏好优先级、管理草稿和冲突、登录方式切换、站点标题、纯文本页脚、双语与双视口。
- E2E：初始化后更新品牌与默认偏好；创建有效 OIDC Provider、关闭本地登录、确认表单隐藏并完成 OIDC 登录；最后 Provider 不能停用或删除；重新开启本地登录后本地账号可登录；清理隔离环境。
- 门禁：Go 全量、vet、race、目标业务覆盖率、migration 往返、SQLC 零漂移、前端测试/覆盖率/lint/typecheck/build、Playwright 和 Compose smoke。CI、安全扫描、外部真实 OIDC 和生产发布证据与本地结果分开记录。
