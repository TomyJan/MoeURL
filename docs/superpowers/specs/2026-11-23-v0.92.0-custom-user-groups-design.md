# v0.92.0 自定义用户组设计

## 意图

在现有权限目录、用户组权限数组、域名授权和单个主用户组模型上开放管理员自定义用户组，使管理员可以按实际团队划分权限并将账号迁入对应组。当前工程只支持 `guest`、`user`、`admin` 三个内置组；v0.5.0 明确将自定义组与多组成员列为未来方向。本阶段先交付可用的自定义组闭环，不同时引入多组权限合并。

这是实现前的设计合同；具体版本实现和交付状态以对应 scope、计划与验收文档为准。已交付产品版本号不因本设计而变化。

## 目标

- 管理员能创建、查看、编辑和删除自定义组；组名和描述可编辑，稳定组标识创建后不变。
- 自定义组使用现有权限目录的权限项；受保护的管理员权限只能属于内置 `admin`，custom group 不能获得 `admin:access` 或其他受保护权限。
- 每个账号仍只属于一个主组。管理员能通过现有单用户组迁移入口把普通账号迁入或迁出自定义组；现有批量内置组迁移仍保持原行为。
- 自定义组可配置已有短链域名授权及一个组默认域名；公开创建和管理操作继续在数据库事务内按当前组权限和域名授权判断。
- 改组继续撤销目标账号全部旧 Session；权限和组配置保存继续使用完整精度乐观并发，后续请求从数据库读取当前组权限，不引入跨请求权限缓存。
- 自定义组新建时采用 fail-closed 初始配置：权限为空、域名授权为空、默认域名为空。管理员显式赋权后组员才获得对应能力。
- 组删除仅允许不存在任何 `app_user` 引用的自定义组；内置组不可删除。自定义组已有域名授权随该组删除而级联清除；审计历史保留。

## 非目标

- 不实现一个账号同时属于多个组、权限并集／交集、拒绝规则或授权优先级。
- 不开放 `guest` 持久化组编辑、创建访客短链或访客归属。
- 不允许自定义组拥有受保护管理权限，不改变 `admin` 的自锁保护。
- 不增加新权限目录项、个人级权限例外、组织／租户、角色模板市场、自动 OIDC 组映射或批量成员迁移。
- 不为本版本新增依赖，不改公开短链地址或已保存短链的域名／归属。

## 产品规则

### 身份与组标识

- `guest`、`user`、`admin` 的既有稳定 key、行为和 API 兼容性保持不变。
- 自定义组 key 由服务端生成 UUID 字符串并在 `user_group.key` 唯一约束下保存；它是不透明、不可变的内部标识，不从可编辑名称推导。名称 1–64 个 Unicode 字符，去除首尾空白后不得为空；描述最多 500 个 Unicode 字符。组名在当前内置及自定义组之间大小写不敏感且去除首尾空白后唯一。
- 数据库保留既有 `key text` 对任意内部 key 的兼容性，不新增 UUID 格式检查；UUID 生成与不可变性由创建／更新 Service 保证，避免拒绝既有内部数据与固定测试夹具。客户端不能提供或更新 key。
- 只有非 builtin 组可以按自定义组规则编辑和删除。所有读写都通过 UUID/key 精确指向组，客户端提交的 builtin 标记不可信。
- 现有每用户单个 `group_id` 外键继续作为唯一主组关系；不建成员关联表。系统内置 guest 身份仍不对应可迁移的持久化 `app_user`。

### 权限

- 组权限使用既有权限 catalog 的完整集合验证、去重并按 catalog 顺序规范化。
- `guest` 保持空权限且只读；builtin `user` 不得持有受保护权限；builtin `admin` 必须持有完整受保护权限集合。自定义组规则与 builtin `user` 相同：可拥有非受保护的目录权限，但任何 protected 权限均拒绝。
- 内置 preset 仍只适用于 `user` 与 `admin`；自定义组 UI 不显示会误导的 builtin preset。逐项编辑为其唯一权限配置方式。
- 所有业务 Service 继续按当前 Cookie 解析的用户数据库主组读取权限，不可用自定义组 key 或 UI 缓存本身授予权限。若组缺失或权限 JSON 损坏，访问失败关闭并按现有基础设施错误边界处理。

### 成员迁移与会话

- 现有单用户组更新端点扩展为接受一个当前存在的目标组 key；不接受 `guest`、builtin 账号、本人改组或失效／已删除组。
- 沿用 v0.19.0 既有边界，管理员可以把其他非 builtin 普通账号迁入 `user`、`admin` 或自定义组；builtin admin 与当前操作者自身仍受保护，不能通过本阶段绕过既有自锁规则。
- 使用目标用户 UUID 与原始完整精度 `updatedAt` 做冲突保护；事务中锁定操作者和目标，再锁定当前 builtin `admin` 组并重读其 `admin:access`，然后校验目标组存在且可分配。沿用当前移组审计和“实际组变化时撤销全部目标 Session”语义。
- 同组请求在版本验证后作为 no-op，不写审计、不撤销 Session。自定义组权限变化立即影响其所有成员的后续请求；不需要批量改写每个成员或其 Session。
- 账号创建入口可以选择任一当前可分配组，但不能创建 builtin admin 账号或把内置账号从保护组移出。现有 builtin-only 批量迁移功能不变，不通过它批量赋予自定义组。

### 域名与默认值

- `domain_user_group` 的现有关系已经按 UUID 关联用户组；管理员域名管理请求和响应扩展为使用当前组 key 列表，目标必须是存在的、非 guest 的用户组。管理界面展示内置及自定义组。
- 新自定义组不继承内置 user/admin 域名 grant。域名使用仍要求当前组的 `domain:use_default` 或 `domain:use_assigned` 与该组在对应域名上的显式 grant 同时成立。
- 复用现有可空 `user_group.default_domain_id` 和组 `updated_at` 版本，允许自定义组设置已启用且已授权、且与组权限相符的短链域名。读取本人可用默认值只返回当前可用选择，不泄露已保存但现已无权使用的域名标识。
- 删除自定义组需同一事务确认其没有任何用户外键引用；无用户时，组自身默认域名列随组删除，已有 domain_user_group 关系按外键级联删除。域名仍保留，任何短链不变。内置组删除始终拒绝。

### API、安全及并发

- 新／扩展接口沿用 `/api/v1`、现有 JSON envelope、业务失败 HTTP 200 + 数字 code、基础设施失败 HTTP 500、严格 JSON 字段和 `no-store` 管理响应约定。
- 创建、更新、删除、权限更新、域名授权、组默认值和成员迁移均要求当前数据库身份和 `admin:access`；配置域名与默认域名的管理操作还要求现有 `domain:manage`。
- 每次写入在事务内重查 actor active、未删除、非 guest、当前 builtin admin 身份和实时权限。锁与事务按现有各模块协议实现，避免增加反向锁序；custom group 的配置写需要和受影响域名／组／账号变更互斥。成功写入推进共享组版本，陈旧版本拒绝，不自动重试写。
- 组 key、名称、描述、权限或域名列表的校验错误不得被翻译为数据库冲突；数据库故障不伪装成“组不存在”或授权拒绝。日志只记录稳定 group UUID/key 与错误类别，不记录权限正文、口令或域名秘密。
- 审计遵循既有用户组及域名审计模型：记录实际变化的资源与字段名，不保存前后配置值；同值 no-op 不产生虚假审计。

## 数据与回滚

- 预计需要 Goose migration 将 `user_group` 的组名唯一性约束扩展为适用于内置与自定义组的规范化唯一性，并调整 `default_domain_id` 现有仅限 builtin 的约束，使其允许自定义组；权限 JSON 继续使用现列，不新增成员关系表。
- Migration 在 Up 时须先检测当前数据是否违反新约束并提供可诊断错误；不得静默重命名、合并组、迁移用户或改权限。Down 只撤销本版约束变化；若已有自定义组或自定义默认值将导致旧约束无法恢复，Down 必须安全拒绝并保留数据，不能级联删除用户组、用户、域名授权或权限。
- 版本号、最终 migration 编号及确切 API 路径由仓库当前 head 和实现计划确认，不在本设计中猜测；任何调整须保持上述外部语义。

## 前端体验

- 在现有用户组管理页中区分内置／自定义组；guest 只读，admin 显示受保护权限，custom group 显示 protected 项但锁定并说明只有管理员组可拥有。
- 创建组先提交空权限组；成功后切换到服务端返回的组并由管理员配置。删除前明确显示组名、成员数量和删除后该组域名授权一并移除；有成员时阻止删除并提供成员筛选入口。
- 组 key 用于请求与稳定身份，显示只用可编辑 name；用户组列表、域名权限选择、用户创建和成员迁移必须使用运行时服务器数据，不硬编码 custom key 集合。
- 保留登录 identity epoch 隔离、冻结编辑草稿、刷新失败停写、乐观并发冲突需显式 reload、窄屏布局与现有双语 i18n 规则。

## 验收重点

- 内置三组既有权限和历史用户迁移／域名行为无回归；guest、builtin admin 及 protected 权限边界通过真实数据库和 HTTP 验证。
- 自定义组从创建、权限配置、域名 grant/default、用户改组、鉴权立即生效到安全删除形成完整成功与失败路径。
- 重名并发、重复／未知权限、受保护权限、自身改组、builtin 账号、陈旧版本、并发删除／移组、软删除账号仍引用、禁用／无授权域名及会话撤销均有验证。
- Up／Down／再次 Up 覆盖有无自定义数据两种回滚分支；数据不丢失且无法恢复旧 schema 时 migration 明确拒绝回滚。
- 前后端类型、SQLC 生成、权限 catalog、域名 grant、API schema、审计字段和 i18n 不漂移；提交前运行仓库规定的本地验证与 `git diff --check`。

## 设计决策归属

本设计按用户的自主推进授权及现有权限规范作出的代理决策：先完成单主组的自定义组，而不是一次引入多组授权；新组 fail-closed；key 使用 UUID 字符串以避免重命名造成引用漂移；组删除只有在无任何账号引用时可用；域名授权／默认值包含在本阶段，使自定义组能与既有短链创建行为完整工作。若后续代码盘点发现无法同时满足现有数据库锁序或 migration 回滚保证，应将受影响能力拆为显式后续增量，不降低上述安全合同。
