# v0.3.0 受保护短链访问设计

## 1. 背景与范围决策

v0.2.0 已完成短链访问配置、中间页、过期时间和二维码闭环。路线图下一组能力包括访问密码、确认页、最大访问次数、标签和 OIDC。本设计选择访问密码作为单独的 v0.3.0，原因是该能力必须同时处理密码哈希、失败限流、授权生命周期和多实例部署；把它与确认页或身份系统混交会扩大安全边界并降低验收质量。

本版本不增加新的跳转模式。密码保护是独立访问条件，保护短链在 `/go/{slug}` 展示密码表单，解锁后仍按原有 `direct` 或 `intermediate` 配置执行。

## 2. 现状盘点

| 能力 | 当前状态 | v0.3.0 决策 |
| --- | --- | --- |
| 直接/中间页访问 | v0.2.0 已完成 | 复用 `Open`、`Preview`、`Continue` |
| 访问配置权限 | 已有中间页和过期权限 | 增加 `short_link:set_password` |
| 密码哈希 | 账号使用 Argon2id | 复用 `internal/auth` 哈希函数 |
| 服务端会话 | 数据库 `session` 表 | 不把访客授权伪装成登录会话 |
| 统计事件 | 仅最终响应计量 | 密码事件不进入统计口径 |
| 多实例部署 | PostgreSQL 为共享状态 | 失败窗口和授权令牌全部落库 |

## 3. 数据模型

`short_link` 新增：

- `password_hash text`：Argon2id 哈希，可空。
- `password_failed_attempts smallint not null default 0`。
- `password_window_started_at timestamptz`。
- `password_blocked_until timestamptz`。
- `password_updated_at timestamptz`：用于让旧授权立即失效。

新增 `short_link_access_grant`：

```text
id uuid primary key
short_link_id uuid references short_link(id)
token_hash text unique not null
expires_at timestamptz not null
created_at timestamptz not null
```

查询授权时同时要求 `expires_at > now()` 且 `created_at >= short_link.password_updated_at`。令牌由 `crypto/rand` 生成 32 字节，数据库只保存 SHA-256 的 base64url 值。

## 4. 解锁与限流流程

1. `Open` 查找短链并执行现有状态、软删除和过期检查；设置密码时返回 `RequiresPassword`，不返回目标 URL。
2. `Preview` 对设置密码的短链允许直达模式预览，仅返回目标主机名、过期时间、原有倒计时和 `requiresPassword`。
3. `Unlock` 通过短链 ID 在事务中 `SELECT ... FOR UPDATE` 读取密码和失败窗口。
4. 若窗口被阻断，返回限流业务错误，不执行密码比较。
5. 密码比较失败时在同一事务递增计数；第五次失败设置 `blocked_until = now() + 15 minutes`。
6. 密码比较成功时清零窗口，写入授权令牌哈希，授权有效期为 15 分钟，并返回原始令牌给 Handler。
7. Handler 设置 `HttpOnly` Cookie：`Path=/go/{slug}`、`SameSite=Lax`、生产环境 `Secure`、`MaxAge=900`。
8. `Continue` 重新检查所有访问条件，并在受保护短链上验证 Cookie 令牌；失败时回到密码页，不写 `redirect_response_sent`。

限流按短链聚合，目的是提供跨实例的一致最低保护，同时不读取未经验证的 `X-Forwarded-For`。管理员修改或清除密码会更新时间戳，使所有旧授权失效。

## 5. API 契约

管理接口中的 `password` 使用显式模式：

```json
{ "mode": "set", "value": "correct horse battery staple" }
```

或：

```json
{ "mode": "never" }
```

省略字段表示保持原值。响应中的短链模型只包含 `passwordEnabled: boolean`，绝不包含哈希。

公开解锁：

```json
POST /api/v1/public/short-link/unlock
{ "slug": "abc123", "password": "..." }
```

成功返回 `{ code: 0, data: { unlocked: true } }` 并设置 Cookie。错误码固定为：`200111` 密码必需、`200112` 密码错误、`200113` 暂时限流；不存在、禁用、过期和数据库错误沿用既有访问边界。

## 6. 前端状态

`RedirectPage` 保留加载、失效和继续失败状态；当预览返回 `requiresPassword` 时展示密码输入和解锁按钮。解锁成功后立即进入原有中间页倒计时，直接模式则调用同一 Continue 路由。错误提示不泄露短链是否存在或密码哈希信息。

创建面板和设置对话框仅在 `short_link:set_password` 权限存在时展示密码开关。设置对话框不能回填密码；开启状态下留空表示不修改，显式关闭才清除现有密码。

## 7. 事件与观测

`password_failed`、`password_verified` 只作为非统计审计事件，写入失败忽略。访问量仍严格只统计 `redirect_response_sent`，并且必须在目标跳转响应成功写出后记录一次。

## 8. 测试策略

- migration：既有短链默认未保护；升级、回滚、密码字段和授权表索引可验证。
- SQLC：创建、读取、列表、更新返回 `passwordEnabled` 所需字段；授权有效期和密码更新时间条件可验证。
- Service：权限、长度边界、显式清除、密码比较、五次失败限流、成功清零、修改密码吊销旧授权。
- Redirect：受保护直接/中间页 Open、预览最小响应、无授权 Continue、有效授权 Continue、禁用/软删除/过期和事件口径。
- Web：创建/设置权限矩阵、空密码保留、清除密码、密码页错误与成功状态。
- E2E：真实创建受保护短链、密码页阻止目标访问、错误与限流、正确密码后成功跳转且访问量为 1、修改密码使旧 Cookie 失效，并覆盖桌面和移动视口。
