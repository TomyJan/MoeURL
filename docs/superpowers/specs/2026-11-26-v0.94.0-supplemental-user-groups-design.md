# v0.94.0 多组补充授权设计

## 意图

v0.92.0 已让管理员配置自定义组；v0.93.0 已让单个主组批量迁移支持自定义源／目标。一个账号仍只能从一组取得权限，因此团队无法组合两组彼此独立的细粒度权限。v0.94.0 增加可叠加的自定义补充组，同时保留一个主组，避免一次把 `app_user.group_id`、公开 API 和默认域名锚点全部改成新的多主组语义。

本设计采用“单主组 + 多个自定义补充组”。主组决定原有 `group` 字段和组默认域名；补充组只叠加权限与域名授权。有效授权为主／补充组可配置权限的并集，不存在拒绝或顺序优先级。设计决策依据为现有项目的保护权限、无跨请求缓存、当前数据库授权及安全回滚合同。

## 目标

- 管理员能按 CAS 为一个非 builtin 账号设置完整补充自定义组集合，并在用户列表查看主／补充组。
- `auth/me` 保留原 `group` 主组字段并增加补充组 key，已有客户端保持兼容。
- 有效权限和显式域名授权读取主组与所有补充组并集；数据库撤权对后续业务操作立即生效。
- 修改补充组与主组、状态、用户删除、组删除并发时不会留下部分集合、孤立授权或不一致计数。
- 实际成员关系变更以一个数据库事务更新用户版本、撤销目标全部旧 Session、写入一条成员关系审计记录。
- 每个受影响业务路径按当前账号身份解析权限；现有业务 Service 不能继续按登录时缓存的单个 `GroupKey` 作最终授权。

## 非目标

- 不删除 `app_user.group_id`，不允许多个主组，也不改变主组变更流程。
- 补充关系只允许现存、非 builtin 的自定义组；不支持 guest、user 或 admin 作为补充组。管理员能力只能由主组 builtin admin 提供。
- 不支持 deny、allow/deny 优先级、组继承、组嵌套、自动 OIDC 映射或个人级权限例外。
- 不改变短链 owner、短码、访问事件、用户个人默认值或默认域名全局 fallback。
- 不允许匿名 guest 持久化成员关系，不新增权限 key 或依赖。

## 数据模型

保留 `app_user.group_id` 并新增 `app_user_group_membership` 关联表。关联表以 `(user_id, user_group_id)` 为主键并有 `(user_group_id, user_id)` 索引；两列均使用现有 UUID 主键，分别外键到 `app_user(id)` 和 `user_group(id)`。硬删除 app_user 时由外键清理补充关联；自定义组仍须先由 Service 确认主成员和补充成员都为零才能删除。应用写入必须拒绝 builtin 组补充关系、主组重复关系和自身／builtin 账号。builtin 账号严格指 `app_user.builtin = true`；普通持久化账号即使以 builtin `admin` 为主组，仍符合补充成员目标资格，但不得因此改变 protected 权限只能由主组 builtin `admin` 提供的规则。不能以显示名称识别或授权组。

`00051` 只创建新表和所需索引，不回填任何用户。现有所有账号的补充组集合为空，`app_user.group_id` 继续唯一表达其既有主组。Down 在存在任一补充关系时明确返回安全迁移错误并保留数据；关系集合为空时才删除新表和索引。Up/Down 均可重试，migration 不删除用户、组、短链或审计。

## 身份与有效权限

`auth/me`、用户列表和创建／修改响应继续返回 `group` 作为主组 key，并新增 `supplementalGroups` 字段。身份读取在同一数据库语句或等效的一致快照中读主组、补充组及其权限，补充组 key 按稳定顺序返回。登录态和前端缓存仅描述当前响应，不能构成后续业务授权证据。

所有数据库 Resolver 改为按账号 ID 解析当前主组与补充组权限集合，并在一个调用中形成不可变 snapshot。其集合语义为并集；任何 protected permission 出现在非 builtin admin 主组之外均为存储不变量损坏，解析失败关闭。actor 已禁用、删除、guest 持久化记录异常、主组缺失、任一补充组缺失或任一 permission JSON 无效，都不得以部分权限继续。生产 Service 逐项检查现有 permission key；静态 resolver 仅服务隔离测试。

被授权 Service 在事务内仍须按既有规则锁 actor 与目标资源，并在拿到锁后读取账号当前版本／状态和实时组关系。后台等待锁期间发生的补充组变化必须参与当前操作的最终授权；不能以请求开始前 actor 的 `supplementalGroups` 替代数据库重读。所有修改同一 actor 的操作以 actor 行锁作首要串行点，成员集合变更后才能读取／锁补充组行，避免与用户删除或组删除形成反序锁。

## 域名语义

可用域名 requires：当前用户主组与补充组 permission 并集含 `domain:use_default` 或 `domain:use_assigned`，且目标域名被上述任意一个组显式授权。个人默认域名沿用既有身份版本和优先级，并以并集重新校验其当前可用性。组默认域名只取主组，不聚合补充组的 `default_domain_id`，以避免多个互斥默认值产生不确定结果。补充组默认值仍可供该组作为主组时使用；既有域名 API 结构不变。

## API 与审计

新增严格 no-store `POST /api/v1/admin/user/update-group-memberships`。请求包含 `id`、`groupKeys` 和完整 RFC3339Nano `expectedUpdatedAt`；`groupKeys` 表示完整补充组集合，不含主组。空数组表示移除全部补充组，字段缺失、null、重复或 key 不规范均拒绝。目标必须是非 builtin、非操作者本人的持久化账号；目标主组可以是 user、admin 或自定义组。业务错误继续 HTTP 200 + 数字 code；基础设施错误按既有 HTTP 500 处理。成功返回主组 `group`、补充组的 key/name 列表与新的完整精度 `updatedAt`。

对比集合完全相同且版本匹配时为 no-op，不推进版本、不撤销 Session、不审计；版本过期即使集合相同也返回冲突。真实变化单事务递增 `app_user.updated_at`、原子替换补充集合、撤销所有目标 Session，并新增一个 `resource_type=user, action=update, changed_fields=['group_memberships']` 审计项；不保存变更前后组列表。禁止逐项多事务、部分成功和自动重试写。

用户列表 `data.items[].supplementalGroups` 返回每个自定义组 key/name，主组 `group` 维持原值。`user_group.memberCount` 对主组与补充组成员去重后统计。组删除在 actor、管理员组与目标组锁序稳定后检查主／补充引用；若有任一引用则返回既有“组有成员”业务错误。

## 前端状态

AdminUsersPage 在主组列之外展示补充组；具备管理权限的管理员能打开补充组选择器。组目录未成功、身份 epoch 变化、用户版本变化、网络失败或 mutation pending 时停写。对话框冻结 target user 的 ID、主组、补充组 key/name 集合及完整版本；目录刷新不能悄然重定目标，提交失败后清除冻结快照并读回用户与组目录，不自动重放。用户列表和 `auth/me` 的新响应仍按身份 epoch 隔离。组名作为文本安全显示；中英桌面与手机都有完整空、加载、错误、冲突、成功状态。

## 事务与测试边界

- Up／Down／Up：空关系可回滚；有一条关系时 Down 安全拒绝且行与 refs 不变，清理该本地 fixture 后可正常 Down/Up。
- 真实 PostgreSQL 验证主组加一／多个 custom、空组、拒绝 builtin/guest/重复/主组重复、删除与追加锁竞争、组 memberCount 去重、用户禁用／删除和 CAS。
- HTTP 与 Service 验证并集的授权／撤权、protected 边界、成员变更后旧 Session 无效、no-op 无审计、陈旧版本零写、锁等待中权限变更后按最新关系拒绝。
- 审查 SQL 直接权限查询与所有 Resolver 调用；短链、域名、用户、组配置和管理入口不能剩下旧单组最终授权旁路。
- 前端单测和真实 E2E 覆盖新字段兼容、添加／删除组、身份切换、迟到响应、读失败停写和双视口。运行仓库完整本地门禁，生成物零漂移，`git diff --check`。

## 设计决策归属

根据路线图多组成员缺口和现有权限／域名合同，本设计由代理自主选择“单主组 + custom-only 补充授权组”，而不是一次取消主组或重写所有 group API。主组维持既有默认域名语义；权限与域名授权使用并集；admin 权限只能由主组 builtin admin 授予；现有用户无补充关系回填。builtin 账号资格按 `app_user.builtin` 判定，账号主组为 admin 不改变普通持久化账号的目标资格。上述边界降低兼容风险且可单独验证。若实现审查证明任一既有授权路径不能统一改为当前账号 Resolver，应缩小影响或暂停该切片，不通过缓存或静态映射绕过。
