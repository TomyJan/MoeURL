# v0.20.0 短链归属转移实现计划

> 执行方式：使用 executing-plans 原生执行，最终按 requesting-code-review 进行独立整分支审查。

**目标：** 交付管理员单条短链的安全移交闭环。

**架构：** 复用 short_link.owner_id、用户行锁和事务审计；独立 TransferPort／TransferHandler 不扩大已有 mock 接口；全站列表提供完整精度版本。

**技术栈：** Go、SQLC 1.30.0、PostgreSQL 18、Vue、Vuetify、TanStack Query、vue-i18n。

**规格：** [设计](../specs/2026-10-23-v0.20.0-link-ownership-design.md)。

## 全局约束

- 只转移 owner_id，不迁移公开域名、访问配置或历史数据，不新增 schema／权限。
- 当前数据库授权、5 秒事务、完整精度乐观版本、同 owner no-op、审计原子提交。
- 严格 JSON，业务错误使用既有数字契约；不降低覆盖率／扩大排除。
- 本地签名原子提交，不自行推送、合并或发布，日常预览不动。

## 审查重点

1. 旧所有者的更新等待转移行锁：锁释放后不得修改新所有者记录。
2. 两个请求持有同版本转给不同人：仅一个成功，其余冲突。
3. actor 被降权、接收人同时被停用／改组：以锁内状态判断，不能相信旧身份。
4. 公开密码、额度及统计：转移不重置、不泄漏凭据，原所有者不能继续查询。
5. 退出换号及迟到请求：弹窗和缓存不能跨身份复用。
