## 固定验收数据

两名 owner、一个 admin，均为测试独占账号；三条目标 A／B／C 使用不同 UUID，至少一条归其他 owner。A 备注为多行私密 canary，B 为 BOM 开头文本，C 为空串。列表主版本记为 L，备注版本记为 N；测试分别保存每条完整业务行和对应审计集合，不只比较返回计数。

preview 输入恰为 items[{id,expectedUpdatedAt:L}]；clear 再带 expectedNoteUpdatedAt:N。preview 响应仅含每项 ID、两版本、hasNote 及 nonemptyCount／emptyCount；clear 响应仅含 changedCount／unchangedCount。API envelope 沿用现有协议。输出顺序保持输入顺序，锁按 UUID 排序；不能把加锁顺序当响应顺序。

## 后端判定矩阵

| 情况 | 结果 | 必须独立核对 |
| --- | --- | --- |
| A／B 非空，C 空，预览 | 2／1，code0 | 全部行及审计不变；响应无正文及 canary |
| 使用准确双版本清空 A／B／C | 2／1，code0 | 只 A／B note 为空、N 推进；L／其他字段全等；恰两条真实 actor 的 note 字段审计 |
| 全空、准确版本直接调用 clear | 0／N，code0 | 备注与主版本均不变；无新审计；UI 预览全空不发此请求 |
| 非空清空后重放旧请求 | 200116 | 完整行及审计与第一次成功后全等 |
| 两个全空准确请求并发 | 均可 no-op 成功 | “唯一赢家”仅指至少含一条非空的旧版本竞争，不制造无意义冲突 |
| 最后一个目标 L 或 N stale | 200116 | 前面的目标也零写，零新审计，不返回失败 ID／版本 |
| 最后一个目标缺失／软删／own 越 owner | 200104 | 整批零写，不返回可见子集或部分计数 |
| 可见 stale 与缺失／不可见目标混合，交换请求顺序 | 均为200104 | 先完整集合与全部所有权，再比较版本；零写且不返回局部事实 |
| actor 失效、guest、当前权限缺一项 | 120001 或既有基础访问拒绝 | 不读取私密响应，不写；scope 固定，不能用 header 冒身份 |
| 备注在 preview 后被单条保存 | 旧 clear 200116 | 新备注完整保留，批内其他目标不变 |
| 主版本在 preview 后被转移／改配置 | 旧 clear 200116 | 即便 admin 仍可访问也不得绕过 L |
| 第二条真实审计写入被拒绝 | 基础设施错误 | 第一条清空及审计亦回滚；错误／日志无正文 |
| 等锁时取消／五秒到期 | 取消或基础设施错误 | 全批不提交，资源回收；不用固定 sleep 证明队列 |

逐项缺权限测试 own:read_own／update_own／set_metadata，admin:admin:access／read_all／update_all／set_metadata。先证明有授权的对照行为，再撤去单项；不能只测试已经被其他条件拒绝的账号。

严格输入需覆盖 0／1／100／101、重复 UUID、大小写或零 UUID、字段缺失／重复／额外／null／类型错误、JSON 非对象或尾随值、错误 Content-Type、查询串、无效 UTF-8 和孤立代理、65536／65537-byte 实际原始体。过大请求在有界读取后拒绝，不无限读取后才检查。版本保留 1–9 位小数，十位拒绝；+08:00 与 Z 等价时可匹配，同一微秒内相差 1ns 仍冲突，不用数据库截断制造匹配。

锁队列测试分别覆盖 actor 禁用／改组、group 撤权、单条备注编辑、批量标签／归属转移、相反输入顺序的两次清空。检测实际等待对象后才释放前置事务，失败时有界取消并清理，不依靠“等了足够久”。五秒期限覆盖初次 authorize、事务开始和全部加锁／写入。

## 前端状态转移

| 当前状态与事件 | 允许动作 | 预期下一状态 |
| --- | --- | --- |
| closed → 打开有效当前页选择 | 仅一次实际 preview | loading；目标 ID／L 固定 |
| loading → 当前 preview 成功 | 有备注才允许确认 | ready，或全空无需操作 |
| loading → 只读网络失败 | 取消或显式重试 preview | preview-error，不能清空 |
| ready → 确认／双击确认 | 仅一个 clear POST | saving，普通关闭及其他写入口锁定 |
| saving → 当前且严格合法成功 | 清选择、受保护失效及成功反馈 | closed；保留过滤和每页大小 |
| saving → 明确业务拒绝 | 可解释提示；冲突退出并要求刷新重选 | 不自动重试写入 |
| saving → transport／5xx／畸形成功 | 显式重新 preview 或退出 | unknown，禁止旧确认 |
| unknown → 实际 preview 成功 | 显示新计数，必要时再次确认 | 新 ready／全空；绝不自动 clear |
| unknown → preview 再失败 | 显式只读重试或退出 | 继续 unknown，旧缓存不解冻 |
| 任意状态 → 身份／授权／打开代际退休 | 立即清私密状态 | closed；晚到 success/error/finally 均无副作用 |

一次预览不会撤销此前已提交的请求。未知结果后重新预览形成一次新的明确确认，不能自动沿用旧确认；若主版本变化，则必须重新加载列表并重新选择。非在途写允许关闭；关闭不会被描述成服务端取消或撤销。

使用受控 promises 对每种完成分支分别测试 A→B→A、同账号退出重登、同 tick 撤权恢复、关闭重开、卸载、外部强制更换筛选／页／大小。旧 finally 不得清新 pending；旧回调不得 invalidate 新身份 cache、清新选择、toast 或重新打开。正常 UI 的分页和筛选入口在对话框打开时互斥；外部变化仍必须使上下文退休。

客户端预览主版本须与打开时主版本精确等时：`.123456Z`与对应 `+08:00` 下的 `.123456000`可匹配，`.123456001Z`不可匹配，不能因 Date 截断成同毫秒而接受。clear 请求保留打开时主版本原字符串，不能采用响应中一个未经匹配的新主版本。

MyLinksPage 与 AdminLinksPage 各自逐项测试双向互斥：清空对话框与单条备注、访问设置、批量标签、启停／删除、本人批量创建、管理员单条／批量转移、CSV 导出、QR、筛选、分页及条数切换。除 disabled 断言外，直接触发已排队事件，确认无第二请求、对话框或导航变化。选中的 ID 必须仍在当前成功、idle、未 invalidated 的列表内。
