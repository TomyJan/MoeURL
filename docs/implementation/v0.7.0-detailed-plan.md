## 2. TDD 切片

### 2.1 配置解析

先写测试覆盖：空值兼容、HTTPS 公共地址、开发回环 HTTP、生产非 HTTPS 拒绝、路径/查询/片段拒绝、Base64 错误和密钥长度错误。随后扩展 `Config`，只做语法校验；是否存在启用 provider 在数据库装配阶段校验。

### 2.2 敏感值封装

新增 `internal/oidc/secret.go`。测试先覆盖随机密文、正确解密、错误 key、错误 AAD、版本错误和截断输入，再实现 AES-256-GCM。错误仅暴露稳定哨兵，不包含输入或底层密文。

### 2.3 Migration

先扩展 `internal/db/migration_test.go`，验证三张表、唯一约束、引用关系、清理索引、空数据回滚、存在 identity 时回滚拒绝、清理后续跑和 reapply。再新增 `00012`。

### 2.4 SQLC 查询

先扩展 `internal/db/sqlc_test.go` 约束查询行为，再新增 `queries/oidc.sql`：

- 管理列表和按 ID/key 加锁读取。
- 创建、乐观更新和软删除 provider。
- 公开启用 provider 列表。
- 创建 attempt、原子消费 attempt、分批清理。
- 查找 identity、首次创建用户和绑定、更新最近登录。

运行仓库 SQLC 生成入口并验证零漂移。

### 2.5 Discovery

定义小型 `Discoverer` 接口，生产实现使用 OIDC 库和带总超时、连接超时、响应头超时的 HTTP Client。测试使用 `httptest.Server`，覆盖标准 metadata、issuer 不匹配、不安全端点、超时、超大响应和无效 JSON。

### 2.6 Provider Service

使用表驱动测试覆盖：

- guest/user/admin 权限。
- 输入规范化和非法 key/domain。
- Secret 加密和响应脱敏。
- create/update/enable 时 Discovery。
- preserve/set 模式。
- optimistic conflict 返回最新值。
- soft delete、重复 key 和 identity 保留。
- 缺少运行时配置时关闭失败。

Service 不信任 Handler 或前端提供的 actor、`updatedAt`、endpoint 或 Secret 状态。

### 2.7 Provider Handler 与 Router

先写 Handler 测试固定业务错误映射，再实现 JSON 解码、actor 读取和响应。Router 测试验证 API 固定路由、no-store、未知路由、BodyLimit 和结构化日志字段。

### 2.8 Start

测试固定随机源和加密器，断言 state 摘要而非原值入库、nonce 摘要、S256 challenge、五分钟过期、固定 callback URL、安全 scope 和 return path。失败不重定向到任意外部地址。

### 2.9 Callback

通过 fake Token Exchanger 与 ID Token Verifier 逐一覆盖：

- state 不存在、过期、provider 不匹配和重放。
- Token 交换失败。
- ID Token 缺失、签名/issuer/audience/时间无效。
- nonce 不匹配。
- sub/email/email_verified 缺失或域名拒绝。
- 已绑定身份、首次供应、禁用用户和并发唯一冲突。
- Session 创建失败时不返回 Cookie。

协议库负责标准 Token 验证；业务层仍显式验证 nonce 和供应声明。

### 2.10 清理与生命周期

复用现有有界周期清理模式，但保持 OIDC 包不依赖 auth 内部未导出实现。测试立即执行、四批上限、短批提前结束、错误后保留下周期以及取消。App 测试验证启动校验和 Shutdown 等待。

### 2.11 前端 API

使用严格 Zod schema 覆盖登录方式与 provider 管理响应，验证未知字段、重复 provider、非法 key/domain、Secret 泄露字段和错误时间戳被拒绝。

### 2.12 登录页

测试无 provider、加载失败、本地登录不受影响、多个 provider、回调错误、return path 编码和完整页面导航。实现稳定高度与移动端布局，不在前端交换授权码。

### 2.13 管理页

按失败测试实现加载、空状态、新增、编辑、preserve/set Secret、Discovery 错误、保存成功、冲突、停用、删除、切换清反馈和请求期间切换目标。Secret 使用瞬时 DOM 输入并在 settled/关闭/切换时清理。

### 2.14 E2E

本地测试 IdP 提供 Discovery、authorize、token 和 JWKS，使用临时签名密钥。场景拆成独立 serial tests：

1. 管理员创建并启用 provider。
2. 新身份首次登录并进入控制台。
3. 同一身份重复登录复用用户。
4. 非白名单邮箱被拒绝且不创建用户。
5. 停用 provider 后入口消失且 start 被拒绝。
6. 本地登录继续可用。

## 3. 错误与日志

provider 管理业务错误使用 34xxxx 数字错误码，HTTP 状态继续遵循项目约定；浏览器 start/callback 只通过受控的 `oidcError` 字符串标识返回登录失败。日志事件使用 `oidc_request_failed`，允许字段仅包括 request ID、operation、provider key 和稳定错误分类。

禁止记录：Client Secret、authorization code、access/refresh/ID Token、state、nonce、verifier、subject、email、完整回调查询或上游响应正文。
