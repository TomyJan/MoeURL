## 实施顺序

1. 数据库迁移与模型：`00050_custom_user_groups.sql`，名称/默认域名约束、审计以及安全拒绝回滚。
2. 自定义组 CRUD：严格 JSON API、事务内实时 admin 授权、CAS、成员删除保护、`memberCount`。
3. 单账号组迁移与账号创建：任意存在的非 guest 组可用，保留既有 Session 撤销和审计；批量迁移不变。
4. 域名授权与组默认域名：custom groups 可单独配置，按事务实时权限验证并共享版本。
5. 前端管理：服务端动态 group key、CRUD/权限草稿/域名授权、创建用户及单账号迁组；protected 项锁定，批量迁组 builtin-only。
6. 文档、生成物漂移和整体验收：同步规格与状态，运行后端及前端本地门禁、所需真实 DB/HTTP/browser 验收并记录准确身份；不以本地证据替代真实 CodeRabbit、PR 合并核验或归档。

- 每个行为先有能按预期失败的测试，再实现最小改动。
- 后端迁移/SQLC 涉及生成物时在当前锁定版本运行生成，并二次生成确认无漂移。
- 只复用与当前 commit 范围相同、运行环境和配置一致的历史验证；Task 5 不改后端，不重复 Go 套件。
