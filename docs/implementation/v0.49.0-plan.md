# v0.49.0 批量清空内部备注实现计划

> 面向 AI 代理：按既有无人值守授权使用 executing-plans 内联执行；不询问常规确认，不派 builder／逐任务审查。浏览器阶段仅一次 fresh 最强 supported 整分支终审。PR263 已完整交付后从 master fa020805ed5499f40a9f437d710f3eb661247057 启动本计划。

**目标：** 当前页 1–100 条私密备注经过计数预览、双版本检查和显式确认后原子清空。

**架构：** 独立四个 POST 端点；当前授权与有序锁保护全部目标，SQLC 分别生成共享锁预览与更新锁清空查询。独立 strict 客户端和代际 controller/dialog 接入两列表，旧单条备注、metadata、CSV 和公开协议不扩展。

**技术栈：** 既有 Go／Chi／SQLC1.30／PostgreSQL、Vue3／Vuetify4／TanStack Query／Vitest／Playwright，无新依赖、权限或 migration。

**规格：** [设计](../specs/2026-11-04-v0.49.0-batch-note-clear-design.md)、[范围](../product/scope-v0.49.0.md)。

**验收判定：** [验收](v0.49.0-acceptance.md)细化固定数据、逐项判定和异步状态转移；所有条目尚未执行。

## 审查重点

1. 混合所有者、部分目标 stale／被删、审计拒写：不能前几条已清空、后几条失败。
2. 预览后别人改了备注或转移：分别检查备注版本与主版本；旧同值请求也冲突。
3. 退出再登录同账号、权限撤回再恢复、重开后旧 finally：不得解除新请求锁或显示旧反馈。
4. 网络写结果未知、畸形成功、重复点击：不能自动重试或把旧缓存当实际读回。
5. 表格／CSV／公开跳转和审计日志：不能因批量操作暴露正文；纯空值 no-op 不推进任何版本。
