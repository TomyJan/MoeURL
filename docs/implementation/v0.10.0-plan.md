# v0.10.0 短链最大访问次数闭环计划

## 目标

在不改变默认无限额访问性能和现有统计口径的前提下，交付权限可控、数据库并发安全的短链最大访问次数闭环。

## 阶段

1. 建立 migration、权限目录和额度字段约束。
2. 扩展 SQLC、短链领域模型及创建、更新事务。
3. 在公开最终跳转中实现原子额度领取和明确写失败补偿。
4. 扩展前端 API、创建面板、设置对话框、列表和公开耗尽状态。
5. 补齐 E2E、部署与技术文档，执行完整门禁和生产级自审。

## 关键决策

- 额度计数不依赖可能丢失的 `short_link_event`。
- 只有有限额短链执行同步额度更新，无限额短链保持现有只读解析。
- 清除限额结束当前额度周期；重新启用从 0 开始。
- `exhausted` 是派生状态，不覆盖 `short_link.status`。
- 降低上限可以立即耗尽，提高或清除上限可以恢复访问。

## 提交策略

- `feat(短链): 建立访问次数额度数据模型`
- `feat(短链): 支持配置访问次数上限`
- `feat(跳转): 原子限制短链访问次数`
- `feat(前端): 管理短链访问次数上限`
- `test(v0.10.0): 覆盖访问次数额度闭环`
- `docs(v0.10.0): 完善最大访问次数交付文档`
