# v0.6.0 生产就绪闭环详细实现计划

状态：实施计划已于 2026-08-29 确认。任务 1 至任务 6 已实现并提交，任务 7 与任务 8 的代码和本机可执行门禁已完成；完整 Compose smoke、隔离恢复和目标 CI 发布门禁仍待验证。

> **面向 AI 代理的工作者：** 必需子技能：使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 在保持 v0.5.0 产品行为和权限边界不变的前提下，完成单机 Docker Compose + 外部 TLS 反向代理部署所需的应用生命周期、安全边界、认证保护、数据维护、运维文档和安全门禁。

**架构：** `internal/config` 负责 production 启动契约；`internal/middleware` 与 `internal/http` 负责应用级 HTTP 边界；`internal/app` 和 `cmd/server` 统一 HTTP Server、后台任务、数据库 Pool 与信号生命周期；认证失败状态和 Session 清理使用 PostgreSQL 与 SQLC 保持多实例一致。默认 Compose 只暴露回环 App 端口，PostgreSQL 留在私有网络，TLS、HSTS 和来源级限流由外部反向代理负责。

**语言基线：** Go 最低版本为 1.25+，`go.mod` 当前声明为 1.25.7。

**构建环境：** `Dockerfile` 当前使用 `golang:1.27.0` 构建镜像，前端构建 Node.js 版本与 `web/package.json` 的 26.x 契约一致。

**技术栈：** Chi、SQLC 1.30.0、Goose、PostgreSQL 18、Vue 3、TypeScript、Vuetify 4、TanStack Query、Zod、Vitest、Playwright、Docker Compose。
