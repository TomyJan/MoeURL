## 配置、初始化与 HTTP 边界

- [x] production 强制至少 32 字符的 `MOEURL_SETUP_TOKEN`，development 保持可选。
- [x] 初始化状态返回是否需要 Token，setup 在普通输入和已初始化检查后执行常量时间校验，Token 不落库、不记录、不回显。
- [x] 增加请求 ID、panic recovery、安全响应头、1 MiB 请求体限制和完整请求日志字段。
- [x] 配置 HTTP 读取、写入、空闲、Header 超时和 `MaxHeaderBytes`。

## 健康检查与生命周期

- [x] `OpenPool` 启动时显式 Ping，失败关闭 Pool 并阻止应用启动。
- [x] 实现 `/api/v1/health/live` 和数据库 `/api/v1/health/ready`，兼容 `/api/v1/health` 使用 readiness 语义。
- [x] 健康路由绕过 Current User 解析，liveness 不依赖数据库。
- [x] 主进程消费 `SIGINT`、`SIGTERM` 和 Server 异常退出，使用 15 秒统一期限优雅关闭。
- [x] Shutdown 按 HTTP drain、后台任务、Pool 顺序执行，支持部分初始化、错误汇总和重复调用。

## 登录与 Session 安全

- [x] 新增 `00011_auth_login_attempt.sql` 和 SQLC 查询，migration 支持 Up、Down、再次 Up。
- [x] 未知用户名、无密码和错误密码执行等价 Argon2id 路径，并保持统一凭据错误语义。
- [x] 登录失败按用户名 SHA-256 摘要落库，在 15 分钟窗口第 10 次失败时阻断 15 分钟；成功登录清理状态。
- [x] 限流在并发请求和多个 Service 实例间一致，禁用账号不创建 Session。
- [x] 登录事务从 `Begin` 到 `Commit` 使用脱离请求取消、最长 10 秒的操作 Context，独立 2 秒清理 Context 负责回滚；请求取消后的错误凭据仍提交计数，基础设施失败仍回滚。
- [x] 登录失败状态按 `updated_at` 清理索引、完整 15 分钟活动窗口和阻断结束条件筛选，每轮最多删除 500 条；启动后立即执行并每 15 分钟运行，失败后继续下一轮，取消后退出。
- [x] App 同时启动登录失败状态和短链授权清理，并在 Shutdown 中等待两者；任务 5 的 Session 清理保持独立数据与调度边界。
- [x] Session 启动后立即并每 15 分钟分批清理最多 500 条过期或撤销记录。
- [x] Session 清理失败不影响在线请求，退出时与登录失败状态和短链授权清理一起停止。
