# v0.75.3 文档入口与执行设计维护设计

## 意图与选择

前版 review 已确认执行设计放错层和六入口重复状态；v0.75.2 又保留四处 EOF 空行。先做有界文档维护，降低后续状态漂移与阅读成本，不扩大产品行为。

Agent 选择沿用现有 linked worktree 内联执行，不派 builder 或逐任务审查；只在版末做一次 fresh 最强整分支终审。常规设计、提交、正常集成及准确清理沿用户无人值守授权；这些范围和实现选择是 Agent 的决定，不写成用户逐项批准。

## 原文保存与导航

保留 development-status 中最近八个历史检查点的完整原文；其他五个入口的对应正文仅在相对链接规范化后逐字相同才缩为引用。保留这些入口的原 H2，保证旧标题仍有落点；短链接指向统一进度页，并写明对应版本标题，不猜平台 fragment。原规范化文本及 hash、源位置和替换范围留证据，所有其他段落保持原样。

40 份正文已只读确认相同。任何一份在执行前发生漂移，都拒绝替换并重新核事实，不采用近似文本或删除不相同的历史。更早及各入口独有历史不纳入本轮，剩余重复明确接续。

v0.75.1 执行设计使用原生移动，文件 bytes/hash 不变；scope 链接及 plan 文字路径同步到 implementation。稳定功能规格不动，旧提交、旧 review 和旧候选失败记录不回写。四个 EOF 仅删多余末尾空行，保留一个终止 LF，不借此更改语句。

## 验证与风险

外置校验器读取基线、目标原文与实际文件，核内容守恒、标题、范围外文本、链接、移动身份、旧引用零残留、完整非 Markdown 输入以及全范围 diff-check。只做文档修正，不把检查失败包装为产品 TDD；不运行未变化的生产套件或生成器。

最大风险是误删唯一历史或将旧 pending 改成假通过。当前摘要与历史标题分开，只在当前摘要记录实际交付；保留的历史原文不重写日期、失败、SHA 或执行身份。另一风险是把部分集中化冒成所有重复已修，验收必须继续列出较早历史边界。

预计临时增量小于 2 MiB，无容器、卷、镜像或新缓存。只有版末恢复 ZIP 需要预算盘点及精确叶目录迁移；源分支和 worktree 保留。审查、正常合并、独立证明与恢复归档分别实证，不查 CI、不发布部署。
