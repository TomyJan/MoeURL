# v0.1.2 实施计划

## 1. 目标

v0.1.2 在既有控制台 Shell、`auth/me` 数据和前端偏好系统之上，补齐个人设置页与当前用户昵称自助修改，让登录用户能够查看账号信息、修改昵称，并继续管理本地语言和主题偏好。

## 3. 阶段

1. 锁定个人设置页、自助昵称修改与入口整合的范围边界。
2. 在后端补齐 `POST /api/v1/user/profile/update`，并只允许当前登录用户修改自己的昵称。
3. 在前端交付 `/profile` 页面，复用 `auth/me`、`PreferenceSwitcher` 与现有控制台 Shell。
4. 跑完后端、前端质量门禁，记录实际验证结果并整理验收记录。

## 4. 技术要求

- 后端继续使用 Go、Chi、SQLC 与 PostgreSQL。
- 前端继续使用 Vue 3、TypeScript、Vuetify 4、TanStack Query、`vee-validate` 和 `zod`。
- 不新增数据库表或 migration；昵称更新直接复用现有 `app_user.nickname` 字段。
- 语言和主题偏好继续由前端本地存储保存，不引入服务端偏好同步。
- 路由、页面文案和导航入口使用稳定的中英文翻译键。
- 页面必须覆盖加载、局部错误、保存成功、移动端布局与空状态。

## 5. 验收重点

- 当前用户可以从首页和控制台进入个人设置页。
- 当前用户可以修改昵称，刷新后仍然可见。
- `guest`、空白昵称、被删除用户、内置账号和数据库错误的处理都符合既有响应约定。
- 所有后端、前端和构建门禁通过，且不引入额外范围。
