## 工程切片

文件职责：后端 `internal/shortlink/batch_service.go` 管理有界请求与授权，`batch_handler.go` 管理严格 JSON 与响应；各自 `_test.go` 验证真实数据库和 HTTP 契约。`queries/short_link_batch.sql` 承载原子状态／删除查询，`internal/db/sqlc/short_link_batch.sql.go` 仅由 SQLC 生成；`internal/http/router.go` 与 `internal/app/app.go` 接入独立端口。前端 `web/src/entities/short-link/batch.ts` 定义 API 契约，`features/short-link-batch/` 管理共享选择／动作／确认；个人与管理页只传列表、上下文和阻塞状态，`ConsoleLinkList.vue` 提供标准选择列，i18n 提供双语。回归分别放在相邻测试与 `web/e2e/v0.17.0-bulk-links.spec.ts`。

1. 提交范围、设计、计划与未勾选验收，修正 v0.16.0 合并状态。
2. 后端先写真实数据库和 HTTP 回归测试，再实现独立 BatchPort／Handler 与两条路由；生成 SQLC 并复跑零漂移，业务覆盖率 100%。本地原子提交。
3. 前端先写 API 与交互测试，再接入标准列表选择、共享批量工具条、双语及身份隔离。补充隔离 Playwright 场景，更新版本与技术契约。本地原子提交。
4. 规格审查通过后进行代码质量审查，修复有效问题；完整 Go／前端门禁、隔离浏览器与资源清理。提交验收和进度记录。

后端定向运行 `go test -count=1 ./internal/shortlink ./internal/http -run 'TestBatch'`，覆盖率使用独立 profile，避免覆盖既有任务文件；SQLC 使用 `go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.30.0 generate` 并比较生成前后散列。前端定向运行相邻 API／组件／页面回归及 `pnpm exec playwright test e2e/v0.17.0-bulk-links.spec.ts`；先观察缺失功能导致的失败，再运行实现后的通过结果。切片提交前检查暂存范围，使用 `feat(短链): ...` 等有语义的约定式提交。

## 验证与环境

Go 1.26.8、Node.js 26.3.0；采用现有本机 PostgreSQL 16.3 隔离数据库回退时明确区别于目标 PostgreSQL 18／Docker。不覆盖日常预览端口 18080 或 `web/dist`。构建输出置于任务 `.tmp/v017-*` 路径，完成后归档证据并清理任务服务／数据库。

运行 `go test ./...`、`go vet ./...`、仓库 Go 覆盖率及 lint 入口；前端运行 lint、typecheck、完整 Vitest 覆盖率、隔离 build 和 Playwright。生成 SQLC 前后比较文件散列；最终 `git diff --check` 和工作区检查。目标 CI 与发布只能按实际证据勾选。
