# v0.5.0 验收清单

> 未执行的项目不得标记为完成。

## 权限与数据

- [x] 权限目录覆盖全部当前权限常量，权限键和预设引用无重复、无未知项。
- [x] `restricted`、`basic`、`standard` 只替换可配置权限，受保护权限固定归属 `admin`。
- [x] `guest` 固定为空权限并且不能通过更新 API 修改，预设只适用于 `user` 和 `admin`。
- [x] 三个内置用户组按稳定顺序返回，数据库权限数组按目录顺序规范化保存。
- [x] 相同旧 `updatedAt` 的并发写入只有第一个成功，后续写入返回 `300202` 且不覆盖数据。
- [x] v0.5.0 不新增 schema 或 migration，SQLC 生成代码与查询一致。

## API 与安全

- [x] 管理员可以列出用户组、权限目录和预设，并更新 `user`、`admin` 权限；`guest` 保持只读。
- [x] 非管理员无法读取或更新用户组权限，前端限制不能替代后端 `admin:access` 检查。
- [x] 未知权限、重复权限、非法时间和非内置组请求被拒绝。
- [x] `admin` 的受保护权限不能移除，`guest` 和 `user` 不能获得这些权限。
- [x] 权限读取或数据库写入失败返回 HTTP `500`，不降级为静态权限或部分成功。
- [x] 更新日志不包含 Session、密码或其他敏感数据。

## 页面与即时生效

- [x] `/admin/user/group` 展示三个真实内置用户组，不再显示规划中占位内容。
- [x] 权限按分类展示，受保护项只读，预设只修改草稿且保存前不写入数据库。
- [x] `user` 和 `admin` 分别保留未保存草稿；`guest` 不创建可保存草稿，保存状态、失败反馈和成功反馈明确。
- [x] 并发冲突提示管理员基于最新数据重新编辑，不自动覆盖或重试写入。
- [x] 更新当前操作者所在组后刷新 `auth/me`，后续页面能力和后端业务请求立即使用新权限。
- [x] 桌面和移动视口无重叠、横向溢出或不可操作控件。
