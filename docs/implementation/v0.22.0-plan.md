# v0.22.0 批量短链归属转移实现计划

> 面向 AI 代理：使用 subagent-driven-development 逐任务执行，任务审查和最终整分支审查均独立进行。用户已授权全程自主工作，无需产品问答或签名解锁；提交仅逐次绕过签名，不改全局配置。

**目标：** 管理员安全原子移交当前列表最多 100 条短链。

**架构：** 沿用单条转移的有序用户锁、当前组授权、WithAuditTx 和 owner_id 触发器；新增有序批量短链锁及全量版本预检。控制台复用既有选择，使用独立不可变快照对话框，不改变旧批量 API。

**技术栈：** Go 1.26.8+、Chi、SQLC 1.30.0、PostgreSQL、Vue 3、Vuetify 4、TanStack Query、vee-validate、zod、vue-i18n，无新增依赖。

**规格：** [设计](../specs/2026-10-25-v0.22.0-batch-ownership-design.md)及[范围](../product/scope-v0.22.0.md)。

## 全局约束

- `POST /api/v1/admin/short-link/batch-transfer`，严格单一 JSON，1–100 条不同规范非零 UUID 与非零 RFC3339Nano 版本。
- `admin:access` 与 `short_link:update_all`；5 秒 WithAuditTx，用户 UUID → 当前组 → 短链 UUID 锁序，预检全部版本后才写入，任一失败整批回滚。
- 同 owner 校验版本且不写／不审计；实际变化仅 owner_id 和单调 updated_at。无 migration／新权限／新依赖。
- 成功 `{transferredCount,unchangedCount}` 合计请求数；业务码沿用 100001／120001／200104／200116／200117，基础设施 500／900000，安全诊断、no-store。
- 当前列表选择、不可变确认快照、写入互斥、冲突刷新及身份轮次隔离；准确用户名不 trim 或大小写折叠。
- Go 业务与前端四项 100%，不降低阈值、不扩大排除；SQLC 只通过标准入口生成，第二次零漂移。
- 不修改 18080 预览／数据库／web/dist。新功能只本地原子提交，推送／合并不自动沿用前一个 PR 的专项授权。

## 审查重点

1. 混合有效／陈旧／同 owner 的批次，后部失败不能留下前部更新或审计；任务 1 的 TestBatchTransferRollback／Versions 证明。
2. 相反输入顺序并发、旧 owner 等待锁、actor 与 recipient 同一人，保证锁序且移交后不越权；任务 1 的真实 PG 并发回归证明。
3. 查询刷新失败仍缓存旧版本，不得重开并再次提交；任务 2 的页面失败／成功刷新回归证明。
4. 同 tick 撤权／身份换号、提交迟到完成与新选择，不能关闭新对话框／清空选择／旧 Toast；任务 2 的 lifecycle 回归证明。
5. 100 条长 URL／多字节 owner 与长用户名在手机确认无溢出，精确用户名及历史统计不丢失；任务 2 布局约束及任务 3 的真实浏览器证明。
