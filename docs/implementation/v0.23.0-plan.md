# v0.23.0 批量标签整理实现计划

> **面向 AI 代理的工作者：** 使用 subagent-driven-development 逐任务实现、测试、提交并独立审查。

**目标：** 为当前列表的一组短链原子添加、移除或替换标签。

**架构：** 使用独立批量标签 API 与同一审计事务，先锁定、重新授权及全量版本预检，再仅更新 tags。控制台复用列表多选、标准 Vuetify 对话框与账号轮次，不扩展通用批量编辑框架。

**技术栈：** 既有 Go／SQLC 1.30.0／PostgreSQL、Vue／Vuetify、TanStack Query、vee-validate／zod；无新依赖或 migration。

**规格：** [批量标签设计](../specs/2026-10-26-v0.23.0-batch-tags-design.md)、[范围](../product/scope-v0.23.0.md)。建造者检查：没有剩下重要的问题。

## 全局约束

- 个人／后台两个 `/api/v1/.../short-link/batch-tags` POST 接口；`items` 为 1–100 条互异的规范非零 UUID 与完整精度非零版本。
- `operation` 为 add／remove／replace；tags 为显式数组，add／remove 1–10 个，replace 0–10 个，每个裁剪后 1–32 个 Unicode 字符，无控制字符、重复或无效 UTF-8。
- 整批原子、结果最多 10 个标签、保留顺序；只改变 tags／严格递增 updated_at；no-op 不写版本或审计。
- 当前数据库授权：个人 update_own + set_metadata + owner；后台 admin:access + update_all + set_metadata。5 秒期限，用户 → 组 → UUID 排序短链锁。
- 成功 `{changedCount, unchangedCount}` 合计等于条数；非法输入 100001、无权 120001、缺失／归属 200104、版本 200116、结果超量 200119、基础设施 500／900000。
- SQLC 只能标准生成；业务与前端覆盖率均 100%，不降低阈值或扩排除；不得影响日常 18080 预览和数据库。

## 审查重点

- 等待归属移交完成的旧 owner 不得在持锁后写入；独立并发测试验证所有批次同序加锁。
- add 的结果超量应在任何写入前拒绝整批，即使前一条有效或 no-op；审计故障同样回滚全部。
- 同标签不同顺序的 replace 属于实际变化，add／remove no-op 不应改变版本；纳秒输入不能被毫秒解析误判为零。
- 对话框打开后列表刷新、筛选或账号变化不得重新授权旧快照；冲突刷新失败不得复用缓存版本。
- 对话框消失后的成功仍刷新缓存，但不得清空新身份选择或显示旧会话提示；导出／单条和其他批量操作双向互斥。
