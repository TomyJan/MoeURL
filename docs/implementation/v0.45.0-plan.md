# v0.45.0 短链列表分页实施计划

> **面向 AI 代理的工作者：** 使用 executing-plans 亲自逐任务实现；沿用既有隔离 worktree，最后整分支一次 fresh 独立终审。本计划由当前执行者按无人值守授权实施。

**目标：** 本人和全站列表能访问第 21 条及后续记录，并保持筛选、当前授权和单页选择边界。

**架构：** 复用现有 page／pageSize／meta.total 协议，两页追加本地页码与单调查询代际；共用只负责展示和发出翻页／重试事件的组件，页面负责 live 授权和操作互斥。页码不进入 CSV 筛选。

**技术栈：** Vue 3、TypeScript、Vuetify 4、TanStack Query、Vitest、Playwright；不改依赖。

**规格：** [分页设计](../specs/2026-11-03-v0.45.0-link-list-pagination-design.md)。

## 全局约束

- 固定 pageSize=20，只有前后翻页和失败重试，不增加跨页全选、跳页、页大小或后端行为。
- 无 API、schema、SQLC、权限及依赖变化；不将备注正文／版本加入列表、公开响应或 CSV。
- A→B→A、筛选和身份轮次使用单调 listRevision 防旧缓存；每次翻页清批量选择。
- 明确本地与候选／master 各自运行身份。所有输出在 v045-evidence，不重已成功且输入不变的 Go／生成器；新前端完整验证。
- 每任务 start／brief／done；最终真实 reviewed／covered、所有有效问题闭环、候选及 master 各九 CI、完整原日志与可恢复归档后才完成。
- 不碰 PR240、18080、日常 DB、未知资源，不发布／部署／tag，不删分支／worktree。automation 仅兜底，不停止持续执行。

## 审查重点（Review Focus）

1. 同一页重新访问或组件重挂载不得短暂恢复旧集合；真实 QueryClient 延迟请求验证。
2. 同 tick 的 queued 页码事件不得绕过当前授权、备注草稿或提交互斥；写请求仍只包含用户实际选择的本页记录。
3. 成功后 total 缩小才收敛页码，失败／pending 不得误当零条或循环切页。
4. 第 2 页导出仍是全部已应用筛选，不混入页码、当前选择、备注或旧身份。
5. 无效／未应用筛选、撤权、换账号和退出期间不得发送翻页请求或显示旧总数；出错仍能重试和返回。
