# v0.7.0 多提供商 OIDC 登录实施计划

状态：功能实现与本地可执行门禁已完成；目标 CI、race、外部 OIDC 互操作和生产发布验收待补。

## 1. 目标

在不替换现有本地登录、Cookie Session 和权限模型的前提下，实现可由管理员维护的多提供商 OIDC 登录。外部身份最终映射为本地 `app_user`，后续请求继续走现有 Session、用户状态和数据库权限解析。

产品边界以 [v0.7.0 范围](../product/scope-v0.7.0.md) 和 [OIDC 登录设计](../specs/2026-09-11-v0.7.0-oidc-login-design.md) 为准。

## 2. 实施原则

- OIDC 使用成熟库完成 Discovery、OAuth 2.0 和 ID Token 验证，不自行实现协议密码学。
- Client Secret 与 PKCE verifier 使用应用部署密钥加密，任何响应和日志都不返回敏感值。
- 外部身份与本地用户、Session、用户组和权限汇合，不建立第二套授权模型。
- 首次供应只进入 `user`，并要求经过验证且命中白名单的邮箱。
- 每个行为先补失败测试，再写最小实现；生成代码只通过 SQLC 入口更新。
- 本地登录、未配置 OIDC 的部署和旧数据库升级路径必须保持兼容。

## 3. 阶段

### 阶段 1：文档与基线

- 固化 v0.7.0 scope、设计、计划、任务和验收边界。
- 记录 Go 1.26.8、Node.js 26.x 基线。
- 修复部署文档测试的换行敏感性，使基线在 Windows 与 CI 一致。

### 阶段 2：配置、加密与 schema

- 增加公共地址和 OIDC 加密密钥配置校验。
- 以 TDD 实现版本化 AES-GCM 敏感值封装。
- 新增 provider、external identity 和 login attempt migration、SQLC 查询及 migration 回滚测试。

### 阶段 3：提供商管理

- 实现 Discovery 端口和有界 HTTP 客户端。
- 实现 provider CRUD、Secret 保留、软删除、权限和乐观并发。
- 注册管理员 API，验证 no-store、错误码与日志脱敏。

### 阶段 4：OIDC 登录协议

- 实现公开登录方式查询。
- 实现 start 的 state、nonce、PKCE 和安全 return path。
- 实现 callback 的一次性状态消费、授权码交换、ID Token 校验、邮箱策略和 Session 签发。
- 实现首次用户供应、身份复用、禁用用户检查和并发竞争处理。
- 增加过期 attempt 有界清理并接入应用生命周期。

### 阶段 5：前端产品闭环

- 登录页展示外部登录方式和受控错误反馈。
- 将 `/admin/setting` 替换为身份认证管理页。
- 实现 provider 列表、创建、编辑、启停、删除、冲突恢复和 Secret 临时输入。
- 补齐双语、响应式和前端 API schema。

### 阶段 6：E2E、文档与收尾

- 使用本地测试 IdP 覆盖 provider 配置、首次登录、重复登录、拒绝和停用。
- 更新部署、备份、升级、技术基线、路线图与文档索引。
- 运行后端、前端、SQLC、migration、覆盖率、构建和 E2E 门禁。
- 完整 review 安全、权限、并发、迁移、日志和用户体验，修复后本地提交。

## 4. 关键验证

- 错误 state、nonce、issuer、audience、签名和过期 ID Token 均不能建立 Session。
- callback 状态消费后不可重放，即使后续 Token 交换失败也不恢复。
- Client Secret 数据库值不是明文，API/日志/前端缓存不出现明文。
- provider 并发更新返回冲突并保留当前草稿。
- 同一外部身份并发首次登录最终只有一个 identity 和一个本地用户。
- 未配置 OIDC 时现有部署和本地登录无行为变化。
