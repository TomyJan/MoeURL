# v0.19.0 用户组成员迁移实施计划

> 执行方式：使用 executing-plans 原生执行，最后进行独立整分支审查。

**目标：** 安全交付管理员单账号改组和强制重新登录。

**架构：** 复用 app_user、session、事务审计和用户管理页面；SQLC 负责有序行锁与更新，不新增 schema。

**技术栈：** Go、Chi、SQLC 1.30.0、PostgreSQL 18、Vue、Vuetify、TanStack Query。

**规格：** [设计](../specs/2026-10-23-v0.19.0-user-group-membership-design.md)。

## 全局约束

- 仅 user／admin，保护 builtin 和操作者自身；保持原始账号、短链和 OIDC 绑定。
- 5 秒事务预算、当前数据库授权、完整精度 expectedUpdatedAt、同组 no-op、真实改组撤销所有旧会话。
- 更新、撤销、审计原子提交；不新增依赖，不降低覆盖率或扩大排除。
- JSON 单对象与已知字段，HTTP 200 业务错误；文档保持候选证据归属。

## 审查重点

1. 操作者在入口之后被降权：事务读当前组拒绝旧 actor。
2. 两个管理员互相改组：按 UUID 顺序锁行，不反向死锁。
3. 修改后旧会话仍有缓存：真实服务验证撤销，重新登录取新权限。
4. 列表小数秒截断：完整精度往返，陈旧版本冲突。
5. 刷新列表或迟到结果切换目标：对话框快照不被替换，pending 禁止换目标。
