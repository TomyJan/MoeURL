# v0.36.0 账号时区显示预设实现计划

> 面向 AI 代理：使用 executing-plans 内联实施；不派 builder。用户持续自主授权覆盖普通设计取舍和执行确认；最终仅一次独立 fresh 最强 supported 整分支审查。

**目标：** 账号选择显示时区，跨设备持久化，身份切换不泄漏旧偏好。

**架构：** 独立 SQLC 表与本人 CAS API；前端沿用共享身份 epoch，新独立偏好协调器与编辑器；Intl 只格式化真实 instant，不改业务时间。

**技术栈：** Go 1.26.8+、pgx／SQLC 1.30／Goose／PostgreSQL、Vue 3／Vuetify 4／TanStack Query／Intl，无新依赖。

**规格：** [正式规格](../specs/2026-11-01-v0.36.0-account-time-zone-design.md)与[产品范围](../product/scope-v0.36.0.md)。

## 全局约束

基线 08b990d70bf30dbe54f885d0b7a3bc9490eacb89；分支 feat/v0.36.0-account-time-zone。null 跟设备；固定九预设；5 秒事务；锁账号→当前组。不改 UTC 分桶、CSV、cursor、到期输入、公开访问及旧 DTO。生成物只由标准 SQLC 生成；所有输出外置，既有阈值与排除不降，不安装本机依赖。不触 PR240、18080、日常 DB、未知资源，不发布部署。

## 审查重点（Review Focus）

1. 当前 Cookie 本人与 DB 撤权／首次竞争／纳秒版本：只能合法本人写一次，失败无部分写，旧偏好不变（Task1 Contract／Concurrent／Authorization）。
2. 同账号新登录、切身份、卸载后的迟到 success／error／finally：不显示旧值、不改新缓存或新草稿（Task2 IdentityRace／EditorRace）。
3. UTC 纯日期、统计桶、CSV、cursor、CAS 和到期输入：只显示改变，原请求及协议完全不变（Task2 DisplayBoundaries 与 Task3 E2E）。
4. DST、跨日、Intl 不支持：真实 instant 格式正确，明确设备回退且保存值不变（Task2 Formatter／Fallback）。
5. 全链路生产 wiring、迁移回退、完整门禁与逐 SHA 证据：不得用 mock callcount、空审查或旧镜像代覆盖（Task1 App／Migration 与 Task3／4）。
