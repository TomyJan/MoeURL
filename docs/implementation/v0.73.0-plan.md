# 有界批量目标规则检查实现计划

> 使用 executing-plans 在已有 linked worktree 内联执行；用户持续自主授权覆盖普通确认。仅版末唯一 fresh 最强全分支终审，不派 builder、逐任务审查或复审。

**目标：** 管理员一次检查 1–20 个目标，保留单目标流程。
**架构：** 独立 batch Port/handler，共用七规则私有快照和 matcher；一个只读事务，独立前端身份与输入隔离。
**技术栈：** 既有 Go／PostgreSQL／Vue3／Vuetify4，无新依赖。
**规格：** [范围](../product/scope-v0.73.0.md)、[设计](../specs/2026-11-14-v0.73.0-batch-target-policy-check-design.md)。BASE `dfc78e9cf6bf1bd3509b2e1e62864b50bccb3755`。

## 全局约束

targetUrls严格数组1–20项，每项1–2048 UTF-8 bytes，body256KiB，不改写／去重，拒绝控制字符／非法UTF-8／孤立surrogate。错误900227，授权120001，基础设施900000。data.items每项连续1起始index及三字面量outcome；一个五秒ReadCommitted/ReadOnly事务，gate先于查询，一次七规则快照。只读为业务只读；不查CI、不部署，预算与精确消费遵守交付规范。

## 审查重点

1. 无权者混入非法目标不得获得结果；Task1当前身份授权矩阵。
2. 七坏规则不得被先遇到拒绝目标掩盖；Task1七坏存储混合批次全失败。
3. 一个批次不得混用保存前后规则或创建20个事务；Task1真实PG查询计数与确定性gate保存队列。
4. 结果不能错配重复输入、丢项或旧草稿；Task1顺序／Task2基数与序号严格检查和revision竞态。
5. 大转义、孤立surrogate和20行手机不得绕容量或遮操作；Task1载荷／Task2输入边界／Task3真实手机布局。
