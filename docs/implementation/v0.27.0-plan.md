> **面向 AI 代理的工作者：** 使用 executing-plans 在当前会话逐任务原生实现，不为每个任务另派实现／审查者。全部任务后仅一次 fresh 最强全分支审查。

## 审查重点（Review Focus）

1. 排序后后台 refetch，旧手动选择或已加载个人偏好不能被新的首项覆盖，且实际创建 payload 与预览一致（Task2 SelectionPriorityAcrossOrderRefresh）。
2. 排序成功后列表刷新失败，不能显示伪排序或允许用陈旧版本继续写；晚到的旧身份响应也不能回写新身份（Task2 RefreshFailureBlocksWrites／LateIdentityResponse）。
3. 操作者在等待 domain lock 时被禁用、删除、改组或撤权，不能用旧 actor.GroupKey 越权（Task1 ReauthorizesAfterDomainLock）。
4. 同值但陈旧版本仍冲突；并发普通详情编辑不能抹去排序或悄悄覆盖版本（Task1 NoopAndConcurrentLegacyUpdate）。
5. 审计触发器改造及回滚不能破坏旧域名写，审计失败须连排序／版本回滚（Task1 AuditRollbackAndMigrationDown）。
