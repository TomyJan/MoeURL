# 控制台导航、版本标识与界面细节计划

本次沿用已批准的雾蓝石墨视觉方向，在 `master` 上完成本地提交，不推送。

## 范围与实施切片

1. 分析作为单条短链的二级页面，分别保留个人和全站上下文、返回入口及既有权限；移除独立分析导航。旧分析 URL 转入个人短链上下文。
2. 列表和详情的长目标地址单行省略，保留完整悬停文本、编辑值和跳转地址；统一分析卡片、页面标题、响应式和失败重试样式。
3. Powered by 始终显示，设置入口不再允许关闭。保留旧 API 字段以兼容客户端，但服务端读取及写入均返回 `true`。
4. 构建时静态注入版本和源码链接：精确 semver tag 使用 tag 版本和 tag 链接；其他提交使用前端包版本及提交短哈希，链接到完整 commit。当前开发基线为已实现的 `0.11.0`，不代表正式发布。
5. 本地 Vite 读取 Git；不携带 `.git` 的 Docker 上下文使用显式提交及可选 tag 构建参数。标准 CI、Compose 演练和部署入口同步提供参数，缺少可追溯提交时构建失败。

## 验证与提交

- 先更新行为测试，确认导航、版本链接、不可隐藏归属和设置兼容策略。
- 用临时 Git 仓库验证带 tag、不带 tag 和无 Git 构建参数解析。
- 运行前端覆盖率、lint、typecheck、build，运行受影响 Go 测试。
- 运行隔离数据库 E2E 和桌面／移动、中英、浅深色布局检查；保留实际预览数据。
- 独立进行规格及代码质量审查，修复后定向复验，按工程切片本地提交。
- 最后重新构建预览，使页脚提交链接对应最终本地 HEAD；Docker daemon 不可用时如实保留 Docker 构建与完整 Compose 验收待验证。
