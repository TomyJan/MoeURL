# 管理员目标规则检查实现计划

> 使用 executing-plans 在已有 linked worktree 内联执行。仅最后一次 fresh 最强全分支终审，不派 builder、逐任务审查或复审；普通设计和正常集成沿用户无人值守授权自主决定。

**目标：** 管理员不创建短链即可检查当前已保存目标规则。
**架构：** shortlink 独立 Port／handler 复用原 validator；targetpolicy 提供窄授权桥接及原七策略函数。只读事务和前端身份／输入轮次隔离。
**技术栈：** 既有 Go／PostgreSQL／Vue3／Vuetify4，无新依赖。
**规格：** [范围](../product/scope-v0.72.0.md)、[设计](../specs/2026-11-14-v0.72.0-target-policy-check-design.md)。BASE `5f0308bb9d3d370a2a1c4917366191acd0f39cd8`。

## 全局约束

strict 单字段 targetUrl、1–2048 UTF-8 bytes、16 KiB body、拒绝控制字符／非法 UTF-8；错误900226，授权120001，基础设施900000。五秒 ReadCommitted／ReadOnly，gate先于查询；invalid_target／restricted／allowed，data恰含outcome。只用已保存七规则，无写入／外部探测，不改旧创建长度语义。不查CI、不发布部署；预算及用完清理遵守仓库交付规范。

## 审查重点

1. 未授权者不能用非法 URL 获得检查结果；Task1当前身份／授权先于结果测试。
2. 等待保存锁不能继续用旧规则；Task1确定性双事务队列、ReadCommitted新规则断言。
3. 合法目标遇关闭但损坏的任一资源不能假允许／假拒绝；Task1七坏存储逐项矩阵。
4. URL改变或切号后的迟到成功不能展示旧允许，旧finally不能解除新loading；Task2具名并发测试，Task3真实SPA场景。
5. 转义载荷不能绕过字节限制或注入重复字段，日志／响应不能泄露URL；Task1 strict／容量／日志与零写入断言。
