# v0.75.2 批量创建错误提示可达性设计

## 现状、原因与取舍

本版由 Agent 在持续自主授权下选择。PR345 唯一独立终审指出手机图无法证明错误进入视口；未直接假定缺陷，而是复用完整生产投影和 102 份产物均相同的准确产品，执行四个真实手机诊断。四次 200108 均保留预览、单次写请求且零持久化；error DOM 已出现，滚动体 scrollTop 仍为 0，错误 top 分别为中文390的811、中文320的979、英文390的1027、英文320的1295像素，全部在滚动体裁切区域外。ROOT 已查看四张原图。

根因为错误位于长说明和预览之后，固定操作区按钮不会带动正文滚动，组件只同步 opened，没有错误焦点定位。toBeVisible 只证明存在可渲染盒，不代表位于可见裁切区域。

采用当前错误的原生 focus 容器与 Vue post-flush watcher：模板以 tabindex=-1 的原生容器包住既有 v-alert；同时观察 opened、errorKey 和显式操作轮次，回调执行时仅在当前打开、有错误且容器仍存在时调用 focus()，由浏览器原生焦点滚动将错误带入视口。手动预览和实际选择文件递增本地轮次，确保同一同步错误键再次拒绝时仍定位；不在普通输入时抢焦点。回调本身不 await、不排队 timer/RAF/nextTick，避免关闭或换身份后遗留 focus。不新增 toast 或重复错误副本。是否完整进入裁切区域必须由新产品浏览器几何断言确认，不能仅依据焦点推断。

拒绝 sticky 错误区域：320×500 下英文错误近276像素，再占固定操作区会挤没输入；拒绝只搬到顶部：用户已滚动时仍可能看不到，键盘焦点也不会得到错误。原生容器可聚焦且真实浏览器负责滚动，JSDOM 只核真实 activeElement/生命周期，不用 mock scroll callcount冒视口证据。

## 状态边界与测试

错误捕获仍完全属于 useBulkCreate；不改其 generation、身份 scope、权限 epoch 或不可变 snapshot。post-flush 只消费当前呈现状态；reset 清空 opened/error，同一 flush 被关闭或卸载不得 focus。重复相同错误由实际状态转换或显式操作轮次重新定位，unknown 请求仍使用相同 ID/payload，明确失败仍允许主动 edit。CSV 格式错误主提示只给出错误、打开既有格式帮助并重新选择文件、草稿保留三项信息；六种完整规则继续留在既有帮助中，避免 320×500 手机上长错误被焦点居中裁切。

先写 BulkCreateErrorFocus.test.ts，真实 parser、组件、Vue Query 与 API transport，仅控制外部 fetch；覆盖明确失败/解析失败/重复未知请求及关闭、身份退休、卸载。断言 activeElement 指向含实际错误正文的容器、输入与UUID不变和无额外请求。移除定位 watcher 必须使焦点断言失败；移除当前 opened/error 守卫必须被退休/关闭用例捕获。

真实 E2E 在中英390/320以及桌面、20行预览下，不先 scroll/focus 错误；以真实拒绝或受控丢ack触发，记录 alert/body/viewport rect，要求错误正文处于裁切区域内且焦点容器包含错误，固定动作可用、无横向溢出。关闭/身份异步晚到由组件和 composable 原有及新增测试共同覆盖。拒绝后修改与未知重试不能因定位而新建批次。
