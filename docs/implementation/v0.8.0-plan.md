# v0.8.0 多域名管理实施计划

状态：功能实现与分阶段本地验证已有记录，当前提交的全量 Playwright 与 Compose smoke 待复验；目标 CI、race、安全扫描、真实 DNS/TLS、隔离恢复和生产验收待目标环境证据。

## 目标和边界

交付管理员管理短链域名、内置组授权、全局默认切换、用户创建选择，以及按短链所属域名限定公开访问的完整闭环。产品约束见 [v0.8.0 范围](../product/scope-v0.8.0.md)，详细数据流和并发约束见 [设计](../superpowers/specs/2026-09-14-v0.8.0-multi-domain-design.md)。本版本不管理系统访问域名，不自动申请 DNS/TLS，也不迁移历史短链。

## 实施阶段

1. **迁移与授权：** 建立 `domain_user_group`，给已有和新初始化的默认短链域名回填内置组授权；迁移 Down 保留历史域名和短链。
2. **域名 Service/API：** 规范化根 Origin、校验同义 authority、启停与引用保护、单事务默认切换和乐观并发；管理接口同时检查 `admin:access`、`domain:manage`。
3. **短链创建及访问：** 省略 `domainId` 保持旧创建行为，显式选择按用户组权限与域名授权取交集；全部公开路径重新检查真实 `Host` 和关联域名启用状态，列表 URL 不受默认切换影响。
4. **前端：** 域名管理页面、可用域名选择、缓存同步、脏草稿和冲突恢复、双语与双视口布局。
5. **集成和上线说明：** 隔离 Compose 双 Host E2E、迁移往返、SQLC 零漂移、后端和前端门禁；文档写明升级别名检查、代理保留 Host、DNS/TLS 责任和真实环境验收。

执行顺序、失败测试和原子提交以 [任务级开发计划](../superpowers/plans/2026-09-14-v0.8.0-multi-domain.md) 为准。各项只在对应命令实际执行且通过后进入 [验收清单](v0.8.0-acceptance.md)；目标 CI、Linux race 和公网证书不能由本地结果替代。

## 上线检查点

- 生产迁移前确认旧应用与 `00013` 的兼容或先停旧应用，先完成卷外备份与隔离恢复。
- 对每个已发布短链核查实际公开 Host 和端口；不一致的旧别名必须在切换前处理，不能以转发头绕过。
- 每个启用域名都需要 DNS、有效 HTTPS 证书及指向同一 App 的代理入口；公开 URL 与请求 Host 必须一致。
- 默认切换与停用被引用域名有用户可见影响，应在维护窗口内验证旧链接、错误 Host、停用/恢复和访问量口径。
