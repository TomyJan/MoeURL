# v0.6.0 实施计划

状态：实施计划已于 2026-08-29 确认，代码实现与生产验收尚未完成。

## 版本目标

v0.6.0 在不新增短链产品能力的前提下，把 v0.5.0 功能基线交付为可验证的单机生产部署：应用通过 Docker Compose 运行，公网 TLS 由外部反向代理终止，PostgreSQL 只保留私有网络访问，并补齐进程生命周期、HTTP 防护、数据库 readiness、初始化与登录保护、Session 清理、备份恢复和安全 CI。

范围以 [v0.6.0 产品范围](../product/scope-v0.6.0.md) 和 [生产就绪设计](../specs/2026-08-29-v0.6.0-production-readiness-design.md) 为准，工程切片与命令见 [详细实现计划](v0.6.0-detailed-plan.md)。

## 实施顺序

1. 配置契约与生产初始化 Token。
2. HTTP 中间件、Server 边界、数据库启动探测和健康端点。
3. 主进程信号处理、有界优雅退出和后台任务生命周期。
4. 登录失败状态 migration、恒定失败路径和数据库一致限流。
5. Session 分批清理与应用生命周期装配。
6. 前端初始化 Token 状态清理和真实 E2E。
7. Compose 安全默认值、开发覆盖和部署、备份、恢复、升级文档。
8. race、漏洞、镜像扫描、Compose smoke test 和最终发布验收。

## 原子边界

每个工程切片必须先写失败测试并确认按预期失败，再写最小实现并运行定向回归；生成文件只能通过仓库锁定版本的生成入口更新。每个切片通过相关验证后创建本地原子提交，不把部署、认证、前端和文档变化混成一个不可审查提交。

## 兼容边界

- `/api/v1/health` 保留路径，但提升为数据库 readiness 语义。
- 初始化请求只在 production 要求 `setupToken`，development 和既有 E2E 可省略。
- 登录错误凭据和禁用账号的既有码保持不变，只新增稳定的登录限流业务码。
- 短链访问、统计、权限目录和用户组管理契约不变。
- migration Down 只删除登录失败临时状态；应用代码回滚可以暂时保留该表。
- 生产 Compose 不保留 PostgreSQL 宿主端口；本地直连数据库使用显式开发覆盖文件。

## 生产验收

版本完成前必须同时取得以下证据：

- Go 全量测试、vet、业务源码 100% 覆盖率、Docstring Coverage 不低于 80%、SQLC 零漂移和 `go test -race ./...`。
- 前端 lint、typecheck、Vitest、四项 100% 覆盖率、生产构建和全量 Playwright E2E。
- production Compose 配置解析、空卷启动、readiness、首次初始化、数据写入、应用重启保留数据和限定 project 清理通过。
- `govulncheck` 和最终容器镜像高危、严重漏洞扫描通过，工具与 Action 使用固定版本。
- 备份在隔离数据库或隔离 Compose project 中恢复，并验证 migration 版本、管理员登录和短链数据。
- 验收文档记录实际运行时、命令、环境变量、清理状态，以及目标 CI 提交 SHA、运行链接和每个任务结果。
